## 总览摘要

今天的榜单把昨天"AI 代理基础设施化"的趋势往前推了一大步：**Agent 技术栈开始像云原生栈一样分层，而且每一层都有了明确的玩家**。Google 一天之内贡献了上下配套的两个项目——google/ax 是声明式编排层（用 YAML 定义任务、CLI 长得像 kubectl），agent-substrate/substrate 是底层沙箱执行运行时（把大量代理高密度复用到少量机器上）；superdesigndev/treg 补上了"工具网关"这一层（一个 token 调 60+ 供应商的 3,000+ 端点，自称工具界的 OpenRouter）；dream-num/univer 则把表格、文档、幻灯片做成可被代理调用的 headless 办公运行时。编排、执行、工具、办公，四层各就各位——"Agent 时代的 Kubernetes"已经不只是比喻，而是正在落地的工程形态。

第二个信号同样值得记住：**"确定性工程 × Agent 混合"正在成为做 Agent 产品的共识方法论**。阿里开源的 open-code-review 把这件事讲得最透：文件选择、打包、规则匹配、评论定位这些绝不能出错的环节，用确定性工程做硬约束，LLM 只负责动态决策，结果是同样的模型下精度更高、token 只用 1/9；video-use 也是类似思路——12 条硬规则保证剪辑的生产正确性，转写文本是代理的主要工作界面，绝不靠堆视频帧硬看。行业正在从"把一切交给代理"的狂热，回归到"确定性骨架 + Agent 大脑"的务实。

需要说明的是：今日 GitHub Trending 日榜仅返回 8 个项目（经多次抓取核实），按 CLAUDE.md 的补齐规则，本期从周榜热度中选取两个今日榜之外的项目——alibaba/open-code-review（本周 +12,590，周榜第一）与 Tencent/WeKnora（本周 +5,303）补齐到 10 个，其 star 数据按本周口径标注。中国大厂把内部历经两年验证的 AI 工具链直接开源并冲上全球榜单前列，本身就是今天不可忽视的趋势。

📖 项目是干什么的

AX 是 Google 开源的声明式 Agent 编排运行时，定位一句话就能讲清：**像 Kubernetes 管理容器一样管理 AI 代理的工作负载**。它跑在 Agent Substrate（今日 #5）之上做沙箱化执行，设计目标是"在单个集群里跑数十亿个自主代理任务"。用户用 `ax.io/v1alpha1` 的 YAML 清单声明任务，然后用 `ax apply -f task.yaml` 提交，工作流和 kubectl 几乎一模一样。

它只提供四个小原语，却覆盖了代理运行的全部要害：**Task** 把不可信的代理代码关进带 CPU/内存限制的隔离沙箱；**Workspace** 提前把 Git 仓库、MCP 服务器、技能包预装到位，让每个代理"暖启动"；**Gateway** 把出站流量锁死在显式主机白名单里；**Model** 声明平台自身使用哪个 LLM，凭证从 Kubernetes Secret 注入。此外还支持 `ax suspend`/`ax resume`（把空闲代理暂停、之后从断点精确恢复）和 `ax ssh`（直接钻进运行中的沙箱看代理在干什么）。

技术上它是典型的云原生项目：Go 编写、CLI 通过 gRPC 与控制面通信、控制面部署在 Kubernetes 上（用 Redis 做状态存储，ko 构建镜像），Apache 2.0 协议。README 也很坦诚：核心概念和协议仍在快速迭代，稳定版之前大概率会有破坏性变更。

💡 可借鉴的优点

- **产品思维**：抓住了代理作为"新型工作负载"的本质——它既不是无状态微服务，也不是跑完即止的批处理，而是会累积状态、会调用模型 API、没人看着就能一直烧钱的东西；四个原语正好对应隔离、预热、网络围栏、模型管控四个真实风险
- **架构设计**：完全复用 Kubernetes 训练了十年的用户心智——声明式、apply/get/watch、多文档 YAML、跟随 kube-context 切换集群，使用者零学习成本，这种"站在巨人范式上"的设计比自创一套 DSL 聪明得多
- **工程化**：`debug: true` 才开放 ssh、凭证只走 K8s Secret、网络默认拒绝，安全默认值（secure by default）贯穿始终；还提供 demo.sh 一键演示完整生命周期
- **文档体验**：文档按"概念 / 清单 / 沙箱 / 运行器 / 网络 / 架构"分表组织，每张表都写明"读它能解决什么"，检索路径极其清晰

🌟 特别亮眼的地方

AX 最有标志性的地方，是 Google 正式把"代理工作负载"纳入了 Kubernetes 的世界观：当代理数量从几个变成几百万个，调度、隔离、密度、成本就成了核心问题，而这正是 Google 最擅长的领域。单日 +2,305 star 说明市场在等待一个"Agent 时代的编排标准"，AX 加上底层 Substrate 的组合，是目前最像标准答案的一个——所有做 Agent 平台的人都该研究它的原语划分。

📖 项目是干什么的

MVT（Mobile Verification Toolkit）是移动设备取证工具集，用于自动化收集取证痕迹，判断 Android 和 iOS 设备是否可能被间谍软件入侵。它由大赦国际安全实验室在 2021 年"飞马（Pegasus）"间谍软件调查中开发并发布，至今仍由大赦国际和社区维护。工具支持用公开的入侵指标（IOCs，来自大赦国际等研究机构）扫描已知间谍活动的痕迹。

近期项目合并了 v3 分支，带来破坏性变更，命令结构也重新梳理：现在提供 `mvt-ios`、`mvt-android` 两个平台命令负责分析设备提取物，而 `mvt` 主命令承载版本、shell 补全、插件管理、IOC 下载等通用能力。插件包可以扩展额外的取证模块和顶层命令。安装方式很现代：pip 或 uv 一条命令即可，还能为 Bash/Zsh/Fish 生成自动补全。

README 保持了一贯的诚实：MVT 是面向技术人员和调查人员的研究工具，不是给普通用户自检用的；仅靠公开 IOC 无法证明设备"干净"，可靠结论需要非公开威胁情报，并通过大赦国际或 Access Now 的援助通道获取支持。项目以自定义许可证发布，目的是防止被滥用于对非自愿者的隐私侵犯。

💡 可借鉴的优点

- **产品思维**：为"可能被国家级间谍软件盯上的人"（记者、律师、公民社会）提供可负担的检查手段，公共价值型开源的定位非常清晰
- **架构设计**：v3 把平台相关命令与通用命令分层、把能力扩展做成插件机制，工具在向更可维护的架构演进
- **工程化**：uv 工具化安装、shell 补全只在显式 `--install` 时才写配置、CI 徽章与完整文档站，命令行工具的易用性打磨到位
- **协作模式**：与 Access Now 等公益组织建立成熟的取证援助通道，是开源项目与 NGO 协作的长期范本

🌟 特别亮眼的地方

MVT 连续两天登上 Trending（今日 +441 比昨日 +177 还高），说明在 AI 叙事之外，"我的手机有没有被监控"这种基本安全诉求始终有真实的关注度。它把调查国家级间谍软件的能力从少数安全公司手里交到潜在受害者手中，是"开源改变现实权力结构"的持久样本。

📖 项目是干什么的

这是 Anthropic 官方维护的金融行业 AI 工作流参考仓库，覆盖投行、股权研究、私募股权、财富管理四大场景，提供一批以工作流命名的端到端代理：Pitch Agent（可比公司、先例交易、LBO 一路做到品牌 pitch deck）、Meeting Prep、Market Researcher、Earnings Reviewer、Model Builder（DCF/LBO/三表模型，活在 Excel 里）、GL Reconciler（总账对账找差异、追根因）、Month-End Closer、Statement Auditor、KYC Screener 等，目前共 10 个。

- **架构设计**："同一份提示词与技能，两种运行方式"的单一事实源设计，从根上避免了双轨维护；技能在 vertical 写一次、用脚本同步到各代理

- **合规意识**：README 用醒目声明明确"不构成投资建议、不执行交易、不绑定风险、不写账本，所有产出留待人工签核"——这是强监管行业里产品能被采纳的前提

📖 项目是干什么的

Univer 是一个开源的全栈同构 Office SDK，让你在自己的产品里构建电子表格、文档和幻灯片体验，而不是被绑定到某个托管应用或固定 UI 上。它不是"表格文件查看器"，而是一个用来搭建生产力界面的框架：插件化架构、Canvas 渲染、自研公式引擎，以及一套在浏览器和 Node.js 上通用的 Facade API。

它提供三种集成路径，把"快速上手"和"完全可控"都照顾到了：**Preset 模式**用策划好的插件包（@univerjs/presets）几行代码跑出可用应用；**Plugin 模式**手动组合包、控制插件注册顺序和包体积；**Headless 模式**在 Node.js 里跑工作簿和文档逻辑，没有 UI——这正是它今天作为"AI 基础设施"上榜的原因：代理、自动化和服务端工作流可以直接调用表格/文档能力。

开源核心包含表格（最成熟，覆盖公式、数据验证、条件格式、筛选排序、批注等）、文档（富文档模型与编辑 UI）、幻灯片（开发中），视图层基于 React 18，同时提供 Vue、Web Components 的集成壳。实时协作、导入导出、打印、图表、透视表等放在 Univer Pro 商业版。生态里还有 univer-mcp（用自然语言驱动表格）和面向代理的 univer-sdk-skills。

💡 可借鉴的优点

- **产品思维**：明确区分"我提供搭积木的 SDK"和"我不替你做成品"，把嵌入场景（SaaS、内部工具、BI、AI 应用）作为主战场，边界清晰
- **架构设计**：同构（isomorphic）是核心亮点——浏览器里的交互逻辑和 Node.js 里的无头处理共用同一套架构，一份能力两处复用；插件优先让功能可增删、可替换、可懒加载
- **工程化**：monorepo 里测试、类型检查、e2e（Playwright）、视觉对比、Codecov、Storybook 一应俱全；兼容性文档细到浏览器版本、polyfill、构建工具的 exports 字段
- **商业模式**：开源核心与 Pro 能力的边界在 README 里写得明明白白，既不藏功能也不模糊承诺，是开源商业化的干净样本

🌟 特别亮眼的地方

当代理开始替人操作表格和文档时，"可被程序调用的 Office 运行时"就成了刚需——Univer 的 Headless 模式正好卡在这个位置，且比 WPS、微软 Office 的自动化接口更开放、更适合嵌入。它从一个"国产开源表格"演进成"AI 时代的办公基础设施"，这个转身方向值得所有做生产力工具的开发者关注。

### #5 agent-substrate/substrate ⭐

| 属性 | 信息 |

| ⭐ Stars | 2,998 (+245) |

| 📦 分类 | AI 基础设施 / 沙箱执行运行时 |

📖 项目是干什么的

Agent Substrate 是一个安全默认的代理执行运行时，目标是跑上百万个沙箱、密度做到标准容器运行时的 10 倍。它的核心洞察很巧妙：**代理类应用绝大多数时间都在空闲**，于是可以把一大批"actor"（代理这样的应用）映射复用（multiplex）到少量就绪的"worker"上，需要时再快速唤醒。官方演示里，约 250 个有状态 actor 被复用到仅仅 8 个物理 Pod 上，超卖比超过 30 倍。

性能指标围绕"快速休眠与唤醒"设计：恢复操作低于 500ms，每秒可完成 500+ 次挂起/恢复激活，通过全状态快照（易失性内存 RAM + 文件系统状态）在休眠周期之间完整保留工作记忆。隔离上采用原生零信任的内核与网络隔离，支持 microVM 和 gVisor 两种沙箱技术，并对所有沙箱类型提供一致的生命周期操作。

它构建在 Kubernetes 之上（用 Pod 和 Pod 自动扩缩做基础设施供给），自己只做代理专用的调度与控制以降低延迟，且刻意保持"低主见"——管理的不必是 AI 代理，任何 OCI 容器都能跑，兼容 ADK、LangChain、Claude Code、Codex、MCP 等各种技术栈。google/ax（今日 #1）就是建在它之上的分布式运行时，CNCF 沙箱项目 kagent 也在使用。Go 编写、Apache 2.0，目前处于早期阶段。

💡 可借鉴的优点

- **产品思维**：把"代理很闲但占着机器"这个资源浪费点，变成密度和成本优势，30 倍超卖对大规模部署是实打实的省钱
- **架构设计**：actor/worker 的映射模型、全状态快照、按需唤醒，本质上是把"进程休眠"思想做到了集群调度层；同时不另起炉灶，地基完全复用 Kubernetes
- **工程化**：提供 Counter、Sandbox、Claude Code Multiplex、请求停泊（Request Parking，路由器在 worker 占满时挂起请求而非返回 503）、自动扩缩 WorkerPool 等六个 Demo，每个设计点都有可复现的验证
- **生态站位**：框架和 harness 无关、内核层管理标准 OCI 容器，不绑定任何一家代理生态，反而成为公共执行层；威胁模型、滚动升级手册、可观测指南等运维文档齐全

🌟 特别亮眼的地方

Substrate 和 AX 组成了今天最完整的一套"Agent 云原生"叙事：一个管调度密度、一个管声明编排，且都出自 Google、都复用 Kubernetes。它揭示了一个容易被忽视的事实——当代理规模化运行时，真正的瓶颈不是模型够不够聪明，而是机器密度、唤醒延迟和隔离成本。这是云基础设施厂商才有的降维视角。

📖 项目是干什么的

Treg 一句话定位就是"**工具界的 OpenRouter**"：OpenRouter 用一个接口聚合各家模型，Treg 用一个 base URL、一个 token 聚合各家工具——60+ 供应商的 3,000+ 端点，覆盖 SEO 与反链、社媒与趋势、人员与公司数据、广告、网页抓取、图像视频生成。按调用计费、最低一美分，不需要在任何供应商那里注册开户。它最初为 Superdesign 团队自建，托管在 treg.to，任何人也可以自托管。

它解决的痛点很具体：代理干真活需要的工具，大多藏在没人会为单次运行购买的订阅后面（Semrush 139 美元/月、Moz 99 美元/月、Crunchbase 99 美元/月、Apollo 59 美元/席位），或者干脆只有注册墙、没有公开 API。Treg 统一持有这些账号，把成本摊到每次零点几美分的调用上。它也支持把团队自己的 API key、OAuth 连接、供应商 CLI、SKILL.md 注册进来，凭证永远留在服务端。

最关键的设计原则是：**代理只中继（relay）、绝不建模（never models）上游，认证在服务端注入**——这样上游 API 怎么变它都不受影响，调用方也永远拿不到 key。凭证使用有明确的优先级阶梯：团队自己的工具 → 团队存的密钥 → 免费公开路由 → Treg 自己的账号（计费）；余额不足直接返回 HTTP 402 并带上机器可读的余额、预估费用和充值链接，代理无需读懂自然语言就能处理。工具分三类：endpoint（HTTP API）、CLI（供应商二进制，可在服务端执行）、skill/bundle（SKILL.md 配方 + 密钥 + 工具打包注册）。

💡 可借鉴的优点

- **产品思维**："问任务，别问工具"——用户不需要知道哪家卖反链数据，直接按"我要做什么"搜索、看价、调用，把工具发现和采购的复杂度全部吃掉
- **架构设计**：忠实中继 + 服务端注入凭证是非常稳的网关范式，自己不实现任何业务逻辑，上游变更零维护；自己的密钥永远优先且不计费，避免重复扣费
- **工程化**：一个安装脚本、一条 login、一次 call 就能跑通；`treg scan` 只读预览可上传的密钥/技能/CLI，`treg upload` 幂等注册；还提供 Enrich Arena 让用户横向比较各家数据供应商的答案、成本与速度
- **生态集成**：同时提供 Claude Code 插件、Claude Connectors（读写分离以给出准确安全信号）、MiniMax 插件、MCP 接口和 llms.txt 代理引导文件，接入路径覆盖了所有主流代理形态

🌟 特别亮眼的地方

Treg 补上了 Agent 技术栈里长期缺失的一层：**工具的统一入口与计费层**。模型有 OpenRouter、执行有沙箱、编排有框架，但代理真正干活要调用的几百个商业 API 一直没有公共网关。它把"API key 经济"改造成"按次微付费经济"，这个定位如果成立，会成为所有代理对外调用的默认出口——值得基础设施创业者高度关注。

📖 项目是干什么的

Open Code Review（命令名 `ocr`）是阿里集团内部官方 AI 代码评审助手孵化出的开源项目：过去两年在阿里内部服务了数万开发者、识别出数百万个代码缺陷，经过大规模验证后才开源。它读取 Git diff，通过一个具备工具调用能力的代理把变更文件发给可配置的 LLM，生成行级精确的结构化评审意见；代理可以读取完整文件内容、搜索代码库、查看其他变更文件获取上下文，做的是深度评审而非表面的 diff 反馈。除了 diff 评审，`ocr scan` 还能直接评审整个文件，用于审计不熟悉的代码库或没有实质 diff 的目录。

它最核心的设计哲学是**"确定性工程 × Agent 混合，各干各最擅长的事"**。绝不能出错的评审步骤，用工程逻辑而非模型来保证：精确的文件选择（确保不漏掉任何重要变更）、智能文件打包（把相关文件如中英文 properties 归为一个评审单元，每个 bundle 作为上下文隔离的子代理运行，分而治之，天然支持并发，在超大变更集上依然稳定）、细粒度规则匹配（用模板引擎按文件特征匹配规则，把模型注意力聚焦、从源头消除信息噪音）、独立的评论定位与评论反思模块（系统性提升位置和内容的准确度）。代理的能力则集中在动态决策与动态上下文获取上：场景深度调优的提示词，以及从大规模生产数据的工具调用轨迹（调用频率分布、单工具重复率、新工具对调用链的影响）中蒸馏出的专用工具集。

数据是它最硬的部分：基于 50 个知名开源仓库、200 个真实 PR、10 种编程语言构建，并由 80+ 资深工程师交叉验证、标注了 1,505 个真实问题（AACR-Bench 数据集已开源到 Hugging Face）。基准结果显示：与通用代理（Claude Code）相比，在同一个底层模型下，它的精确率（Precision）和 F1 显著更高，token 消耗仅约 1/9，评审速度更快；召回率（Recall）略低是刻意权衡——宁可少报，也不要噪音误报。

💡 可借鉴的优点

- **产品思维**：精准命中通用代理做评审的三大痛点——大变更集"偷工"漏文件、问题位置漂移、纯语言驱动导致质量随提示词波动；并用"精度优先、1/9 成本"给出可量化的差异化
- **架构设计**："确定性骨架约束流程、Agent 只在需要判断力的地方发挥"是今天榜单最值得抄的架构范式；文件打包 + 隔离子代理同时解决了上下文爆炸和并发两个难题
- **工程化**：评审模式覆盖工作区、分支范围（merge-base）、单 commit、全文件扫描、JSON 输出，还支持会话恢复；Delegation 模式让宿主代理用自己的模型评审、OCR 只负责文件选择和规则解析，无需另配 API key
- **生态集成**：提供 Claude Code、Codex、Cursor、Kimi Code、OpenCode 插件与 MCP 服务，并打通 GitHub Actions、GitLab CI 等 CI/CD；Session Viewer 可在浏览器回放评审、标记已修复/忽略；拿下 OpenSSF Gold 徽章

🌟 特别亮眼的地方

这是"**中国大厂内部工具链开源**"最有说服力的样本之一：不是把一个 demo 扔出来，而是带着两年生产验证、数万用户、百万级缺陷数据、公开基准和开源数据集一起亮相，本周 +12,590 冲上全球周榜第一。它对行业最大的贡献，是用硬数据证明了"纯 Agent"不如"确定性工程 × Agent"——这个结论会影响接下来一整批 Agent 开发工具的设计方向。

## 📊 今日趋势洞察

**核心方向：Agent 技术栈进入"分层定型"阶段。** 今天的榜单罕见地把一整套栈同时摆上台面：google/ax（声明式编排）+ agent-substrate/substrate（高密度沙箱执行）是 Google 的上下层配套，superdesigndev/treg（工具网关）补上对外调用的统一入口，dream-num/univer（headless 办公运行时）补上文档与表格能力。对比昨天"代理基础设施化"的判断，今天的信号更进了一步——每一层都有了明确的范式和玩家，且整体刻意复刻云原生（Kubernetes）的分层结构与用户心智。行业共识正在收敛：Agent 的未来不是单个聪明的对话框，而是一套可调度、可隔离、可治理的分布式系统。

**升温领域："确定性工程 × Agent 混合"成为新方法论。** alibaba/open-code-review 用公开基准证明：关键环节交给确定性工程做硬约束、LLM 只做动态决策，可以做到精度更高、成本只剩 1/9；video-use 的"12 条硬规则 + 转写文本主界面"、treg 的"只中继不建模、服务端注入凭证"，都是同一思想的不同表达。经历了一年"全交给代理"的尝试后，行业正在重新认识工程约束的价值——这对所有 Agent 产品的架构设计都是直接可用的指导。

**对开发者的启发：** 一是大厂内部工具链开源正在成为新的项目源头，阿里（代码评审）、腾讯（知识框架）带着真实生产数据和方法论出场，比从零做的 demo 更有学习价值，也值得关注其架构与基准；二是"生态位"比"大而全"更容易成功，treg 做工具网关、claude-code-templates 做配置聚合，都证明在爆发的 Agent 生态里，做好一层（网关、模板、监控、运行时）就能成为关键节点；三是代理的落地场景持续外扩，从写代码延伸到视频剪辑（video-use）、办公文档（univer）、企业知识（WeKnora）与金融工作流，每个垂直场景都还缺"把链路做穿"的产品，窗口依然敞开。
