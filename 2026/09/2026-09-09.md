📖 项目是干什么的

AI 编码代理有一个普遍的"废话"问题：你问它一个简单的修复方案，它会先来一段"Great question!"的开场白，再绕一大圈背景介绍，最后才给出答案。对于任何有时间压力的开发者来说，这种输出模式极其低效。**i-have-adhd** 就是为了解决这个问题而生的——它是一个 Agent Skill，用 10 条简洁的规则约束代理的输出行为。

这 10 条规则的核心哲学来自 ADHD 临床治疗的认知框架：**行动先行、步骤编号、结尾给下一步、压制跑题、每轮重述状态、时间估计精确到分钟、让成功可见、错误陈述用事实语气、列表最多 5 项、不要开场白/总结/结尾**。安装后，代理的输出风格从"热心但啰嗦的同事"变成了"经验丰富的高级工程师"——直接给方案、给命令、给文件路径。

💡 可借鉴的优点

- **产品思维**：精准切中了"代理输出过于冗长"这一高频痛点，用最轻量的方式（10 条 Markdown 规则）解决了一个普遍问题
- **架构设计**：零依赖、零配置，一个 SKILL.md 文件就是全部，极致的简洁
- **工程化**：规则可 fork 可定制，用户可以根据自己的偏好微调输出风格
- **社区运营**：项目名"i-have-adhd"极具辨识度和传播性，Star 可以从 README 的 Before/After 对比中直接获得价值感

🌟 特别亮眼的地方

这个项目的深层洞察是：**约束 AI 的输出行为，比增强 AI 的能力更重要**。当模型能力已经足够强大时，瓶颈不在"它能不能做"，而在"它怎么表达"。从 ADHD 临床实践中借鉴的认知框架，证明了跨学科思维在 AI 产品设计中的巨大价值——心理学对人类注意力的研究，恰好可以指导 AI 输出的信息架构。

📖 项目是干什么的

让 AI 代理生成设计师不会骂你的图表——这是 **diagram-design** 的核心承诺。项目提供 39 种编辑级图表类型（架构图、流程图、甘特图、Sankey 图、鱼骨图、Wardley 地图等），全部用自包含的 HTML + SVG 实现，不依赖 Mermaid、不需要 Figma，直接在浏览器中打开就能看。

v2.5.10 新增了 10 种布局语法，v2.3 引入了语义化系统模式。每种图表都有三个变体：极简浅色、极简深色、完整编辑风格。核心设计哲学是"**最高质量的操作通常是删除**"——每个节点都必须赚到它的位置，强调色只用于 1-2 个需要读者首先注意的元素，目标信息密度 4/10。

项目作者 Cathryn Lavery 本身是内容创作者（littlemight.com）和电商品牌运营者（BestSelf.co），这个技能诞生于她自己使用 Claude 生成图表时"得到一堆丑陋圆角框"的真实痛点。

💡 可借鉴的优点

- **产品思维**：从"AI 生成的图都很丑"这个具体痛点出发，定义了"编辑级"品质标准，而非仅仅"能用"
- **架构设计**：纯 HTML + SVG，无构建步骤、无 JS 依赖，与 Agent Skills 标准完美契合——代理可以直接生成和修改
- **工程化**：39 种图表类型覆盖了从技术架构到商业分析的几乎全部场景，语义化模式让行为描述与布局解耦
- **社区运营**：提供 Live Gallery 让用户先看到效果再安装，大幅降低决策成本

🌟 特别亮眼的地方

"No Figma. No generic rounded boxes. No 30-minute color-picking sessions." 这三个"No"精确描述了目标用户的痛苦。这个项目证明了一个重要趋势：**Agent Skills 的竞争正在从"功能"转向"品质"**——不是"能不能画图"，而是"画出来的图够不够上得了台面"。当代理的输出品质达到设计师可接受的水平时，整个内容生产流程将被重新定义。

📖 项目是干什么的

**ECC（Engineering Command Center）** 是一个代理级别的"操作系统"——它不是一个技能，而是一整套让代理"像高级工程师一样工作"的协调系统。核心流程是：**plan → test → implement → review → verify → remember → improve**。你不需要在每个 prompt 里重复这套流程，安装一次就成为代理的默认工作方式。

ECC 提供了惊人的规模：68 个专业代理（规划、审查、构建修复、安全、架构）、286 个技能（TDD、研究、安全、文档、前端、数据、ML、运维）、94 个命令入口，外加 hooks、记忆、持续学习、直觉系统和 AgentShield 安全扫描。它支持 Claude Code、Codex、OpenCode、Cursor、Gemini、Zed、GitHub Copilot 等 7+ 个代理平台。

最值得关注的是它的安全层 **AgentShield**——对 prompts、hooks、MCP 配置、权限、secrets 和代理文件进行扫描，这在代理安全越来越受重视的当下具有前瞻意义。

💡 可借鉴的优点

- **产品思维**：从"单个技能"升维到"完整工程系统"，定义了代理工作方式的全生命周期
- **架构设计**：68 个代理 + 286 个技能的分层架构，每个代理专注于一个领域，组合起来覆盖整个开发流程
- **工程化**：`npx ecc-universal setup` 一键安装，支持引导式配置；每周跨 7 个平台发布更新
- **社区运营**：MIT 开源 + ECC Pro 付费 GitHub App 的商业模式，平衡了社区增长和可持续运营

🌟 特别亮眼的地方

254K⭐ 让 ECC 成为 GitHub 上最大的代理工具项目之一。它的核心洞察是：**代理不缺能力，缺的是工程纪律**。一个没有测试习惯、不做代码审查、不管理记忆的代理，再聪明也只是一个"不靠谱的天才"。ECC 用软件工程的最佳实践（TDD、code review、plan-first）驯服了代理的随机性，这是"代理可靠性"领域最成熟的解决方案。

📖 项目是干什么的

**HyperFrames** 是 HeyGen 开源的视频生成框架：用 HTML + CSS + 可寻址动画写视频，用 headless Chrome + FFmpeg 渲染成 MP4。核心卖点是 **"Write HTML. Render Video."**——代理已经会写 HTML，所以 HyperFrames 让代理天然具备了视频制作能力。

项目提供了 20 个 Agent Skills，覆盖完整的视频生产循环：`/product-launch-video`（产品发布视频）、`/faceless-explainer`（无人脸解说视频）、`/pr-to-video`（PR 变更日志视频）、`/motion-graphics`（动效短片）、`/music-to-video`（音乐驱动视频）等。还有一套 **frame.md** 设计系统——它是你品牌 design.md 的视频版翻译层，让代理能用你的品牌规范制作视频。

v2 版本的 HyperFrames Stack 已经非常完整：CLI、Core Engine、Catalog（可复用组件库）、Studio（浏览器编辑器）、AWS Lambda 分布式渲染、hyperframes.dev 社区 playground。

💡 可借鉴的优点

- **产品思维**："HTML 即视频"的范式创新，将视频制作的门槛从"会用剪辑软件"降低到"会写 HTML"
- **架构设计**：Adapter-based 动画系统（GSAP / CSS / Lottie / Three.js / Anime.js / WAAPI）提供了最大的灵活性；确定性渲染（同输入同输出）使 CI/回归测试成为可能
- **工程化**：20 个技能按意图路由——代理只需描述"做什么"，路由器自动选择工作流
- **生态思维**：开源 Apache 2.0 + 商业 HeyGen 平台，形成了"开源用户→商业客户"的转化漏斗

🌟 特别亮眼的地方

日增 2,628⭐ 是今日 Top 10 的最高值。HyperFrames 的真正意义不在于"又一个视频工具"，而在于它**重新定义了视频的创作范式**：视频不再是设计师在时间线上拖动素材，而是开发者（或代理）用声明式语法描述意图，然后确定性地渲染出结果。这使得视频生产可以像软件开发一样——有版本控制、有自动化测试、有 CI/CD 管线。

📖 项目是干什么的

**Superpowers** 是一套完整的编码代理开发方法论框架。它的核心理念是：代理不应该直接写代码，而应该先理解你要做什么、设计方案、制定计划、然后用子代理逐步执行。整个流程是自动触发的——代理看到你在构建东西时自动启动，无需手动调用。

工作流覆盖 7 个阶段：brainstorming（苏格拉底式设计精炼）→ git-worktrees（隔离工作空间）→ writing-plans（拆分为 2-5 分钟的任务）→ subagent-driven-development（子代理执行+两阶段审查）→ TDD（严格 RED-GREEN-REFACTOR）→ code-review（按严重度评审）→ finishing（合并/PR/保留/丢弃）。

Superpowers 支持所有主流代理平台：Claude Code、Codex、Cursor、Devin、Factory Droid、Gemini CLI、GitHub Copilot、Grok Build、Kimi Code、OpenCode、Pi、Hermes Agent——是目前跨平台支持最广的代理方法论框架。

💡 可借鉴的优点

- **产品思维**：把软件工程最佳实践（TDD、code review、plan-first、YAGNI）固化为代理的"肌肉记忆"
- **架构设计**：技能自动触发机制——代理在每个任务前自动检查相关技能，是"强制"而非"建议"
- **工程化**：子代理驱动开发（subagent-driven-development）让主代理可以连续自主工作数小时不偏离计划
- **生态思维**：283K⭐ + 12 个平台支持 + Prime Radiant 商业服务，是开源开发方法论的标杆

🌟 特别亮眼的地方

283K⭐ 使 Superpowers 成为 GitHub 上 Star 最多的代理项目之一。它与 ECC 形成了有趣的竞争格局——两者都是"代理操作系统"，但 Superpowers 更偏"方法论"（怎么工作），ECC 更偏"工具箱"（用什么工作）。这种竞争本身说明了市场的成熟度：**代理开发方法论已经是一个独立的产品品类**。

📖 项目是干什么的

一个 CLAUDE.md 文件解决 Andrej Karpathy 指出的 LLM 编码四大痛点：**错误假设（不确认就开干）、过度工程化（100 行能解决非写 1000 行）、手术刀变电锯（改 A 顺手"改进"B）、目标模糊（做完不知道算不算成功）**。

项目将这四个痛点转化为四条原则：**Think Before Coding**（先想再做——说出假设、给出多种解读、该反对就反对）、**Simplicity First**（最少代码解决问题——没要求的功能不加、单用途代码不抽象、200 行能变 50 行就重写）、**Surgical Changes**（只动该动的——不"顺便改进"、不重构没坏的、匹配现有风格）、**Goal-Driven Execution**（定义成功标准——把命令式任务转化为声明式目标+验证循环）。

关键洞察来自 Karpathy 本人："**LLMs are exceptionally good at looping until they meet specific goals... Don't tell it what to do, give it success criteria and watch it go.**"

💡 可借鉴的优点

- **产品思维**：以 AI 领域最具影响力的技术领袖的公开反思为起点，用一个文件解决四个高频痛点
- **架构设计**：一个 Markdown 文件 = 全部产品，可以直接放入任何项目的 CLAUDE.md 或合并到现有配置
- **工程化**：提供了 Claude Code Plugin 和 Cursor Rule 两种安装方式，覆盖主流开发环境

📖 项目是干什么的

**MarkItDown** 是微软开源的轻量级 Python 工具，将各种文件格式转换为 Markdown——PDF、PowerPoint、Word、Excel、图片（EXIF + OCR）、音频（转录）、HTML、CSV、JSON、XML、ZIP、YouTube URL、EPub 等。它不是为了让人类阅读转换后的文档（那是 Pandoc 的活），而是专为 LLM 和文本分析管线设计——保留文档结构（标题、列表、表格、链接），同时最大化 token 效率。

项目采用模块化的可选依赖架构：`pip install 'markitdown[pdf, docx, pptx]'` 只安装你需要的格式支持。v2 版本新增了插件系统（支持第三方扩展）、markitdown-ocr 插件（LLM Vision 驱动的 OCR）、Azure Content Understanding 集成（多模态文档理解）和 MCP 包。

181K⭐ 使 MarkItDown 成为微软在 AI 工具链领域最成功的开源项目之一。

💡 可借鉴的优点

- **产品思维**："为 LLM 而非人类转换文档"——精准定位了 AI 时代文档处理的新需求
- **架构设计**：模块化依赖 + 插件系统 + 多级 API（convert_stream / convert_local / convert_response）提供了精确的安全和性能控制
- **工程化**：CLI 一行命令 `markitdown file.pdf > doc.md`，极致的 Unix 哲学；Docker 支持开箱即用
- **生态思维**：Azure Document Intelligence 和 Content Understanding 的集成，展示了微软"开源工具→云服务"的经典战略

🌟 特别亮眼的地方

MarkItDown 是代理的"**阅读眼镜**"——代理需要理解世界，而世界上的信息大多封装在 PDF、PPT、Word 里。MarkItDown 的日增 2,045⭐ 反映了一个关键的基础设施需求：**代理要从"只能处理代码"进化到"能处理一切文档"**。插件系统的引入意味着社区可以为任何新格式添加转换器，这个项目将成为代理文档理解能力的标准基础设施。

📖 项目是干什么的

AI 代理需要浏览真实的互联网，但 Playwright 会被拦截、Headless Chrome 会被指纹识别、Stealth 插件本身反而成为指纹特征。**Camofox Browser** 基于 Camoufox（一个在 C++ 层面进行指纹伪装的 Firefox 分支），将反检测能力封装为 REST API，专为代理设计。

核心技术方案是在浏览器引擎的 C++ 实现层伪装——navigator.hardwareConcurrency、WebGL 渲染器、AudioContext、Screen geometry、WebRTC 全部在 JavaScript 执行前就已完成伪装，没有 shim、没有 wrapper、没有可检测的特征。在此基础上提供：稳定的元素引用（e1, e2, e3）、Accessibility Snapshot（比原始 HTML 小 90%）、Session 隔离、Cookie 导入、代理 + GeoIP、YouTube 转录、搜索宏（@google_search、@youtube_search 等）、VNC 交互式登录等。

空闲时仅占 ~40MB 内存，可以在树莓派或 $5 VPS 上运行。

💡 可借鉴的优点

- **产品思维**：精准解决了"代理上网会被拦"这个日益严重的基础设施缺口
- **架构设计**：C++ 层面的指纹伪装 vs. JS 层面的 Stealth 插件，是"治本"与"治标"的区别；Accessibility Snapshot 将页面信息压缩 90%，极大降低了代理的 token 消耗
- **工程化**：REST API 设计让任何代理平台都能直接调用；Docker / Fly.io / Railway 一键部署
- **社区运营**：作为 jo（个人 AI 代理）团队的开源项目，形成了"开源基础设施→付费代理服务"的商业闭环

🌟 特别亮眼的地方

Camofox Browser 揭示了 AI 代理生态中一个被低估的问题：**代理与互联网之间存在一堵"反爬墙"**。当越来越多的网站部署 Cloudflare、bot 检测、anti-scraping 措施时，代理的"上网能力"正在被系统性地削弱。在 C++ 层面而非 JS 层面做反检测，是目前已知最彻底的解决方案。这个项目预示着一个新的基础设施品类：**代理级浏览器**。
