## 总览摘要

今日 GitHub Trending Top 10 呈现出一个清晰的核心叙事：**AI 代理正在从"通用助手"进化为"专业工匠"，而支撑这一进化的是一套日趋成熟的"技能-协作-治理"三层基础设施**。排名第一的 **i-have-adhd** 用 10 条规则约束代理输出行为，与第三名 **superpowers** 的完整开发方法论、第六名 **diagram-design** 的图表技能库形成互补——它们共同定义了"代理该怎么做事"的行为规范层。腾讯的 **teamai-cli** 则将这些技能、规则统一推送给团队成员的所有代理工具，标志着"代理治理"从个人走向组织。在垂直场景端，**text-to-cad** 让代理直接输出 CAD 制品、**pascalorg/editor** 通过 MCP 将 3D 建筑编辑器变成代理的工作台、**TradingAgents** 用多代理辩论机制做金融决策，分别代表制造业、建筑业和金融业的代理化浪潮。OpenAI 正式开源 **plugins** 仓库则释放了平台级信号——插件标准即将统一。整体来看，今日榜单折射出一个正在发生的产业拐点：代理的价值不再取决于底层模型有多强，而取决于技能生态有多深、团队协作有多顺、领域知识有多厚。

📖 项目是干什么的

AI 编码代理的一个通病是"话多"——先来一段 "Great question!"，然后洋洋洒洒讲一堆背景，把真正的答案埋在最后。i-have-adhd 是一个代理技能（Skill），用 10 条简洁的规则彻底改造代理的输出行为：先说动作、步骤编号、结尾给一个明确的下一步、禁止废话开场和收尾。

其灵感来自《The Adult ADHD Tool Kit》，但并非教人类如何组织一天，而是教 LLM 如何组织一条回复。安装极其简单——一句话粘贴到 CLI 即可。项目支持 fork 后自定义规则，用户可以调整 SKILL.md 中的 10 条规则来适配自己的偏好。

💡 可借鉴的优点

- **产品思维**：抓住了一个极其普遍但被忽视的痛点——LLM 回复冗长且结构混乱。用"ADHD"这个概念做类比，既精准又容易传播
- **架构设计**：极简到极致——整个项目核心就是一个 SKILL.md 文件，10 条规则。证明了"技能"不需要代码，纯文本指令就够了
- **工程化**：支持 Claude 插件市场安装和卸载，遵循新兴的 Agent Skills 标准
- **社区运营**：README 中的 Before/After 对比极具说服力，一眼就能看到价值

🌟 特别亮眼的地方

日增 4,650 星，在今日 Top 10 中增速第一。这个项目的成功揭示了一个深刻洞察：**在代理时代，最有价值的"技能"可能不是让代理做更多事，而是让代理少说废话**。它用 10 条规则证明了行为约束比功能扩展更稀缺、更刚需。这也意味着未来的"代理调优"将不仅是模型层面的，更是"输出规范"层面的。

📖 项目是干什么的

TeamAI 是腾讯推出的一个命令行工具，目标是"让每个团队原生 AI 化"。它解决的核心问题是：当团队中每个人都在用不同的 AI 编码代理（Claude Code、Codex、Cursor、OpenCode 等），如何确保所有代理遵循同一套技能、规则和知识？

TeamAI 的核心架构分三层：**Team Execution**（统一分发技能/规则/hooks/MCP 配置）、**Team Context**（让代理理解团队经验，包括学习记忆、代码知识图谱）、**Team Improvement**（从每次会话中提取经验反哺团队）。工作流程类似 Git：管理员 push 配置到共享仓库，成员 pull 到本地，所有 AI 工具自动同步。

最独特的是"摩擦驱动学习"机制：当一次 AI 会话中出现用户打断、工具重试等"摩擦信号"时，系统会建议将经验文档化并分享给团队——这意味着团队的知识库不是人工维护的，而是从真实的痛点中自动生长的。

💡 可借鉴的优点

- **产品思维**：精准定位了"代理治理"这个新兴但刚需的场景。当代理从个人工具变成团队基础设施，统一管理就成了必需品
- **架构设计**：三层架构（执行-上下文-改进）非常清晰，Team Context 中的代码知识图谱使用 WASM tree-sitter 做 AST 分析，技术含量高
- **工程化**：支持 11 款主流 AI 代理工具，覆盖面极广。角色-标签-来源三维分发控制非常企业级
- **社区运营**：作为腾讯开源项目，起步阶段星标不高但产品完成度极高，企业背景为其长期维护提供了保障

🌟 特别亮眼的地方

这是今日 Top 10 中最具"企业级"气质的项目。它试图回答一个关键问题：**当 AI 代理成为团队生产力工具后，谁来管理代理本身？** TeamAI 给出的答案是"用 Git 工作流管理代理配置"——这个类比既直觉又实用。尤其是"摩擦驱动学习"机制，让组织知识从"被动文档化"变成"从痛点中自动生长"，这是一个非常前沿的知识管理理念。

📖 项目是干什么的

Superpowers 是一个完整的 AI 代理软件开发方法论，它不只是一个工具或技能包，而是一整套"如何让代理正确写代码"的工作流。从头脑风暴、设计文档、实施计划到子代理驱动开发、TDD、代码审查、分支管理——每个环节都有对应的技能自动触发。

核心工作流是：代理先不写代码，而是通过苏格拉底式提问明确需求→生成设计文档→分解成 2-5 分钟的小任务→用子代理逐个执行→两阶段审查（规格符合性+代码质量）→整合并完成。整个过程强调真正的红绿 TDD、YAGNI 原则和 DRY 原则。

项目支持几乎所有主流代理平台：Claude Code、Codex、Cursor、Devin、Gemini CLI、GitHub Copilot、Grok Build、Kimi Code、OpenCode、Pi、Hermes Agent 等。

💡 可借鉴的优点

- **产品思维**：将软件工程方法论产品化为代理技能，定位远超"工具"层面，直接对标"开发流程"
- **架构设计**：子代理驱动开发（Subagent-Driven Development）是核心创新，让主代理做项目经理，子代理做工程师，两阶段审查保证质量
- **工程化**：12 个技能高度模块化且自动触发，用户零配置即可使用。跨 10+ 平台统一安装
- **社区运营**：28.4 万星的巨型社区，由 Prime Radiant 公司商业化运营，Discord 社区活跃

🌟 特别亮眼的地方

284K 星使其成为 Agent Skills 领域当之无愧的头部项目。Superpowers 最深刻的洞察是：**代理写代码的问题不在于代码能力不够，而在于没有遵循正确的软件工程流程**。通过将 TDD、代码审查、需求分析等最佳实践"硬编码"为自动触发的技能，它让代理从"能写代码"进化到"能做工程"。这代表了 Agent Skills 生态的最高成熟度。

📖 项目是干什么的

Pascal Editor 是一个开源的、本地优先的 3D 建筑编辑器，基于 React Three Fiber 和 WebGPU 构建。它可以在浏览器中运行或通过 CLI 启动，最关键的是——它通过 MCP（Model Context Protocol）将编辑器变成了 AI 代理的工作台。

架构上采用 Turborepo monorepo，核心包括 @pascal-app/core（场景状态）、@pascal-app/viewer（3D 渲染）、@pascal-app/editor（编辑工具）、@pascal-app/nodes（内置节点定义）和 @pascal-app/mcp（AI 接口）。状态管理用 Zustand，场景采用扁平字典结构，脏节点机制保证渲染性能。

项目还提供了两个 Agent Skills：pascal-3d（安全的 MCP 设置和场景操作）和 furniture-fit（家具适配度评估），让 AI 代理可以直接在 3D 场景中工作。

💡 可借鉴的优点

- **产品思维**：将建筑编辑器与 AI 代理深度集成的思路极具前瞻性，MCP 协议让代理能直接操作 3D 场景
- **架构设计**：扁平节点字典 + 脏节点系统 + 注册表模式的组合非常优雅，既保证了数据访问效率，又保证了渲染性能
- **工程化**：Turborepo 分包非常清晰，每个包职责单一。支持插件系统，第三方可扩展节点类型
- **社区运营**：提供了插件开发模板（plugin-trees），降低了社区贡献门槛

🌟 特别亮眼的地方

Pascal Editor 代表了一个重要的产业趋势：**专业软件从"被 AI 增强"到"为 AI 而生"**。传统 AEC 软件如 Revit、SketchUp 是为人设计的，AI 只是辅助；而 Pascal 从一开始就将 MCP 作为一等公民，AI 代理可以像人一样在编辑器中创建墙壁、放置家具、检查适配度。这种"AI-native 专业工具"的设计范式值得所有垂直领域借鉴。

📖 项目是干什么的

text-to-cad 是一个专为 CAD、CAE 和 CAM 场景设计的 Agent Skills 库。它让 AI 代理具备完整的制造业数字化能力：从文本生成 CAD 模型（STEP/STL/3MF/GLB）、创建 2D DXF 图纸、编写 URDF 机器人描述文件、创建 SDF 仿真模型，一直到切片生成 G-code、上传到 Bambu Lab 3D 打印机执行打印。

项目包含 11 个专业技能：CAD（建模）、CAD Viewer（预览）、step.parts（标准件采购）、DXF（2D 图纸）、URDF（机器人结构）、SRDF（MoveIt 规划）、SDF（仿真）、SendCutSend（外协加工检查）、DfAM Check（可打印性分析）、G-code（切片）和 Bambu Labs（3D 打印执行）。

💡 可借鉴的优点

- **产品思维**：覆盖从设计到制造的全链路，不是"玩具"级的 CAD 生成，而是能真正落地到生产的完整工作流
- **架构设计**：11 个技能高度解耦，每个技能有独立的 requirements.txt 和版本管理，可按需安装
- **工程化**：支持 Skills CLI、Claude Code 插件、Codex 插件、Grok Build 四种安装方式。使用 LFS 管理大型模型文件
- **社区运营**：与 SendCutSend 等外协加工平台集成，构建了从设计到制造的生态闭环

🌟 特别亮眼的地方

text-to-cad 最令人印象深刻的是它的**全链路覆盖**——从一段文字描述开始，经过 CAD 建模、可制造性分析、切片、直到物理世界的 3D 打印执行，全程由代理技能驱动。这不是"text-to-image"那种生成一张好看的图，而是生成可以直接拿去工厂加工的工程制品。它证明了 AI 代理已经具备"从比特到原子"的能力闭环。

📖 项目是干什么的

diagram-design 提供了 39 种编辑级图表类型，专为 Claude Code、Codex、Factory Droid、Pi 等 AI 代理设计。每种图表都是自包含的 HTML + SVG，不依赖 Mermaid、不用阴影、不走"AI slop"风格——而是追求设计师不会嫌丑的专业品质。

v2.0 引入了 Loop（飞轮图），v2.3 加入了语义系统模式和可选的无障碍动画，v2.5.10 新增了 10 种布局语法：Sankey 图、鱼骨图、Wardley 地图、看板、用户旅程图、部署图、依赖图、UML 类图、故事地图和数据库 Schema。每种图表都有完整的语义约定：字体层级、颜色语义、spacing token、交互语法。

项目完全兼容 Agent Skills 标准，支持通过 Skills CLI 或 Claude Code 插件安装。

💡 可借鉴的优点

- **产品思维**："让设计师不嫌丑"这个定位精准——AI 生成的图表一直被诟病为"一看就是 AI 做的"，diagram-design 直接对标专业设计品质
- **架构设计**：39 种图表类型用统一的语义层（字体/颜色/spacing token）约束，保证风格一致性
- **工程化**：自包含 HTML + SVG 的方案非常聪明——零依赖、可离线、可嵌入任何上下文
- **社区运营**：版本迭代节奏快（已到 v2.5.10），每次更新都增加新的布局语法，保持社区活跃度

🌟 特别亮眼的地方

日增 2,249 星，在 Top 10 中排名第二。diagram-design 的核心创新在于**将设计标准编码为代理技能**。传统做法是让设计师手动调整 AI 输出，而 diagram-design 通过严格的语义约定（颜色代表什么含义、字体层级如何映射、spacing 遵循什么规则），让代理在生成阶段就遵循设计规范。这不仅是一个图表库，更是"Design as Code"理念在代理时代的最佳实践。

📖 项目是干什么的

TradingAgents 是一个多代理 LLM 金融交易框架，模拟真实交易公司的组织架构。它部署了多个专业化的 LLM 代理：基本面分析师、情绪分析师、新闻分析师、技术分析师组成分析团队，牛熊研究员通过结构化辩论平衡收益与风险，交易员综合报告做出交易决策，风控团队和组合经理做最终审批。

v0.4.0（2026 年 8 月）新增了前瞻/时间点修复、决策日志记忆、价格锚定等关键改进。框架支持几乎所有主流 LLM 提供商（OpenAI、Google、Anthropic、xAI、DeepSeek、Qwen、GLM、MiniMax、Ollama 等），覆盖美股、港股、A 股、加密货币等全球市场。

💡 可借鉴的优点

- **产品思维**：将多代理系统应用于金融交易的完整实现，不是 demo 而是可运行的框架
- **架构设计**：基于 LangGraph 的模块化架构，多代理辩论机制（牛熊研究员对抗）是亮点。决策日志 + 反思机制实现了跨会话学习
- **工程化**：支持检查点恢复、Docker 部署、多 LLM 提供商切换。数据访问合约和前瞻过滤保证了回测的严谨性
- **社区运营**：完善的多语言文档，学术论文背书（arXiv），研究与工程并重

🌟 特别亮眼的地方

103K 星的金融 AI 项目，其最深刻的创新在于**用组织架构模拟替代简单的 prompt engineering**。传统做法是让一个 LLM 做所有分析，TradingAgents 则让不同角色的代理各司其职、互相辩论、层层审批。这种"以组织架构为模型"的多代理设计，比单纯堆叠 LLM 调用更接近真实的决策过程。

openai/plugins 是 OpenAI 官方的 Codex 插件示例集合，包含一系列精心策划的插件模板和实现。每个插件都遵循标准结构：.codex-plugin/plugin.json 清单文件 + skills/、.app.json、.mcp.json、agents/、commands/、hooks.json 等可选组件。

项目维护了默认 marketplace 和 API key 用户 marketplace 两套索引，标志着 OpenAI 正在构建类似 App Store 的插件分发体系。

💡 可借鉴的优点

- **产品思维**：OpenAI 官方开源插件模板，降低了插件开发门槛，同时定义了"好插件长什么样"的标准
- **架构设计**：统一的插件清单格式（plugin.json + 多种可选 surface），既灵活又规范

- **社区运营**：作为 OpenAI 官方仓库，直接影响 Codex 生态的发展方向

🌟 特别亮眼的地方

这个仓库的意义不在于代码量或星标数，而在于它代表的**平台级信号**。OpenAI 正式开源 Codex 插件集合，意味着插件标准从"社区自发"走向"平台主导"。结合 Anthropic 的 Agent Skills 和 superpowers 的跨平台方案，AI 代理的插件/技能生态正在经历一场"标准之战"——而开发者需要密切关注哪个标准最终胜出。

awesome-gpt-image-2 是一个 GPT-Image2 工业级提示词引擎与模板库，包含 544+ 个逆向工程案例和 20+ 套工业级模板。项目的核心理念是"Prompt as Code"——将散落的社区提示词案例转化为结构化、可组合、可复用的提示词协议。

案例覆盖 13 大类：UI 界面（73 例）、图表信息图（53 例）、海报排版（90 例）、产品电商（42 例）、品牌 Logo（27 例）、建筑空间（12 例）、摄影写实（78 例）、插画艺术（59 例）、人物角色（31 例）、场景叙事（21 例）、历史国风（16 例）、文档出版（11 例）等。

最新的 GPT Image 2.5 Spotlight 专区展示了 Sunburst 和 Flare 两种新模式。项目还提供了 Agent Skill（gpt-image-2-style-library），让 AI 代理直接调用风格库。

💡 可借鉴的优点

- **产品思维**："Prompt as Code"的定位将提示词从"文案"升级为"工程资产"，符合代理时代的需求
- **架构设计**：原子化 schema（主体/光照/材质/布局/视觉细节分离）让提示词可组合、可批量生成

- **社区运营**：中日英三语文档，WeChat 社群运营，赞助商机制保证可持续发展

🌟 特别亮眼的地方

544 个案例的规模本身就是护城河。但更深层的价值在于**将提示词工程从"手艺"变成"工业"**——通过原子化 schema 和结构化模板，任何人都可以像填表一样生成专业级图像提示词。结合 Agent Skill 的发布方式，它让 AI 代理不仅能"画图"，更能"按照专业视觉标准画图"。

## 📊 今日趋势洞察

### 核心方向：AI 代理的"职业化"与"组织化"

今日 Trending 的核心叙事可以用一句话概括：**AI 代理正在经历从"个人助手"到"职业工匠"再到"组织成员"的三级进化**。i-have-adhd 和 diagram-design 约束代理的输出行为，superpowers 规范代理的工作流程——这些都是在塑造代理的"职业素养"。而腾讯的 teamai-cli 则将代理管理提升到组织层面，让技能、规则和知识在团队中统一流转。当代理有了职业技能（Skills）、有了工作规范（Rules）、有了组织管理（TeamAI），它就不再是一个"聊天窗口"，而是一个真正的"数字员工"。

### 升温领域

1. **代理行为治理**（i-have-adhd、superpowers）：从"代理能做什么"转向"代理该怎么做"，输出规范和工作流约束成为新刚需
2. **垂直领域代理化**（text-to-cad、pascalorg/editor、TradingAgents）：CAD 制造、3D 建筑、金融交易三个重资产行业同日登榜，代理正在突破"写代码"的边界
3. **代理生态标准化**（openai/plugins、teamai-cli、superpowers）：OpenAI、腾讯、社区三方同时推动插件/技能标准化，生态基础设施进入"军备竞赛"
4. **提示词工程化**（awesome-gpt-image-2、diagram-design）：提示词从"灵感驱动"走向"协议驱动"，Prompt as Code 和 Design as Code 成为新范式

### 对开发者的启发

- **如果你在做 AI 代理产品**：重点关注 teamai-cli 的三层架构设计，它代表了"代理管理"这个新品类的产品形态。同时学习 superpowers 的自动触发技能设计，用户零配置是关键
- **如果你在做垂直行业应用**：text-to-cad 和 pascalorg/editor 展示了"为代理而生"的专业工具应该是什么样——不是在现有软件上加 AI 功能，而是从一开始就以 MCP/Skills 为一等公民
- **如果你在做开发者工具**：i-have-adhd 用 10 条规则改变代理行为的案例值得深思——有时候最有价值的产品不是增加功能，而是减少噪音
- **如果你是技术学习者**：system-design-notes 提醒我们，在追逐 AI 浪潮的同时，系统设计、分布式架构等基本功永远不过时。扎实的工程素养是驾驭任何新技术的前提
