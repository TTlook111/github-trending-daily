📖 项目是干什么的

i-have-adhd 是一个为编码代理设计的"行为约束技能"，核心目标只有一个：**让代理别废话，直接给答案**。它用 10 条精炼规则彻底重塑代理的输出风格——动作优先、步骤编号、结尾给出下一步、压制跑题、不要开场白也不要"Hope this helps!"。

项目灵感来自《The Adult ADHD Tool Kit》这本关于成人 ADHD 的心理学著作，但把"帮助人类组织思维"的方法论转化为"让 LLM 更好地组织输出"。Before/After 的对比极具说服力：原本 150 字的"热心废话"变成 50 字的"操作清单"。安装方式极简，一行指令即可集成到 Claude Code 插件系统。

💡 可借鉴的优点

- **产品思维**：精准定位了 LLM 输出的最大痛点——信息密度低、关键信息被废话淹没。不做加法做减法，用"约束"而非"能力"来提升体验
- **架构设计**：极度轻量化——整个项目核心就是一个 SKILL.md 文件里的 10 条规则，没有复杂依赖，没有模型训练，纯粹用"提示工程"解决问题
- **工程化**：支持 Fork 后自定义规则，插件化安装/卸载，体现了 Agent Skills 标准的可组合性
- **社区运营**：MIT 许可 + "Star if it saved you one scroll"的文案，低门槛高传播

🌟 特别亮眼的地方

这个项目最大的启示不在技术，而在**认知**：当所有人都在给代理增加能力时，最实用的技能反而是"教代理少说话"。38K Star 和持续日增 3,800+ 证明了市场对此的强烈需求。这暗示 AI 代理生态正在经历从"功能竞赛"到"体验打磨"的转折——正如互联网产品从功能堆砌走向极简设计的历程。10 条规则 = 38K Star 的投入产出比，也重新定义了开源项目的价值衡量标准。

📖 项目是干什么的

God's Eye View 是一个运行在浏览器中的"间谍卫星模拟器"——但所有数据都是真实的。它在光照逼真的 3D 地球仪上叠加了 13 个实时数据图层：11,000+ 实时航班、全球船舶、838 颗卫星轨迹、地震、公共摄像头、交通流量、消防热点、自行车站、太空发射任务等，全部来自公开数据源。

技术栈以 Vanilla JavaScript + CesiumJS + Vite 为核心，搭配 Google Photorealistic 3D Tiles 和 OpenAI Realtime API 实现语音交互。28 个语音工具支持四类操作：操控镜头（"带我去东京"）、标注世界（"画出德克萨斯州的轮廓"）、查询数据（"德克萨斯上空有多少航班"）、控制系统（"切换到夜视模式"）。驾驶舱模式可以骑在真实航班上飞行，夜视/热成像等 7 种传感器滤镜让画面具有军事侦察的视觉冲击力。

💡 可借鉴的优点

- **产品思维**：把"开源情报(OSINT)"这个专业概念包装成"间谍卫星模拟器"的体验，降低认知门槛，提升传播力。"看起来像机密控制室，但每行代码都可以检查"
- **架构设计**：无框架策略——纯 JavaScript + CesiumJS，模块化的图层系统让每个数据源都是独立模块。服务端代理架构保护 API 密钥安全，浏览器端只暴露 Google Maps 和 Cesium ion 的 token
- **工程化**：渐进式密钥策略——零配置即可启动（11 个免费图层），按需添加 API key 解锁更多能力。成本控制透明到"每分钟几美分"
- **社区运营**：从 YouTube 系列视频（500 万+ 播放）到开源代码，实现了内容创作者到开源开发者的完美转化

🌟 特别亮眼的地方

God's Eye View 最震撼之处在于它重新定义了"公开数据的力量"——仅凭公开的 ADS-B、AIS、TLE、USGS 等信号，就能构建出媲美军事情报系统的态势感知界面。项目明确画出了伦理红线："不做人脸识别，不追踪个人"。这种"能力很强但自我约束"的姿态，既是产品立场也是开源社区的价值观示范。实时语音 AI + 3D 地球仪的交互方式，则预示了下一代地理空间应用的范式。

📖 项目是干什么的

Superpowers 是一个面向编码代理的完整软件开发方法论框架。它不仅是一组可组合的技能（Skills），更是一套强制执行的工作流程：从头脑风暴（brainstorming）→ 设计审查 → 创建 Git Worktree → 编写实施计划 → 子代理驱动开发（每个任务由独立子代理执行，两阶段审查）→ 严格的 RED-GREEN-REFACTOR TDD → 代码审查 → 分支完成。

核心理念是"让代理先理解你要什么，再动手写代码"。安装后技能自动触发，支持 Claude Code、Codex、Cursor、Pi、Gemini CLI、GitHub Copilot、Kimi Code 等几乎所有主流编码代理。284K Star 使其成为 Agent Skills 领域的事实标准。

- **架构设计**：可组合技能系统 + 子代理驱动开发，每个任务用全新子代理执行，隔离上下文污染。两阶段审查（规格合规 + 代码质量）确保输出质量
- **工程化**：跨平台插件安装支持 12+ 个编码代理，从 Claude Code 到 Gemini CLI 全覆盖。自动触发机制让用户"什么都不用做"
- **社区运营**：Prime Radiant 团队运营，Discord 社区活跃，商业支持可用。MIT 许可确保生态开放

🌟 特别亮眼的地方

284K Star 背后是一个深刻的行业信号：**编码代理需要的不是更多能力，而是更好的纪律**。Superpowers 本质上是把资深工程师脑中的"怎么做项目"外化为代理可执行的流程。子代理驱动开发（每个任务用全新子代理、两阶段审查）的设计特别精妙——它承认了当前 LLM 上下文退化的现实，用"换人"代替"修人"。这不是技术突破，而是方法论突破。

📖 项目是干什么的

TeamAI 是腾讯推出的"团队 AI 原生化"工具，解决一个核心问题：**怎么让一个团队的所有 AI 代理统一工作方式**。它通过 Git 仓库管理团队的 Skills、Rules、MCP、Knowledge，然后通过 push → review & merge → pull 的流程分发到每个成员的本地 AI 工具中。

架构分三层：Team Execution（统一技能/规则/文档/Hooks/MCP）、Team Context（团队知识库 + 代码库知识图谱）、Team Improvement（使用分析 + 会话摘要 + 看板）。支持 Claude Code、Codex、Cursor、CodeBuddy、WorkBuddy、OpenCode 等 12+ 个 AI 代理。最精妙的功能是"摩擦驱动的经验分享"——当一个 session 中出现用户中断、纠正、工具重试等"摩擦信号"时，自动建议将经验分享给团队。

💡 可借鉴的优点

- **产品思维**：看到了"代理管理从个人到团队"的关键跃迁点。不是做更好的代理，而是做"代理的团队管理工具"，类似从单机版到企业版的升级
- **架构设计**：基于 Git 的分发机制极其聪明——利用现有 Git 基础设施，支持 GitHub/GitLab/GitCode/CNB/TGit 等多种 Git 服务。角色(Roles) + 标签(Tags) + 来源(Sources) 的分发控制精细到个人
- **工程化**：代码库知识图谱（codebase graph）使用 WASM Tree-Sitter 做 AST 分析 + 启发式回退，纯 JS 无需编译器。BM25 + 图增强排序的知识检索
- **社区运营**：腾讯品牌背书 + 中英文双语文档 + 开放贡献，降低企业用户采纳门槛

🌟 特别亮眼的地方

TeamAI 最前瞻的设计是"**摩擦驱动的团队学习**"——它不要求人主动总结经验，而是通过检测 session 中的摩擦信号（中断/纠正/重试）自动识别"值得记住的教训"，然后通过 `/teamai-share-learnings` 将经验结构化并推送到团队知识库。这解决了知识管理最大的难题：**没人愿意写文档**。当 AI 代理成为团队常规工具后，"如何管理一群代理"将成为每个技术团队的新课题——TeamAI 提前占位了。

📖 项目是干什么的

llmfit 解决一个极其实际的问题：**你的硬件到底能跑哪些开源大模型？** 它自动检测 CPU、RAM、GPU/VRAM、加速器配置（NVIDIA CUDA、Apple Silicon、AMD ROCm、Intel OneAPI），然后分析数百个模型在不同量化格式（GGUF、AWQ、GPTQ、EXL2）下的内存占用和推理速度，给出四维评分：内存适配度、预估速度、质量、上下文长度。

提供 TUI 交互界面、Web 仪表盘、REST API 三种使用方式。支持 Ollama、llama.cpp、MLX、Docker Model Runner、LM Studio 等本地运行时。独特的"社区基准"功能允许用户在自己硬件上实测 tok/s 后提交 PR，所有人的推荐结果都会被社区实测数据逐步替代。

💡 可借鉴的优点

- **产品思维**：切中了本地 LLM 部署最大的痛点——不是"哪个模型好"，而是"哪个模型在我的机器上跑得动"。从决策辅助而非模型训练的角度切入
- **架构设计**：Rust 实现确保了跨平台性能。基于内存带宽模型的速度估算 + 社区实测数据的渐进替代，形成了"先估算后验证"的数据飞轮
- **工程化**：安装覆盖 Scoop/Homebrew/MacPorts/pip/Docker，真正做到了"one command"。TUI 内直接下载模型 + 基准测试 + 分享结果的一站式体验
- **社区运营**：社区基准贡献机制设计精巧——TUI 内一键提交 PR，无需 gh CLI 或第三方账号

🌟 特别亮眼的地方

llmfit 的真正价值在于它建立了一个**硬件-模型匹配的知识众包平台**。随着越来越多用户提交基准数据，推荐系统从"理论估算"逐步进化为"社区实测"。这种"先给估计值，再用真实数据渐进替代"的策略，既解决了冷启动问题，又构建了持续优化的飞轮。在本地 LLM 部署需求爆发的当下，llmfit 扮演的角色类似于"PC 硬件天梯图"——但它是自动化的、个性化的、可验证的。

项目由 littlemight.com 的作者创建，起因是"每次让 Claude 画图都得到丑到不能用的圆角框"。核心理念是"删除是最高质量的操作"——每个节点必须有存在价值，重点色只用于 1-2 个最需要关注的元素。支持品牌适配（60 秒从网站提取品配色）、draw.io/Mermaid/Excalidraw 导入转换、SVG/PNG 导出。兼容 Claude Code、Codex、GitHub Copilot、Pi、Factory Droid、Kiro 等主流代理。

💡 可借鉴的优点

- **产品思维**：精准打击"AI 生成图表丑"这个普遍痛点。"Editorial diagrams your designer won't hate" 是极好的定位
- **架构设计**：语义模式系统（semantic patterns）将行为和布局分离——先选行为模式（队列瓶颈、策略追踪、安全层级等），再选视觉类型。4 个导入控制旋钮（格式/尺寸/详细度/受众）实现了精确的输出控制
- **工程化**：自包含 HTML + SVG，零依赖零构建步骤。品牌适配从网站自动提取配色方案并检查 WCAG AA 对比度。多客户端 profile 系统支持平行项目
- **社区运营**：跨 7+ 个代理平台的插件市场分发，每个平台都有详细的安装和更新文档

🌟 特别亮眼的地方

Diagram Design 代表了 Agent Skills 的一个重要进化方向：**从"教代理做事"到"教代理做出有品味的事"**。项目内置 WCAG 无障碍支持、可选动画、品牌适配、导入转换等功能，已经构成了一个完整的"代理视觉设计系统"。39 种图表类型 + 8 种语义模式的组合，远超"画个图"的范畴——它实质上是在定义"AI 代理应该如何进行视觉表达"的标准。从 draw.io/Mermaid 导入转换的功能也说明，它的目标不仅是替代手动画图，而是成为所有图表的"最终格式化出口"。

🌟 特别亮眼的地方

📖 项目是干什么的

ArmorPaint 是一个用于 3D PBR（Physically Based Rendering）纹理绘制的专业软件。它允许艺术家和开发者直接在 3D 模型上绘制纹理，支持基于物理的渲染材质系统。项目以开源开发为核心（所有开发都在 GitHub 上进行），分发版二进制文件为付费下载以支持项目资金。

支持 Windows (x64)、Linux (x64)、macOS (arm64)、Android (arm64)、iOS (arm64) 和 WASM 构建。编译需要 Clang 工具链（Windows 用 Visual Studio + Clang、Linux 用 Clang、macOS 用 Xcode）。支持 C23 的 `#embed` 特性嵌入数据文件，支持国际化（locale 文件生成工具）。

💡 可借鉴的优点

- **产品思维**：开源开发 + 付费分发的混合模式——代码完全开放透明，但预编译二进制收费。这解决了"开源项目如何可持续"的经典问题
- **架构设计**：跨 6 个平台的统一构建系统，包括 WASM 支持，体现了底层图形引擎的扎实程度。使用自研 base 构建系统而非 CMake
- **工程化**：C23 #embed 支持数据内嵌，减少运行时 I/O。locale 生成工具支持社区翻译贡献

🌟 特别亮眼的地方

在 AI 生成内容横扫 Trending 的今天，ArmorPaint 作为传统 3D 创作工具登榜有其深意——AI 生成的 3D 内容仍然需要专业工具来精修。它的"开源代码 + 付费二进制"模式也为开源项目提供了一个可持续的商业化范本。ArmorPaint 瞄准的是 Substance Painter 这个 Adobe 旗下的垄断产品，以开源和跨平台（含 WASM！）来挑战商业巨头，精神值得敬佩。

## 📊 今日趋势洞察

### 核心方向：AI 代理从"能力堆叠"转向"品质管控"

今日 Top 10 中 7 个项目直接服务于 AI 代理生态，但方向发生了明显转变——不再是"让代理能做更多事"，而是"让代理把事做得更好"。i-have-adhd 管住代理的嘴、diagram-design 管住代理的手、superpowers 管住代理的脑、teamai-cli 管住整个团队的代理。这标志着 AI 代理生态正式进入**品质管控时代**——从 MVP 阶段跨入产品化阶段。

### 升温领域

1. **代理行为约束与输出品控**（i-have-adhd、diagram-design、awesome-gpt-image-2）：用规则、模板、设计系统来约束代理的输出质量，而非增加能力。"做减法"成为新趋势
2. **代理团队管理与组织化**（teamai-cli、superpowers）：代理从个人工具走向团队基础设施，统一工作方式、分发知识、记录摩擦经验。"管理代理"正在成为新职能
3. **代理自主金融决策**（CloddsBot）：AI 代理开始接管交易全链路——从策略生成到执行到风控到审计，甚至包含代理间经济协议。"代理经济"从概念走向实现
4. **开源情报与地理空间可视化**（gods-eye-view）：公开数据 + 3D 可视化 + 语音 AI 的组合开创了新型情报产品范式，"数据主权"的边界在被重新定义

### 对开发者的启发

- **如果你在做 AI 代理产品**：不要再堆功能了，学 i-have-adhd 做减法——用 10 条规则约束代理输出可能比增加 10 个能力更有价值。用户要的不是"更强的代理"，而是"更好用的代理"
- **如果你在管理工程团队**：关注 teamai-cli 的"摩擦驱动学习"机制——让代理使用过程中的痛点自动转化为团队知识，比任何文档制度都有效
- **如果你在做开源项目**：armorpaint 的"代码开源 + 二进制付费"和 awesome-gpt-image-2 的"案例库 + SaaS + 赞助商"都是值得参考的可持续模式
- **如果你在学系统设计**：system-design-notes 证明了结构化整理 + 高质量外部资源策展仍然是建立技术影响力的有效方式，AI 时代架构能力反而更珍贵
