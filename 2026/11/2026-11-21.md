📖 项目是干什么的

Claude-BugHunter 是一套面向**授权漏洞赏金与外部红队**的 Claude Code 技能包：README 标注 **83 条技能、15 个斜杠命令、681 条已披露报告模式**（其中 433 条单独引用、可逐条审计），覆盖 24 类核心漏洞，另附企业身份与基础设施攻击矩阵、engagement 目录脚手架与 Burp MCP 集成。安装一次，Claude Code 就不再是通用聊天助手，而是按资深赏金研究员的方式工作——你用自然语言描述在测什么，对应主题的技能自己会加载。

结构是四层堆叠：Think（方法论与红队思维）、Hunt（58 条 `hunt-*` 技能，逐类给出检测模式、绕过表与链式模板）、Perimeter（M365/Entra、Okta、vCenter、SSL-VPN、SharePoint、云 IAM 的 2024–2026 CVE 链）、Ship（7-Question Gate 分诊、VRT 分级、OOS 反驳、PII 脱敏与报告交付）。同一套知识层可以装进 Claude Code、OpenCode、Codex CLI、Hermes、Google AntiGravity 五个宿主，斜杠命令与 `/hunt` 引擎留在 Claude Code。

真正让它区别于「攻击工具合集」的，是那份**故意不做**的清单：内网 AD 攻击、C2 框架、后渗透与持久化、免杀对抗、二进制与内核利用，都被明确排除并给出理由——它们属于不同的操作风险模型。与之配套的是写进校验闸门的范围确认（资产是否在授权范围内、是否落在项目接受的影响清单里），以及「代码 MIT + 内容 CC BY 4.0」的双许可。

💡 可借鉴的优点

- **产品思维**：把「资深研究员的判断」拆成可按主题自动加载的技能，而不是写成一万多字的长文档。用户不需要记 83 个技能名字，只需要说清楚自己在测什么。
- **架构设计**：四层各管一段，58 条 hunt-* 按漏洞类别而非按工具组织；外层再用一份确定性 engine 把目标面映射到技能，避免模型「随手挑一个」。

- **社区运营**：文档拆成 INSTALL / USAGE / architecture / cve-coverage / credits 五层，贡献指南写清技能质量标准；赞助商进 README，但不影响内容分层。

📖 项目是干什么的

Firecrawl 的定位已经从「网页抓取 API」换成「让 Agent 更聪明的知识基础设施」，并且把部署形态拆成了三份。**Firecrawl Local** 是一个 Rust 二进制，`cargo install firecrawl-local` 装上就能在本机 scrape / crawl / map，用你系统里已有的 Chrome 渲染 JS 页面，PDF 与 Office 文档也在本地解析；`init` 能自动把 MCP 服务接进 Claude Code、Claude Desktop、Cursor、Windsurf、Gemini CLI、Codex 六种宿主，并且先备份每一份配置；`serve` 则在 3002 端口跑一份兼容 v2 的 API，现有 SDK 改个地址就能用。

**Firecrawl Cloud** 提供规模化版本：96% 的网页覆盖率、P95 延迟 3.4 秒、结构化 JSON / 截图 / 浏览器动作，外加 Search 与 Alexandria——一个打包了 550 多家数据源的知识库；免登录每月 1,000 次额度。**Self-hosting** 则把 `apps/api` 的队列、worker 与数据库整套搬到你自己的基础设施上。抓取、爬取、映射跑在本地；需要搜索、Alexandria、Interact、Agent、Monitor 时走云端；`FIRECRAWL_CLOUD=off` 还能强制全部留在本机。

今天它拿到 +999，是五天在榜以来的最高值。对一个 205,811 星的成熟项目来说，这个数字不是「被发现」，而是「被重新评估」——本地版把隐私敏感和延迟敏感的场景兜住了，云端版把规模兜住了，两条腿都在往前迈。

💡 可借鉴的优点

- **产品思维**：把「给 Agent 供数据」做成独立生意，并且用「本地免费 + 云端按量」分层。本地版不是阉割版，而是先把隐私与延迟敏感的场景兜住——这是数据类产品少见的克制。
- **架构设计**：本地与云共用同一套 API 契约，代码可平移、SDK 不用重写；`init` 自动识别六种宿主并写配置、先备份，这种「零摩擦接入」比写十页文档有效。
- **工程化**：公开 benchmark 说清覆盖率与 P95 延迟，而不是只说「快」；本地渲染复用系统 Chrome 而不是自带一个浏览器；云端调用失败会标注 `source: firecrawl-cloud`，来源不糊弄。
- **社区运营**：多语言 SDK、playground、Discord 与 X / LinkedIn 三条反馈渠道；免费额度不要求注册，先把「试一下」的门槛降到零。

🌟 特别亮眼的地方

一个 20 万星的老项目，靠「本地化 + 数据源扩张」重新上桌，而且今天成了榜单第二。它反映的是这条暗线：**Agent 的瓶颈正在从「会不会推理」转向「看到的是不是真的」。** 当模型能力趋同，谁能提供更干净、更新鲜、更可追溯的上下文，谁就决定了输出质量的上限。技能决定下限，数据决定上限——这句话在今天这份「工具回补」的榜单里比昨天更成立。

📖 项目是干什么的

Superpowers 卖的不是单条技能，而是一整套**给编码 Agent 装上的软件开发方法论**：一批可组合的技能，加上一段保证「Agent 真的会去加载它们」的引导指令。Agent 判断你在造东西之后不会立刻写代码，而是先退一步问你到底想解决什么；把 spec 从对话里逼出来，分段展示给你确认，每段都短到能真正读完；设计签字才进入计划环节。

计划环节的要求很硬——「一个热情但品味差、没有判断力、没有项目背景、还讨厌写测试的初级工程师也能照着做」，每个任务 2–5 分钟，写清文件路径、完整代码和验证步骤。落地时两套模式二选一：`subagent-driven-development` 每个任务派一个新子 Agent，做完立刻两段式评审；`executing-plans` 则在当前会话内逐条实现，最后统一评审整个分支。工作流被写成七步：brainstorming → git worktrees → writing-plans → 子 Agent 执行 → 红绿 TDD → 代码评审 → 收尾分支。

安装面依旧是它的护城河：Claude Code（官方插件市场）、Codex App / CLI、Cursor、Antigravity、Gemini CLI、GitHub Copilot CLI、Grok Build CLI、Kimi Code、OpenCode、Pi、Qwen Code、Hermes Agent、Muse、Devin CLI、Factory Droid——**16 个 harness，一套技能**。MIT 协议，作者是 Jesse Vincent 与 Prime Radiant 团队。

💡 可借鉴的优点

- **产品思维**：它不卖「能力」，卖「流程」和「否决权」。TDD 技能会删掉那些先写实现、后补测试的代码；评审技能把 Critical 问题设为硬阻断。
- **架构设计**：技能之间用「触发时机」串成流水线，而不是靠一张总提示词硬压；引导技能在会话启动时注入，压缩上下文后再注入一次。技能可组合、可单装，比一个大而全的提示词可维护得多。
- **工程化**：技能行为用 drill eval harness（superpowers-evals）做回归测试，插件基础设施另有 `tests/` 与 `npm test`；连「会话跑歪了怎么办」都有 `diagnosing-superpowers` 去读会话记录、给出行级证据、打包脱敏报告。
- **社区运营**：明确不接受新技能投稿、只接受跨 harness 的修改，且不接受「替别人修 issue」的 Agent PR——用规则守住了质量下限。

🌟 特别亮眼的地方

从昨天的 +2,028 腰斩到 +884，是今天最显眼的一次降温。但注意它守住了第 2——28 个在榜日、从 9 月 8 日的 283,059 走到今天的 323,416，这不是一个靠脉冲活着的项目。**腰斩更像是一轮「方法论尝鲜」的结束，而不是价值被否定**：把流程装进 Agent 这件事已经完成了认知普及，接下来拼的是谁能把它真正跑进日常项目里。它自己就演示了这份榜单的规律——热度会回落，位置靠产品力守。

📖 项目是干什么的

Ghost-Downloader-3 是一个跨四端的下载器：Windows 10+、macOS 13+、Linux（glibc 2.35+）、Android 9+，基于 Qt 6.6+ / PySide6（也因此要求 CPU 支持 AVX）。协议覆盖 HTTP、Magnet/BT、FTP、M3U8、MPEG-DASH、eD2k；站点侧支持 YouTube 与 Bilibili（分段选择、任意清晰度、字幕、播放列表与多集），GitHub 与 HuggingFace 走镜像加速。

它的宣传语很实在：「每个下载器在好网络下都快，真正的考验是差网络。」做法是智能分块且不需要合并文件、自动探测带宽、使用真实浏览器的 TLS 指纹躲过反爬误判。浏览器扩展会在页面上跟随视频出现下载按钮，弹窗列出页面里所有媒体，点一下交给桌面端接管，登录态直接带过去；Android 端能录制直播 M3U8 并在后台继续下载。

可编程性也没落下：`ghd` 命令行提供 `probe / add / tasks / task / pause / start / remove / wait`，`add` 支持 BT 种子按文件序号选择，`wait` 可以阻塞到任务完成；另有 aria2 兼容的 RPC API，第三方工具可以无缝接上。周边还有 Feature Packs 插件生态、Crowdin 翻译流水线（桌面文案翻译到 60% 才进应用），GPL-3.0 协议。

💡 可借鉴的优点

- **产品思维**：不追功能数量，追「一个 app 替五个」——把散落在五个工具里的协议、站点、平台收进一个入口，同时保留「差网络下的真实体验」这个别人不测的场景。
- **架构设计**：下载引擎、协议适配、UI 三端分离；RPC 兼容 aria2 是一个聪明的选择——不要求生态来适配你，而是直接复用现成的生态。
- **工程化**：四平台构建与发布、免费代码签名（SignPath）、CLI 与桌面共享同一套任务模型、翻译走 Crowdin 而不是 PR 改语言文件。
- **社区运营**：QQ 群 + Discord 双通道，AUR 包交给社区维护，issue 模板分 bug / feature 两类，贡献者与翻译贡献者都单独列墙。

🌟 特别亮眼的地方

日增从 +341 直接翻到 +774，是它五天在榜的最高值。它是榜上唯一和 AI 无关的项目，却提供了 Agent 最需要的东西：**确定性、可脚本化的接口。** `ghd` 的每条命令都能被 Agent 直接调用、`wait` 能等到任务结束、RPC 兼容 aria2 意味着现成的自动化脚本不用改。而今天它的翻倍还有另一层含义——周六是「装机日」，人们终于有时间把收藏的下载器装上，去处理攒了一周的链接。

### #5 HKUDS/CLI-Anything ⭐

| 属性 | 信息 |
| --- | --- |
| 🔗 链接 | [HKUDS/CLI-Anything](https://github.com/HKUDS/CLI-Anything) |
| ⭐ Stars | 61,816 (+767) |

| 📦 分类 | Agent 基础设施 / 软件 CLI 化 |

📖 项目是干什么的

CLI-Anything 的目标一句话说清：**让所有软件都对 Agent 原生可用。** 它给两条路。第一条是直接用现成的：`pip install cli-anything-hub`，然后 `cli-hub list / search / info / install / launch`，从注册表里挑一个已经做好的 CLI 装上就跑。第二条是造一个新的：装上插件后执行 `/cli-anything <软件路径>`，走一套 7 阶段 harness 生成器，把一个有源码的软件变成可安装的 Python CLI 包——从代码库分析、架构设计、实现、测试计划、测试编写到文档，全流程自动化。

它有一套叫 `HARNESS.md` 的方法论 SOP 当唯一事实源，核心原则五条：必须调用真实软件渲染，不做替代实现；每个 CLI 同时提供有状态 REPL 与子命令两种模式；统一 REPL 皮肤与输出格式；每条命令都带 `--json` 给机器读；真后端缺失时测试必须失败而不是跳过。README 里那份「关键教训」清单很值钱：渲染鸿沟、滤镜翻译（MLT → ffmpeg 的参数空间差异）、非整数帧率的时间码累积误差，以及「退出码 0 不等于导出成功」——必须验 magic bytes、容器结构、像素与音频 RMS。

项目由港大数据智能实验室（HKUDS）维护，仓库里已经有 40 多个软件的 harness（GIMP 107 个测试、Blender 208 个、Inkscape 202 个、Audacity 161 个……），徽章标注 2,461 个测试通过，还有 18 个应用演示（CAD、3D 场景、图表、游戏、字幕），另有一份 arXiv 技术报告（arXiv:2606.03854），Apache 2.0 协议。

💡 可借鉴的优点

- **产品思维**：押注「CLI 是人和 Agent 的通用接口」，而不是再造一个 GUI 或一堆工具调用。命令行天然自带 `--help` 自描述、可组合、可管道、可脚本化。
- **架构设计**：软件适配层（每个软件一个 agent-harness 包）+ 统一 UX 层（repl_skin）+ 后端包装层，三层分明；同一套 SOP 既能生成新 harness，也能用 `refine` 扩覆盖、用 `validate` 查合规。
- **工程化**：「零妥协依赖」这条最硬——宁可测试红，也不让 mock 混过去；输出验证细到像素分析与音频 RMS；每个 harness 都带可安装的包与独立测试目录。
- **社区运营**：CLI-Hub 注册表 + wishlist 请求 + contributor signup + 「PR 合并即上架」的机制，把生态扩张做成了流水线；同时支持 Claude Code、Cursor、Codex、Pi、OpenCode 等多个宿主。

🌟 特别亮眼的地方

从 11-18 的 +384 翻到 19、20 两天的 +899 / +898，今天回落到 +767，但仍是榜单第 5。十五个在榜日说明它不是一波流：它补的是技能生态里最容易被忽略的一环——**没有可执行的接口，Agent 再会规划也只能聊天。** 当别的项目在比「谁的技能写得好」，它在解决「技能怎么真的把 Blender 的一个场景、LibreOffice 的一份文档、FreeCAD 的一个零件做出来」。基础设施型项目的曲线，本来就比热点平缓。

📖 项目是干什么的

这是一个**把 App Store / Google Play 被拒变成「提交前就能查出来」**的开源 playbook，外加一个自动守卫。正文是一份 117 条被拒模式与修复方法的资料库，覆盖隐私清单与 Data safety 检查、演示账号与后端可用性、内购规则、账号删除、权限声明，还跟踪 95 个监管截止日（EU AI Act、DSA、COPPA、GDPR、各年龄段法规）。

真正让它上榜的是那个 guard 脚本：`bash agent-os/hooks/app-store-compliance-guard.sh "/path/to/your/app"` 扫一遍工程，输出三种结论——`BLOCKED.`（发现 Critical 风险，逐条给出 `fix.`）、`CLEAR.`（代码侧无 Critical）、`NOT CHECKED.`（没找到 iOS/Android 工程）。把它装成 hook 后，Agent 在每次提交命令（fastlane、`xcrun altool`、`eas submit`、`gradle bundleRelease`、App Store Connect 上传）前都会先跑一遍，出现 Critical 就**直接拦住命令**。

安装器覆盖 13 个宿主：Claude Code、Codex CLI、Gemini CLI、OpenCode、Cursor、GitHub Copilot（CLI / VS Code / cloud agent）、Grok、Qwen Code、Kimi Code、Factory Droid、Augment Auggie、Windsurf。它的验证方式很少见：只有真的喂一条 submit 命令给对应工具的 hook、并看到被拦住，才会打印 `Install verified.`；写配置前留日期备份，非法 JSON 不重写而是给你一段可粘贴的块；卸载精确到它自己写入的那一条。许可证是 OpenRoots Agent License 2.3。

💡 可借鉴的优点

- **产品思维**：把一个价值「一周」的痛点（被拒 → 等审 → 猜原因 → 再等）压缩成 2 分钟的本地检查；并且给非开发者准备了纯英文 checklist，给开发者准备了 hook 与 `--dry-run`。
- **架构设计**：同一份 guard 适配十几种 hook 协议，配置写入按工具各自的格式与位置分别处理（`~/.claude/settings.json`、`~/.codex/hooks.json`、`~/.kimi-code/config.toml` 里只追加一个标记块……），把「兼容」当成工程而不是口号。

- **社区运营**：一个人维护，明确「只求一个 star、fork 或关注」，且要求使用者自己决定是否 star，连安装提示词里都写着「不要替我 star」——把诚实写进流程。
