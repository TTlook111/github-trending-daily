📖 项目是干什么的

这是 Modern Web Guidance 的源码仓库，由 Google Chrome、Microsoft Edge、Mozilla Firefox 和 MDN 团队联合维护，Apache-2.0 许可。它是一组嵌入编码 Agent 的技能，专门引导 Agent 远离遗留写法、转向现代 Web 平台的原生能力。一个很现实的出发点是：LLM 的训练数据里有海量旧代码，导致它们总爱用臃肿的 JavaScript 去解决那些浏览器现在已经原生支持的问题。

它提供一个 CLI，支持 install 安装、search 搜索指南、retrieve 按 ID 取指南、legacy-scan 直接扫描代码库里的过时写法。内容覆盖 250 个现代 Web 特性，分六大领域：用户体验（View Transitions、滚动驱动动画）、CSS 布局（容器查询、subgrid、oklch 色彩）、性能（预加载、INP 诊断、scheduler.yield）、表单与 UI（Popover、dialog、锚点定位）、无障碍，以及浏览器内置 AI。一个关键工程理念是「token 高效」：通过评测持续裁剪模型本来就会的低价值内容，只把真正需要的专家指南塞进上下文。今天它以 1,875 的单日新增从昨天的 #8 直接登顶。

💡 可借鉴的优点

- **产品思维**：精准命中「Agent 生成过时代码」这个普遍痛点，由浏览器厂商亲自下场，权威性无可替代。
- **架构设计**：指南按技能组织、CLI 多入口，既能整体安装也能按需检索，legacy-scan 还能反向审计存量代码。
- **工程化**：评测驱动内容裁剪，公开 Eval Dashboard 和 GOVERNANCE 治理文件，把「内容质量」变成可量化的事。
- **社区运营**：四大浏览器团队 + Web 社区共建，跨厂商协作本身就是很强的信任背书。

🌟 特别亮眼的地方

它的登顶是一个明确信号：**当平台厂商开始主动为 Agent 写指导，「Agent 生成的代码质量」已经成为浏览器生态自己要操心的事。** 相比再做一个会写代码的 Agent，把一整个平台的现代能力翻译成 Agent 能听懂的规范，反而是更稀缺、也更有壁垒的位置。

📖 项目是干什么的

Astryx 是 Meta 开源的设计系统，目前处于 Beta，MIT 许可。它在 Meta 内部生长了八年，是公司内使用最多、规模最大的设计系统，支撑了 13,000+ 应用。它基于 React 19+ 和 StyleX，提供 150+ 无障碍组件、品牌级主题、暗色模式、开箱即用的模板和一套 CLI，导入预构建 CSS、使用类型化 React 组件即可，无需构建插件或额外样式库。

它的差异化设计很明确：**开放内部**——组件可在任意层级组合，构建块直接导出，需要深入时用 swizzle 把组件完整源码「弹出」到项目里自己拥有；**无样式锁定**——样式用 StyleX 编写但对消费者透明，可用 Tailwind、CSS Modules 或普通 CSS 通过 className 覆盖；**主题即 CSS 变量覆盖**，无需 fork 或包裹组件即可定制；并且从 API、文档到 CLI 都按「人和 Agent 用同一套方式构建」来设计。仓库是标准 monorepo，分为 apps、packages、internal 三层，自带 7 套现成主题。

💡 可借鉴的优点

- **架构设计**：swizzle 弹出源码 + CSS 变量主题 + 样式层可覆盖，把「可定制性」做到不牺牲一致性。
- **产品思维**：明确「引导而非强制」，组件给能力而不是设护栏和用户对抗。
- **工程化**：强约定（命名、props、组合规则统一）+ 完整文档 + Storybook + CLI，让人和 AI 都能预测陌生组件行为。
- **社区运营**：贡献 wiki 公开 API 约定、设计约定、组件生命周期和评审 rubric，降低外部贡献者的上手成本。

🌟 特别亮眼的地方

它连续多日保持单日新增过千，正在成为 Agent 生成 UI 的事实标准。它给所有设计系统指了一个新方向：**你的下一个核心用户，可能是一个 Agent**——当 AI 大量生成界面，一套可靠、可预测、可组合的组件语言就是刚需。

📖 项目是干什么的

这是 Google 工程师 Addy Osmani 发起的项目，MIT 许可，把资深工程师的工作流、质量门和最佳实践编码成一套「技能」，让 AI 编码 Agent 在软件开发的每个阶段都能一致地遵循。它把完整生命周期拆成 DEFINE → PLAN → BUILD → VERIFY → REVIEW → SHIP 六段，对应 `/spec`、`/plan`、`/build`、`/test`、`/review`、`/ship` 等 9 个斜杠命令，一共包含 25 个技能。

技能本身是纯 Markdown，每个 SKILL.md 都有统一骨架：概述、触发时机、分步流程、「反合理化表」、危险信号和验证要求。内容里融入了大量 Google 工程文化——API 设计讲 Hyrum's Law，测试讲测试金字塔和 Beyonce Rule，简化代码讲 Chesterton's Fence，Git 讲主干开发，CI/CD 讲 Shift Left。它还提供 4 个专家角色和 7 份共享检查清单，通过一个开放 CLI 可安装到 70 多种 Agent 里，仓库内带 25 个评测用例来验证技能的实际效果。

💡 可借鉴的优点

- **产品思维**：瞄准 Agent「默认走最短路径、爱跳过规范」的天性，把工程纪律做成可执行流程而非口号。
- **架构设计**：渐进式披露——SKILL.md 只放入口，参考资料按需加载，把 token 消耗压到最低。
- **工程化**：每个技能都以「验证证据」收尾，并用 evals 持续检验，「看起来对」永远不算数。
- **社区运营**：一份技能包适配 70+ Agent，每个宿主都有专门的安装文档，还坦诚记录已知限制。

🌟 特别亮眼的地方

「反合理化表」是它最狠的设计：Agent 想偷懒说「测试稍后再补」，技能里早就备好了反驳依据。它本质上是在给 Agent 建一套**防自我欺骗的操作系统**，也预示未来工程能力的沉淀，可能不再是文档和 wiki，而是 Agent 能直接执行的技能文件。

📖 项目是干什么的

它用 Python 3.14 编写、uv 管理依赖，工程上最下功夫的是可靠性：自动重试、可配置限流、并发控制、模型/提供商自动回退、多 API key 自动切换，让你在某个提供商宕机时也能继续写代码。使用面覆盖终端、桌面应用、IDE 插件、手机（Discord/Telegram，支持 Whisper 语音转写）和浏览器原生会话，还能通过 RTK、Headroom 把 token 用量最多降低 90%。项目明确声明与 Anthropic 无关，且承诺遵守各提供商的服务条款，一旦某集成不再被允许就下架。

- **工程化**：把故障当作常态设计——重试、限流、回退、多 key 一应俱全；Pytest、Ty、Ruff 配齐。
- **合规意识**：主动声明商标边界、跟随提供商 TOS 调整，在灰色地带里尽量把自己做干净。

🌟 特别亮眼的地方

- **产品思维**：个人玩具有免费本地授权、团队用有完整企业版，从单机到 K8s 路径平滑，商业分层清晰。
- **架构设计**：前后端与 Intelligence 三层解耦，Agent 走 AG-UI、工具走 MCP、沙箱可插拔，每一层都能独立替换。
- **工程化**：签名安装包、Helm chart、完整架构文档和 prompt.txt 辅助 AI 部署，企业场景考虑周到。
- **社区运营**：不强迫用户迁移已有 Agent，把各大主流 Agent 框架和托管平台都接进来，生态站位开放。

🌟 特别亮眼的地方

它把企业用 Agent 最关心的三件事——**公司登录、工具权限、动作审批与审计**——做进了平台核心。当 Agent 能自己开浏览器、点按钮、发请求，「每个动作先经批准、事后留痕」就不是可选项，OpenBot 给整个行业打了个企业治理的样。

📖 项目是干什么的

HermesEnabler 是一个小众但精准的工具：让任意 Apple Watch 都能启用原本只有爱马仕联名款才有的 Hermès 表盘，MIT 许可，当前仅支持 watchOS 27.0 到 27.3 beta 1。它的原理是修改系统的 MobileGestalt 配置来「骗过」设备识别，因此 App 内提供完整的 MobileGestalt 备份，删除应用前必须先恢复备份。

最新版文档把安装路径拆得很细：macOS 上可以用 Sideloadly 侧载 IPA 或用 Xcode 编译，并明确记录了 Sideloadly 0.72 会剥离手表 App 的已知问题；Windows 上则借助社区工具 WatchBridge 完成开发者模式准备和双端安装。README 还把几个真实门槛讲在前面——免费个人团队的描述文件 7 天就过期、项目用到 App Groups 权限而免费账号无法配置（可能需要付费开发者账号）、开发者模式必须手动开启，多语言文档还新增了越南语。

💡 可借鉴的优点

- **产品思维**：需求极其聚焦，就解决一个「想要那个表盘」的具体愿望，且把 macOS/Windows 两条路径都写透。
- **安全设计**：动系统配置前先强制备份、给出明确恢复路径，把「玩坏了能救回来」做成内置流程。
- **工程化**：同时提供 IPA 侧载和 Xcode 源码两条路径，并坦诚记录工具版本缺陷和权限限制，不藏坑。
- **社区运营**：主动联动 Windows 社区工具、多语言文档覆盖全球用户，issue 里的已知问题直接写进 README。

🌟 特别亮眼的地方

它是典型的「小而美」，而且文档质量随着版本快速进化——从昨天一页纸的简略说明，变成今天把双平台、已知缺陷、权限门槛全部摊开的详尽指南。**开源小工具的可靠性，很大程度上就体现在它敢不敢把「什么情况下会失败」老老实实写出来。**

📖 项目是干什么的

llama.cpp 的目标是用最少的配置、在尽可能广的硬件上做 LLM（和视觉模型 VLM）的本地推理，MIT 许可。它是纯 C/C++ 实现、默认无外部依赖，构建在自研的 ggml 张量库之上，提供 `llama cli` 命令行和 `llama serve` 起一个 OpenAI 兼容 API 服务器，还能直接从 Hugging Face 拉模型运行。

它最大的护城河是硬件覆盖和量化：Apple Silicon 是一等公民，通过 ARM NEON、Accelerate 和 Metal 深度优化；x86 支持 AVX/AVX2/AVX512/AMX，RISC-V 也有对应指令集；GPU 侧有自研 CUDA 内核，并通过 HIP 支持 AMD、MUSA 支持摩尔线程，另有 Vulkan、SYCL、WebGPU、OpenVINO 等十几种后端，还支持 CPU+GPU 混合推理来跑比显存更大的模型。量化覆盖 1.5-bit 到 8-bit，用更小内存换更快速度，并保持正式版 + nightly 的活跃发布节奏。

💡 可借鉴的优点

- **产品思维**：一行安装脚本、一条命令跑模型，把「本地跑大模型」的门槛降到普通人能接受。
- **架构设计**：无依赖的 C/C++ 内核 + 可插拔后端矩阵，新硬件只需加一个后端就能接入整个生态。
- **工程化**：CI 覆盖服务器、Docker、安装包多条流水线，量化、混合推理等关键能力都有文档和工具支撑。
- **社区运营**：清晰的贡献者晋升路径，issue 和 PR 规模巨大但运转有序。

🌟 特别亮眼的地方

它是「本地 AI」运动的基石级项目，在大家都往云端挤的时候，反其道而行把推理塞进每个人自己的设备。今天榜单上的 free-claude-code、qwen-code 都能接它做本地后端，**隐私、离线、零 API 费用这三件事，让它在 Agent 分层架构里牢牢占住「推理底座」。**

📖 项目是干什么的

Qwen Code 是阿里 Qwen 团队开源的 AI 编码 Agent，跑在终端里，同时覆盖编辑器、桌面、浏览器和聊天入口，Apache-2.0 许可，要求 Node.js 22+。最新的 1.0 Preview 把 Qoder 的 Agent 外壳能力融合进来，作为完全开源的版本发布。

- **社区运营**：多语言文档、丰富的周边生态，对中文开发者尤其友好。

🌟 特别亮眼的地方

它证明了开源编码 Agent 已经能和商业对手掰手腕，而且**框架与模型双开源、协同演进**——你不必担心被某个厂商锁死，从模型到外壳都可以自己掌控，是 Agent「执行层」最开放的一个选择。

## 📊 今日趋势洞察

**核心方向：规范层领跑，Agent 技术栈加速固化——执行层位置基本排定，安全、规范、治理成为最热的新一层。**

今天的 10 个项目可归成三条线：

- **规范/监督层（今日领跑）**：modern-web-guidance（#1，现代 Web 实践）、codex-security（#4，安全审计）、agent-skills（#5，工程规范），不直接干活，专门保证其他 Agent 做得对。
- **持续固化的分层底座**：astryx（#2，组件）、free-claude-code（#6，路由）、OpenBot（#7，企业治理）、llama.cpp（#9，推理）、qwen-code（#10，执行），连续多日守在各自层级。
- **应用与极客向**：sure（#3，自托管理财）、HermesEnabler（#8，设备解锁）。

**升温领域：**
1. **Agent 安全与规范层**——三个监督类项目同时占据头部，「怎么保证 Agent 做得对」的价值正在超过「让它能做什么」。
2. **技术栈事实标准收敛**——同一批项目连续霸榜且高基数仍高增长，分层格局从探索走向固化，后来者很难再挤入执行层。
3. **安全工程闭环**——codex-security 把扫描、验证、补丁、导出、成本控制做成完整链路，DevSecOps 正在被 Agent 重写。
4. **平台厂商主动立规**——浏览器厂商、模型厂商都在亲自为 Agent 写规范，平台开始接管 Agent 输出质量。

**对开发者的启发：**
- 选赛道要往「上层」看：执行层已经拥挤，做安全、规范、审计、治理类工具，壁垒和热度都更高。
- 小工具也要把「失败条件」写清楚——HermesEnabler 主动暴露权限门槛和版本缺陷，这种坦诚本身就是信任资产。
- 技术栈选型可以更果断：连续多日霸榜的分层组合正在成为事实标准，没必要再等。
- 安全能力要前置：当 Agent 能自动扫漏洞、打补丁，懂安全的开发者在 Agent 时代有明显溢价。
- 高基数项目仍在增长说明赛道远未到顶，但窗口正在从「人人可做」收窄到「有标准、有治理能力者胜出」。
