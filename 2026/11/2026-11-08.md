📖 项目是干什么的

这是 Cloudflare 官方开源的安全审计技能，让编码 Agent 按一套多阶段流程完成代码安全审计，输出经过独立复核、机器可读的发现记录。它也是 Cloudflare 全量漏洞发现体系（vulnerability harness）的单仓库起点。流程分为六步：侦察（梳理架构、信任边界、输入面并写入覆盖账本 `coverage-ledger.json`）、按覆盖账本派出隔离的「猎手」Agent、把每个候选漏洞交给全新的验证者去设法证伪、写入 `findings.json` 并按 JSON schema 校验、再由新 Agent 复核源码断言、最后从已验证记录生成报告。

它的关键在于「结论必须可验证」：发现分成 confirmed / needs_validation / rejected 三档，只有带完整源码追踪和实际观察的才能 confirmed；两个零依赖 Node.js 校验脚本（覆盖账本、发现记录）在流程中反复运行；目标代码必须在 OS 级沙箱里执行，否则一律保持待验证。连续两天登顶，单日仍新增 2,000+ star。

💡 可借鉴的优点

- **架构设计**：「发现者」与「验证者」强制分离，验证者的任务是证伪——这种对抗式复核可以直接搬到代码评审、数据核对等任何需要高可信结论的 Agent 流程里。
- **工程化**：用「覆盖账本」把「查了哪些、没查哪些」显式记录下来，多次运行增量叠加，避免模型自称「已全面检查」。
- **产品思维**：三档裁决让「证据不足」成为合法输出，而不是逼模型给出确定答案，显著减少误报。
- **安全设计**：沙箱、断网、资源限额写成硬性前提，审计工具本身不会变成新的攻击面。

🌟 特别亮眼的地方

它示范了「怎么让 LLM 的结论值得信任」：**不靠模型更聪明，而靠流程设计——隔离、对抗、schema 校验、覆盖账本。** 这套方法论的价值远超安全领域，是今天所有技能类项目里最值得精读源码的一个。

📖 项目是干什么的

OpenMausBot 自称开源的 Grok Bot 替代品，核心主张是：Agent 不该是「一个对话框里的一个助手」，而应像聊天软件里的一排联系人——每个 Bot 有自己的人格、记忆、模型、虚拟电脑和已连接应用，你和它们聊天、看它们干活、在风险操作上点批准。

实现上它坚持本地优先、自带 Agent：Bot 底层直接调用你本机已安装的 claude / codex / grok CLI，沿用已有的登录与订阅；一个只监听 127.0.0.1 的 harness 服务管理所有 Agent 进程，数据存在本地用户目录。每个 Bot 可以使用云端 Linux 桌面、本地隔离 VM，或在显式开启后操作你的电脑；应用连接借助 Composio。Shell 命令、文件修改等风险操作以内联卡片请求允许/拒绝。桌面端基于 Electron，移动端用 Expo，Apache-2.0 许可。两天内 star 从 1.6 万涨到近 1.7 万，热度未减。

💡 可借鉴的优点

- **产品思维**：用「聊天联系人」这个人人熟悉的隐喻承载多 Agent 管理，几乎零学习成本。
- **架构设计**：编排用户已有的 Agent CLI 而不是自己接模型，省掉 API Key 托管，也天然兼容新出的 Agent。
- **安全设计**：统一的权限代理 + 审批卡片，加上「每个 Bot 一台隔离电脑」，把 computer-use 的风险关进笼子。
- **增长打法**：README 直接写「X 的开源替代」及差异对比，精准承接搜索流量。

🌟 特别亮眼的地方

它把「多 Agent」从工程概念变成了产品形态：**不拼模型，而在用户已有能力之上做组织、权限和工位。** 对想做 Agent 产品的个人开发者，这是一条资源需求低、差异化清晰的路线。

| 💻 语言 | Python |
| 📦 分类 | OSINT / 社交账号搜索工具 |

📖 项目是干什么的

Sherlock 是一个老牌开源情报（OSINT）命令行工具：输入一个用户名，它并发去数百个社交网络和网站检测该用户名是否存在，输出命中的个人主页链接。它的核心是一份站点数据清单（每个站点的 URL 模板与「存在/不存在」的判定方式，如状态码、错误文本、重定向），程序本身负责并发请求、判定和结果导出（如 CSV / XLSX）。

今天它的总 star 正式突破 **10 万**（100,489），单日新增 1,766，连续多日在榜。用户名枚举是安全研究、反诈调查、个人隐私自查的入门工具，而它简单、可脚本化的 CLI 形态，也很适合被 Agent 当作原子能力调用。

💡 可借鉴的优点

- **架构设计**：「数据（站点规则）与逻辑（并发判定）分离」——新增站点只需改规则文件，社区贡献门槛极低，项目因此能长期覆盖数百个站点。
- **工程化**：针对不同站点采用不同的判定策略（状态码 / 页面文本 / 重定向），是做「多源探测」类工具的实用模板。
- **社区运营**：清晰的单一用途 + 低门槛贡献方式，让一个小工具维护多年依然活跃。

🌟 特别亮眼的地方

一个多年前的「小工具」在 2026 年跨过 10 万 star，说明 **单一用途、可脚本化、数据驱动的工具在 Agent 时代反而更值钱**——它们是 Agent 最容易调用、最不容易出错的积木。同时也提醒开发者：用户名跨站复用是隐私暴露的主要来源之一。

📖 项目是干什么的

Prometheus 是 CNCF 旗下的系统与服务监控系统：按固定间隔从目标拉取指标，评估规则表达式，展示结果，并在条件满足时触发告警。它的标志性设计包括：用「指标名 + 键值标签」定义时间序列的多维数据模型、强大的查询语言 PromQL、单节点自治（不依赖分布式存储）、HTTP pull 采集模型（批处理任务可通过网关推送）、服务发现或静态配置发现目标，以及分层与水平联邦。

仓库结构本身就是一份架构说明书：`scrape`（采集）、`tsdb`（时序存储）、`promql`（查询引擎）、`rules`（规则）、`notifier`（告警通知）、`discovery`（服务发现）各自独立。值得注意的是，仓库根目录已加入 `AGENTS.md`、`CLAUDE.md` 以及 `.agents/skills` 目录，为 AI 编码代理参与贡献提供了约定。

💡 可借鉴的优点

- **架构设计**：pull 模型 + 单节点自治让系统简单可靠，「监控系统自己不能先挂」的设计哲学非常值得学习。
- **数据模型**：多维标签模型 + PromQL 已成为可观测性领域的事实标准，设计指标体系时可直接参考其命名与标签规范。
- **工程化**：按功能拆分的清晰包结构、完善的 Makefile / 发布流程 / 安全声明，是大型 Go 项目的组织范本。
- **社区治理**：CNCF 毕业项目 + MAINTAINERS / CODEOWNERS 明确职责，并率先为 AI 贡献者编写规范。

🌟 特别亮眼的地方

一个十多年的基础设施项目重新冲上 Trending，又恰好在仓库里放上了 Agent 技能目录，这是今天最有代表性的信号：**成熟开源项目开始主动「面向 Agent 维护」。** 同时，随着 Agent 系统越来越复杂，指标与告警也正成为 Agent 可靠运行的底座。

📖 项目是干什么的

Vercel Labs 推出的 Rust 原生浏览器自动化 CLI，专为 AI Agent 设计。核心交互是「快照 + 引用编号」：`snapshot` 把页面转成紧凑文本，每个可交互元素带一个引用（如 `@e1`），Agent 用引用点击、填写，再重新快照确认结果。浏览器由后台 daemon 常驻，经 Chrome DevTools Protocol 控制，每个会话独立隔离，空闲后自动关闭。

它支持接入已运行的 Chrome、切换多种浏览器引擎、移动端 Safari 模拟以及多家云浏览器服务，并随 CLI 自带版本匹配的技能，也能以 MCP server 方式运行。今天排在榜单第一位（趋势位置），但当日新增 190 star，按新增量排序列第 8。

💡 可借鉴的优点

- **产品思维**：用结构化文本快照替代截图或完整 DOM，大幅节省 token，且「操作后必重读」形成天然闭环。
- **工程化**：元素被遮挡、禁用或不可见时明确报错而不是「假成功」，让失败可见。
- **生态策略**：技能与 CLI 同版本发布，避免「文档说一套、工具做一套」。

🌟 特别亮眼的地方

如果你要给 Agent 做任何「操作外部系统」的工具，它的设计原则可以直接借鉴：**状态外置（daemon）、接口文本化（快照）、动作可寻址（引用编号）、失败显式化。**

📖 项目是干什么的

Ruff 是 Astral（uv、ty 的作者团队）用 Rust 写的 Python linter 和代码格式化器，官方称比 Flake8、Black 等快 10–100 倍。它可通过 pip 安装，支持 `pyproject.toml` 配置，内置 900+ 条规则（原生重写了 flake8-bugbear 等热门插件），对 Flake8、isort、Black 做到可直接替换，并支持自动修复（如删除未使用的 import）、内置缓存、编辑器集成，以及适合 monorepo 的分层级联配置。

它已被 Apache Airflow、FastAPI、Hugging Face、Pandas、SciPy 等大型项目采用。与 Prometheus 类似，仓库根目录也已加入 `AGENTS.md`、`CLAUDE.md` 与 `.agents`、`.claude` 目录。今天它出现在 Trending 列表中，但页面未显示总 star 与当日新增，按规则以榜单位置补齐。

💡 可借鉴的优点

- **产品思维**：「一个工具替代一堆工具」+「兼容旧规则可直接替换」，迁移成本几乎为零，这是开发者工具抢占市场的经典打法。
- **架构设计**：用 Rust 重写热点路径、统一解析一次供所有规则复用、配合缓存跳过未改动文件——这是「如何让工具快 100 倍」的范本。
- **工程化**：仓库内含 fuzz 测试、playground、schema 文件（`ruff.schema.json`）与详细的破坏性变更记录，大型工具项目的成熟实践。

🌟 特别亮眼的地方

Ruff 的意义在 Agent 时代被放大了：**Agent 写代码越多，越需要快到可以每次修改都跑一遍的静态检查。** 毫秒级的 lint + 自动修复，正是 Agent 编码循环里最便宜、最可靠的反馈环。

## 📊 今日趋势洞察

**核心方向：技能即规范，基础设施全面「Agent 化」——好项目不仅要好用，还要让 Agent 读得懂、调得动、验得了。**

今天的 10 个项目可归成三条线：

- **技能库持续扩张**：Cloudflare 安全审计（#1）、mattpocock/skills（#4）、google/skills（#5）、anthropics/skills（#6），技能仓库包揽前六中的四席。
- **Agent 的手脚与工位**：OpenMausBot（#2，多 Bot 编排）、agent-browser（#8，浏览器自动化）、meta/astryx（#9，Agent 就绪组件库）。
- **成熟基础设施被重新估价**：sherlock（#3，突破 10 万 star）、Prometheus（#7，监控）、Ruff（#10，Python 工具链）。

**升温领域：**
1. **可验证的 Agent 流程**——对抗式验证、覆盖账本、schema 校验，让 Agent 结论可信。
2. **仓库级 Agent 规范**——`AGENTS.md` / `CLAUDE.md` / `.agents/skills` 进入 Prometheus、Ruff 等主流项目。
3. **快反馈工具链**——Rust 重写的 linter、CLI 化的浏览器，为 Agent 编码循环提供毫秒级反馈。
4. **本地优先的多 Agent 产品**——复用用户已有 CLI 与订阅，在其上做组织与权限。

**对开发者的启发：**
- 给自己的项目加一份 `AGENTS.md`：写清构建、测试、代码规范，是让 Agent 高质量贡献的最低成本投入。
- 设计 Agent 流程时，把「验证」和「生成」拆给不同的 Agent，并允许「证据不足」作为合法输出。
- 为 Agent 准备快速、确定性的反馈工具（lint、测试、类型检查），比换更强的模型更划算。
- 单一用途、可脚本化、数据与逻辑分离的工具，最容易成为 Agent 的积木。
