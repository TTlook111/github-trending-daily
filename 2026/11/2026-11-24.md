📖 项目是干什么的

Claude-BugHunter 是一套面向**授权范围内**漏洞赏金与外部安全测试工作的 Claude Code 技能包：84 个技能、15 个斜杠命令，外加从 681 份公开披露报告中整理出的模式库（覆盖 24 类核心漏洞，其中 433 条逐条标注了出处），以及企业身份与基础设施侧的知识矩阵。作者的定位很直接——装上之后，Claude Code 不再是一个「什么都懂一点的聊天机器人」，而像一个知道方法、知道边界、也知道该怎么写报告的安全研究员。仓库今年 5 月 5 日建仓，2,172 个 fork，今天 +2,029 登顶；最新 release 是 6 月的 v2.1，但仓库今天仍在提交。

它的结构是四层叠加：**Think**（方法论与思维纪律，规定工作流）、**Hunt**（按漏洞类别拆分的技能，每一类都对应公开报告里真实被支付过的模式）、**Hit the perimeter**（企业平台与身份侧的知识）、**Ship it**（分级验证、报告撰写与证据卫生）。技能按话题自动加载——你用自然语言描述「我在测什么」，相关技能就会被调起，不需要记名字。除了 Claude Code 插件市场，它也能装进 OpenCode、Codex CLI、Hermes Agent、Antigravity 等 harness，并接入了 HackerOne MCP，用来查重和核对项目范围。

最值得看的其实是它对「边界」的处理。README 用一整节列出**不做**的事——内网域渗透、C2、后渗透与持久化、规避检测、二进制利用——并明确写「这是设计决定，不是缺口」。授权部分写得很清楚：只用于你拥有或已获得书面授权的资产；验证关卡会直接问「这个资产在不在范围内」「这个影响在不在项目接受列表里」。它甚至提醒用户：模型自带的安全防护可能拒绝某些请求，即使你的工作是授权的——正确的路径是去申请官方的网络安全验证计划，而不是换个说法绕过去。

💡 可借鉴的优点

- **产品思维**：「一个通用的安全提示词」和「收藏夹里的三十份公开报告」是两个极端，前者太泛，后者不可扩展。它把两者之间的事做成了产品：把公开报告里的经验整理成可检索、按类别组织的技能，让第二次、第十个目标也能用上。
- **架构设计**：四层职责分明——方法论管流程，类别技能管知识，平台技能管场景，验证与报告管交付；技能按话题自动触发，降低了「不知道该调哪个」的使用成本。范围（scope）不靠提示词约束，而是写进代码层面的强制检查。
- **工程化**：安装脚本记录清单，多个技能包共存时卸载一个不会弄坏另一个；漏洞覆盖快照由工作流每周刷新；内容与代码分开授权（代码 MIT，方法论文档 CC BY 4.0），边界写得很细。
- **社区运营**：对「能做什么、不做什么、为什么」毫不含糊；上游来源（8 个技能来自另一个项目）逐一致谢；模型防护、拒绝与回退行为都如实写进文档，而不是回避。

🌟 特别亮眼的地方

它今天登顶的方式很说明问题：一个 5 月才建仓、半年攒到两万星的技能包，靠的不是某个漏洞或某条新闻，而是**把一门高度依赖经验的手艺，整理成了别人可以审计的知识库**——433 条模式逐条可追溯到公开报告。对非安全行业的读者，它的启发同样成立：任何「老师傅才知道怎么做」的工作，都可以被拆成「方法论 + 可检索的案例库 + 提交前的验证关卡」三件套。而第三件往往最容易被忽略，也最值钱：**会做的人很多，知道什么时候不该交的人很少。**

📖 项目是干什么的

Ghost Downloader 是一个跨平台下载器，口号是「The only downloader you need / 下载器的集大成者」。它把通常要装四五个软件才能覆盖的协议收进一个应用：HTTP、磁力 / BT、FTP、M3U8、MPEG-DASH、eD2k；YouTube 与 Bilibili 支持分 P、任意清晰度和字幕；GitHub 和 HuggingFace 走镜像加速；还能配浏览器扩展嗅探页面媒体，点一下由桌面端接管，登录态一并带过去。项目 2023 年 8 月建仓，GPL-3.0 协议，1,019 个 fork，今天 +1,087；最新版本 v4.5.11 于 11 月 20 日发布，仓库今天仍有提交。

它的工程底子是 Python + PySide6，界面基于 PyQt-Fluent-Widgets 的 Fluent Design；网络层跑在 asyncio 上（uvloop / winloop），HTTP 客户端用带 TLS 指纹模拟的 wreq；BT 交给 libtorrent，M3U8 交给 N_m3u8DL-RE，站点解析复用 yt-dlp，最后用 Nuitka 编译分发。功能列表里有两点很「下载器才懂」：智能分片、不合并文件，自动探测带宽；下载中途可以改 URL、请求头或代理，进度不丢。四个平台都是原生体验——Windows 10+、macOS 13+、Linux（glibc 2.35+）与 Android 9+，Android 端还能录制直播流并在后台持续下载。

💡 可借鉴的优点

- **产品思维**：不追求单点极限，而是「一个应用替掉五个」。差异化落在真实痛点上——弱网下的速度、反爬严格的站点、下载到一半想换代理。浏览器扩展与桌面端接力这件事，把「复制链接」这个最烦的步骤去掉了。
- **架构设计**：协议层各取所长（libtorrent、N_m3u8DL-RE、yt-dlp、aioftp），自己专注调度与界面；对外提供 aria2 兼容的 RPC，第三方工具可以无缝接入；`ghd` 命令行把 probe / add / pause / wait 做成可脚本化的入口。
- **工程化**：用 Crowdin 管理多语言，源语言是简体中文，桌面端文本翻译到 60% 才会进入应用；代码签名由 SignPath 基金会与社区成员免费提供；社区维护了 Arch Linux 的 AUR 包。
- **社区运营**：QQ 群与 Discord 双通道；Roadmap 老实写着「插件 API 尚未公开、还在稳定」，Issue 与 PR 模板齐全。

🌟 特别亮眼的地方

一个 2023 年的项目在今天拿到 +1,087、总量 16,873，说明「基础工具」的需求从来不会被 AI 热潮取代。更值得注意的是它的技术选型：Python 写下载器在很多人眼里是「慢」的代名词，它用 asyncio、编译分发和成熟的 C++ / Rust 引擎把这件事做成了体验。对开发者还有另一层提醒——在 Agent 时代，下载器有了新角色，它是 Agent 的「取物通道」：`ghd add` / `ghd wait` 这种命令行接口和 aria2 兼容的 RPC，让「把一个链接变成一个本地文件」成为可被编排的一步。**一个老工具只要补上命令行与 RPC，就能搭上新一轮的顺风车。**

📖 项目是干什么的

Firecrawl 是给 AI Agent 用的「网页数据基础设施」——把任意网站变成干净的 Markdown、结构化 JSON 或截图，再加上搜索、页面交互与自主取数。项目 2024 年 4 月建仓，AGPL-3.0 协议（SDK 与部分 UI 组件为 MIT），10,886 个 fork，今天 +924，仓库今天仍在提交。它的自我定位已经从「爬虫 API」变成了「让 Agent 更聪明的知识基础设施」。

这一版 README 把产品拆成三种形态。**Firecrawl Local**：一个 Rust 写的单文件，`cargo install firecrawl-local` 装完就能抓取、爬站、列 URL，不需要数据库、队列和容器；需要 JavaScript 的页面用本机已有的 Chrome / Chromium 渲染，PDF 与 Office 文档也在本地解析。`firecrawl-local init` 会自动发现 Claude Code、Claude Desktop、Cursor、Windsurf、Gemini CLI、Codex 并把自己注册成 MCP 服务；`serve` 则在本机 3002 端口提供与云端 v2 API 兼容的接口，为 Firecrawl 写的代码改个地址就能跑在本地。**Firecrawl Cloud**：在此之上增加搜索、结构化输出、Interact（在已抓取的页面上点击、输入）、Agent（给一句话，自己去找）以及 Alexandria——550 多家数据提供方（2.5 亿多人、7,500 多万家公司、4,100 多万篇论文）通过一个 API / MCP / CLI 接入。**自托管**：完整的 API 服务带队列、worker 和数据库，Docker Compose、Kubernetes 清单与 Helm Chart 都有。

一些细节看得出它在认真对待「被 Agent 使用」这件事：有一份 `agent-onboarding/SKILL.md`，Agent 可以自己读完、帮用户注册并拿到 API key；Keyless 模式每月送 1,000 个额度，不需要注册；技能目录 `firecrawl/skills` 由 CI 从仓库镜像生成、只读；README 末尾提醒用户遵守目标网站的条款，默认尊重 robots.txt。云端声称覆盖 96% 的网页、P95 延迟 3.4 秒。

💡 可借鉴的优点

- **产品思维**：同一个能力做成三档——本机单文件、托管云、完整自托管——分别对应「想马上试」「不想运维」「数据不能出门」三种人。Local 不是阉割版：抓取、爬站、Map 都在本机，只把搜索和 Alexandria 转给云端，而且可以用一个环境变量彻底关掉。
- **架构设计**：本地与云端共用同一套 v2 API 契约，SDK 只改 `api_url`；Local 默认在单页抓取失败时回退到云端，并在结果里标注来源——「降级可见」比静默失败好得多。
- **工程化**：Local 做成 Rust 单文件，免去了 Node 依赖和容器；MCP 一条 `init` 覆盖六个主流 Agent 宿主，改配置前先备份；Kubernetes 与 Helm 给了规模化路径。
- **社区运营**：SDK 覆盖 Python、Node、Go、Java、Rust、Ruby、.NET、PHP、Elixir；技能目录只读、由 CI 同步，避免「文档说有、仓库没有」；924 个 open issue 说明反馈量巨大。

🌟 特别亮眼的地方

208,349 星的 Firecrawl 是今天榜上「最不新」的项目之一，却也是最能说明 Agent 基础设施走向的一个：两年前它卖的是「把网页转成 Markdown」，今天它卖的是「Agent 可以自己发现、注册并调用的数据层」——Agent 读一份 SKILL.md 就能替用户完成接入，Alexandria 则把「数据源」做成了可检索、可计价的市场。这与今天的 last30days、CLI-Anything 是同一个方向：**Agent 的能力上限，越来越取决于它能拿到多少「带钥匙」的数据，而不是模型本身。** 而它把本机单文件放在 README 第一节，则是对「数据不想出门」这类客户的回答。

📖 项目是干什么的

AutoClip 的口号是「一个链接，一键出片」：把播客、访谈、课程或游戏直播的长视频，自动剪成适配抖音、小红书、TikTok、Reels、YouTube Shorts、Bilibili 的短视频，顺手生成字幕、封面和发布文案。核心能力是「挑片段」——用转录文本和抽帧理解内容，找出值得单独成片的高光时刻，再做竖屏智能重构（跟踪说话人）、烧字幕、出封面标题。项目 2025 年 7 月建仓，MIT 协议，2,244 个 fork，今天 +907；**v1.6.0 正是今天发布的**。

v1.6 的主线是「直播回放」：新增独立的 Live Replay 标签页，支持 OBS、Twitch、YouTube、Kick、Discord 与本地录像六种来源；连上 OBS 的 WebSocket，下播后无损裁剪（`-c copy`）并自动排队切片；游戏类回放的高光识别放宽到 8 秒以上的独立回合。另一项是「一键换平台」——同一条片段以卡片形式呈现，切换目标平台不用重新导出。界面、托盘和文档覆盖 13 种语言，字幕支持阿拉伯语从右到左。

它的工程形态很完整：桌面端是 Tauri + React + FastAPI，Python 与 FFmpeg 随安装包一起分发；也有 CLI 与 MCP（`uvx autoclip-mcp`）和 Agent Skill（`npx skills add zhouxiaoka/autoclip`），以及 Docker / Web 部署。定位是 local-first：剪辑与渲染都在本机，模型可以自带 API key，也可以用 Ollama / LM Studio + Whisper / SenseVoice 完全离线。README 给的实测数字：1 小时 43 分、已有字幕的英文访谈，7.5 分钟出 10 条片段，LLM 成本约 ¥0.09；2 小时 52 分、无字幕的中文播客走本地 Whisper，29.5 分钟出 10 条，约 ¥0.20。

💡 可借鉴的优点

- **产品思维**：不卖「视频编辑器」，卖「内容再利用」——输入是一个链接，输出是可直接发布的一组成品，中间的选段、重构、字幕、封面、文案全部打包。面向的是「有一期两小时播客、想发短视频」的创作者，而不是剪辑师。
- **架构设计**：流水线按阶段拆开（转录、选段、重构、渲染、发布），每个阶段都可以换后端——云 ASR 或本地 Whisper，云 LLM 或本地模型；同一套能力同时暴露为桌面应用、CLI、MCP 和 Skill，人用界面、Agent 用接口。
- **工程化**：安装包在 GitHub Actions 上公开构建，附带 `build-provenance.json` 做 SHA-256 校验；代码签名与 Apple 公证的状态在 issue 里公开跟踪，没有含糊过去；基准测试把耗时与成本分开列，并注明估算口径。
- **社区运营**：16 条以上可播放的样片、Showcase 页面、专门的 show-and-tell 讨论区；README 直接写明「单人维护、只能异步回复」，预期管理很诚实；还附了一篇研究笔记《Pick the Moment, Not the Effect》。

🌟 特别亮眼的地方

今天是它的发版日，+907 是对一个 16 个月大的项目的即时反馈。更值得注意的是它的定位选择：在一个几乎所有 AI 视频工具都在做「生成」的年份，AutoClip 做的是「剪辑已有的东西」——不生成新画面，只负责把两小时里最值钱的三分钟找出来、摆成竖屏、配好字幕。这件事的难点从来不是模型，而是**把一堆开源组件（FFmpeg、Whisper、yt-dlp、Tauri）拼成普通人能双击安装的成品**。当「一人公司」和「播客转短视频」成为常态，这类 local-first 的内容流水线会像今天的下载器一样，变成默认装机软件。

Superpowers 是给编码 Agent 装上的一整套软件开发方法论：一组可组合的技能，加一段保证「Agent 真的会用它们」的启动指令。流程是固定的——**brainstorming → using-git-worktrees → writing-plans → subagent-driven-development / executing-plans → test-driven-development → requesting-code-review → finishing-a-development-branch**。Agent 看到你要做东西，会先退一步问清意图，把规格分段讲给你确认；计划要细到「一个热情但没品味、没判断力、讨厌写测试的初级工程师也能照做」，每个任务 2–5 分钟；实现阶段每个任务交给一个全新的子 Agent，做完就评审，主会话只保留决策与验收。项目去年 10 月建仓，MIT 协议，28,865 个 fork，359 个 open issue；当前版本 v7.0.2（11 月 3 日），今天 +840。

分发宽度仍是它最大的资产：README 目录里列了 16 个 harness——Claude Code、Antigravity、Codex App 与 CLI、Cursor、Devin CLI、Factory Droid、Gemini CLI、GitHub Copilot CLI、Grok Build CLI、Kimi Code、OpenCode、Pi、Qwen Code、Hermes Agent、Muse——而且其中好几个走的是**厂商官方插件市场**：Anthropic 官方市场、OpenAI 的官方 Codex 市场、xAI 的官方 Grok 市场、Kimi Code 市场。技能库里除了流程类技能，还有调试类（systematic-debugging、verification-before-completion）和元技能（writing-skills、diagnosing-superpowers）。

它对「什么时候会失效」也写得很直白：Hermes 没有压缩后的 hook，一个在第一轮就被压缩的长会话会丢失启动指令，技能不再触发，解决办法是开新会话；Pi 包在压缩后会重新注入；Muse 通过 SessionStart hook 注入，版本号由 `.version-bump.json` 跟踪。

💡 可借鉴的优点

- **产品思维**：卖纪律而不是能力。每个环节都在回答同一个问题——怎样让 Agent 的产出可验收：规格分段确认、任务拆到 2–5 分钟、测试先红后绿、评审按严重度分级且严重问题阻断。
- **架构设计**：子 Agent 隔离是核心——实现细节留在子会话，主对话只负责拍板，上下文不被污染，这是它能连续自主跑几小时的前提；同一份技能在 16 个 harness 上复用，差异都收在安装层。
- **工程化**：技能行为用独立的评测框架测（`evals/` 里的 drill 评测），插件基础设施另有测试；对「失效模式」有专门的诊断技能 `diagnosing-superpowers`，读会话记录给出逐行证据，而不是让人猜。
- **社区运营**：明确不接受「Agent 代写、修别人 issue」的 PR，除非维护者点名；遥测默认只上报版本号且可一键关闭；企业支持留了入口。

🌟 特别亮眼的地方

连续四期在榜（11-17、11-18 的第 1，11-19 的第 4，今天第 5），它已经成了这张榜单的「背景噪声」——而这正是方法论产品成功的标志。今天更值得看的是一个信号：一个独立开发者写的 Shell 技能包，同时进了 Anthropic、OpenAI、xAI 三家的官方插件市场。这意味着「开发纪律」正在从「某个厂商的 Agent 特性」变成「跨厂商都可安装的公共品」。当模型能力趋同、价格战开打，**能被装进所有 Agent 里的流程，比任何单一 Agent 的功能都更难被替代。**

📖 项目是干什么的

MiniMind 是一个「从零训练一个 64M 参数小语言模型」的完整开源项目，口号是「两小时、三块钱，从 0 训出你的大模型」。主线最小版本的体积约为 GPT-3 的 1/2700，目的是让个人 GPU 也能完整走一遍训练链路。项目 2024 年 7 月建仓，Apache-2.0 协议，9,107 个 fork，今天 +828；最近一次提交是 11 月 23 日。「两小时」指的是在单张 3090 上跑完 SFT 一个 epoch 的实测耗时，「三块钱」是对应时段的 GPU 租用成本——README 特意注明了这一点。

它的特别之处是「不依赖高层封装」：所有核心算法都用 PyTorch 原生实现，覆盖 Dense 与 MoE 结构、Tokenizer 训练、数据清洗、预训练、SFT、LoRA、DPO、RLAIF（PPO / GRPO / CISPO）、工具调用、Agentic RL、自适应思考与蒸馏。2026 年 4 月发布的 minimind-3 把主线结构对齐到 Qwen3 / Qwen3-MoE 生态：Dense 约 64M，MoE 约 198M 总参数、64M 激活，去掉了共享专家；Tokenizer 改为 BPE + ByteLevel，加入了 `<tool_call>`、`<tool_response>`、`<think>` 等标记并预留扩展位；新增原生的 Agentic RL 训练脚本，RLAIF 与 Agentic RL 的 rollout 引擎也做了解耦。

生态兼容是它一直在维护的东西：权重命名对齐 Transformers，能直接跑在 llama.cpp、vllm、ollama 上，也兼容 transformers / trl / peft 与 Llama-Factory；训练支持单机多卡（DDP、DeepSpeed）、断点续训、wandb / SwanLab 可视化；评测支持 C-Eval、C-MMLU、OpenBookQA；自带兼容 OpenAI API 的服务端与 Streamlit 聊天界面。项目还长出了一组孪生方向：视觉版 MiniMind-V、全模态 MiniMind-O、扩散语言模型 MiniMind-dLM、线性注意力 MiniMind-Linear。

💡 可借鉴的优点

- **产品思维**：把「大模型」这件让人望而生畏的事，压缩到一个学生在一台游戏显卡上能复现的尺度，再用「两小时 / 三块钱」把这个尺度翻译成任何人都能感知的数字。它卖的不是模型效果，而是「理解的门槛」。
- **架构设计**：代码结构与主流生态对齐（Qwen3 系结构、Transformers 命名、OpenAI 接口），小模型因此可以无缝使用为大模型准备的工具链；主线之外用独立仓库承接视觉、全模态、扩散等分支，主线保持可读。

- **社区运营**：Hugging Face 与 ModelScope 双渠道发布，B 站有视频介绍，有在线体验；赞助完全自愿、不换取特权，并直接写明「算力可能用于项目相关或不相关的探索」。

🌟 特别亮眼的地方

一个 2024 年的「教学项目」今天 +828，靠的不是新模型，而是它一直在跟着前沿走：当业界在讨论 Agentic RL、工具调用、自适应思考，它就把这些做成了一个 64M 模型上也跑得通、看得懂的版本。这是开源里最少见的一类项目——**既是教程，又是一面镜子**：大厂实验室里的新训练范式，这里都会有一个「缩小到能看清每一行代码」的对应实现。对想真正理解 LLM 的人，它的价值不在于省了多少钱，而在于让「预训练 → SFT → RL」从一堆缩写变成一段你亲手跑过的日志。

📖 项目是干什么的

这是一个「在审核员之前，先告诉你为什么会被拒」的 App Store 与 Google Play 合规手册，外加一个提交前检查脚本。规模：124 个有文档记录的拒审模式与修复方法、隐私清单（Privacy Manifest）与数据安全表单检查、112 个被跟踪的法规截止日期（欧盟 AI 法案、DSA、COPPA、年龄相关法规），以及一份给 AI 编码 Agent 用的技能。项目今年 6 月 6 日建仓，338 个 fork，今天 +761；最新版本 v2.5.1 是 11 月 22 日发布的；README 标注的许可证为 OpenRoots ORA 2.3。

用法被压缩成两条命令：clone，然后运行守门脚本并指向你的工程目录——什么都不安装，也不改动你的工程。小工程一秒扫完，大的最多一分钟，结果按严重度排序，每条都带文件与行号。结论只有四种：`BLOCKED.`（存在致命风险，逐条修复后重跑）、`CLEAR.`（代码里没有致命风险，但这不是「会通过」的保证）、`Rule pack STALE.`（规则包超过 60 天没更新，先 `git pull`）、`NOT CHECKED.`（没找到 iOS / Android 工程）。

真正有意思的是「装进 AI 编码工具」这一步。安装脚本支持 Claude Code、Codex CLI、Gemini CLI、OpenCode、Cursor、GitHub Copilot（CLI、VS Code、云 Agent 与 JetBrains）、Grok、Qwen Code、Kimi Code、Factory Droid、Auggie 与 Windsurf：写入守门脚本、技能和一个 hook，当 Agent 即将执行上传命令（fastlane、`xcrun altool`、`eas submit`、`gradle bundleRelease`）时自动扫描，发现致命风险就拦下。每次安装只有在该工具自己的 hook 载荷格式下「真的喂了一条提交命令并被拦住」之后，才会打印 `Install verified.`；改配置前先做带日期的备份，JSON 不合法就不改写；Kimi 的配置里可能含 API key，所以只在末尾追加一个带标记的块。

💡 可借鉴的优点

- **产品思维**：把「被拒一次损失一周」翻译成一个两分钟的检查，并且把最常见的两个拒审原因放在最前面——可用的演示账号（连着真实后端）和与运行时行为一致的隐私声明。作者反复强调「不保证通过」，并把「扫描能证明什么」单独写成文档。
- **架构设计**：数据与逻辑分离——拒审模式在 `data/rejection-patterns.json`，法规截止日期在 `data/regulatory-deadlines.json`，守门脚本只读这些数据；同一套规则既可以被人读（手册、清单），也可以被 Agent 读（技能），还可以在命令执行前被强制执行（hook）。
- **工程化**：规则包带「过期」检测；安装有 `--dry-run`、`doctor`、`uninstall`，并明确「从不触碰你的 GitHub 账号与凭据」；对十几款工具的 hook 格式逐一核对，无法确认的宁可写「请手动接线」也不猜；`scripts/verify-citations.py` 用来验证手册引用的来源真实可达。
- **社区运营**：README 贴出用户的反馈截图，也贴出「它报了我无法确认的项、看起来像误报」的部分，并解释这是有意为之——「漏掉一个警告的代价是被拒，多显示一个的代价是一分钟」。

🌟 特别亮眼的地方

它是今天「守门」主题里最纯粹的一个样本：一个 6 月才建仓、一个人维护的仓库，靠「诚实」拿到了 5,334 星和今天的 +761——诚实地说不保证通过，诚实地列出扫描看不到的东西（账号状态、协议签署、元数据），诚实地告诉用户哪些工具它还没法自动接线。在 AI 让「一下午做出一个 App」成为现实的年份，审核并没有变松，反而更紧——README 引用的数据是 2026 年一季度应用发布量同比增加约六成，而苹果近年约四分之一的提交被拒。**生成越容易，把关越值钱**——这句话今天是字面意思。

📖 项目是干什么的

Diagram Design 是一个「让 Agent 画出你愿意发布的图」的技能：用大白话描述——「画一个前端、后端、数据库加 Redis 缓存的架构图」「画一个 401 时刷新 token 的时序图」——Agent 自己选类型、说出计划，然后写出一个自包含的 HTML 文件（内联 SVG，无外部依赖），双击就能打开，可以导出 PNG 或 SVG。52 种图表类型，每种有极简浅色、极简深色、完整编辑风三个变体。口号很直白：「No shadows. No Mermaid slop.」项目今年 4 月 16 日建仓，MIT 协议，4,767 个 fork，今天 +620；最近一次提交是 11 月 23 日。

它的核心资产其实是一份「品味说明书」：只用一个强调色，留给读者最先该看的一两样东西；1px 细线；不用阴影；所有坐标落在 4px 网格上；「最高质量的一招通常是删除」。作者 Cathryn Lavery 的出发点很朴素——给博客配图时，让 Claude 画出来的总是千篇一律的圆角方块，跟网站风格毫无关系，要么去 Figma 里磨半小时，要么干脆不配图。于是她把「品味」写了下来。

围绕这份说明书，项目做了三件事。一是 **Onboarding**：说一句「onboard diagram-design to https://yoursite.com」，技能会抓取首页、提取主色与字体、映射到 paper / ink / muted / accent / link 等语义角色，之后的每张图都跟你的站点一致，配置保存在 `~/.diagram-design/profiles/`。二是**互操作**：可以把 Mermaid、draw.io、Excalidraw、PlantUML 的现有图重新画成这套风格。三是**分发**：Claude Code 插件市场、Codex 市场、GitHub Copilot 市场、Factory Droid、Qoder、Pi、Kiro、Cursor、Gemini CLI、Windsurf、Amp 等，甚至为 Claude Desktop「ZIP 不超过 200 个文件」的限制单独写了一个打包脚本。CI 会检查布局是否重叠、是否裁切。

它也没有回避自己的短板：输出质量取决于你用的模型，同一个提示词两次布局可能不同；结果不是可编辑的源格式，没有可以在 PR 里 diff 的文本，也没有可以拖拽的画布——「每个 sprint 都要改的文档图，Mermaid 仍然更合适；Diagram Design 是给那张你要发布的图准备的」。

💡 可借鉴的优点

- **产品思维**：把「模型理解内容，但缺品味」这个判断变成产品——不跟 Mermaid 比「可维护」，而是占住「要发布的那张图」这个场景，并直接写出自己不适合什么。
- **架构设计**：风格指南（`references/style-guide.md`）与 52 个类型参考分离，onboarding 生成的 profile 单独保存、不被更新覆盖；输出是单个 HTML + 内联 SVG，没有构建步骤、没有 JavaScript、没有外部图片。
- **工程化**：CI 校验重叠与裁切；每类图都有编号的参考文档与可直接打开的样例；针对宿主的限制（文件数上限、无符号链接的 Windows）提供脚本或回退方案；PRIVACY.md 写明技能会往网络发什么。
- **社区运营**：在线画廊可切换浅色 / 深色 / 完整编辑风；明确指出官方构建只来自本仓库、其他名字下的列表是非官方副本；对小众宿主（Kiro、Pi、OpenCode）也写了安装路径。

🌟 特别亮眼的地方

这是它时隔一个多月再次回到前十（上一次是 10 月 14 日的第 4 名），71,387 星说明「让 AI 画得好看」是一个被长期低估的需求。它给出的方法值得每个做生成式产品的人记下：**当输出质量取决于模型「品味」时，不要只想着换模型，把品味写成一份可执行、可校验的规范**——一个强调色、1px 线、4px 网格，再加一个检查重叠的 CI。这和 Claude-BugHunter 把安全研究员的经验写成技能、app-store-compliance 把拒审经验写成数据，是同一件事：**专家的判断正在被翻译成 Agent 可以执行、CI 可以验证的文件。**

## 📊 今日趋势洞察

**核心方向：守门前移——技能从「让 Agent 会做」变成「让 Agent 别交」。**

今天榜上的十个项目可以按「在流程里的位置」排成三层。**把关层**有四个：Claude-BugHunter 在提交报告前设验证关卡，app-store-compliance 在上传命令前用 hook 拦截，superpowers 在评审环节阻断严重问题，diagram-design 用 CI 检查重叠与裁切——对象分别是漏洞报告、应用上架、代码和配图，机制却一模一样：把「不通过就不许往下走」写成机器可执行的规则。**感知层**有三个：firecrawl 的网页抓取与 550 多家数据源、last30days 近三十个来源的取证与排序、CLI-Anything 把几十款专业软件变成可调用的 CLI——它们回答的是「Agent 能看到什么、调用什么」。**本地层**有三个：Ghost-Downloader-3 的四平台原生桌面、AutoClip 的本机剪辑渲染、firecrawl Local 的 Rust 单文件，加上一张 3090 就能跑的 minimind——它们回答的是「东西在哪跑」。把关层之所以今天最显眼，是因为它第一次同时出现在安全、移动、开发、设计四个不相干的领域里。

**升温领域：守门型技能、本地优先的成品、老项目回春。**

四个信号值得记住。其一，**「拦住提交」成了技能的新卖点**：三个守门项目今天合计 +3,630，其中 Claude-BugHunter 与 app-store-compliance 分别是今年 5 月、6 月才建仓的新仓库——需求出现得晚，供给刚刚跟上。其二，**本地优先不再是口号而是产品形态**：Ghost-Downloader-3、AutoClip、firecrawl Local 三个项目的 README 第一节写的都是「在你自己的机器上跑」，对应的是数据隐私、订阅疲劳与离线可用三种焦虑。其三，**老项目集体回春**：今天前十名里五个项目建于 2026 年之前（2023、2024、2024、2025、2025），最新的一个也是今年 6 月建的——没有一个下半年才出现的仓库；第十名门槛从 +314 抬到 +620，说明热度在向「已经被验证过的东西」集中。其四，**Agent 的入口在往命令行走**：`ghd add`、`firecrawl-local scrape`、`autoclip produce`、`cli-hub install`——同一件事，界面给人，命令行给 Agent。

**对开发者的三点启发。**

第一，**给你的流程加一道「提交前关卡」，并让它真的能拦**。守门这件事最难的不是检查规则，而是让它发生在正确的时刻——hook 比提醒可靠，CI 比口头约定可靠。今天三个最热的项目都把「拦下」做成了默认行为，而不是可选步骤。第二，**把专家判断写成文件**：品味写成风格指南，拒审经验写成 JSON 模式库，安全方法论写成技能——专家经验的载体一旦从「某个人的脑子」变成「可执行、可校验、可版本管理的文件」，它就能被 Agent 用、被 CI 验、被别人审计。第三，**同一能力留三个入口**：界面、CLI、MCP / Skill。AutoClip 与 Firecrawl 都是这么做的；Ghost-Downloader-3 这种三年前的项目，靠一个 `ghd` 命令行和 aria2 兼容的 RPC，今天重新进入了 Agent 的视野——**在 Agent 时代，一个工具会不会「被调用」，比它功能多不多更决定它的寿命。**
