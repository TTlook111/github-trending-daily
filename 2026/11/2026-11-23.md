📖 项目是干什么的

Firecrawl 的定位是「让 Agent 更聪明的知识基础设施」，并且把部署形态拆成三份。**Firecrawl Local** 是一个 Rust 二进制，`cargo install firecrawl-local` 装上就能在本机 scrape / crawl / map，用系统里已有的 Chrome 渲染 JS 页面，PDF 与 Office 文档也在本地解析；`init` 能自动把 MCP 服务接进 Claude Code、Claude Desktop、Cursor、Windsurf、Gemini CLI、Codex 六种宿主，并且先备份每一份配置；`serve` 在 3002 端口跑一份兼容 v2 的 API，现有 SDK 改个地址就能用。

**Firecrawl Cloud** 提供规模化版本：96% 的网页覆盖率、P95 延迟 3.4 秒、结构化 JSON / 截图 / 浏览器动作，外加 Search 与 Alexandria——一个打包了 550 多家数据源的知识库；免登录每月 1,000 次额度。**Self-hosting** 把 `apps/api` 的队列、worker 与数据库整套搬到你自己的基础设施上。抓取、爬取、映射跑在本地；需要搜索、Alexandria、Interact、Agent、Monitor 时走云端；`FIRECRAWL_CLOUD=off` 还能强制全部留在本机。

今天它拿到 +915，比昨天少 91，名次仍是第 2。对一个 207,044 星的成熟项目来说，这个数字不是「被发现」，而是「被持续调用」——本地版兜住隐私与延迟敏感的场景，云端版兜住规模，两条腿都在往前迈。

💡 可借鉴的优点

- **产品思维**：把「给 Agent 供数据」做成独立生意，并用「本地免费 + 云端按量」分层。本地版不是阉割版，而是先把隐私与延迟敏感的场景兜住。
- **架构设计**：本地与云共用同一套 API 契约，代码可平移、SDK 不用重写；`init` 自动识别六种宿主并写配置、先备份，这种「零摩擦接入」比写十页文档有效。
- **工程化**：公开 benchmark 说清覆盖率与 P95 延迟，而不是只说「快」；本地渲染复用系统 Chrome 而不是自带一个浏览器；云端调用失败会标注 `source: firecrawl-cloud`，来源不糊弄。
- **社区运营**：多语言 SDK、playground、Discord 与 X / LinkedIn 三条反馈渠道；免费额度不要求注册，先把「试一下」的门槛降到零。

🌟 特别亮眼的地方

连续两天位置不动、增量小幅回落，它成了这份榜单里最像「基础设施」的项目：热搜换了三轮，它还在第 2。原因很朴素——**模型能力趋同之后，谁能给出更干净、更新鲜、更可追溯的上下文，谁就决定了输出质量的上限。** 技能决定下限，数据决定上限；这条判断在周一的退潮里反而更清楚，因为技能类项目全在下滑，它只掉了 9%。

📖 项目是干什么的

Superpowers 卖的不是单条技能，而是一整套**给编码 Agent 装上的软件开发方法论**：一批可组合的技能，加上一段保证「Agent 真的会去加载它们」的引导指令。Agent 判断你在造东西之后不会立刻写代码，而是先退一步问你到底想解决什么；把 spec 从对话里逼出来，分段展示给你确认，每段都短到能真正读完；设计签字才进入计划环节。

计划环节的要求很硬——「一个热情但品味差、没有判断力、没有项目背景、还讨厌写测试的初级工程师也能照着做」，每个任务 2–5 分钟，写清文件路径、完整代码和验证步骤。落地时两套模式二选一：`subagent-driven-development` 每个任务派一个新子 Agent，做完立刻两段式评审；`executing-plans` 在当前会话内逐条实现，最后统一评审整个分支。工作流被写成七步：brainstorming → git worktrees → writing-plans → 子 Agent 执行 → 红绿 TDD → 代码评审 → 收尾分支。

安装面依旧是它的护城河：Claude Code（官方插件市场）、Codex App / CLI、Cursor、Antigravity、Gemini CLI、GitHub Copilot CLI、Grok Build CLI、Kimi Code、OpenCode、Pi、Qwen Code、Hermes Agent、Muse、Devin CLI、Factory Droid——**16 个 harness，一套技能**。MIT 协议，作者是 Jesse Vincent 与 Prime Radiant 团队。

💡 可借鉴的优点

- **产品思维**：它不卖「能力」，卖「流程」和「否决权」。TDD 技能会删掉那些先写实现、后补测试的代码；评审技能把 Critical 问题设为硬阻断。
- **架构设计**：技能之间用「触发时机」串成流水线，而不是靠一张总提示词硬压；引导技能在会话启动时注入，压缩上下文后再注入一次。技能可组合、可单装。
- **工程化**：技能行为用 drill eval harness（superpowers-evals）做回归测试，插件基础设施另有 `tests/` 与 `npm test`；连「会话跑歪了怎么办」都有 `diagnosing-superpowers` 去读会话记录、给出行级证据、打包脱敏报告。
- **社区运营**：明确不接受新技能投稿、只接受跨 harness 的修改，且不接受「替别人修 issue」的 Agent PR——用规则守住了质量下限。

🌟 特别亮眼的地方

+788，比昨天少 95（-10.8%），位置仍在第 3。它刚好落在今天这条曲线的中间：比「必须每天用」的 BugHunter 掉得多，比周末尝鲜型的新面孔掉得少。这也印证了昨天的判断——方法论类项目已经完成认知普及，现在拼的是能不能真正跑进日常项目里；**周一是检验这件事的日子，因为周末你可以随便试，周一你得对交付负责。**

📖 项目是干什么的

AnyPS5 是一个把可执行文件自动移植到 Linux 和 Windows 的工具，并且明确**不做模拟器**。核心是一个 relinker：把 PS5 可执行文件转换成目标系统的原生格式，再配上一套为动态链接准备的 system prx 库实现（`core/libs/prx`）。README 第一句就写清「No emulation or separate runtime process」——没有模拟层，也没有独立运行时进程，跑起来就是原生二进制。

图形侧有一个着色器重编译器，把参考着色器形式解码并产出 SPIR-V，编译时打开 `ANYPS5_ENABLE_SPIRV_TOOLS` 还会用 Spirv-Tools 校验产物。输入靠 SDL 映射手柄（含摇杆与扳机），键鼠可以在 `anyps5-input.ini` 里配置。遇到不支持或意外状态，代码统一抛 C++ 异常（通常是 `std::runtime_error`），没人接住就把 `what()` 打到 stderr 并退出——移植项目里少见的「失败要说得清楚」。

透明程度也值得单独说：首页挂着进度地图，徽章分别显示系统库覆盖率（明确注明是「项目目前已知函数」的比例，不是 PS5 全部系统函数）、RDNA2 与 gfx1013 参考着色器形式解码进度，以及「7 天内实现」的时间线；Web 转换器处理的文件留在本地；13 种语言的 README；兼容状态按游戏标题在 Discussions 里一个标题一个线程。GPL-2.0-only，声明不包含、不分发、不要求任何版权软件、固件、密钥或专有库，与 Sony 无关联。

💡 可借鉴的优点

- **产品思维**：把自己定位成互操作 / 研究 / 存档工具，而不是模拟器——这个定位既划清了法律与风险边界，也决定了技术路线（重链接而不是模拟）。
- **架构设计**：转换层（relinker）与库实现层（prx）分离，着色器重编译、输入映射、异常处理各自独立；relinker-only 构建能在 macOS（含 Apple silicon）上跑，把「转换」和「运行」解耦成两个可独立验证的环节。
- **工程化**：SPIR-V 产物要过 Spirv-Tools 校验；异常类型统一、失败有明确出口；进度用可刷新的徽章与进度地图量化，而不是「大概能跑了」。
- **社区运营**：13 种语言 README 直接扩到非英语用户；兼容性靠分标题的 Discussions 线程维护，比一个巨大的兼容表更容易协作；免责声明写在正文而不是藏进 LICENSE。

🌟 特别亮眼的地方

+716，是八个老面孔里跌幅最大的（-15.8%），位置却仍是第 4——因为门槛降得更多。它昨天靠「两只新面孔」的叙事上位，今天跟着退潮，正好提供一个对照：**硬件移植这类项目的热度天生是脉冲式的，靠一次 bring-up 进度更新推一波，而不是靠日更。** 它把进度做成可刷新的徽章，恰恰是在用工程手段对抗这种脉冲——让围观者随时能看到「又推进了一点」。使用时仍须自行确保镜像与固件来源合法。

📖 项目是干什么的

Ghost-Downloader-3 是一个跨四端的下载器：Windows 10+、macOS 13+、Linux（glibc 2.35+）、Android 9+，基于 Qt 6.6+ / PySide6（也因此要求 CPU 支持 AVX）。协议覆盖 HTTP、Magnet/BT、FTP、M3U8、MPEG-DASH、eD2k；站点侧支持 YouTube 与 Bilibili（分段选择、任意清晰度、字幕、播放列表与多集），GitHub 与 HuggingFace 走镜像加速。

它的宣传语很实在：「每个下载器在好网络下都快，真正的考验是差网络。」做法是智能分块且不需要合并文件、自动探测带宽、使用真实浏览器的 TLS 指纹躲过反爬误判。浏览器扩展会在页面上跟随视频出现下载按钮，弹窗列出页面里所有媒体，点一下交给桌面端接管，登录态直接带过去；Android 端能录制直播 M3U8 并在后台继续下载。

可编程性也没落下：`ghd` 命令行提供 `probe / add / tasks / task / pause / start / remove / wait`，`add` 支持 BT 种子按文件序号选择，`wait` 可以阻塞到任务完成；另有 aria2 兼容的 RPC API，第三方工具可以无缝接上。周边还有 Feature Packs 插件生态、Crowdin 翻译流水线（桌面文案翻译到 60% 才进应用），GPL-3.0 协议。

💡 可借鉴的优点

- **产品思维**：不追功能数量，追「一个 app 替五个」——把散落在五个工具里的协议、站点、平台收进一个入口，同时保留「差网络下的真实体验」这个别人不测的场景。
- **架构设计**：下载引擎、协议适配、UI 三端分离；RPC 兼容 aria2 是一个聪明的选择——不要求生态来适配你，而是直接复用现成的生态。
- **工程化**：四平台构建与发布、免费代码签名（SignPath）、CLI 与桌面共享同一套任务模型、翻译走 Crowdin 而不是 PR 改语言文件。
- **社区运营**：QQ 群 + Discord 双通道，AUR 包交给社区维护，issue 模板分 bug / feature 两类，贡献者与翻译贡献者都单独列墙。

🌟 特别亮眼的地方

+701，比昨天少 78（-10.0%），名次从第 6 升到第 5——因为是别人掉得更多，而不是自己涨了。它是前十唯一和 AI 无关的项目，却提供了 Agent 最需要的东西：**确定性、可脚本化的接口。** `ghd` 的每条命令都能被 Agent 直接调用、`wait` 能等到任务结束、RPC 兼容 aria2 意味着现成的自动化脚本不用改。周一的榜单里它证明了一件事：不带 AI 的工具，只要接口干净，照样能稳定占位。

📖 项目是干什么的

CLI-Anything 的目标一句话说清：**让所有软件都对 Agent 原生可用。** 它给两条路。第一条直接用现成的：`pip install cli-anything-hub`，然后 `cli-hub list / search / info / install / launch`，从注册表里挑一个已经做好的 CLI 装上就跑。第二条是造一个新的：装上插件后执行 `/cli-anything <软件路径>`，走一套 7 阶段 harness 生成器，把有源码的软件变成可安装的 Python CLI 包——从代码库分析、架构设计、实现、测试计划、测试编写到文档，全流程自动化。

由港大数据智能实验室（HKUDS）维护，仓库里已经有一批现成的软件 harness（GIMP 107 个测试、Blender 208 个、Inkscape 202 个、Audacity 161 个……），徽章标注 2,461 个测试通过（1,732 单元 + 579 端到端，100% 通过），18 个应用演示（CAD、3D 场景、图表、游戏、字幕），另有一份 arXiv 技术报告（arXiv:2606.03854），Apache 2.0 协议。
