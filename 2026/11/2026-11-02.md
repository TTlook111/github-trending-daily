### #2 ifixai-ai/iFixAi ⭐

| 属性 | 信息 |

| 💻 语言 | Python |
| 📦 分类 | AI 安全 / Agent 独立审计 |

📖 项目是干什么的

iFixAi 自称「AI Agent 的独立审计员」：把你的 Agent 放进一个模拟的业务环境，发送真实一天会遇到的请求（包括故意让它越权的请求），再由另一家厂商的模型担任裁判，逐条打分。每条发现都附上「问了什么、Agent 做了什么」的证据。

默认跑 10 项检查：角色只能用被授权的工具、不能被说服提权、不能替无权限的人执行破坏性操作、抵抗提示词注入、不把一个用户的隐私交给另一个用户、不确定时说不确定、失败时如实报告等。其中 B01、B08、P01 是三条硬底线，任何一条不过，总评最高只能拿 D；加 `--full-run` 可跑全部 61 项。结果是 A–F 等级加 JSON / Markdown 报告，可以接入 CI。它也提供 Claude Code、Codex 插件和 Cursor、VS Code 等的 skill，可以直接让编码 Agent「对我的 Agent 跑一遍 iFixAi」。

今天 +1,584，总 star 约 4.25 万，单日增量排第二。

💡 可借鉴的优点

- **产品思维**：把 Agent 安全从「模型会不会说错话」改成「Agent 在业务里会不会越权」，更贴近企业的真实风险。
- **架构设计**：裁判模型强制选用与被测 Agent 不同的厂商，避免「自己给自己打分」。
- **工程化**：内置 mock 演示 Agent，不用 API Key 一分钟就能跑通；`--dry-run` 先报告调用次数和费用再执行。
- **社区运营**：提供中、英、日、韩四种 README，插件覆盖主流编码 Agent。

🌟 特别亮眼的地方

「三条硬底线封顶评分」的设计很值得借鉴：**权限类问题不能被其他项的高分平均掉**。👉 上线 Agent 前：先用模拟业务环境跑一轮越权、注入和隐私泄露测试，并把报告作为 CI 关卡。

📖 项目是干什么的

Orkas 是 MIT 开源、local-first 的多 Agent 桌面应用（macOS、Windows）。你把目标告诉「Commander（指挥官）」，它把目标拆成待办，调度 16 个内置专业 Agent（深度研究、PPT、视频、语音、UI 设计、产品开发、办公文档，以及 5 个电商 Agent 等），还能把 Claude Code、Codex、OpenCode、OpenClaw、Hermes 等已有 Agent 拉进来一起干活。

它以「项目」为单位保存目标、规则、记忆和文件，新会话能接着上次的进度；待办在人和 Agent 之间分配，Auto-advance 让团队自动接手下一个待办，还支持按小时、天、周、月运行的定时自动化。数据留在本机，成果交回用户审核。内置模型送 500 积分，也可以接 Claude、OpenAI、Gemini、DeepSeek、Kimi、GLM、Qwen 等自己的 Key 或本地兼容接口。

今天 +1,146，总 star 约 7,300，属于新冲榜项目。

💡 可借鉴的优点

- **产品思维**：从「回答一个问题」转向「让一个项目持续推进」，项目、待办、定时任务都是为长期工作设计的。
- **架构设计**：Commander 负责拆解与汇总，专业 Agent 各有技能、记忆与工具；外部编码 Agent 作为团队成员接入，而不是被替代。
- **工程化**：仓库里有 Playwright 端到端测试和模型回归评测（`eval/model-eval/regression`）。
- **社区运营**：Agent 市场提供 30+ 个 Agent，也可以让 Commander 按描述生成自定义 Agent。

🌟 特别亮眼的地方

它和同榜的 Claude-Code-Game-Studios 一样用「团队」来组织多 Agent，但做成了**普通用户可以直接下载的桌面产品**。👉 做多 Agent 产品：把「项目上下文 + 待办 + 定时任务」做成一等公民，比单次对话更接近真实的工作方式。

📖 项目是干什么的

Impeccable 是给编码 Agent 用的「设计词汇表」。`npx impeccable install` 安装后，在 Agent 里用 `/impeccable` 加命令和目标来调整界面：`bolder` 让保守的设计更大胆，`quieter` 让吵闹的页面收敛，`polish` 做上线前的最后打磨，`critique` 按可用性原则打分并排出修复优先级，`audit` 检查无障碍、性能、主题和响应式（按 P0–P3 分级），共 24 个命令。

它还内置 62 条确定性规则的「AI 味检测器」，不调用 LLM、不需要 API Key，专门抓 Agent 常见的设计套路：全站 Inter 字体、紫到蓝的渐变、卡片套卡片、彩色背景上的灰字等。`/impeccable init` 读代码、只问推断不出来的问题，然后写出 PRODUCT.md；`document` 把现有视觉体系记到 DESIGN.md，让后续修改保持一致。支持 Claude Code、Cursor、Codex CLI、Copilot、Gemini CLI、Kiro、Trae 等近 20 种 Agent。

今天 +1,140，总 star 约 9.9 万。它从 10-26 起几乎每天在榜（10-30 曾以 +2,870 登顶），离 10 万 star 只差几百。

💡 可借鉴的优点

- **产品思维**：把「让它更好看」这种模糊指令拆成有名字的动作，每个动作配一份专门的操作手册。
- **架构设计**：确定性规则负责检测，LLM 负责修改，检测结果可以复现。
- **工程化**：PRODUCT.md / DESIGN.md 作为持久上下文，不用每次对话都重新解释产品。
- **社区运营**：一次覆盖近 20 种编码 Agent，用户换工具也能继续用。

🌟 特别亮眼的地方

连续一周多在榜，说明**「Agent 写出来的界面千篇一律」是普遍痛点**。👉 做 Agent 技能：给模糊需求起名字、配手册，再加一层不依赖模型的检查，是值得照搬的结构。

📖 项目是干什么的

技能按编码 Agent 的常见失败来组织：Agent 没理解需求，就用 `/grill-me`、`/grill-with-docs` 让它先追问细节；Agent 太啰嗦，就在 grill-with-docs 里和它一起建立项目的「共享语言」文档，并用 ADR 记录难解释的决策；代码跑不通，就用 `/tdd` 强制红-绿-重构循环，用 `/diagnosing-bugs` 把调试拆成分阶段的流程。支持 Claude Code、Codex、GitHub Copilot、Gemini CLI 等，可以装插件自动更新，也可以复制成可编辑的文件。

今天 +970，总 star 约 30.9 万、fork 约 2.6 万，是本期总 star 最多的项目。

💡 可借鉴的优点

- **产品思维**：从具体的失败场景出发设计技能，每个技能都说得清「解决什么问题」。
- **架构设计**：小而可组合，不绑定流程，可以只取需要的部分。
- **工程化**：把《程序员修炼之道》、DDD、TDD 等经典方法翻译成 Agent 能执行的步骤。
- **社区运营**：作者有约 6 万人的邮件订阅，安装 30 秒完成，传播成本很低。

🌟 特别亮眼的地方

它说明**经典软件工程方法在 Agent 时代反而更重要**：对齐需求、统一术语、缩短反馈循环。👉 给团队写 Agent 规范：先列出 Agent 最常出错的地方，再一条条写成技能，而不是先设计一整套流程。

### 对开发者的启发

- **做开发者工具**：把底层 Agent 当可替换的引擎，专注交互层与多任务管理。
- **做 Agent 技能**：从 Agent 最常出错的地方出发，给模糊需求起名字、配手册，再加一层不依赖模型的检查。
- **上线 Agent 前**：用模拟业务环境测越权、注入和隐私泄露，把结果作为 CI 关卡。
- **一个贯穿的共性**：今天的热门项目大多不碰模型本身，而是在**模型之外补齐体验、记忆、技能、审计和输入方式**。
