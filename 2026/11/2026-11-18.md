📖 项目是干什么的

Superpowers 不卖单条技能，卖的是一整套**给编码 Agent 装上的软件开发方法论**：一批可组合的技能，加一段保证「Agent 真的会去加载它们」的引导指令。Agent 一旦判断你在造东西，不会立刻写代码，而是先退一步问清你到底想解决什么；把 spec 从对话里逼出来之后，分段展示给你确认，每段都短到能真正读完；设计签字后才进入计划。

计划之后是一条被固定下来的工作流：**brainstorming → using-git-worktrees → writing-plans → subagent-driven-development / executing-plans → test-driven-development → requesting-code-review → finishing-a-development-branch**。README 里对计划的要求很硬——「一个热情但品味差、没有判断力、没有项目背景、还讨厌写测试的初级工程师也能照着做」，并且强调真·红绿 TDD、YAGNI 与 DRY。真正落地时由子 Agent 逐任务实现、检查、评审、推进，主会话只保留决策与验收。

今天它继续第一，靠的还是分发宽度：Claude Code 官方插件市场、自建市场、Codex App / CLI、Cursor、Devin CLI、Factory Droid、Gemini CLI、GitHub Copilot CLI、Grok Build CLI、Kimi Code、OpenCode、Pi、Qwen Code、Hermes Agent、Muse、Antigravity——**16 个 harness，一个仓库**。最新版本 v7.0.2（11 月 3 日）仍在持续迭代，连「技能为什么没触发」都单独做了 `diagnosing-superpowers` 诊断技能。

💡 可借鉴的优点

- **产品思维**：卖的不是能力而是纪律。它解决的不是「Agent 不会写代码」，而是「Agent 不受流程约束」；把返工成本前置到 spec 与计划阶段，是这类产品最有价值的位置。
- **架构设计**：可组合技能 + 启动引导 + 子 Agent 隔离。实现细节留在子会话，主对话只负责拍板与验收，上下文不被污染，这也是它能连续自主跑几小时的前提。
- **工程化**：把「计划好不好」翻译成可检验的标准；技能行为用独立的 eval harness 测，插件基础设施另有测试，不靠「我感觉它变聪明了」。
- **社区运营**：官方市场与自建市场双通道，企业侧留商业支持入口；明确不接收「Agent 代写的、修别人 issue 的 PR」，把维护成本挡在门外。

🌟 特别亮眼的地方

连续两天第一、319K 星，说明「方法论可以被安装」这件事已经被市场彻底接受。更值得注意的是它的自我修正能力：当技能不触发、Agent 跑偏时，它有一个专门读会话记录、给出逐行证据的诊断技能。**一个框架开始能解释自己的失败，才算真的成熟。**

📖 项目是干什么的

PaperOrchestra 是 Google Cloud AI Research 开源的多 Agent 框架，目标很直接：把**零散的研究想法与实验日志**，变成一篇按目标会议模板排好版的 LaTeX 投稿稿件。作者是 Yiwen Song、Yale Song、Tomas Pfister、Jinsung Yoon，配套论文挂在 arXiv（2604.05018）。

它不是让一个大模型一口气写完，而是像课题组一样分工：**Outline Agent** 先搭结构，**Literature Review Agent** 负责检索、排序、整合文献，**Section Writing Agent** 逐节写，**Content Refinement Agent** 打磨内容，**Plotting Agent** 从代码生成图表，另外还有反思类 Agent 负责复核。文献侧接 Semantic Scholar API，模型可切 Gemini（走 Vertex）或 OpenAI；产出直接套 `templates/` 里的会议模板，CVPR2025 已内置，也能自建。

工程形态很「研究项目」：Conda + Python 3.11、`.env` 配 key、bash 脚本与 Python CLI 两种入口、`autoraters/` 放自动评估、`methods/` 放流水线核心、`frontend/` 提供 Streamlit 交互 demo。数据集不在仓库里，声明后续单独发布。

💡 可借鉴的优点

- **产品思维**：把「写论文」这条长链路拆成可并行、可复审的角色。分工的意义不只是提速，而是让质量问题可以归因到具体环节。
- **架构设计**：五个专职 Agent + 反思层，写作、文献、作图各自独立；LaTeX 模板可插拔，换会议不用改代码。
- **工程化**：自动评估脚本与主流程分离，模型供应商可切换，原始材料目录与输出目录解耦，适合批量跑对比实验。
- **社区运营**：论文、代码、demo 三件套齐备，数据集单独发布——典型的研究型开源节奏，先把方法说清楚，再谈工具好不好用。

🌟 特别亮眼的地方

昨天 +313，今天 +1,072，一天之内三倍多的加速，是今天涨势最猛的项目。它值得警惕也值得兴奋：当结构、文献、写作、作图都能被编排，「论文」这种知识产品的最低门槛会被迅速拉平。真正的分野会落在两处——**想法本身的原创性，和实验的说服力**。工具能补齐格式、综述与排版，补不了「你凭什么值得被引用」。

📖 项目是干什么的

这是一个面向**授权范围内的漏洞挖掘与外网红队**的 Claude 技能包。装一次之后，Claude Code 会按资深漏洞研究员的习惯工作：知道先测什么、盯哪些类别、怎么把结果整理成能交付的报告，以及最重要的——始终待在授权范围里。

体量是它的第一卖点：**83 个技能、15 个斜杠命令、681 条来自已披露漏洞报告的模式**（其中 433 条逐条标注出处、可单独审计），覆盖 24 类核心漏洞；另带企业身份与基础设施攻击矩阵、engagement 目录脚手架、Burp MCP 集成。结构分四层：**Think**（方法论与红队心态）、**Hunt webapps**（58 个 `hunt-*` 技能，按类别组织检测模式、payload、绕过表与组合链）、**Hit the perimeter**（M365 / Entra、Okta、vCenter、SSL-VPN、SharePoint、云 IAM 的 2024–2026 CVE 链）、**Ship it**（分诊、VRT 严重度、误报反驳、PII 脱敏）。

安装给了两条路径：插件市场一条（技能命名空间隔离、跟着版本更新），复制安装一条（锁版本、附带 `cbh` 命令行与 `hunt` 脚手架）。知识层是纯 `SKILL.md`，因此同一套技能能落到 Claude Code、OpenCode、Codex CLI、Hermes Agent、Google AntiGravity 五个 harness。

💡 可借鉴的优点

- **产品思维**：打包的不是工具集，而是「资深研究员的判断顺序」。扫描器人人能装，真正贵的是先测什么、什么时候停、什么该写进报告。
- **架构设计**：Think / Hunt / Perimeter / Ship 四层对应「方法论—手法—边界—交付」，缺任何一层，产出都不可用。
- **工程化**：681 条模式里 433 条逐条引用来源，把「经验」变成可审计的证据链；插件与复制两条安装路径，分别照顾持续更新和锁死版本两类团队。
- **社区运营**：授权范围写在 README 最前面，配合 DVWA、OWASP Juice Shop、Hacker101 等公开靶场验证，这是这类敏感技能唯一能建立信任的方式。

🌟 特别亮眼的地方

昨天 7,962，今天 10,257，一天净增两千多，正式跨过 10K。它说明技能正在从「通用能力」走向「职业能力」：当 Agent 装上 83 条由真实报告蒸馏的技能，它模仿的不再是「会写代码的人」，而是**某个具体职业的人**。这也顺手抬高了门槛——不在「能不能跑」，而在「有没有出处、有没有边界、有没有交付标准」。

📖 项目是干什么的

「江山时序」是一张**能拖着时间轴走的中国历史地图**：从公元前 403 年三家分晋，到今天，覆盖 18 个历史时期、198 个疆域快照。拖时间轴，战国七雄、三国、南北朝、五代十国、宋辽金西夏会并排出现在同一张羊皮纸色画布上；每个重大疆域节点还留了虚线「幽灵边界」，让你一眼看出这一阶段谁失了哪块地。

它的功能密度高得不像个人项目：时间轴气泡会显示当年在位的君主与年号；一级行政区（郡 / 州 / 府）能悬停查看辖区与对应现代省份；黄河改道、云梦泽与罗布泊的盈缩、历代长城、大运河、丝绸之路、郑和航线都会随年代变化；点任意古城或关隘，会打开一张「点事溯局」卡片，讲它 2400 年来的名字与建制沿革；还能沿着苏轼、李白、玄奘、诸葛亮、王阳明的足迹做「点人溯事」，多人同行时会把同年的相遇标出来。角落里甚至藏了一个「地图定位挑战」小游戏，十轮之后按误差给你一个古代官职。

技术形态却极轻：**纯静态站点，不需要构建，`python -m http.server` 就能跑**；几何数据用拓扑去重的 VLQ 压缩包发布，另可导出标准 GeoJSON 给 Leaflet / MapLibre / QGIS；Docker 镜像就是一个 nginx:alpine。前端之外它还配了零依赖的 MCP server（三个原生工具，离线响应小于 5ms）、`llms.txt`、Agent Skill 与 `window.atlasAPI`，并提供可嵌入的 iframe 深链。

💡 可借鉴的优点

- **产品思维**：把「历史地理」这种门槛极高的知识，做成可以手指拖动、点开就读的探索体验；深链让每一次具体的历史瞬间都能被分享和复现。
- **架构设计**：**零坐标双参数协议**——模型只需给出 `year` 和 `place`，atlas 自己解析古今地名、定位镜头、渲染疆域与路线。把「模型不擅长的事」封装进产品，这是最聪明的地方。
- **工程化**：无构建、无运行时依赖，静态文件 + nginx 即可部署；几何数据做拓扑去重；数据授权单独说明（CHGIS 底图不得再分发），边界写得很清楚。
- **社区运营**：四语言 README、在线 demo、可分享深链、嵌入方式、项目背后的故事长文，都是「让人愿意点进来」的基础设施。

🌟 特别亮眼的地方

今天唯一一个非 AI 原生项目，却可能是最适合 Agent 的：它把「历史地理」压缩成两个语义参数，顺手补齐 MCP、WebMCP、llms.txt 与 CLI 截图工具，让 Claude Desktop、Cursor、Windsurf、Gemini CLI 都能直接问「819 年韩愈被贬的蓝关在哪」。**它证明了一件事：Agent 友好的前提不是接入大模型，而是先把自己的领域知识整理成机器能理解的坐标。**

📖 项目是干什么的

ECC 把自己叫做「agent harness operating system」：给编码 Agent 一套协同的工程系统与工具箱，让它在动手之前先计划、改完用测试验证、换个干净上下文自审、把重要的东西记住，最后把反复奏效的做法沉淀成技能。它的流程被压缩成一行：`plan -> test -> implement -> review -> verify -> remember -> improve`。

体量已经很惊人：**72 个专职子 Agent、327 条按需加载的技能、98 个维护中的斜杠命令**，外加 rules、hooks、scripts 与 `.claude-plugin` 市场清单。仓库根目录是唯一事实源，各平台的适配层只做打包与映射，不再维护第二份拷贝——Claude Code、Codex、Cursor、OpenCode、Copilot、Kimi Code、Qoder、Antigravity、Pi 都能装。

最新版 v2.2.3（10 月 1 日）的重点在「装得住」：清单驱动的引导安装、安装状态归属、doctor / repair / uninstall 全套，加上跨 Linux / macOS / Windows 的打包产物发布闸门。再往前，v2.0 把控制面、worktree 生命周期服务与 `orch-*` 编排族扶正，才真正有了「操作系统」的样子。

💡 可借鉴的优点

- **产品思维**：不做「更聪明的模型」，做「模型外面的那层工程约束」。定位清楚，所以能跨 7 个以上 harness 复用同一套资产。
- **架构设计**：单一事实源 + 平台适配器，是这套东西能在多 harness 间保持一致的根因；worktree 与子 Agent 的编排把并行开发变成默认选项。
- **工程化**：引导安装、体检、修复、卸载四件套齐全；发布闸门在三个操作系统上跑打包产物，说明它把「安装成功率」当成核心指标。
- **社区运营**：17 种语言 README、Discord、GitHub App 与订阅制托管版并行，开源 MIT 永久免费、Pro 只卖私有仓库的托管能力，边界干净。

🌟 特别亮眼的地方

305K 星、45K fork，背后只有一个维护者，却能每周跨 7 个 harness 发布。这件事的启示不在「个人能写多少技能」，而在**适配层本身就是护城河**：技能内容可以被抄，跨 harness 的一致体验与升级路径很难被抄。它和 superpowers 一起，构成了今天榜单的前二——两种不同形态的「Agent 工程基础设施」。

📖 项目是干什么的

SkillEvaluator 回答一个所有技能作者都该回答、但大多没回答的问题：**你这个技能，到底好不好？** 它把答案拆成三档独立流水线：Tier 1 做验证（质量、schema、版本、PII、许可证、Unicode、脚本 lint、Harness 兼容性，共 11 项 CI 检查、500+ 条静态规则与检测模式）；Tier 2 做去重（用 embedding 与语义重叠检测，看它和已有技能是否在讲同一件事）；Tier 3 做真机评测（在沙箱里跑 Agent，对比「有技能」与「没技能」的任务结果，量化 skill lift）。

最能说明问题的是 **Harness Check**：不需要 API Key，也不跑 Agent，直接告诉你这条技能在 codex、claude-code、opencode、hermes、openclaw、copilot-cli 上到底会不会被加载。它甚至会把原因列出来——描述被截断到 1,021 字符、`.agents/skills` 目录不被扫描、描述 1,028 个 UTF-16 单元超出 1,024 上限。**技能写得好不好是一回事，能不能被装上、被读到，是另一回事。**

工程侧也很完整：`pip install skillevaluator` 即用；`skillevaluator ci init` 会在你的 GitHub 仓库里开一个配置 PR，GitLab 也有现成模板；Tier 1 无需模型即可跑，扫描器接 SkillSpector、Gitleaks、Bandit、可选 Semgrep 与 pip-audit；Tier 3 用 Harbor 沙箱。项目是 NVIDIA Verified Skills 流水线的一部分，配套论文 arXiv 2608.20614，今天刚发布 v1.0.1。

💡 可借鉴的优点

- **产品思维**：把「技能好不好」变成 CI 里可执行的闸门，而不是靠主观感觉。它卡的位置很准——不是写技能时，而是合并技能前。
- **架构设计**：三档互相独立、可分别运行，各自决定是否阻断；Tier 1 不需要模型与容器，把使用门槛压到最低，Tier 3 才需要沙箱与推理预算。

💡 可借鉴的优点

- **产品思维**：不跟 GUI Agent 硬碰硬，换一条更便宜的路——把软件的能力翻译成命令行。同一件事，CLI 的 token 成本与稳定性都远优于截图点击。
- **架构设计**：SOP 与生成器分离，`HARNESS.md` 是可迭代的方法论，生成器只是执行者；CLI-Hub 把零散产物收成一个可检索的注册表。
- **工程化**：2,461 个测试分三层（合成数据单测、真实文件与软件的 E2E、安装后子进程验证）；XML / SVG / ODF 等不可信输入统一走 `defusedxml`，安全意识到位。
- **社区运营**：CLI wishlist、贡献者招募、飞书与微信群、18 个演示视频、多语言文档，把「你也可以加一个」写得很具体。

🌟 特别亮眼的地方

它赌的是一个很现实的判断：**Agent 不需要更像人的界面，它需要更像机器的接口。** 当所有人都在做「让 Agent 学会点鼠标」时，CLI-Anything 选择「让软件学会被命令」。前者要模拟人，后者只需要暴露能力——后者的成本低一个数量级，也更接近工程可控的边界。

## 📊 今日趋势洞察

**核心方向：从「能力供给」转向「可信度基础设施」。**

今天榜上的十个项目，可以按「谁在供给、谁在验收、谁在接入」排成三层。供给层仍然是 superpowers（方法论）、ECC（harness OS）、Claude-BugHunter（职业安全技能）、paper-orchestra（研究写作）；验收层是第一次挤进前十的 SkillEvaluator——三档流水线、11 项 CI 检查、Harness Check，把「技能能不能被加载、会不会重复、跑起来有没有提升」变成可执行的闸门；接入层是 CLI-Anything 与 arcane，一个给软件补 CLI，一个把管理面板的 REST / OpenAPI 做成一等公民。中间的 last30days 与 jiangshan-map 则代表另一种可信：**结论要有出处，领域知识要有坐标。**

**升温领域：真实软件接入、证据链、非 AI 项目的 Agent 化。**

CLI-Anything 的 2,461 个测试与 18 个真实软件 demo，说明「让 Agent 碰真东西」已经从口号变成流水线；last30days 用 upvotes、likes、盘口赔率排序，并在每条结论下挂引用，说明「grounded」正在成为研究类技能的标配；jiangshan-map 用两个语义参数 + MCP + llms.txt 服务模型，arcane 用 OpenAPI 3.1 服务 CI 与 Agent——jiangshan-map、arcane、svelte 三个非 AI 原生项目同时上榜，其中前两个直接靠「给 Agent 留接口」取胜，是这个趋势最硬的证据。

**对开发者的三点启发。**

第一，**给技能配体检，而不是配更多技能**：先跑 Harness Check 确认它真的会被加载，再用质量门与回归评测确认它真的让结果变好；「装上了但没生效」比「没装」更浪费时间。第二，**给结论配出处**：像 last30days 和 BugHunter 那样，把来源、时间窗、可审计引用写进产物里；在 Agent 内容泛滥之后，可追溯性会成为最贵的属性。第三，**给软件配接口**：CLI、OpenAPI、MCP 都比 GUI 自动化更稳、更便宜；把复杂度收进产品内部，让 Agent 只面对确定性的输入输出——**能被程序稳定调用的东西，才配进入 Agent 的工作流。**
