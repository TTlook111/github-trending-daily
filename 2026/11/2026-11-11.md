## 总览摘要

今天全站正好 10 个项目上榜，整体热度不算火爆，但出现了一个非常清晰的结构性现象：**一批「不直接干活、专门监督和指导其他 Agent」的元技能集中爆发。** 它们审计代码、扫描漏洞、纠正过时写法、把实现计划写好再交给更便宜的模型执行——Agent 开始有了自己的「监工」和「参谋」。今日主题：**元技能崛起，Agent 审计与规划 Agent。**

第一条线是**审计、规划、指导类元技能**。shadcn/improve（#6）用最强模型理解代码、写实现计划，自己绝不执行，把干活交给弱模型；codex-security（#10）把漏洞扫描、补丁验证、威胁建模做成 CLI 和 SDK；modern-web-guidance（#8）由 Chrome、Edge、Firefox、MDN 团队联合维护，专门纠正 Agent 因训练数据陈旧而生成的过时 Web 写法；再加上昨天已在榜的 addyosmani/agent-skills（#5），一个「监督层」正在 Agent 体系里独立成形。

第二条线是 **Agent 深入生活与金融场景**：ha-mcp（#3）用 87 个工具让 AI 接管 Home Assistant 智能家居，sure（#7）是已停摆的 Maybe Finance 的社区接力 fork、把个人理财做成可自托管应用，daily_stock_analysis（#2）继续把多市场股票分析做成每日推送。第三条线是**持续在榜的稳定底座**：astryx（#1）今日登顶、agent-browser（#4）、经典的 TheAlgorithms/Java（#9）。把这 10 个串起来看，**当 Agent 越来越多地自主执行，人类和平台都需要一层「检查它做得对不对、规划下一步做什么」的机制——元技能正是为可靠性而生的新一层。**

📖 项目是干什么的

Astryx 是 Meta 开源的设计系统，目前处于 Beta。它在 Meta 内部生长了八年，是公司内使用最多、规模最大的设计系统，支撑了 13,000+ 应用。它基于 React 19+ 和 StyleX，提供 150+ 无障碍组件、品牌级主题、暗色模式、开箱即用的模板和一套 CLI，导入预构建 CSS、使用类型化 React 组件即可，无需构建插件或额外样式库。

今天它以 3,108 的单日新增登顶。它的差异化设计很明确：**开放内部**——组件可在任意层级组合，构建块直接导出，需要深入时用 swizzle 把组件完整源码「弹出」到项目里自己拥有；**无样式锁定**——样式用 StyleX 编写但对消费者透明，可用 Tailwind、CSS Modules 或普通 CSS 通过 className 覆盖；**主题即 CSS 变量覆盖**，无需 fork 或包裹组件即可定制；并且**从 API、文档到 CLI 都按「人和 Agent 用同一套方式构建」来设计**。

💡 可借鉴的优点

- **架构设计**：swizzle 弹出源码 + CSS 变量主题 + 样式层可覆盖，把「可定制性」做到不牺牲一致性。
- **产品思维**：明确「引导而非强制」，组件给能力而不是设护栏和用户对抗。
- **工程化**：强约定（命名、props、组合规则统一）+ 完整文档 + CLI，让人和 AI 都能预测陌生组件行为。
- **生态策略**：Meta 把内部标准对外开放，同时兼容主流样式工具，降低采用门槛。

🌟 特别亮眼的地方

它把「Agent 就绪」写进设计初衷——**当 AI 开始大量生成界面，设计系统的价值不只是给人用，更是给 Agent 提供一套可靠、可预测、可组合的组件语言。** 连续多日高增长，正在成为 Agent 生成 UI 的事实标准。

📖 项目是干什么的

agent-browser 是 Vercel Labs 推出的原生 Rust CLI，给 AI Agent 一个能逐条命令驱动的浏览器。它的核心交互是**「快照 + 引用编号」**：`snapshot` 把页面读成紧凑文本，每个可交互元素带一个类似 `@e1` 的引用；Agent 基于引用执行点击、填写，再重新读页确认结果，如此循环。浏览器在命令之间保持开启，每一步都是一次很短的 shell 调用，无需把整个页面塞进上下文。

它的工作方式是：首个命令启动后台 daemon，通过 Chrome DevTools Protocol 控制浏览器，每个 `--session` 有独立的 daemon 和浏览器，默认一小时无操作自动关闭。默认用 Chrome for Testing，也可用 `--cdp` 接入已运行的 Chrome，用 `--engine` 切换 Lightpanda、Obscura 等引擎，支持 iOS 模拟器里的 Mobile Safari 和多家云浏览器。CLI 还随版本自带匹配的技能，并提供 `mcp` 子命令启动 MCP server，Apache-2.0 许可。

💡 可借鉴的优点

- **产品思维**：用「快照引用」而不是截图或完整 DOM 与 Agent 交互，极大节省 token，且每次操作后强制重读确认，天然闭环。
- **架构设计**：daemon 常驻 + 会话隔离 + 协议解耦（CDP），兼容多种浏览器引擎和云服务。
- **工程化**：点击在元素被遮挡、禁用、不可见时会明确失败而非假成功，把「不可靠操作」显式暴露。
- **生态策略**：自带版本匹配的技能和 MCP server，让任何 Agent 宿主都能接入。

🌟 特别亮眼的地方

它代表了 Agent 浏览器自动化的务实流派：**不追求让 Agent「看懂」一张图，而是把页面结构化、把动作编号化，用最小的上下文开销换最高的确定性。**

📖 项目是干什么的

这是 Google 知名工程师、《Learning JavaScript Design Patterns》作者 Addy Osmani 开源的「生产级工程技能」，定位是把资深工程师构建软件时使用的工作流、质量门和最佳实践编码下来，让 AI Agent 在开发每个阶段都能一致遵循。它包含 25 个技能和 9 个斜杠命令，用一条完整流水线映射软件开发生命周期：**DEFINE（/spec）→ PLAN（/plan）→ BUILD（/build）→ VERIFY（/test）→ REVIEW（/review）→ SHIP（/ship）**，另有 `/constraints`、`/webperf`、`/code-simplify`。

它的工程设计很务实：`/build auto` 可在你一次批准计划后自动执行全部任务，去掉的是「任务之间的人工干预」而不是验证——每个任务仍测试驱动、单独提交，遇到失败或风险步骤会暂停。技能还会根据当前工作自动激活。分发上通过开放的 skills CLI 一条命令安装到 70+ Agent，也支持 Claude Code 插件市场，并对单技能安装时共享清单缺失等问题显式跟踪。

💡 可借鉴的优点

- **产品思维**：用 9 个命令对齐工程师熟悉的 SDLC，`/build auto` 平衡了自主性与可控性。
- **架构设计**：25 个技能按生命周期解耦、可整体或单技能安装，自动激活减少手动调用。
- **工程化**：强制 TDD、单独提交、五轴代码评审、质量门，把「可靠」写进流程。
- **文档诚实**：对安装路径、SSH 报错、单技能清单缺失都给出明确 workaround 和 issue 跟踪。

🌟 特别亮眼的地方

它和今天 #6 shadcn/improve、#8 modern-web-guidance 一起，构成了「Agent 工程规范」的完整光谱：**一个管全流程，一个管审计规划，一个管技术栈正确性。** 权威工程师集体下场，正在统一 Agent 的工作标准。

📖 项目是干什么的

improve 是知名 UI 库作者 shadcn 做的一个 Agent 技能：**审计任意代码库，并为其他 Agent 写出可执行的实现计划，自己绝不实现任何东西。** 它的核心洞察是成本分工——把「智能会复利」的部分（理解代码、判断什么值得做、写 spec）交给最强模型，把执行交给更便宜的模型。计划即产品，且是普通 Markdown，任何 Agent 或人都能接手。

它的流程闭环很完整：**侦察**（摸清技术栈、约定和确切的构建/测试/lint 命令，这些成为每个计划的验证门，并读取 ADR、PRD 等文档避免把已决策的权衡重复报为问题）→ **审计**（跨正确性、安全、性能、测试、技术债、依赖、DX、文档、方向九类并行派出子 Agent，每个发现都带 `file:line` 证据、影响、工作量和置信度）→ **复核**（顾问亲自重读每个引用位置，剔除误报、记录驳回理由）→ **排序**（按影响 ÷ 工作量、以置信度加权）→ **计划**（每个发现一个文件写入 `plans/`，附索引和依赖图）。`/improve execute` 还能派便宜模型在隔离 worktree 执行、对照计划 review diff，合并权留给用户。

💡 可借鉴的优点

- **产品思维**：「为最弱执行器写计划」的定位，让强弱模型各司其职，显著降低成本，且计划可读、可审、可拒绝。
- **架构设计**：侦察-审计-复核-排序-计划五段式，子 Agent 过度报告 + 顾问强制复核，系统性压制误报。
- **工程化**：把仓库自己的测试/lint 命令作为验证门、写 STOP 条件，让计划在现实不符时停下来而非硬跑。
- **知识管理**：读取 ADR/PRD 并记录驳回理由，避免同一问题反复出现。

🌟 特别亮眼的地方

它最有启发的是「计划与执行分离」这个组织模式：**像资深架构师只出设计、初级工程师负责实现一样，Agent 团队也开始按能力和成本分层。** 这与今天 #10 codex-security 的「发现者不验证」异曲同工，都在用角色隔离换可靠性。

🌟 特别亮眼的地方

📖 项目是干什么的

这是 Modern Web Guidance 的源仓库，由 **Google Chrome、Microsoft Edge、Mozilla Firefox 和 MDN 团队联合维护**。它是一组嵌入编码 Agent 的技能，把 Web 平台专家知识、最佳实践和浏览器兼容数据直接注入 Agent，引导它远离遗留模式、转向现代 Web 平台的原生高性能方案。

它要解决的问题很具体：**LLM 训练数据里有大量旧代码，导致 Agent 倾向用臃肿的 JavaScript 去实现现在已有原生方案的功能**，即使模型知道某个 API，也缺少生产级现代实现的密度。CLI 提供 `search`、`retrieve`、`legacy-scan`（扫描代码库的遗留模式）等命令，内容覆盖现代浏览器 API、性能与无障碍、轻量 fallback，以及 View Transitions、容器查询、subgrid、oklch 色彩等新特性。指南刻意做到 token 高效——通过 eval 剔除模型已经掌握的低价值内容，并配有评估仪表盘。

💡 可借鉴的优点

- **产品思维**：精准定位「训练数据陈旧」这一 Agent 通病，用专家策展的指南而非更多代码来纠正。

Codex Security 是 OpenAI 推出的代码安全工具，帮助你**发现、调查并修复代码中的漏洞**。它可以在 Codex 内选择安全工作流，也可以用 `@openai/codex-security` CLI（命令名 `cs`）和 TypeScript SDK 自动化，还能在 GitHub Action、CI 和容器中运行。

功能覆盖完整安全生命周期：扫描整个仓库、指定路径或 Git diff（深度扫描会重复标准扫描并去重）；验证候选发现、生成补丁、验证已有修复；起草 `SECURITY.md`、保存威胁模型；浏览历史扫描、识别重复、按你自己的 rubric 评估严重度、从源码和 Git 历史建议负责人；对接 Linear、Jira、GitHub，并导出 SARIF、JSON、CSV；还能导入第三方扫描器结果。它要求 Node 22+，并对需要更高权限的网络安全场景提供专门的访问机制。

💡 可借鉴的优点

- **产品思维**：把「发现-验证-修复-跟踪-导出」整条安全链做成统一工具，而不只是一个扫描器。
- **架构设计**：同一能力提供 Codex 工作流、CLI、SDK、CI Action 多形态，覆盖人机和自动化场景。
- **工程化**：扫描可限定 diff/路径、支持去重和批量活动，结果可对接标准 SARIF 与主流工单系统。
- **开放集成**：能导入第三方扫描器、按自定义 rubric 定级，避免把用户锁死在单一工具。

🌟 特别亮眼的地方

## 📊 今日趋势洞察

**核心方向：元技能崛起，Agent 审计与规划 Agent——在执行层之上长出独立的「监督与规划层」。**

今天的 10 个项目可归成三条线：

- **审计/规划/指导类元技能**：shadcn/improve（#6）、codex-security（#10）、modern-web-guidance（#8）、addyosmani/agent-skills（#5），不直接产出业务，而是检查、规划、纠正其他 Agent。
- **生活与金融场景**：ha-mcp（#3，智能家居）、sure（#7，个人理财）、daily_stock_analysis（#2，股票分析），Agent 深入真实生活决策。
- **稳定底座**：astryx（#1，设计系统）、agent-browser（#4，浏览器）、TheAlgorithms/Java（#9，经典教育）。

**升温领域：**
1. **Agent 监督层**——审计、规划、指导类工具独立成层，角色隔离（发现者不验证、强模型规划弱模型执行）成为通用可靠性模式。
2. **强弱模型成本分工**——把智能复利的判断交给强模型、机械执行交给便宜模型，计划与执行分离，显著降本。
3. **Agent 接管生活场景**——家居控制、个人理财、投资决策等高敏感场景，权限最小化和数据自托管成为核心诉求。
4. **现代 Web 实践纠偏**——浏览器厂商联合出手，纠正 Agent 因训练数据陈旧而生成的遗留代码。

**对开发者的启发：**
- 「元技能」是 Agent 工程的新机会：做检查、规划、规范类工具，价值不亚于直接执行的 Agent。
- 用角色隔离和强制复核来保证可靠性——子 Agent 会过度报告，必须有独立的复核与验证环节。
- 进入高敏感场景（家居、理财）时，安全和权限设计要前置，专用账户、最小权限、清晰信任边界是底线。
- 关注成本分层：让强模型只做不可替代的判断，把可复用的执行下沉，是规模化使用 Agent 的关键。
- 经典基本功（算法、现代 Web API）不会过时，反而是 Agent 生成内容是否可靠的评判标尺。
