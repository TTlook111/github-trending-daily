📖 项目是干什么的

这是 Modern Web Guidance 的**源码仓库**，真正的产物是 `GoogleChrome/modern-web-guidance` 那套面向编码 Agent 的技能。它要解决的问题很具体：LLM 的训练数据里堆满旧代码，Agent 总爱用臃肿的 JavaScript 去实现浏览器早已原生支持的能力；即便模型知道某个 API 存在，也缺乏生产可用的现代写法密度。这套技能就是把浏览器厂商的权威知识，直接注入到编码 Agent 的上下文里。

机制上有四个 CLI 入口：`install` 交互式安装、`search` 检索相关指南、`retrieve` 按 ID 取单篇、`legacy-scan` 反向扫描代码库里的过时写法。内容覆盖 250 个现代 Web 特性，分六大领域：用户体验（View Transitions、滚动驱动动画）、CSS 布局（容器查询、subgrid、oklch）、性能（预加载、INP 诊断、`scheduler.yield`）、表单与 UI（Popover、dialog、锚点定位）、无障碍，以及浏览器内置 AI。

这个仓库本身负责「作者、校准、评测」：包含内容生产代码、Eval Dashboard 和 GOVERNANCE / CONTRIBUTING 治理文件。它是今年 1 月底才建仓的项目，今天站上 6,754 星，单日 +1,220，连续三天保持日均 1,200 以上的净增。

💡 可借鉴的优点

- **产品思维**：没有再做一本文档站，而是把「浏览器厂商的权威知识」做成 Agent 可直接消费的技能，卡位在 LLM 的知识盲区上。
- **架构设计**：技能 + CLI 双入口，能整体安装也能按需检索；`legacy-scan` 还能反向审计存量代码，形成「正向指导 + 反向体检」的闭环。
- **工程化**：用评测驱动内容裁剪——只保留模型不掌握的专家级内容，把 token 效率当成可量化指标，并公开 Eval Dashboard。
- **社区运营**：Chrome、Edge、Firefox、MDN 四个团队联署，跨厂商背书本身就是极强的信任资产。

🌟 特别亮眼的地方

浏览器厂商开始**亲自为 Agent 编写「知识供给侧」内容**，这是一个信号：竞争已经从「模型能不能写」延伸到「喂给模型的知识够不够新、够不够准」。连续三天日均净增 1,200 星说明这不是尝鲜式围观，而是真实的装机需求——当四大浏览器团队愿意共同维护一份 Agent 技能，现代 Web 的事实标准就有了一个面向 AI 的官方入口。

📖 项目是干什么的

Plannotator 是一个跑在本地的**浏览器审阅面板**，专治「Agent 干得太快、人跟不上」。当 Agent 提出一个决策、一份计划、一个 HTML 产物，或者刚干完一段活，界面会自动在浏览器里打开，你可以在上面标注、评论，然后一键把反馈发回给 Agent 让它接着做。

接入面铺得很宽：Claude Code、Codex、Copilot CLI、Gemini CLI、OpenCode、Kiro、Droid、Amp、DeepSeek Harness、Pi 都支持，靠插件、hooks 和命令挂上去；个人助理类（Grok Bot、Muse、Hermes、OpenClaw）则通过 Inbox 接入。功能分三块：标注计划 / 规格 / Markdown / HTML 等交互产物；代码审阅（本地 diff 或远程 PR，兼容 Git、GitButler、Jujutsu、Perforce、GitHub、GitLab）；以及刚上线的 Plannotator Inbox。

Inbox 是它今天冲到第 2 的直接原因：一个本地窗口，所有 Agent 把提问、文件、待评审内容放在这里，你点一下就能回答，标注完点发送即可。关键设计是**回复会回到提问的那个会话，且不会挂起会话**——Agent 不用干等人。另外它还留了 MCP 入口（`plannotator inbox mcp`）和终端形态的 Herdr Annotate，覆盖从 IDE 到纯终端的全谱系。Apache-2.0，2025 年 12 月底建仓，今天 11,656 星、1,145 个 fork。

💡 可借鉴的优点

- **产品思维**：Agent 越自主，人越需要一个「低摩擦的介入点」——不是审批弹窗，而是能写批注的画板。
- **架构设计**：本地服务 + 浏览器 UI + 插件 / Hook / MCP 三种接入方式，覆盖从 CLI 到个人助理的全谱系。
- **工程化**：多版本控制系统（Git / GitButler / Jujutsu / Perforce）与多代码托管（GitHub / GitLab）适配，说明它按真实工程环境设计，而不是只服务一条理想路径。
- **社区运营**：官网、文档、演示视频、HTML 视觉技能配套，把「怎么用」讲得很轻，降低第一次上手的成本。

🌟 特别亮眼的地方

从 +412 到 +860、从第 10 到第 2，一天之内翻倍的不是功能数量，而是**形态的变化**：从「每个会话开一个审阅窗口」变成「一个收件箱收所有 Agent」。这一步把审阅从被动响应变成主动排队，也让 Plannotator 从工具变成了工作流里的一个「收件处」。人机协作的瓶颈已经从「生成」转移到「审阅」，而审阅产品的胜负手，正在于能不能让人的注意力不被切碎。

📖 项目是干什么的

Veyra 是一个面向 Windows 的**实时 GPU 视频增强**工具：超分辨率、降噪、HDR、补帧，再加上采集与串流——本地视频、采集卡、PS5 / Xbox / PC 游戏串流（兼容 Moonlight / Sunshine），全部塞进同一条实时管线。它的自我定位很直白：一个引擎，接任意源，实时增强。

技术栈是 C++ + DirectX 12，显卡路径覆盖 NVIDIA 与 AMD：RTX Video SR（含真·双 SR 与 SR 后再降采样）、DLSS / FSR / XeSS、DLAA、NVIDIA Low Latency，以及 RX 7000 / RX 9000 各自的降噪与超分方案。界面给到 Cinema、Professional List、Nodes、Colour、Export、Settings 六个工作区，支持节点式编辑与分层降噪，简繁中文、英文、日文。

README 首页把下载量写成了硬指标：便携包累计下载 112,870 次，全部 Release 资产 140,848 次（截至 11 月 15 日，明确标注是下载事件而非独立用户）。更新日志同样偏工科：2.1.2 带来双 SR、SR 后降采样、NVIDIA Low Latency、实验性 RX 7000 降噪，以及采集 / 补帧 / 音频 / 音量的修复清单。GPL-3.0，2026 年 9 月建仓，今天 +731 冲到第 3，是本周单日增幅最高的非 AI 项目。

💡 可借鉴的优点

- **产品思维**：把 DLSS 的思路从「玩游戏」搬到「看视频」，用户不需要换硬件就能改善既有内容。
- **架构设计**：一个引擎接任意源（本地文件、采集卡、串流），节点式管线让效果可以组合而非写死。
- **工程化**：每个版本都附修复清单与已知限制，下载量按「事件」而非「人数」披露，口径比多数消费级软件干净。
- **社区运营**：双语知识库、Wiki 排障、B 站与 YouTube 双通道教程，把桌面软件最难的那段「怎么装、怎么调」讲清楚了。

🌟 特别亮眼的地方

当全行业都在用 GPU「生成内容」时，Veyra 用它来**修复已有内容**：把 1080p 的老视频、主机游戏的实时画面拉到接近 4K 的观感。这条路不性感，但用户需求极其刚性，也是消费级算力最容易被低估的落地路径。它在周日拿到 +731，说明周末的时间真正流向了「让自己已有的内容更好看」这件事。

📖 项目是干什么的

Chrome DevTools 团队出品的 MCP Server 与 CLI，让编码 Agent（Antigravity、Claude、Cursor、Copilot 等）能够**控制并检查一个真实的 Chrome 浏览器**。这是「让 Agent 能动手」到「让 Agent 能看见问题」的关键一跳。

三个核心能力：用 DevTools 录制 trace 并抽取可执行的性能洞察；分析网络请求、截图、读取 console 消息（带 source map 后的堆栈）；用 puppeteer 执行动作并自动等待结果，保证自动化可靠。性能工具还可以把 trace URL 发给 Google CrUX 换取真实用户体验数据，让实验室数据与线上真实数据并排看——不想要的话 `--no-performance-crux` 一键关闭。

边界写得很清楚：只官方支持 Chrome 与 Chrome for Testing，其它 Chromium 内核浏览器不保证；默认收集使用统计（可 `--no-usage-statistics` 关闭，CI 环境自动关闭）。Apache-2.0，2025 年 9 月建仓，一年时间做到 56,780 星、4,720 个 fork，昨天 +673、今天 +718，增幅还在走高。

💡 可借鉴的优点

- **产品思维**：Agent 会写前端但不会「看」前端，把调试能力通过 MCP 直接接进模型，痛点命中得很准。
- **架构设计**：MCP 与 CLI 双形态，复用 puppeteer 和 devtools-frontend，官方团队反而最懂得不重复造轮子。
- **工程化**：明确的兼容边界、遥测默认开启但可关闭、CI 下自动关闭——把「隐私与可运维」当成设计约束而非事后补丁。
- **社区运营**：工具参考、FAQ、设计原则、故障排查齐全，官方维护降低了信任成本。

🌟 特别亮眼的地方

浏览器自动化的竞争点正在从「能不能点」转向「点完能不能解释为什么慢」。当性能 trace、console 与网络时序成为 Agent 的一等输入，前端 Agent 才算真正具备可观测性。这也是 MCP 生态里少数由**被观测方自己**提供的服务——Chrome 团队直接下场，等于给「Agent 需要 DevTools」这件事盖了章。

📖 项目是干什么的

这是一个起点非常「个人」的项目：作者想用 AI 改进自己的交易流程，于是把「市场复盘—风险管理—交易计划—日记—复盘改进」整套流程拆成了 Claude Skills。它的目标写得很克制——**不是把买卖决策外包给 AI**，而是把决策过程结构化；也不是信号服务，不承诺盈利。

组织方式很像一个正经工程：`skills/` 放单个技能（每个含 SKILL.md、参考资料、辅助脚本），`skills-index.yaml` 是**唯一权威索引**（README 与 CLAUDE.md 冲突时以它为准），`workflows/` 用 YAML 定义五条操作流：15 分钟日检（market-regime-daily）、周度长期组合复盘、只在风险允许时找波段机会、每笔平仓后的记忆回路、月度绩效复审。`skillsets/` 再按目标打包成六种安装组合。

难能可贵的是它照顾了「没有付费数据源的人」：五技能起步路径用公开 CSV、图表截图和本地 YAML 日记即可跑通，FMP / FINVIZ / Alpaca 都是可选。它服务的画像也很明确——以长期投资、ETF、股息股为核心，把波段当卫星仓的时间紧张型个人投资者。MIT 许可，2025 年 10 月建仓，今天 5,230 星、单日 +707，昨天是 +556，连续两天加速。

- **架构设计**：skills / workflows / skillsets 三层结构，技能可单用、可编排、可打包，扩展性很自然。
- **工程化**：schema 校验器（`--strict-workflows`）、发布包 SHA256SUMS 校验、明确的版本兼容与迁移策略，规格接近正式软件。
- **社区运营**：免责声明写得比功能还认真，还单独提供了隐私政策与安全策略文档，降低「AI 碰钱」的信任门槛。

这是 Agent 技能第一次大规模进入「高风险决策」领域，但它的答案不是「让 AI 替你决定」，而是「让你按流程决定」。**技能的价值可以是约束人的随意性**——这条思路在投资、医疗、合规等场景都能复用。它连续两天加速增长，说明市场对「有纪律的 AI」比对「会预测的 AI」更有信心。

📖 项目是干什么的

这是阿里集团内部「官方 AI 代码审查助手」的开源版：在内部经过大规模真实调用验证之后才孵化成开源项目。安装后得到 `ocr` 命令，配置一个模型端点即可使用，官方口径是「安全、快速、高效，经得起阿里规模考验」。

它的工作方式是读 Git diff，把变更文件交给一个具备工具调用能力的 Agent——Agent 可以读完整文件、检索代码库、查看其它变更文件以获取上下文，最终输出**行级精度**的评审意见，而不是浮于 diff 表面的泛泛点评。除 diff 评审外，`ocr scan` 可以对整个文件做审计，适合接手陌生代码库。内置多语言规则集覆盖空指针、线程安全、XSS、SQL 注入这些老问题，模型侧兼容 OpenAI 与 Anthropic 协议。

真正的差异点在架构：**确定性的工程逻辑 × Agent**。不该出错的部分交给代码——精确的文件筛选、智能文件打包（例如 `message_en.properties` 与 `message_zh.properties` 合并成一个评审单元，各自跑隔离子 Agent，天然支持并发）、模板引擎驱动的细粒度规则匹配、独立的评论定位与反思模块；该动态判断的部分交给模型——场景化 prompt 与从生产调用链里蒸馏出的专用工具集。仓库 topics 里直接写着 `harness` 与 `repository-level-context`，态度很坦诚。

数据也拿得出手：AACR-Bench 基于 50 个热门开源仓库、200 个真实 PR、10 种语言，由 80+ 资深工程师交叉标注出 1,505 条 ground truth。官方口径是：同一底座模型下，Precision 与 F1 明显高于通用 Agent，token 消耗约为其 1/9，代价是 Recall 更低——这是主动取舍，宁可少报也不制造噪声。今天 51,865 星、+688，4,224 个 fork。

💡 可借鉴的优点

- **产品思维**：不跟通用 Agent 抢「全能」，而是承认纯语言驱动缺乏硬约束，用工程把底线兜住。
- **架构设计**：文件打包 + 隔离子 Agent 的「分而治之」，是超大 changeset 下保持稳定的关键；定位与反思拆成独立模块，也是可复用的做法。
- **工程化**：自建 benchmark、把数据集放到 HuggingFace，把「审查质量」拆成 F1 / Precision / Recall / 耗时 / token 五个可测指标。
- **社区运营**：多语言 README、官网、npm 分发、兼容 Claude Code、Codex、Cursor、Kimi Code，接入面铺得很宽。

🌟 特别亮眼的地方

它把「AI 评审 AI 写的代码」从玄学拉回可复算的工程问题：**精度优先、召回让位**，是面向真实 CI 流水线的取舍，而不是刷榜。当 Agent 写的代码越来越多，「谁来判断它对不对」会变成比生成能力更刚性的需求，而这个位置由一家有十万级开发者的公司用自己的生产数据填上了。

Sure 是个人财务应用的社区续作。它原本叫 Maybe Finance：团队在 2021—2022 年砸了将近 100 万美元做一整套个人财务与财富管理功能，甚至提供真人 CFP/CFA 顾问服务，但 B2C 商业模式没跑通，2023 年中停止开发、把代码开源并短暂上线过托管版，也没能持续。现在是社区 fork 在维护这套代码。

💡 可借鉴的优点

- **产品思维**：一个商业失败但工程有价值的项目，通过社区 fork 而不是「fork 出走」的方式续命，路径值得研究。
- **架构设计**：Rails 单体承载多客户端 + API + Agent 接入，一套领域模型服务多种终端，复杂度可控。
- **工程化**：公开性能看板让「优化」有靶子和数据，比空喊「欢迎 PR」有效得多。
- **社区运营**：把商标与归属写进 README（禁止 fork 使用 Maybe 商标），提前规避法律摩擦，这是成熟做法。

🌟 特别亮眼的地方

GitHub 上有大量「作者跑路」的项目直接烂尾，Sure 给出了另一种可能：**代码资产可以脱离公司存续**，只要有人愿意接、且授权（AGPL）允许接。它在 Agent 时代还有额外意义——一个能被 LLM Agent 调用的财务 API，本身就是新的产品边界，也是自托管阵营最容易长出新玩法的品类。

📖 项目是干什么的

Univer 是一个 Office SDK，目标是把「电子表格、文档、演示、关系表、画布、PDF」的编辑、计算、协作与文件处理能力，嵌进你自己的产品里——给人用，也给 Agent 用，并且用的是你的数据和你的权限。

它拆成三块：**Web SDK** 是地基（内容模型与快照格式、插件与依赖管理、命令系统、公式与渲染引擎、Facade API、UI 基础），既可以嵌成编辑器，也可以 headless 复用同一套模型与计算；**Server SDK** 负责实时协作、编辑历史与 Office 文件导入导出；**AI SDK** 把 Office 能力接给现有 Agent 与工作流，提供内容工具、执行与审阅集成。

本仓库开源的是 Web SDK 的核心架构与引擎实现（Apache-2.0），商业插件、Server SDK 与商业 AI 扩展另行授权。开源部分的能力已经相当完整：单元格样式、合并单元格、单元格内富文本、冻结窗格、浮动图片、撤销重做；公式、定义名称、筛选排序、数据校验、条件格式、超链接、评论、查找替换；Docs 侧的富文本、段落格式、列表、链接与绘图集成。快速上手只要 `pnpm add @univerjs/presets @univerjs/preset-sheets-core`，用一个预设就能拿到完整表格编辑器；在 Node.js 里还能复用同一套插件与模型做快照处理与自动化任务。

跨特性撤销是它架构上最能说明问题的地方：在筛选范围内插入一行，会同时改动本体内容与筛选范围，撤销必须把两者一起还原——每个特性各自提供变更与撤销数据，由命令系统组合执行与历史。2022 年 9 月建仓，今天 24,790 星、+495，和昨天完全同额，说明它是被稳定拉进审阅清单的，而不是靠一次性事件。

💡 可借鉴的优点

- **产品思维**：把 Excel / Word 当成 SDK 而不是产品来卖，卖给的是「想在自己产品里塞一个表格」的团队。
- **架构设计**：插件与依赖管理 + 命令系统 + 可 headless 的计算引擎，让同一份逻辑既能渲染也能被 Agent 调用。
- **工程化**：开源与商业边界写得清楚（功能对照表 + 授权说明），避免「先用后付费」的信任崩塌。
- **社区运营**：多语言 README、Showcase、Open Collective 赞助、Discord 社区，商业与开源分工讲得明白。

🌟 特别亮眼的地方

「让 Agent 直接编辑你的表格和文档」不是接个 LLM 就完事，底层必须支持**可撤销、可协作、可复算**——公式算错一次就可能污染整张表。Univer 押注的正是这层别人不愿意啃的脏活。它连两天 +495 也说明一件事：Agent 办公的想象力已经不缺，缺的是能扛住真实编辑操作的地基。

📖 项目是干什么的

Airgorah 是一款用 Rust 写的 WiFi 安全审计软件，图形界面基于 GTK4。它的定位是「审计」而不是「入侵」：抓取周边 WiFi 流量、发现接入点下连着的客户端、捕获握手包与 PMKID，并对无线口令的强度做离线审计。换句话说，它把过去散落在一堆命令行工具里的流程，收进了一个桌面窗口。

权限模型是这个项目最讲究的地方：图形界面**以普通用户身份运行**，X11 和 Wayland 都能用；只在需要特权操作时，通过 polkit 拉起一个小的 `airgorah-agent`，并且只弹一次认证。硬件上要求网卡支持 monitor mode 与 packet injection，运行环境限定 Linux。

README 把法律边界写在最前面：软件设计用于测试和发现**你自己拥有的**网络中的缺陷，在绝大多数国家对他人 WiFi 发起攻击是违法的。这份声明不是免责套话，而是产品的一部分——它明确划定了使用者的责任范围。装包走 crates.io 与 AUR，MIT 许可，2022 年 9 月建仓。今天 6,107 星、单日 +270，是本期唯一低于 300 门槛、按补齐规则进榜的项目。

💡 可借鉴的优点

- **产品思维**：把一个偏极客的命令行流程做成有界面的桌面应用，降低的是「认知门槛」而不是「技术门槛」。
- **架构设计**：GUI 非特权 + polkit 特权代理的最小权限模型，是桌面端做高权限操作的干净做法，比「sudo 启动整个 GUI」安全得多。
- **工程化**：Rust + GTK4 的原生组合，crates.io / AUR 双分发，CI 徽章齐全，符合 Linux 桌面软件的常规发布路径。
- **社区运营**：把法律与道德声明前置、用 wiki 承载安装与用法、用 discussions 承接问答，README 只保留最短路径。

🌟 特别亮眼的地方

安全类工具的产品化，卖的不是「攻击力」，而是**合规边界 + 最小权限**。Airgorah 愿意把「只对你自己的网络用」写在第一屏，也愿意为一次特权操作设计一个独立代理，这种克制恰恰是它能被放进正规工具箱、并且拿到 6,000 星的原因。它进榜也说明：在没有大新闻的周日，实用型工具能靠稳定口碑占住位置。

## 📊 今日趋势洞察

**核心方向：审阅层从「建起来」进入「用起来」。**

昨天四个项目分别对应 Agent 工作流的四个关口，今天它们还在榜，但位置和增速变了：plannotator 靠 Inbox 从第 10 跳到第 2，chrome-devtools-mcp 增幅从 +673 升到 +718，modern-web-guidance-src 连续三天日均 1,200+。**这说明审阅层已经被验证，接下来的竞争不在「要不要有」，而在「怎么让它不打断人」**——Inbox 的「回复回到原会话、不挂起会话」正是这一类细节。

**升温领域：本地算力、自托管、以及「能被 Agent 调用的基础设施」。**

Veyra（+731）、uptime-kuma（+352）、sure（+520）、airgorah（+270）四个本地优先项目合计净增近 1,900 星，占了今天总量的三分之一。周日的注意力流向自己的机器：修视频画质、盯自己的服务、管自己的账、审自己的网络。这类需求不会因为模型变强而消失，反而会因为「人人都能用 Agent 写代码」而增加——能本地跑、能自己掌控的东西，优先级在上升。

**对开发者的三点启发。**

第一，**给 Agent 的产品要设计「人的入口」**：Plannotator 的批注画板、open-code-review 的行级评论、chrome-devtools-mcp 的性能 trace，本质都是把机器行为翻译成人能判断的形式。第二，**技能的护城河是评测，不是文案**：现代 Web 指南靠 Eval 裁剪内容，代码审查靠 AACR-Bench 校准精度，没有度量的技能只是提示词。第三，**确定性的部分永远该写成代码**：阿里的文件打包与规则引擎、Univer 的跨特性撤销，都是「不该让模型猜的地方就别让模型猜」。
