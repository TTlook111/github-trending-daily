📖 项目是干什么的

PaperOrchestra 是 Google Cloud AI Research 开源的多 Agent 框架，作者是 Yiwen Song、Yale Song、Tomas Pfister 与 Jinsung Yoon，配套论文挂在 arXiv（2604.05018）。它要解决的是一个非常具体、也非常昂贵的问题：**把零散的研究想法与实验日志，变成一篇按目标会议模板排好版、可以直接投稿的 LaTeX 论文**，中间还要求有像样的文献综述与图表。

它的做法不是「让一个大模型一口气写完」，而是像课题组一样分工：Outline Agent 先搭骨架，Literature Review Agent 负责检索、排序、整合文献，Section Writing Agent 逐节撰写，Content Refinement Agent 打磨逻辑与表达，Plotting Agent 从代码生成图表；再叠一层反思类 Agent 做复核。文献侧接 Semantic Scholar API，写作模型可在 Gemini（走 Vertex AI）与 OpenAI 之间切换，产出直接套 `templates/` 里的会议模板，CVPR 2025 已内置，也能自建。

工程形态是很典型的「研究项目」：Conda + Python 3.11、`.env` 配 key、bash 脚本与 Python CLI 两种入口、`autoraters/` 放自动评估、`methods/` 放流水线核心、`frontend/` 给了一个 Streamlit 交互 demo。仓库创建于今年 5 月，11 月 15 日仍在提交，已有 583 个 fork、43 个 open issue；数据集不在仓库里，声明后续单独发布。

💡 可借鉴的优点

- **产品思维**：把「写论文」这条长链路拆成可并行、可复审的角色。分工的意义不只是提速，而是让质量问题可以被归因到具体环节——是文献找漏了，还是某一节写虚了。
- **架构设计**：五个专职 Agent 加反思层，写作、文献、作图彼此独立；LaTeX 模板可插拔，换会议不用改代码，这是「产品化」最关键的一步。
- **工程化**：自动评估脚本与主流程分离，模型供应商可切换，原始材料目录与输出目录解耦，适合批量跑对比实验、也适合做消融。
- **社区运营**：论文、代码、demo 三件套齐备，数据集单独发布——研究型开源的标准节奏：先把方法说清楚，再谈工具好不好用。

🌟 特别亮眼的地方

从昨天的 +1,072 到今天的 +1,524，它连续两天加速，并从第 2 直接登顶，是今天唯一一个日增破千五的项目。这件事值得兴奋也值得警惕：当结构、文献、写作、作图都能被编排，「论文」这种知识产品的最低门槛会被迅速拉平。真正的分野会落在两处——**想法本身的原创性，和实验的说服力**。工具能补齐格式、综述与排版，补不了「你凭什么值得被引用」。4,750 星在半年内攒下，说明学术界对「写作流水线」的饥渴程度远超想象。

📖 项目是干什么的

ECC 自称「agent harness operating system」——不是又一个提示词合集，而是给编码 Agent 装上一整套工程操作系统：**72 个专职子 Agent、327 条按需加载的技能、98 个维护中的斜杠命令**，加上 rules、hooks 与安装/修复/同步脚本。它把工作流压成一行：`plan → test → implement → review → verify → remember → improve`，并强调「技能是主工作面，命令正在迁移」。

真正的差异化在「一套源文件，多种发行版」：仓库根目录是唯一真相源，`.claude-plugin/`、`.codex/`、`.opencode/`、`.cursor/` 等目录只是适配层，把同一批工作流映射到 Claude Code、Codex、OpenCode、Cursor、Kimi Code、Antigravity、Pi 七个 harness，而不是各维护一份。当前版本 2.2.3（10 月 1 日），MIT 协议，npm 上有 `ecc-universal` 与 `ecc-agentshield`，另有托管版 GitHub App（ECC Pro，私有仓库 $19/seat/月）给商业团队用。

细节密度也很高：`ecc memory` 统一记忆仓库、`continuous-learning-v2` 用置信度打分沉淀「本能」、`strategic-compact` 管理上下文压缩时机，README 甚至专门警告「别把所有 MCP 全开，每个工具描述都在吃掉 200K 窗口」。仓库还有 17 种语言的 README、Discord 社区、CodeRabbit / Greptile / Kimi 等赞助商。

💡 可借鉴的优点

- **产品思维**：开源主体免费、商业能力（私有仓库、托管 App）收费，这是「方法论型产品」目前最健康的分层：个人随便用，团队为合规与私有性付费。
- **架构设计**：根目录单一真相源 + 平台适配器，避免多仓库分叉导致的「同一个技能七个版本」；hooks 负责运行时强制，skills 负责流程知识，边界清楚。
- **工程化**：有 `doctor` / `repair` / `uninstall` 与安装状态归属，发布前跑打包产物的 release gate，Linux / macOS / Windows 三端都测；连「装两次会重复技能」这种坑都写进文档。
- **社区运营**：17 种语言文档、Discord、赞助商体系、每周发版；对第三方镜像明确警告「可能含恶意代码」，把供应链安全写进了首页。

🌟 特别亮眼的地方

306,885 星、45,174 个 fork，这个体量已经超过绝大多数老牌框架，而它今年 1 月才建仓。更值得看的是它的运营方式：**一个维护者，七个 harness，每周发版**——这背后是「技能库当发行版运营」的新范式。当技能数量到 327 条，真正的护城河不再是「我会写提示词」，而是「我能保证它在七个不同的运行时里表现一致」。这也是今天榜单的第一层隐喻：**分发的复杂度，正在超过生产的复杂度。**

📖 项目是干什么的

last30days 是一个「由 Agent 驱动、按真人互动排序」的搜索引擎：你给它一个题目、一个人名或一家公司，它并行扫 Reddit、X、YouTube、TikTok、Instagram、Hacker News、Polymarket、GitHub、Digg、arXiv、Techmeme、专利申报、招聘页、Yahoo Finance 等来源，把过去 30 天里真实发生的事按 upvotes、likes、播放量和真金白银的赔率排好，再由一个 Agent 裁判合成一份带引用的简报。

它的产品哲学写在标题里：**「Google 聚合的是编辑，last30days 搜索的是人。」** 一个 1,500 赞的 Reddit 帖，比没人读的博客更有信号；一个有真实成交量的 Polymarket 盘口，比评论员的猜测更难反驳。v4 又加了两个很刁的「秘密信号」：读一家公司的美国专利申报，挑出那些「不像它会做、也没发布过」的申请；读它自己的招聘页，找出泄露了新团队或新产品的岗位。

工程上它把「来源」做成了插件系统：Reddit、HN、Polymarket、GitHub 零配置即用；X、YouTube、TikTok、arXiv 等在首轮向导里解锁；需要登录态的明确标为 opt-in。除了单次简报，还有 `--store` 落 SQLite 做趋势累积、`watchlist.py` 定时跑并推 Slack / webhook、`briefing.py` 出日报周报、`library feed` 把历史简报变成可订阅的 Atom 源。技能规范以 `skills/last30days/SKILL.md` 为唯一事实源。

💡 可借鉴的优点

- **产品思维**：用「时间窗 + 真人互动」做差异化。全网的「最新信息」其实被编辑过滤过一遍，它直接回到原始投票现场——这是搜索类产品少有的、结构性的空位。
- **架构设计**：来源插件化 + 多查询扩展 + 实体解析 + 同题聚类 + Agent 裁判，五步流水线各司其职；同一件事在 Reddit、X、TikTok 出现时合并成一个故事，而不是三条链接。
- **工程化**：输出有版本化的 JSON 契约，脚本与 Agent 两种消费方式都照顾到；`--preflight` 先干跑一遍确认要写哪些文件；离线库检索是确定性的，不依赖模型。
- **社区运营**：Claude 官方市场 + `npx skills` 覆盖 50 多个宿主，社区研究 feed 做成展示位；README 里直接放用户原话，把「省下 90 分钟」这种价值说得非常具体。

🌟 特别亮眼的地方

昨天它还是第 7，今天以 +1,059 冲到第 3，70,453 星只用了十个月。它证明了一件事：**在 Agent 时代，「搜索」不再是一个输入框，而是一条可编排的取证流水线。** 每个平台都是围墙花园，各自有 API、token 与登录态；真正可复用的能力，是让 Agent 带着你自己的钥匙同时进十几个园子，再把它们互相印证。这也是「技能」这个词最值钱的形态——不是会调用一个 API，而是知道该问谁、信谁、怎么交叉验证。

📖 项目是干什么的

Superpowers 不卖单条技能，卖的是一整套**给编码 Agent 装上的软件开发方法论**：一批可组合的技能，加一段保证「Agent 真的会去加载它们」的引导指令。Agent 一旦判断你在造东西，不会立刻写代码，而是先退一步问清你到底想解决什么；把 spec 从对话里逼出来之后，分段展示给你确认，每段都短到能真正读完；设计签字后才进入计划。

计划之后是一条被固定下来的工作流：**brainstorming → using-git-worktrees → writing-plans → subagent-driven-development / executing-plans → test-driven-development → requesting-code-review → finishing-a-development-branch**。README 对计划的要求很硬——「一个热情但品味差、没有判断力、没有项目背景、还讨厌写测试的初级工程师也能照着做」，并强调真·红绿 TDD、YAGNI 与 DRY。落地时由子 Agent 逐任务实现、检查、评审、推进，主会话只保留决策与验收。

它最大的资产其实是分发宽度：Claude Code 官方插件市场、自建市场、Codex App / CLI、Cursor、Devin CLI、Factory Droid、Gemini CLI、GitHub Copilot CLI、Grok Build CLI、Kimi Code、OpenCode、Pi、Qwen Code、Hermes Agent、Muse、Antigravity——**16 个 harness，一个仓库**。它还专门做了 `diagnosing-superpowers`：技能该触发没触发、Agent 跑偏、重复劳动时，让 Agent 自己读会话记录、给出逐行证据。

💡 可借鉴的优点

- **产品思维**：卖的不是能力而是纪律。它解决的不是「Agent 不会写代码」，而是「Agent 不受流程约束」；把返工成本前置到 spec 与计划阶段，是这类产品最有价值的位置。
- **架构设计**：可组合技能 + 启动引导 + 子 Agent 隔离。实现细节留在子会话，主对话只负责拍板与验收，上下文不被污染，这也是它能连续自主跑几小时的前提。
- **工程化**：把「计划好不好」翻译成可检验的标准；技能行为用独立的 drill eval harness 测，插件基础设施另有测试，不靠「我感觉它变聪明了」。
- **社区运营**：官方市场与自建市场双通道，企业侧留商业支持入口；明确不接收「Agent 代写的、修别人 issue 的 PR」，把维护成本挡在门外；遥测默认只报版本号，且可一键关闭。

🌟 特别亮眼的地方

321,610 星，仍是全榜 star 存量第一；但今天 +822、排名第 4，说明热度正在被更「新」的故事分走。这恰恰是它成功的证据：**方法论一旦被市场接受，就会退成背景，像 IDE 的默认设置一样不再被讨论。** 它留在榜上的意义，是提醒所有人——16 个 harness 的兼容不是苦力活，而是护城河；当你的流程能在别人的 Agent 里跑，你就不需要自己有模型。

📖 项目是干什么的

Svelte 是那个「在编译期把活干完」的前端框架：你写声明式组件，编译器把它变成高效的 JavaScript，运行时只做精准的 DOM 更新，而不是像传统框架那样在浏览器里做 diff。README 一句话就把定位说完了——「web development for the rest of us」。

它昨天发布了 **5.58.0**：dev 模式的 `__svelte_meta` 栈里加进了 `snippetName`，devtools 能追踪元素是被哪个组件实例渲染的；编译器会在编译后主动释放组件的 AST；另有 SSR `<title>` 一致性、`autocorrect` 属性、snippet 泛型解析等一串修复。今天 +692，是发布日的余温，也是一个十年老项目仍在高频迭代的证据：6,226 个 fork、1,310 个 open issue，社区讨论从未停。

💡 可借鉴的优点

- **产品思维**：核心卖点是「少」——少运行时、少样板、少心智负担。在一个不断给框架加概念的市场里，持续做减法反而形成了最强辨识度。
- **架构设计**：编译期与运行期彻底分工，编译产物只含真正用到的代码；Svelte 5 的 runes 把响应式从「编译魔法」变成显式 API，可读性与可迁移性都更好。
- **工程化**：把「编译器」当成产品来维护——每个版本都在修 DX 细节（栈信息、devtools、AST 释放），而不是只堆新特性；这种耐心是长期复利。
- **社区运营**：Open Collective 资助、Discord 常驻、Roadmap 公开；README 短得克制，把解释权交给官网与社区。

🌟 特别亮眼的地方

在一个被 Agent 技能刷屏的榜单里，Svelte 的存在像一次提醒：**前端框架的复利来自确定性。** 当越来越多的前端代码由 Agent 生成，「编译期就能发现错误、运行时行为可预测、产物足够小」反而成了稀缺品质。框架不会因为 Agent 而消失，它只会变成 Agent 更愿意选择的那个目标——因为编译器是唯一能在生成阶段就把错误拦住的东西。

📖 项目是干什么的

Arcane 是一个现代化的 Docker 管理面板，口号是「Modern Docker Management, Designed for Everyone」。打开就是实时监控：容器状态、CPU / 内存 / 网络曲线、日志；能起停重启容器、拉取镜像、建网络、管卷、清理磁盘；还能扫镜像里的已知漏洞，把结果放回仪表盘。技术栈是 Go 后端 + SvelteKit 前端，API 用 Huma on Gin 构建、自带 OpenAPI 3.1 文档，BSD-3-Clause 协议，镜像同时发在 ghcr、quay 与 Docker Hub。

## 📊 今日趋势洞察

**核心方向：技能从「内容」变成「发行物」，分发层开始成型。**

今天榜上的十个项目可以按「谁在生产、谁在定规范、谁在分发」排成三层。生产层是 paper-orchestra（研究写作）、last30days（取证研究）、CLI-Anything（软件 CLI 化）——它们把某一类复杂劳动做成可复用的流水线。规范层是 cursor/plugins 与 stitch-skills：前者给出 `plugin.json` + skills/rules/mcp 的清单格式，后者按 agentskills.io 开放标准把 Google Stitch 打包成 3 个插件、16 个技能；ECC 与 superpowers 则用「一套源文件适配 7 / 16 个 harness」证明规范的价值在于跨运行时一致。分发层是 n8n 的 9,000+ 模板、CLI-Anything 的 CLI-Hub、last30days 的 50+ 宿主市场，以及 Arcane 的模板注册表——**能被检索、能被安装、能被版本管理的，才叫生态；躺在仓库里的，只叫代码。**

**升温领域：插件清单、跨 harness 兼容、模板/注册表即渠道。**

四个信号值得记住。其一，Cursor 把插件规范开源，第三方 SaaS 连接器直接进官方库，说明 IDE 厂商已经意识到「扩展范式」比「功能数量」更能锁定用户。其二，Google Labs 用开放标准发技能，而不是发 SDK——大厂开始把能力拆成 Agent 可消费的零件。其三，ECC 的 327 条技能要同时跑在 7 个 harness、superpowers 要跑在 16 个，兼容性本身成了工程难题，也成了壁垒。其四，n8n 与 Arcane 这类「非 AI 原生」项目靠模板库与 API 进入榜单，说明**渠道与接口是 Agent 时代最被低估的资产**。另一个不容忽视的数字：今天全站只有 19 个项目、11 个达标——榜单正在被「技能与插件」高度同质化，差异化只能往规范和生态位里找。

**对开发者的三点启发。**

第一，**把能力做成插件，而不是脚本**：脚本只服务你自己，插件能被别人安装；一旦有了清单、版本与权限边界，你的经验才可能被复用。第二，**把接口写成规范**：`SKILL.md`、`plugin.json`、OpenAPI、MCP 都是「让机器读懂你」的载体；规范的价值不在于好看，而在于别人可以不改你的代码就接上。第三，**把分发做成注册表**：无论是 CLI-Hub、模板库还是插件市场，能被搜索与安装的东西才会产生网络效应——**在 Agent 时代，写得好不如装得上，装得上不如传得开。**
