## 总览摘要

如果说前几天的榜单在回答「Agent 能写代码之后缺什么」，那今天的热榜把问题又推进了一层：**当一个人手头同时有五六个 Agent，怎么把它们管成一支队伍？** 今天 10 个项目里有 8 个不再是「Agent 本身」，而是站在 Agent 之上的东西——编排面板、记忆层、技能规范、专用浏览器。一个清晰的信号是：**Agent 赛道的竞争重心，正从模型层上移到「组织层」。**

第一条线是**给 Agent 搭「管理班子」**。claude-mem（#1）继续霸榜，用跨会话记忆解决「关掉窗口就失忆」；Theo 所在的 T3 团队推出 t3code（#4），把自己定位成「Agent harness 的控制面板」，一个手机/网页/桌面端控制本机所有 Agent；Orkas（#6）用一个 Commander 把目标拆成待办、协调 16 个内置专家加 5 个外部 CLI；OpenMausBot（#3）则坚持「像聊天软件一样管理一排 Bot」。第二条线是**把专业能力固化成可复用的技能与纪律**：impeccable（#2）用确定性规则对抗「AI 味」界面，TypeScript 名师 Matt Pocock 把自己 `.agents` 目录里的工程技能全部开源（#9），Claude-Code-Game-Studios（#10）干脆用 49 个 Agent 复刻了一整套游戏工作室的层级。

第三条线是**为 Agent 重造基础设施**：lightpanda（#8）用 Zig 从零写了一个无头浏览器，比 Chromium 轻 16 倍、快 9 倍。榜单里还藏着两个「非典型」项目——港大 DeepTutor（#7）继续深耕 AI 学习工作台，而紫微斗数排盘引擎（#5）用最硬核的工程化方式（67.5 万张命盘、56.6 GB 数据集、确定性生成、回归测试 + CI）做传统文化，它的走红提醒我们：**在一个人人堆砌大模型的时代，「确定性」和「可验证」反而成了稀缺品。** 把这 10 个串起来看，今天的主题是：**Agent 正在从「一个好用的工具」变成「一支需要管理的团队」，而管理工具本身成了新的主战场。**

📖 项目是干什么的

claude-mem 解决的是编码 Agent 最顽固的一个痛点：**会话一结束就失忆**。它自动捕获 Agent 在会话里的工具调用观察——读了哪些文件、改了什么、做了什么决定，用 AI 压缩成语义摘要，之后在新会话里把相关上下文自动注入，让 Agent 对项目的认知在会话之间连续起来。名字带 Claude，实际已经适配 Claude Code、Codex、Gemini、Copilot、OpenCode、Cursor、Pi、OpenClaw、Grok Bot 等几乎所有主流宿主。

它的设计有几个关键取舍：**渐进式披露**——分层检索记忆并显示每一层的 token 成本，避免一次性把全部历史塞进上下文；本地 worker 服务提供查看器，展示进行中的请求、进度、人工交接和审阅队列；存储侧用 SQLite + ChromaDB 做 embedding 检索。对没有钩子（hooks）的宿主，它退化为监听聊天日志文件来采集。安装走 `npx claude-mem install`，默认引导登录其托管记忆服务，也支持用自有 Key 或完全跳过登录，Apache-2.0 许可。

💡 可借鉴的优点

- **架构设计**：「采集 → 压缩 → 按需注入」的记忆管线，加上分层检索和 token 成本可视，是在有限上下文窗口里做长期记忆的标准答案。
- **工程化**：对有 hooks 的宿主走钩子，对没有的退化为监听日志文件——按宿主能力选择采集方式，是做跨平台插件的务实手法。
- **产品化**：开源核心 + 可选托管服务 + 自带 Key 三条路径并存，并明确提供「跳过登录」开关，兼顾商业化与开发者信任。
- **可观测性**：本地查看器让「Agent 到底记住了什么」可见，便于排查「它这次为什么做错」。

🌟 特别亮眼的地方

claude-mem 连续多日稳居榜首，证明**记忆是独立于模型和宿主的一层基础设施**。它不绑定任何一个 Agent，而是像「外挂海马体」一样插到各家宿主上。当 Agent 从一次性对话变成长期队友，谁掌握了连续、可控、可检视的记忆，谁就掌握了用户粘性——这也是今天 #4、#6 等编排工具都把记忆当核心模块的原因。

📖 项目是干什么的

impeccable 自称「给编码 Agent 的设计词汇表」，瞄准的是所有用 AI 写过前端的人都见过的现象：不加指导时，Agent 产出的页面高度雷同——全站 Inter 字体、紫到蓝的渐变、卡片套卡片、彩色背景上的灰字。它把这些「AI slop（AI 味）」系统化，给 Agent 一套能精确表达设计意图的命令，而不是让它去猜「make it pop」到底什么意思。

核心是 **24 条命令**：Steer（bolder 放大、quieter 收敛、distill 做减法、typeset 排版、animate 动效等）、Review（critique 按可用性启发式打分、audit 做无障碍/性能/响应式审查，问题按 P0–P3 分级）、Finish（polish、harden 处理边界、onboard 首次引导），以及在运行中的 dev server 上叠加覆盖层、点选元素热替换的 live 模式。更关键的是一个**不依赖 LLM、无需 API Key 的「slop 检测器」**：62 条确定性规则直接扫出 AI 味特征和留白过挤、标题层级跳跃等问题。工程上 `npx impeccable install` 一键安装，同时适配近 20 种编码 Agent，主体用 Rust（规则引擎）+ TypeScript/Bun（CLI 与扩展），Apache-2.0 许可。

💡 可借鉴的优点

- **产品思维**：把「品味」这种模糊的东西拆成可命名的动作（bolder / quieter / distill…），给用户一个精确的词，比给模型一段长提示更能稳定输出。
- **架构设计**：确定性规则 + LLM 生成分层——能用规则判断的（字体滥用、对比度、层级）就不交给模型，既省钱又可复现，只把需要创造力的部分留给 LLM。
- **工程化**：`PRODUCT.md` / `DESIGN.md` 作为持久上下文文件，让每次命令都站在同一份产品认知上，避免多轮迭代后风格漂移。
- **生态适配**：一套核心、近 20 种 Agent 的适配目录，把「跨 Agent 分发技能」做成了基础设施。

🌟 特别亮眼的地方

impeccable 最值得借鉴的是它对「AI 生成内容趋同」的系统化回应：**先把平庸的默认值显式列出来，再给出能对抗它的词汇和检测器。** 这个思路可以迁移到任何领域——AI 写的文案、代码、报告都有自己的「slop 特征」。近 10 万 star 说明，在 Agent 能写代码之后，「品味」成了新的稀缺品。

| 属性 | 信息 |

📖 项目是干什么的

OpenMausBot 是一个开源的「Grok Bot 替代品」，核心理念是：**「一个盒子里一个助手」对 Agent 来说是错误的形态**。Agent 应该像聊天软件里的联系人——侧边栏一排 Bot，每个都有自己的人格、记忆、模型、电脑和已连接应用，你跟它们聊天、看它们干活、在关键动作上点「批准」。README 直接把自己定位为近期几款闭源个人 Agent 产品的开源对应物，并逐一列出差异。

实现上它坚持「自带 Agent、本地优先」：Bot 底层跑的是你本机已安装的 claude / codex / grok CLI，沿用现有登录和订阅，中间没有代理；一个监听 127.0.0.1 的小型 harness 服务管理所有 Agent 进程，转录、密钥、事件都存在 `~/.openmausbot`。每个 Bot 可以使用云端 Linux 桌面、隔离的本地 VM，或在明确开启后控制你自己的电脑；通过 Composio 连接 500+ 应用。Shell 命令、文件编辑等风险动作以内联卡片请求 Allow / Deny，由统一的「权限代理」裁决。桌面端基于 Electron，移动端用 Expo，Apache-2.0 许可，并特别声明没有发行任何代币。

💡 可借鉴的优点

- **产品思维**：用「聊天软件 + 联系人」这个所有人都熟悉的隐喻管理多个 Agent（置顶、未读、隐藏），学习成本几乎为零，把多 Agent 从工程概念变成日常交互。
- **架构设计**：不自己接模型，而是编排用户已有的 Agent CLI——复用现有订阅，极大降低门槛，也避开了「再托管一层 API Key」的信任问题。
- **安全设计**：所有风险动作走统一权限代理并以审批卡片呈现；密钥「只写不读」；控制本机需显式开启，安全边界划得很清楚。
- **增长打法**：README 系统化地做「X 的开源替代」对比页，精准承接搜索流量，是开源项目 SEO 的教科书式操作。

🌟 特别亮眼的地方

OpenMausBot 抓住了一个正在成形的产品形态：**Agent 不再是一个对话框，而是一个团队**。它最可借鉴的是「编排而非替代」——不跟大厂拼模型，而是站在用户已有的 Claude / Codex / Grok 之上做组织、权限和工位，把闭源产品「模型、电脑、数据都在厂商那边」翻转成「都在你这边」。

📖 项目是干什么的

t3code 来自打造 T3 Stack 的 pingdotgg 团队（Theo 所在团队），它把自己明确定义为「**Agent harness 的控制面板**」：用一流的移动 App（iOS/Android）、Web App 和基于 Electron 的桌面端，控制你本机上的所有 Agent。只要你电脑上装了 Claude Code、Codex、Cursor、Grok Build、OpenCode、Google Antigravity 并完成认证，t3code 就能接管它们，复用你已有的订阅。

README 里那句「Wait, what are you selling me? Nothing.」很能说明动机：团队想要一个高性能、可远程、真正开放的 Agent 开发体验，而现有方案（Codex 桌面端、Conductor、Claude Desktop、Cursor Glass）都没达到他们的标准，于是自己造，并承诺如果项目走偏，用户可以拿走全部代码 fork 出自己想要的编辑器。命令行用 `curl ... install.sh` 或 PowerShell `irm ... | iex` 安装，`t3` 启动服务并打开本地 Web App，`t3 service install` 可常驻后台；桌面端覆盖 winget、scoop、Homebrew、AUR、Nix 等几乎所有分发渠道，MIT 许可。

💡 可借鉴的优点

- **产品定位**：不做又一个 Agent，而是做「所有 Agent 的统一入口」，这是典型的「卖铲子」思路——当工具碎片化，控制面板本身就是刚需。
- **分发工程**：一套产品覆盖安装脚本、各大包管理器、AUR、Nix、桌面/移动/Web 全端，安装体验打磨得极其完整，值得任何开发者工具学习。
- **架构设计**：本地服务 + 多端客户端的架构，让手机远程控制本机 Agent 成为可能，且数据不过第三方。
- **信任建设**：坦诚「项目非常早期、会有 bug」，并以 MIT + 可 fork 作为长期承诺，把开放当作核心卖点。

🌟 特别亮眼的地方

t3code 的上榜是一个标志性事件：**连 T3 这种以「教开发者」闻名的团队，都不再做新模型或新 Agent，而是做 Agent 的管理面板。** 它和今天 #3、#6 形态相近、取舍不同，共同印证「Agent 控制层」正在成为独立的新品类。对开发者来说，它的多端分发策略和「控制面板」定位本身就是一份产品教材。

📖 项目是干什么的

这是一个基于倪海厦《天纪》体系的**紫微斗数开源排盘引擎**，包含完整排盘算法、四化系统、格局知识库和古籍原文数据。项目理念很清晰：「算法是公开的传统智慧，不应该被锁在围墙里」，真正的价值在于解读深度、用户体验和持续运营，所以他们把排盘内核和数据集全部开源。

工程上它的硬核程度远超多数「AI 项目」：排盘引擎在 `lib/ziwei/` 下，模块划分清晰——`algorithm.ts` 主流程、`sihua.ts` 四化飞星、`patterns.ts` 是 1100 多行的格局知识库、`true-solar-time.ts` 真太阳时校正、`dst-cn.ts` 中国夏令时判定、`lunar-solar.ts` 农历公历互转；支持真太阳时、闰月四种口径、晚子时换日、星曜亮度流派切换等复杂规则。更惊人的是 **v4.0 解读数据集：674,976 张命盘 × 13 维 = 877 万段解读，正文约 204 亿字，解压后 56.6 GB**，由排盘引擎 + 断语库确定性生成、不经 AI，同一输入恒得同一输出。仓库从零补齐了 5 条排盘回归测试和 GitHub Actions CI，界面则是一套基于 Next.js 16 + Tailwind 的最小可运行 Demo。

💡 可借鉴的优点

- **工程化**：复杂领域规则被拆成职责单一的模块，并用金标准盘做回归测试 + CI 钉住输出——这是把「玄学」做成「可验证工程」的范本。
- **架构设计**：引擎、断语库、数据集、界面分层，开源边界划得清楚（引擎和数据开源，断语库与商业后端不开源），商业化与开源互不伤害。
- **数据严谨**：发布前 77 个文件逐字节比对，已知问题（如 2,520 条不存在日期的样本）主动披露，不掩盖。
- **产品思维**：56.6 GB 的数据集压缩后仅 161 MB、按年份分文件按需下载，充分考虑了用户的实际使用成本。

🌟 特别亮眼的地方

在一个人人堆砌大模型、强调「生成式」的榜单里，这个项目最打动人的是它的**确定性**：同一输入恒得同一输出、可复现、可回测、可审计。它和今天 #8 lightpanda 一起提醒我们——AI 浪潮之外，靠扎实的工程化、严谨的数据和清晰的开源边界，一样能单日涨千星。它也证明了传统文化 + 现代工程是一个被严重低估的方向。

📖 项目是干什么的

Orkas 是一个开源、本地优先的**多 Agent 桌面应用**。你告诉 Commander（指挥官）需要什么，简单任务它自己完成，复杂工作它负责规划步骤、协调 16 个内置专家 Agent 以及你已经在用的 Claude Code、Codex、OpenCode、OpenClaw、Hermes 等外部 CLI 一起干活。

它围绕「让项目持续推进」而设计：**Project** 保存目标、规则、记忆和文件，每个新会话都能接着上次继续；**To-dos** 在人和 Agent 之间拆分工作，**Auto-advance** 让团队自动接手下一个待办，**定时自动化**可以按小时/日/周/月重复例行任务；数据默认全部留在本机，成品交回给你审阅。16 个内置专家覆盖深度研究、股票分析、PPT、视频/配音、UI 设计、产品开发、Office 文档、电商等，每个都有独立技能、记忆和工具。技术实现上，Commander 通过 `dispatch_to`、`hand_off_to`、`run_worker` 三种工具路由任务，并有上下文预算、检查点、执行锁、执行限制和基于活动的后台学习机制，MIT 许可。

💡 可借鉴的优点

- **架构设计**：Commander 用三种语义清晰的委派工具（同步调用、异步交接、隔离子任务），并配独立并发控制和执行锁，是多 Agent 编排的成熟设计。
- **产品思维**：把「项目」「待办」「自动推进」「定时自动化」这些项目管理概念搬进 Agent 产品，让 AI 从「答一次」变成「持续干活」。
- **上下文管理**：按模型可用容量预算上下文，用检查点压缩早期过程、保留结构化记录，是长任务不爆窗口的工程化方案。
- **开放策略**：MIT 开源 + 本地优先，同时明确区分开源版与打包版的功能边界，商业化路径清晰。

🌟 特别亮眼的地方

Orkas 把「AI 团队」这个概念做得最接近一家真实公司：有指挥官、有分工、有项目、有节奏、有复盘学习。它和 #3、#4 同属「Agent 控制层」，但更强调**开箱即用的专家团队和持续自动化**，适合不想自己拼装技能的非纯开发者用户。它的任务路由三工具和上下文预算机制，值得任何做 Agent 编排的团队细读。

DeepTutor 是香港大学数据智能实验室 HKUDS（也是 LightRAG 团队）出品的「终身个性化 AI 导师」，定位是一个 Agent 原生的学习工作台：把答疑、解题、出题测验、深度研究、可视化讲解、掌握度练习、沉浸式阅读、音频概览等模式放在同一个能力运行时和会话上下文里，各模式保留专用流程，但共享知识库、笔记、题库、人设和记忆。

技术底座很「HKUDS」：**多引擎知识库**同时支持 LlamaIndex、GraphRAG、LightRAG、WeKnora、Kiwix 离线百科、Obsidian 等，文档解析可插拔；**可检视记忆**分 L1 原始轨迹、L2 表层摘要、L3 综合认知三层，并用记忆图谱把 L3 结论链接回 L1 证据，让个性化过程可见、可改；还能在对话中直接调用 Claude Code、Codex、Grok CLI 等外部 Agent。安装方式颇具时代特色——除 pip / Docker 外，README 首推「把这段提示词复制给你的编码 Agent，让它帮你装」，并专门准备了 `AGENT_SETUP.md` 和 `SKILL.md`，Apache-2.0 许可。

💡 可借鉴的优点

- **产品思维**：不做又一个聊天答疑机器人，而是把学习闭环（读 → 问 → 练 → 测 → 复盘）放进同一个工作台，「一个运行时、多种模式」是做复杂 AI 应用的好结构。
- **架构设计**：RAG 引擎和文档解析都可插拔，不绑定单一方案；记忆分三层并保留证据链接，让个性化可解释、可编辑。
- **工程化**：「给 Agent 看的安装文档」是值得学习的新实践——面向 Agent 写清环境准备、配置和验证步骤。
- **社区运营**：清晰的里程碑公告、Roadmap 投票、多渠道运营，是学术团队把开源项目当产品运营的典型。

🌟 特别亮眼的地方

DeepTutor 把「记忆」当成一等公民并让用户看得见，L1→L2→L3 + 证据回链回答了个性化 AI 最大的信任问题：「它为什么觉得我是这样的？」对任何做长期陪伴型 AI（教育、健康、助理）的团队，这套分层记忆 + 可追溯的思路都值得直接借鉴。

📖 项目是干什么的

Lightpanda 是一个**从零写起、专为 AI Agent 和自动化设计的无头浏览器**——不是 Chromium 分支、也不是 WebKit 补丁，而是用 Zig 全新实现。官方基准显示，在 AWS EC2 上请求 933 个真实网页，它处理 100 个页面的内存峰值仅 123MB（Headless Chrome 为 2GB，约轻 16 倍），执行时间 5 秒（Chrome 46 秒，约快 9 倍）。

它通过 CDP（Chrome DevTools Protocol）和 WebDriver BiDi 对外提供服务，Puppeteer、Playwright 等现有客户端改个 `browserWSEndpoint` 就能直接接入；命令行支持把页面直接 dump 成 HTML、Markdown、PNG、PDF 或结构化数据。特别值得关注的是 **Agent 模式**：用自然语言驱动浏览器，输出产物是 PandaScript——一套内置原生浏览器原语的 JavaScript，确定性执行、运行时无需 token，可用 LLM 原型、再把脚本直接发到生产。它还内置 MCP server，支持多会话隔离，技术栈为 Zig 0.17 + V8 引擎 + Libcurl + html5ever，并用 Web Platform Tests 标准化测试套件持续验证兼容性，AGPL-3.0 许可。

💡 可借鉴的优点

- **架构设计**：砍掉图形渲染引擎、只保留自动化所需的最小内核，用「做减法」换取数量级的性能优势，是面向特定场景重构基础设施的好范例。
- **协议兼容**：不发明私有接口，而是兼容 CDP 和 WebDriver BiDi，让存量 Puppeteer/Playwright 生态零成本迁移。
- **工程化**：用标准化的 Web Platform Tests 做兼容性验证并每日发布结果，让「支持哪些 Web 能力」完全透明、可量化。
- **成本意识**：Agent 模式把 LLM 产出固化成无 token 的确定性脚本，直击「Agent 每跑一次都要花钱」的痛点。

🌟 特别亮眼的地方

Lightpanda 代表了一个重要趋势：**当浏览器的主要使用者从「人」变成「Agent」，为人类设计的重型浏览器就不再是最优解。** 它和 #5 一样强调确定性与可复现，单日近千星说明市场对「轻量、快速、可脚本化」的 Agent 基础设施有真实而强烈的需求。

技能围绕编码 Agent 的四大失败模式组织：**没对齐需求**——用 `/grill-me`、`/grill-with-docs` 让 Agent 在动手前反复盘问你；**过于啰嗦**——通过构建共享语言（GLOSSARY 术语表 + ADR）让表达更精炼；**代码不能跑**——用 `/tdd` 的红-绿-重构循环和 `/diagnosing-bugs` 调试纪律建立反馈环；**代码变成泥球**——用 `/to-spec`、`/improve-codebase-architecture` 关注模块深度。技能还按「用户调用」和「模型自动调用」两类划分职责，分发上覆盖 Claude Code、Codex、Copilot、Gemini 等官方插件市场，MIT 许可，仓库已达 30.8 万 star。

📖 项目是干什么的

这个模板能把一个 Claude Code 会话变成一整个**游戏开发工作室**：包含 49 个专业 Agent、74 个工作流技能、15 个钩子、14 条路径作用域规则和 62 个文档模板。它要解决的问题是——单人用 AI 做游戏时，单个聊天会话没有任何结构：没人阻止你硬编码魔法数字、跳过设计文档、写意大利面式代码，也没有 QA 和设计评审。

它的核心是**复刻真实工作室的三层层级**：Tier 1 总监（创意总监、技术总监、制作人）、Tier 2 部门负责人（游戏设计、主程、美术、音频、叙事、QA 等）、Tier 3 一线专家（玩法/引擎/AI/网络程序员、关卡/系统/数值设计师、技术美术、音效、编剧、测试、本地化等），并为 Godot、Unity、Unreal 三大引擎各配了专家集。每个 Agent 在 frontmatter 里声明模型，仅三个总监要求 Opus、部分专家用 Sonnet，其余 30 个继承当前会话模型。配置集中在 `project.yaml`，其中 `modes.rigor`（minimal/standard/full）一个开关控制流程重量；仓库还做了一个很诚实的实验——用数据证明更重的流程买到的是可追溯性而非更好的游戏，因此默认采用 minimal。模板附带完整的钩子安全机制、路径作用域编码规范和针对技能自身的测试框架，通过 `/start` 引导上手。

💡 可借鉴的优点

- **架构设计**：用真实组织的层级（垂直委派 + 同级协商 + 冲突上报 + 变更传播）设计多 Agent 协作，每个角色职责、升级路径和质量门都明确。
- **工程化**：钩子在提交、推送、资源变更等环节自动校验，路径作用域规则按文件位置强制编码标准，把规范自动化而非靠自觉。
- **产品思维**：用 rigor 单开关收敛六个底层配置，并提供系统级覆盖和个人本地覆盖，兼顾团队统一与个人灵活。
- **坦诚的实证文化**：主动用实验暴露「重流程不等于好结果」，并据此设置默认值，而非一味堆功能。

🌟 特别亮眼的地方

它把「**一个人 + 一套 Agent = 一家工作室**」的想象落到了可操作的模板层面，而且难得地保持了克制——默认 minimal、强调「跑起来看一眼」比文档数量重要。对任何想把复杂团队协作流程封装成 Agent 模板的人，这个仓库的层级设计、钩子机制和 rigor 配置都极具参考价值。

## 📊 今日趋势洞察

**核心方向：Agent 竞争从「模型层」上移到「组织层」——工具本身开始被工具化管理。**

今天的 10 个项目可以归成四条线：

- **管理与编排**：t3code（#4，控制面板）、Orkas（#6，Commander 团队）、OpenMausBot（#3，聊天软件式多 Bot），加上做记忆的 claude-mem（#1），共同构成「Agent 之上的组织层」。
- **技能与纪律**：impeccable（#2，设计品味）、mattpocock/skills（#9，工程基本功）、Game Studios（#10，工作室层级），把专业能力固化成可复用、可自动执行的规范。
- **Agent 专用基础设施**：lightpanda（#8）为 Agent 从零重写无头浏览器，用确定性脚本和数量级性能降低自动化成本。
- **应用与文化**：DeepTutor（#7，终身学习）和紫微斗数（#5，传统文化 + 工程化），在 AI 浪潮之外验证了确定性与可验证的价值。

**升温领域：**
1. **Agent 控制层 / 控制面板**——当开发者手头的 Agent 越来越多，统一入口、跨端远程、权限裁决成为刚需，正在形成独立品类，连 T3 等知名团队都已入场。
2. **跨会话记忆**——从插件功能演变为独立基础设施，分层压缩、可见可查、可移植是共同方向。
3. **Agent 原生基础设施**——为 Agent 而非人类重造浏览器、运行时和脚本，确定性、无 token、可复现是核心卖点。
4. **技能工程化**——技能不再是一次性提示词，而是带测试、CI、版本管理和分发渠道的软件资产。

**对开发者的启发：**
- 不必都去做模型或新 Agent：Agent 碎片化之后，编排、记忆、权限、可观测这些「管理层」环节都有独立机会。
- 把团队的专业流程和工程纪律固化成带测试的技能/模板，比单次提示词更有复用价值和分发潜力。
- 重视「确定性」：在生成式泛滥的时代，可复现、可审计、零 token 的脚本和数据，反而能建立信任、形成差异化。
- 保持克制：流程和文档是手段不是目的，真正的衡量标准是东西能不能跑、结果对不对，重流程应按需开启而非默认拉满。
