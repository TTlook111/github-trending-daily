📖 项目是干什么的

Claude-BugHunter 是一套只面向**授权范围内**外部安全测试的 Claude Code 技能包：84 个技能、15 个斜杠命令，外加一个确定性的“交战引擎”（`engine/`）和配套的 `cbh` 命令行。技能的构成是 58 个按漏洞类别拆分的 hunt 技能、10 个企业身份与平台侧的技能、7 个报告与验证技能、5 个侦察与 OSINT 技能、4 个方法论技能；知识底座是从 681 份公开披露报告里整理出的模式库，覆盖 24 类核心漏洞，其中 433 条逐条标注了出处。README 把“不做什么”写得和“做什么”一样清楚：内网域渗透、C2、后渗透与持久化、规避检测、二进制利用统统列为范围之外，并注明“这是设计决定，不是缺口”。

它的流程是侦察 → 映射与排序 → 狩猎 → 验证 → 报告，范围校验写在代码里，任何东西在提交之前都要过一道“七问关卡”。昨天上午到傍晚合入的四笔提交，有三笔都在加固“验证”这一环。#228 给引擎加了一个不依赖大模型的取证模块：对候选发现只重放一次只读的 GET 请求，把真实的请求响应（状态码、脱敏后的响应头、截断的正文片段）存下来，再给它打一个“已佐证 / 未佐证 / 不适用”的标签。提交说明里特意写明“这是证据，不是闸门”——它不改变严重级别，也不改变哪些发现算已确认；XSS 只会被标成“反射且未编码”，不会写成“XSS 已确认”。#229 新增了一个叫 exploit-completion 的技能（技能数由此从 83 变成 84），针对的是“漏洞找到了、payload 也对，但证明差最后一步就放弃”的情况：跟着每一次重定向走到底、把响应和事先写明的预期结果逐项对比、连续几次同样的失败就换思路。

#230 是一笔治理性的修复。引擎的“自动驾驶账本”过去每次运行都会把带主机名和 URL 的发现写进共享目录，而读取这部分记忆的开关却是默认关闭的——写是默认开、读是默认关，结果就是能识别目标的信息默认被留了下来。修复之后，写入同样要显式开启；新加的 `--use-metrics` 只存泛化的计数（尝试次数、成功次数、成本，按技术栈特征和漏洞类别聚合），采用“白名单不通过就拒绝”的策略，主机、URL、payload、响应体一概不落盘。提交说明里附了测试结果：引擎 103 项、测试 129 项全部通过。仓库本身的状态有点特别：最新的 GitHub Release 仍是 6 月的 v2.1，主分支却连着合并了四笔带 PR 号的提交，其中昨天傍晚的那一笔把 GitHub Pages 首页换成了终端操作台风格——带数字滚动动画的统计面板（84 / 58 / 681 / 15 / 5）和一段自动打字的狩猎会话演示。

💡 可借鉴的优点

- **产品思维**：把“证明”当成独立的一道工序。多数安全流程只区分“发现 / 未发现”，它把“发现了但没证明完”单独做成一个技能，因为这才是赏金猎人最常见的损失点。
- **架构设计**：证据采集是纯函数、不让大模型参与——“确定性”在这里不是为了性能，而是为了可复现、可审计；标签与闸门分离，新增的佐证信息不会悄悄改变原有判定。
- **工程化**：隐私默认值按“对称”来修——读要授权，写也要授权；指标存储用白名单做失败关闭；新增模块都带独立测试（取证 14 例、指标 8 例、写入闸门 4 例）。
- **社区运营**：README 连“模型为什么中途换成了别的版本”都单独写了一节，按“审计自己的代码 / 授权的攻击性工作 / 只想关掉切换”三种情况分别给出处理办法；对 Anthropic 运行时的安全防护也不回避，直接建议做授权工作的人去申请官方的网络安全验证计划。

🌟 特别亮眼的地方

昨天说它代表“技能学会拦住提交”，这三笔提交给出了更有意思的一层：**拦住别人之前，先管住自己的确定性。** 证据由代码生成，结论仍由模型和人来下；数据默认不留，要留就只留无法反推目标的计数。这是一个安全工具对“我自己会不会成为风险源”的回答。对不做安全的读者，方法同样成立——把“证据”和“判断”拆成两个模块，中间只留一个只读接口，是让 Agent 的产出能被别人复核的最省力的办法。

📖 项目是干什么的

Ghost Downloader 是一个跨平台下载器，口号是“The only downloader you need / 下载器的集大成者”。HTTP、磁力 / BT、FTP、M3U8、MPEG-DASH、eD2k 六类协议收在一个应用里；YouTube 与 Bilibili 支持分 P、任意清晰度和字幕；配上浏览器扩展可以嗅探页面媒体，点一下由桌面端接管，登录态一并带过去。项目 2023 年 8 月建仓，GPL-3.0 协议，1,067 个 fork，今天 +1,092，连续第二天排在第二。**v4.6 是今天下午 4 点发布的**，距上一个版本 v4.5.11 只隔了五天。

v4.6 的新功能都很“日常”：新增“记住上次使用的下载目录”的选项，给计划任务加了一个“退出程序”的动作，Android 支持增量更新，Linux 支持应用内更新（AppImage 除外）并新增一条命令的安装脚本，新增越南语。优化项是启动更快、内存占用更低、Windows 下文件列表滚动更顺；修复包括主窗口收进托盘后计划任务触发报错、断网时检查更新一直卡住、Windows 下超长路径删除任务后残留文件夹。发版说明的开头还有一句不太像更新日志的话：作者写明“由于本人学业原因，更新节奏有所放缓”。

更新放缓不等于功能停摆。v4.6 的发版说明单列了一节“功能包更新”：m3u8_pack 1.3.3 修了 fMP4 直播停止录制后无法保存等五个问题，bittorrent_pack 1.4.2 新增“只下载 .torrent 文件”的开关，yt_dlp_pack 1.4.2 和 bili_pack 1.4.3 各修了一个解析问题，并注明“这些更新可能已经通过自动更新提前推送”。也就是说，协议支持被拆成了可以独立热更新的包，应用本体不发版，站点解析规则也能跟上。它的底子是 Python + PySide6 + PyQt-Fluent-Widgets，网络层跑在 asyncio 上（uvloop / winloop），HTTP 客户端是带 TLS 指纹模拟的 wreq，BT 交给 libtorrent，M3U8 交给 N_m3u8DL-RE，FTP 用 aioftp，最后由 Nuitka 编译分发。

💡 可借鉴的优点

- **产品思维**：更新日志写给用户看，不写给版本号看——每一条都是用户能感知的场景（“下载到一半想换目录”“断网时检查更新卡住”），并且如实说明节奏变化。
- **架构设计**：把“变得快的部分”（站点规则、协议细节）做成功能包，与“变得慢的部分”（界面、调度）解耦；功能包系统已经可用，Roadmap 上老实写着“插件 API 尚未公开、还在稳定”。
- **工程化**：译文在 Crowdin 上管理，源语言是简体中文，新语种翻译到桌面文本的 60% 才会进入应用，这次新增越南语这一条的署名就是 GitHub Actions 机器人；README 顶部明确要求不要提修改翻译文件的 PR。
- **社区运营**：QQ 群与 Discord 双通道，Arch Linux 有社区维护的 AUR 包；README 顶部挂了赞助商位，发版说明里附了捐赠入口——一个学生项目的持续运营有了明确的经济来源。

🌟 特别亮眼的地方

一个 2023 年的下载器，在作者说明更新放缓之后，今天靠一次 v4.6 拿到 +1,092，排名纹丝不动。值得记的是它对“更新”的拆法：**应用发版是重操作，功能包更新是轻操作**——把重的那部分留给一年几次的里程碑，把轻的那部分留给每周都在变的站点规则。AutoClip 今天的模板目录走的是同一条路。对任何需要“经常变一点”的桌面软件，这都是比“求用户勤升级”更现实的设计。

📖 项目是干什么的

CLI-Anything 来自香港大学数据智能实验室（HKUDS），一句话概括是“让所有软件对 Agent 原生”。它解决的问题是：绝大多数专业软件——CAD、3D、剪辑、GIS、笔记、办公——只有图形界面，Agent 只能靠截图和点击去操作，慢、贵且不稳定。它的做法是给软件生成命令行：一条命令，把任意软件变成 Agent 可调用的工具，并附带一份让 Agent 知道何时调用的 SKILL.md。项目今年 3 月 8 日建仓，Apache-2.0 协议，5,935 个 fork，今天 +1,074，从昨天的第 8 升到第 3。README 的 News 栏记录了它长成的生态：FreeCAD（258 条命令、17 个分组）、QGIS、Blender、Krita、MuseScore、Godot、Kdenlive、Zotero、Obsidian、Calibre、Rekordbox、n8n、Dify 等几十个 harness；方法论固化成 HARNESS.md 的七个阶段，从代码库分析、架构设计、实现、测试到文档、SKILL.md 生成、PyPI 发布，详细指南放在 `guides/` 里按需加载。

配套的是 CLI-Hub：`pip install cli-anything-hub` 之后可以浏览、安装、更新和卸载这些 harness，v0.2.0 起也收录来自 pip、npm、brew 与系统自带的公共 CLI；还有一个 meta-skill，让 Agent 自己发现并安装需要的 CLI。所有 SKILL.md 统一放在顶层 `skills/` 目录，可以单独安装其中一个：`npx skills add HKUDS/CLI-Anything --skill <名字>`。质量上，README 徽章标着 pytest 100% 通过、覆盖单元与端到端测试；News 栏里记着几处安全处理——不可信的 XML / SVG / ODF 等输入统一走 `defusedxml`，Sketch CLI 的 token 文件处理加固了路径穿越与符号链接逃逸，Rekordbox 的强制写入路径要求先备份。

今天它冲到第三，仓库的表面却是“静止”的：默认分支最近一次提交停在 9 月 22 日，README 的 News 栏最新一条是 5 月 30 日，最新的 GitHub Release 是 6 月 25 日的 v0.4.0。抓取时往前数一小时的事件流里，40 条事件有 39 条是新 star，平均一分半钟一个。默认分支没动，仓库并没有停：分支列表里能看到 `ca-autoagent/eez-studio-…`、`codex/ollama-harness`、`feat/add-godot-cli`、`feat/add-musescore-cli` 这类工作分支。

💡 可借鉴的优点

- **产品思维**：不与“GUI Agent”比谁点得准，换一条更便宜的路——把软件能力翻译成命令行。对用户的卖点是“你的 Agent 终于会用你装的那些专业软件了”。
- **架构设计**：方法论文档（HARNESS.md）与生成器分离；产物（CLI + SKILL.md）与注册表（CLI-Hub）分离，于是“怎么造”和“造了什么”可以各自迭代。
- **工程化**：News 栏里每次合并都带 PR 号与测试数量（例如 Joplin CLI 的提案附 134 项验证基线，Obsidian CLI 是 48 项单测加 7 项端到端）；对不可信输入有一致的安全处理约定。
- **社区运营**：中 / 日 / 德三语 README，飞书与微信群；贡献者的提案（ArcGIS Pro、Obsidian Agent CLI、Joplin CLI）即便尚未合并也会进 News 栏。

🌟 特别亮眼的地方

CLI-Anything 今天给看榜的人提了个醒：**star 是关注度的账，不是活跃度的账。** 一个默认分支两个月没动的仓库照样能冲到第三，对技能包这类项目来说并不矛盾——产品是装进 Agent 里的那份技能，仓库更像货架，路过的人多了，star 就涨。所以评估一个技能仓库时，README 的 News 栏、最近提交、release 时间比星数诚实得多。反过来对维护者也是提醒：两个月不更新 News，新来的人只能从星数判断你。

📖 项目是干什么的

Superpowers 是给编码 Agent 装上的一整套软件开发方法论：一组可组合的技能，加一段保证“Agent 真的会用它们”的启动指令。流程是七步：brainstorming → using-git-worktrees → writing-plans → subagent-driven-development 或 executing-plans → test-driven-development → requesting-code-review → finishing-a-development-branch。Agent 看到你要做东西，会先退一步问清意图；计划要细到“一个热情但没品味、没判断力、讨厌写测试的初级工程师也能照做”，每个任务 2–5 分钟。项目去年 10 月 10 日建仓，MIT 协议，28,949 个 fork，372 个 open issue，今天 +1,003——这是它连续第五期在榜（11-17、11-18 的第 1，11-19 的第 4，11-24 的第 5，今天第 4）。

第四步其实有两条路，README 把取舍写得直白：subagent-driven-development 给每个任务派一个全新的子 Agent，做完就评审，“最彻底”；executing-plans 则在当前会话里一口气执行，只在最后对整个分支做一次全新评审，“最便宜”。前者让主会话只保留决策与验收、上下文不被实现细节污染，代价是 token；后者省 token，代价是上下文变长后更容易跑偏。技能库里除了流程类，还有调试类（systematic-debugging、verification-before-completion、diagnosing-superpowers）和元技能（writing-skills、using-superpowers）。

分发宽度仍是它最大的资产：README 目录里列了 16 个 harness，从 Claude Code、Antigravity、Codex App 与 CLI、Cursor、Devin CLI、Factory Droid、Gemini CLI、GitHub Copilot CLI、Grok Build CLI、Kimi Code、OpenCode、Pi、Qwen Code 到 Hermes Agent、Muse。仓库状态则很平静：默认分支最近一次提交是 11 月 4 日的 v7.0.2，之后三周没有新提交，日增却从昨天的 +840 涨到 +1,003。

💡 可借鉴的优点

- **产品思维**：同一套方法论给出“彻底”与“便宜”两种执行档位，让用户按任务重要性选，而不是替所有人决定。
- **架构设计**：子 Agent 隔离加每任务评审，是“长时间自主运行不跑偏”的结构性保障；技能在 16 个 harness 上复用，差异全部收在安装层。
- **工程化**：技能行为用独立的评测框架测（`evals/` 里的 drill 评测），插件基础设施另有测试；对“失效模式”有专门的诊断技能，读会话记录给出逐行证据。
- **社区运营**：明确不接受“Agent 代写、修别人 issue”的 PR；遥测默认只上报版本号且可一键关闭；README 单列了企业支持的联系方式。

🌟 特别亮眼的地方

过去两天它没有新提交。最近的三笔都在 11 月 22 日：一笔 CPU / Windows 兼容性修复（对应 issue #925），一笔新增 warmup ratio，还有一笔合并了社区贡献者关于“可选学习率预热”的 PR（#866）；11 月 23 日更新了 README。最新的 GitHub Release 仍是 2025 年 10 月的文档版本 v2，日常迭代都直接提交到 master。

💡 可借鉴的优点

- **产品思维**：把“大模型”压缩到一张游戏显卡能复现的尺度，再用“两小时 / 三块钱”翻译成任何人都能感知的数字；同时把每个数字的口径写清楚。
- **架构设计**：代码结构与主流生态对齐（Qwen3 系结构、Transformers 命名、OpenAI 接口），小模型因此可以无缝使用为大模型准备的工具链。
- **工程化**：每个训练阶段都有对应的 jsonl 数据集；rollout 引擎与训练算法解耦；这次合入的“可选学习率预热”保留了原行为，不强迫所有用户改超参。
- **社区运营**：SwanLab 替代 WandB 的理由写得很实在——国内访问友好、API 完全兼容；更新日志不回避代价，比如为了兼容 llama.cpp 和 vllm 需要付出“一些可观的代价”。

🌟 特别亮眼的地方

在一个每天都有新框架的领域里，minimind 今天 +727 靠的不是新东西，而是“把最新的东西做小”：业界在讨论 Agentic RL，它就有一个 64M 模型上也跑得通、每一行都看得懂的版本。两天没有提交、排名下滑三位，对它来说不算坏消息——**教程类项目的价值不随提交频率衰减**，它更像一本书，而不是一个服务。想真正理解“预训练 → SFT → RL”的人，需要的不是更强的模型，而是一段自己亲手跑过的日志。

v4.6.0 里最值得展开的是“本地研究库”：技能可以在一轮对话结束后静默捕获生成的简报，原子写入 `<save_dir>/finished/`，按内容哈希去重，文件权限仅限本人，再用 `library.db` 做增量索引；之后 `library search` 和 `library feed` 会优先命中这些历史简报，`library harvest` 还能从离线对话记录里回补。同一个版本里，TikTok 的热评改走公开网页接口，不需要 key，一次 “Kanye West” 的检索里 Top Community Comments 的 TikTok 条目从 4 条增加到 14 条。今天凌晨还合并了四笔社区修复，上一期没来得及写：Reddit 的网页发现尊重 SearXNG 配置、配置了服务商 key 时仍尊重显式的本地推理设置、Truth Social 帖子文本的 HTML 实体解码，以及打分环节的“单调性、激活下限、平局救援与 URL 去重”。这四笔合入之后，主分支只多了一次 star 历史图的自动更新。

## 📊 今日趋势洞察

**核心方向：榜面没换人，叙事往前走了一格——从“会拦”到“拦得讲道理”。**

十个项目和昨天完全相同，按“过去一天做了什么”可以分成三组。**交付组**有三个：Ghost-Downloader-3 的 v4.6、AutoClip 的 v1.6.1 与模板目录、diagram-design 的三次版本递增，共同点是都把“会变的部分”拆成了可以独立更新的包——功能包、模板目录、按合并自动递增的插件版本。**守门组**有两个：Claude-BugHunter 的证据与数据隔离、app-store-compliance 的安装器修复，共同点是给“拦截”补上了可解释与不破坏。**静默组**有三个：CLI-Anything、superpowers、minimind 的默认分支在 24 小时内没有新提交（前两者分别停了两个月和三周），star 却照涨。剩下两个属于日常维护：firecrawl 在补可观测性，last30days 合并了四笔社区修复。

**升温领域：热更新层、可解释的拦截、“看不见的质量”进 CI。**

四个信号值得记住。其一，**“不发版也能上新”同时出现在两个不相干的项目里**：Ghost-Downloader-3 的功能包、AutoClip 的模板目录与动态服务商配置，前者是下载器，后者是视频剪辑工具，做法却一样——应用本体求稳，云端目录求新。其二，**拦截开始讲道理**：app-store-compliance 让守门脚本点名触发的字符串，Claude-BugHunter 把证据和结论拆开，superpowers 的评审按严重度分级——三个项目的对象分别是应用、漏洞和代码，方向一致。其三，**日增过千的从两个变成四个**，前十合计 +10,126，榜面的“腰部”在变厚。其四，**过去靠人盯的质量，正在变成 CI 闸门**：diagram-design 把 WCAG 对比度检查加进 CI，firecrawl 给每次抓取引擎的尝试打 trace，app-store-compliance 今天合并了无障碍检查的修复。

**对开发者的三点启发。**

第一，**把“会变的部分”从版本号里拆出去**。问自己一个问题：我的产品里哪一部分每周都在变？它真的需要跟着应用一起发版吗？Ghost-Downloader-3 和 AutoClip 今天的答案都是“不需要”。第二，**拦截要带原因，失败要发出声音**。守门类工具最容易被弃用的原因不是误判，而是误判了还说不清——点名触发的那条字符串、不合法就明确失败，成本很低，决定的是别人愿不愿意把它留在流程里。第三，**看技能类仓库，先看 News 栏和提交记录，再看星数**。今天第 3、第 4 名的默认分支分别两个月、三周没有新提交；star 衡量的是关注，不是维护。装之前多花十秒，能省掉装完才发现早已无人维护的麻烦。
