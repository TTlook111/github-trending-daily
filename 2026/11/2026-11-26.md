📖 项目是干什么的

Claude-BugHunter 是一套只面向**授权范围内**外部安全测试的 Claude Code 技能包，今天已经是连续第三天排在第一。规模比昨天大了一号：85 个技能、16 个斜杠命令，知识底座仍是从 681 份公开披露报告里整理出的模式库（覆盖 24 类核心漏洞，其中 433 条逐条标注了出处）。技能分五类：58 个按漏洞类别拆分的 hunt 技能、10 个企业身份与平台侧的技能、7 个报告与验证技能、5 个侦察与 OSINT 技能，以及方法论类——这一类从 4 个变成了 5 个，多出来的那个叫 regression-hunting。仓库今年 5 月建仓，MIT 协议，2,418 个 fork。

regression-hunting 是今天早上 7 点半合入的（#239，由社区贡献者提交）：一句话概括，**复测一个目标时只看“和上次比变了什么”**。它的引擎是 `engine/diff.py`，一个纯函数模块，输入是两次侦察生成的清单，输出五类差异——新出现的资产、新进入排序的攻击面、技术栈漂移、状态码翻转、新标记出的密钥；不发请求，也不让大模型下判断。命令是 `cbh diff <目标>`，结果写进 `recon/<目标>/REGRESSION.md`，并把这次的快照推进为新的基线；配套的 `/diff` 斜杠命令带一份分级建议——密钥优先，其次是状态码翻转。提交说明里给了定位：适合范围持续开放的赏金项目，不必每次把已经清理过的面重读一遍。这个模块自带 11 项单测。

同一个早上，作者还合入了五笔修复，几乎都在处理“守门工具自己的问题”。最要紧的一笔（#247）修的是范围校验里的一个绕过：校验用的 URL 解析器和真正发请求的 HTTP 客户端，对主机名里某个字符的理解不一致，结果是一个范围外的地址能通过范围检查。两处问题都由外部研究者通过负责任披露私下报告，作者没有运行对方给的复现代码，而是在本地独立复现后修复。修法是“失败关闭”：主机名里出现反斜杠、空格或控制字符，一律不放进范围。同一笔提交还补上了证据留存里的脱敏缺口——此前只遮了访问密钥的 ID，密钥本体和会话令牌会留在本地状态文件里。另外几笔分别是：把国际化域名统一成 punycode 比较（一个 Unicode 主机名和它的另一种写法此前被当成两个主机）；范围导入时，被排除的一侧不再静默丢弃；给 Agent 发放范围清单时附带解释；以及首页在禁用 JavaScript 时几乎空白的问题。范围修复那一笔附的测试结果是引擎 123 项、其余 132 项全部通过。

💡 可借鉴的优点

- **产品思维**：把“复测”当成独立场景。赏金项目大多是持续开放的，第二次、第十次来的成本比第一次更高——它没有让模型重新读一遍，而是先算差集。
- **架构设计**：diff 引擎和狩猎引擎一样坚持“纯函数、无网络、无大模型”：差异由代码算，判断留给后面的分级步骤；基线快照和报告落在目标自己的目录里，不污染别处。
- **工程化**：修自己家的门也不含糊：解析差异用失败关闭兜底，而不是枚举特例；每笔修复都带独立测试文件；还给技能分发表加了自检，防止“装了却没被加载”的漂移再次发生。
- **社区运营**：一天之内回应了八位社区成员的报告：安全类问题走负责任披露并在变更日志里署名致谢，文档类贡献由作者在内部整理后合入、同样署名；外部贡献者提交的回归狩猎直接合进了主干。

🌟 特别亮眼的地方

一个安全工具连续三天坐在榜首，靠的不是“能找到更多漏洞”，而是持续回答“我凭什么可信”。今天的六笔提交里，有两类尤其值得不做安全的读者记下：一是**用自己的工具审查自己的流程**——范围校验、证据留存、技能分发，每个环节都被当成可能出错的代码去测；二是**把“拒绝”设为默认**，拿不准的主机名不进范围，被排除的目标不静默丢弃。任何要替用户做“放行 / 拦截”决定的系统，迟早都要回答同样的问题。

📖 项目是干什么的

Diagram Design 是一个“让 Agent 画出你愿意发布的图”的技能：用大白话描述需求，Agent 自己选类型、说出计划，然后写出一个自包含的 HTML 文件（内联 SVG，无外部依赖），双击就能打开，可导出 PNG 或 SVG。52 种图表类型，每种有极简浅色、极简深色、完整编辑风三个变体。仓库今年 4 月建仓，MIT 协议，4,890 个 fork，今天 +1,141，从昨天的第 8 跳到第 2，日增比昨天多了四成多。

先说一个反常的事实：**它过去一天没有任何新提交。** 默认分支最近一次提交是昨天中午 12 点 52 分的版本号更新（插件版本 2.6.179），Release 页没有版本，README 也没有更新。日增从 +802 涨到 +1,141、排名升了六位，完全不是代码推动的。README 里能看到的是使用面：声明支持任何读取 Agent Skills 的宿主，点名了 Cursor、Claude Code、Codex、Qoder、GitHub Copilot、Gemini CLI、Cline、Windsurf、Amp，以及 Zed、Warp、Roo、Kilo 等。

它的核心资产是一份写得非常具体的“品味说明书”：只用一个强调色，留给读者最先该看的一两样东西；1px 细线；不用阴影；圆角最大 10px；所有坐标、宽度、间距都能被 4 整除；三套字体各司其职（Instrument Serif 做标题与旁注、Geist 做节点名、Geist Mono 做技术标签）；目标密度 4/10。作者的出发点很朴素——给博客配图时，让模型画出来的总是千篇一律的圆角方块，要么去设计软件里磨半小时，要么干脆不配图。工程上则是按需加载：Agent 启动时只看到技能的名字和描述，请求命中后才加载 SKILL.md，再按需拉一个类型参考。生成的文件默认只在字体上发一次网络请求，改成系统字体后就完全不联网。

💡 可借鉴的优点

- **产品思维**：定位卡在“要发布的那一张”，不和图表工具比可维护性；短板也写在明处——同一个提示词两次布局可能不同、没有可以 diff 的文本、没有可以拖拽的画布。
- **架构设计**：风格指南与类型参考分离，按需加载让上下文占用与类型数量无关；默认唯一的网络请求是字体，可一键换成系统字体。
- **工程化**：版本号由合并后的自动流程统一提升（昨天一天升了三次）；CI 检查重叠、裁切和对比度；`self_check.py` 会拒绝被截断的生成文件，而不是放过残缺的那部分。
- **社区运营**：针对宿主的限制给出方案——Claude Desktop 的技能包上传有 200 个文件的上限，仓库提供了打包脚本；并明确声明官方构建只来自本仓库。

🌟 特别亮眼的地方

今天最值得想的不是它做了什么，而是它什么都没做却涨得更快。对一个七万多星、52 种类型的技能来说，仓库早就不只是代码，而是口碑的载体——每一个被 Agent 画出来的图，都是一次展示。它给出的方法也可以迁移到任何“输出质量取决于品味”的产品：**把品味写成可执行、可校验的规范**，剩下的交给传播。至于今天的排名，不必过度解读：在一个十个项目日增都过八百的榜上，第二名和第八名的差距，可能只是一天的传播波动。

📖 项目是干什么的

Firecrawl 是给 AI Agent 用的“网页数据基础设施”：同一个能力做成三种形态。**Firecrawl Local** 是一个 Rust 写的单文件，`cargo install firecrawl-local` 装完就能抓取、爬站、列 URL，不需要数据库、队列和容器。**Firecrawl Cloud** 在此之上加搜索、结构化输出以及 Alexandria——550 多家数据提供方（2.5 亿多人、7,500 多万家公司、4,100 多万篇论文）通过一个 API / MCP / CLI 接入，官方给的覆盖是 96% 的网页。**自托管**是带队列、worker 和数据库的完整 API 服务。仓库 2024 年 4 月建仓，AGPL-3.0 协议，11,020 个 fork，今天 +1,135，从昨天的第 5 回到第 3。

过去 24 小时它合入了 8 笔提交，除一笔 SDK 包描述外全在 `api` 模块，主线是三件事。**重构**：一笔提交写明“完成模块化的服务架构”，把 API 服务拆成更清晰的服务层，并清理环境变量。**可观测**：Webhook 日志不再打印整份配置，只记录目标主机和事件；随后又给爬取状态单独配了一个 Redis 存储。**失败方式**：后一笔提交的标题里有一个很直白的词——“loud handling of missing crawl state”（丢失的爬取状态要响亮地处理），并补了“任务结束时存储里的爬取记录已不存在”的测试用例；API 密钥增加了可选的过期时间，过期后以独立的 `key_expired` 原因拒绝；PDF 预取的临时文件只有在新下载了一份副本时才删除，读取失败时保留调用方自己传进来的那份。

Release 页也在变：今天凌晨到上午连发了七个版本（v2.11.865 到 v2.11.871），其中后三个的说明都只有一句“Release API image”——API 镜像在跟着主干滚动发布。Local 这一层的细节保持不变：`init` 自动发现 Claude Code、Claude Desktop、Cursor、Windsurf、Gemini CLI、Codex 并把自己注册成 MCP 服务；`serve` 在本机 3002 端口提供与云端 v2 API 兼容的接口；单页抓取在本地打不开时默认转给云端并在结果里标注来源。

💡 可借鉴的优点

- **产品思维**：三档形态分别对应“想马上试”“不想运维”“数据不能出门”；Local 不是阉割版，抓取、爬站、Map 都在本机，还能关掉云端回退。
- **架构设计**：本地与云端共用同一套 v2 API 契约；爬取状态从通用存储里拆出来单独管理，丢状态时宁可让任务明确失败，也不悄悄继续。
- **工程化**：日志最小化（Webhook 只记主机和事件）、鉴权有过期与独立的拒绝原因、临时文件的归属写清楚；API 镜像跟随主干滚动发版，今天上午就连发了七版。
- **社区运营**：Keyless 模式每月送 1,000 个额度，不需要注册；有一份 Agent 可以自己读取的 `agent-onboarding/SKILL.md`；今天还统一更新了各语言 SDK 的包描述。

🌟 特别亮眼的地方

Firecrawl 是榜上“最不新”的项目之一，却始终没有掉队，今天靠八笔维护性提交回到第三。它今天做的事情里最值得借鉴的是那句提交标题：**丢失的状态要“响亮地”处理。** 分布式系统里最难查的问题，从来不是报错，而是状态没了、任务还在跑。把“找不到记录”变成一次明确的失败，比多加十次重试更有价值。

📖 项目是干什么的

CLI-Anything 来自香港大学数据智能实验室（HKUDS），一句话概括是“让所有软件对 Agent 原生”。绝大多数专业软件只有图形界面，Agent 只能靠截图和点击去操作；它的做法是给软件生成命令行，并附带一份让 Agent 知道何时调用的 SKILL.md。仓库今年 3 月建仓，Apache-2.0 协议，6,002 个 fork，今天 +1,106，排在第 4。README 的 News 栏记录了它长成的生态：FreeCAD（258 条命令、17 个分组）、QGIS、Blender、Krita、MuseScore、Godot、Zotero、Obsidian、Calibre、Rekordbox、n8n、Dify 等几十个 harness；方法论固化成 HARNESS.md 的七个阶段，从代码库分析、架构设计、实现、测试到文档、SKILL.md 生成、PyPI 发布。配套的 CLI-Hub（`pip install cli-anything-hub`）负责浏览、安装、更新和卸载，所有技能统一放在顶层 `skills/` 目录，可以单独安装其中一个。

它的仓库表面是“静止”的：默认分支最近一次提交停在 9 月 22 日，README 的 News 栏最新一条是 5 月 30 日，最新的 GitHub Release 是 6 月 25 日的 v0.4.0。但名次三期都没掉出前列——11-24 第 8，11-25 第 3，今天第 4；日增从 +790、+1,074 到 +1,106，一期比一期高。

从已有信息看，它的工程质量在同类“生成器”项目里比较扎实：README 徽章标着 pytest 100% 通过、覆盖单元与端到端测试；News 栏里每次合并都带 PR 号与测试数量（例如 Obsidian CLI 是 48 项单测加 7 项端到端）；不可信的 XML / SVG / ODF 等输入统一走 `defusedxml`。

💡 可借鉴的优点

- **产品思维**：不与“GUI Agent”比谁点得准，换一条更便宜的路——把软件能力翻译成命令行；对用户的卖点是“你的 Agent 终于会用你装的那些专业软件了”。
- **架构设计**：方法论文档（HARNESS.md）与生成器分离；产物（CLI + SKILL.md）与注册表（CLI-Hub）分离，“怎么造”和“造了什么”可以各自迭代。
- **工程化**：七个阶段里测试与文档是硬性环节，详细指南按需加载；每次合并都公开测试数量；对不可信输入有一致的安全处理约定。
- **社区运营**：中 / 日 / 德三语 README；贡献者的提案即便尚未合并也会进 News 栏。

🌟 特别亮眼的地方

一个默认分支两个月没动的仓库，连续三期留在榜上，今天还日增过千。它已经是老话题了，但今天恰好提供了一个对照：同一张榜上，提交最多的项目在降温，它一行没改却在涨。对技能类项目来说这并不矛盾——产品是装进 Agent 里的那份技能，仓库更像货架。所以它的风险也不在热度，而在别处：News 栏停在 5 月，新来的人只能从星数判断它还在不在维护。**热度可以靠口碑续命，信任却需要更新记录来续。**

- **产品思维**：把“大模型”压缩到一张游戏显卡能复现的尺度，再用“两小时 / 三块钱”翻译成任何人都能感知的数字，并把每个数字的口径写清楚。
- **架构设计**：代码结构与主流生态对齐（Qwen3 系结构、Transformers 命名、OpenAI 接口），小模型可以直接用为大模型准备的工具链。
- **工程化**：每个训练阶段都有对应的数据集；训练支持单机多卡、断点续训和 wandb / SwanLab 可视化；可选的预热功能保留默认行为，不强迫所有用户改超参。
- **社区运营**：功能可以由贡献者起头、作者接力：预热从社区提议、合并到作者补充，再到另一位贡献者修正计数口径，前后有三位参与者；更新日志不回避代价。

🌟 特别亮眼的地方

一个三行的修复，值得写进日报吗？值得——因为它正好落在“教程类项目”最要紧的地方。教程的价值在于“照着跑能对上”，而一个让第一步学习率翻倍的差一错误，不会报错，只会让照着跑的人得到一条略有不同的损失曲线，然后怀疑是自己环境的问题。**能被社区发现并修掉的“小错”，恰恰是这份教程还活着的证据。** 它今天日增不降反升，排在第十位只是因为榜上的人都在涨。

## 📊 今日趋势洞察

**核心方向：原班人马第三天——坏也要坏得明白。**

十个项目连续三期没有换人，今天按“过去 24 小时做了什么”正好对半分。**有新提交的六个**：Claude-BugHunter（6 笔）、firecrawl（8 笔）、Ghost-Downloader-3（2 笔）、last30days（5 笔）、app-store-compliance（11 笔）、minimind（1 个修复）；**没有新提交的四个**：diagram-design、CLI-Anything、superpowers、AutoClip。把这份名单和“比昨天涨得更快”的名单放在一起，看不出任何关系：涨得更快的五个里有两个今天零提交，回落的五个里却包含全榜提交最多的两个项目（app-store-compliance 11 笔、Claude-BugHunter 6 笔）。

**升温领域：诚实的失败、承诺兼容的规则、被认真对待的“路由层”。**

三个信号。其一，**“失败要响、要有界、要诚实”成了跨项目的共识**：firecrawl 的提交标题写的是“丢失的爬取状态要响亮地处理”，app-store-compliance 把版本说明的一节直接命名为 “Honest failures”，Claude-BugHunter 对拿不准的主机名一律拒绝，last30days 给卡住的规划步骤加了上限。它们分属四个不同的领域，处理的是同一类问题——最危险的不是出错，而是出了错还没人知道。其二，**守门工具开始承诺兼容**：app-store-compliance 的补丁版本写明“在 2.5.1 下能通过的，没有任何一项会开始被拦”，规则变严只发生在声明过的版本里。其三，**“装了却没生效”这种无声的失效开始被测试覆盖**：last30days 为 60 个字符的技能描述路由配了一百多行测试，Claude-BugHunter 给技能分发表加了自检——两个项目修的都是“技能存在，但该出场时沉默”。

**对开发者的三点启发。**

第一，**把“找不到”当成一种要报告的结果**。状态丢了就明确失败，来源卡住就限时退回，检查做不了就说“没检查”——都比静默继续更省排查时间。第二，**规则引擎的补丁版本，要敢于承诺“不新增拦截”**。做不到这句话的改动，应该放进一个大版本、提前告知，而不是混在修复里。第三，**别用“今天提交了多少”解释热度，也别用热度解释健康度**。今天零提交的项目冲到了第二，一天合入 11 笔的项目反而在降温；评估一个仓库，发版说明、变更日志和 News 栏的最近更新，比 star 诚实得多。
