📖 项目是干什么的

Sherlock 是一个 2018 年诞生、至今活跃维护的开源情报（OSINT）工具，做的事一句话讲清：**给定一个用户名，在 400+ 社交网络上搜索同名账号是否存在**。它逐个请求各站点的用户主页，根据返回状态判断账号是否被注册，把找到的账号连同链接汇总到文本、CSV、XLSX 或 JSON 文件，是安全研究、品牌保护和个人足迹排查的常用工具。

今天它以 2,373 的单日新增登顶，总星数突破 10 万。工程上它已迭代到 0.16.0，默认分支为 master，安装方式覆盖 pipx、uv、Docker、dnf 及多个社区维护的系统包，并对失效的第三方包主动在 README 给出警告；命令行支持多用户名、代理、超时、站点限定、NSFW 过滤、本地 `data.json` 离线运行等。站点清单本身是一个可独立更新的 JSON，这让它能持续跟上社交网站的变化。

💡 可借鉴的优点

- **架构设计**：把「站点规则」与「检测逻辑」解耦——站点清单是数据文件、核心引擎只读数据，新增站点无需改代码，是规则引擎的经典结构。
- **工程化**：多渠道安装 + 对失效分发包显式预警，文档对兼容性极其诚实。
- **产品思维**：一个极窄需求（查同名账号）做深做透、覆盖 400+ 站点，靠近八年长期维护积累起 10 万 star。
- **可扩展性**：支持 `--json` 加载自定义站点清单，让工具能被二次集成而非只能命令行使用。

🌟 特别亮眼的地方

连续多日在榜且今日登顶，说明**成熟、可靠、可脚本化的基础工具正在被 Agent 浪潮持续重新估价**。它的数据驱动站点清单设计，今天依然是做「可插拔规则平台」的优秀范本，也正是最适合被 Agent 调用的原子能力。

📖 项目是干什么的

OpenMausBot 是一个开源的「Grok Bot 替代品」，核心理念是：**「一个盒子里一个助手」对 Agent 来说是错误的形态**。Agent 应该像聊天软件里的联系人——侧边栏一排 Bot，每个都有自己的人格、记忆、模型、电脑和已连接应用，你跟它们聊天、看它们干活、在关键动作上点「批准」。

实现上它坚持「自带 Agent、本地优先」：Bot 底层跑的是你本机已安装的 claude / codex / grok CLI，沿用现有登录和订阅，中间没有代理；一个监听 127.0.0.1 的小型 harness 服务管理所有 Agent 进程，转录、密钥、事件都存在 `~/.openmausbot`。每个 Bot 可使用云端 Linux 桌面、隔离的本地 VM，或在明确开启后控制你自己的电脑；通过 Composio 连接 500+ 应用。Shell 命令、文件编辑等风险动作以内联卡片请求 Allow / Deny，由统一的「权限代理」裁决。桌面端基于 Electron，移动端用 Expo，Apache-2.0 许可，且明确声明没有发行任何代币。

💡 可借鉴的优点

- **产品思维**：用「聊天软件 + 联系人」这个所有人都熟悉的隐喻管理多个 Agent，学习成本几乎为零。
- **架构设计**：不自己接模型，而是编排用户已有的 Agent CLI——复用现有订阅，也避开了「再托管一层 API Key」的信任问题。
- **安全设计**：所有风险动作走统一权限代理并以审批卡片呈现，密钥「只写不读」，控制本机需显式开启。
- **增长打法**：README 系统化地做「X 的开源替代」对比页，精准承接搜索流量。

🌟 特别亮眼的地方

它最可借鉴的是「编排而非替代」——不跟大厂拼模型，而是站在用户已有的 CLI 之上做组织、权限和工位，把「模型、电脑、数据都在厂商那边」翻转成「都在你这边」。

📖 项目是干什么的

agent-browser 是 Vercel Labs 推出的原生 Rust CLI，给 AI Agent 一个能逐条命令驱动的浏览器。它的核心交互是**「快照 + 引用编号」**：`snapshot` 把页面读成紧凑的文本，每个可交互元素带一个类似 `@e1` 的引用；Agent 基于引用执行点击、填写，再重新读页确认结果，如此循环。浏览器在命令之间保持开启，每一步都是一次很短的 shell 调用，无需把整个页面塞进上下文。

它的工作方式是：首个命令启动后台 daemon，通过 Chrome DevTools Protocol 控制浏览器，每个 `--session` 有独立的 daemon 和浏览器，默认一小时无操作自动关闭。默认用 Chrome for Testing，也可用 `--cdp` 接入已运行的 Chrome，用 `--engine` 切换 Lightpanda、Obscura 等引擎，支持 iOS 模拟器里的 Mobile Safari 和多家云浏览器。CLI 还随版本自带匹配的技能，并提供 `mcp` 子命令启动 MCP server，Apache-2.0 许可。

💡 可借鉴的优点

- **产品思维**：用「快照引用」而不是截图或完整 DOM 与 Agent 交互，极大节省 token，且每次操作后强制重读确认，天然闭环。
- **架构设计**：daemon 常驻 + 会话隔离 + 协议解耦（CDP），兼容多种浏览器引擎和云服务。
- **工程化**：点击在元素被遮挡、禁用、不可见时会明确失败而非假成功，把「不可靠操作」显式暴露。
- **生态策略**：自带版本匹配的技能和 MCP server，让任何 Agent 宿主都能接入。

🌟 特别亮眼的地方

它代表了 Agent 浏览器自动化的务实流派：**不追求让 Agent「看懂」一张图，而是把页面结构化、把动作编号化，用最小的上下文开销换最高的确定性。**

📖 项目是干什么的

GBrain 的口号是「给你已经在用的 Agent 加一层你自己掌控的记忆」。它存储**带来源的显式事实**，支持纠正和撤回，并让同一记忆在多个 Agent 之间共享——你可以从无需密钥的记忆和关键词检索起步，按需再加语义搜索、综合回答和后台富化。软件本身 MIT 许可、可免费自托管，gbrain.io 是可选的付费托管。

它的作者是 Y Combinator 总裁兼 CEO Garry Tan，他用 GBrain 跑自己的生产 Agent：155,795 个页面、24,589 个人物、5,340 家公司、66 个自主 cron，在夜间自动摄入会议、邮件、推文、语音并整理记忆。除了关键词和语义检索，它还提供两个进阶能力：**带引用的综合层**（直接给出有出处的答案，并显式说明「大脑还不知道什么」）和**类型化知识图谱**（广度优先的关系遍历，在 BrainBench 关系题上把 R@5 从 0.6626 提升到 0.7241）。记忆可通过 `gbrain mcp expose` 经 Tailscale 暴露给远程 Agent，并对共享访问设置来源与操作授权。

💡 可借鉴的优点

- **产品思维**：记忆「带溯源、可纠正、可撤回」，把可信度和可纠错作为第一性，而非简单的向量存储。
- **架构设计**：关键词 → 语义 → 综合 → 知识图谱分层递进，用户可按需启用，避免一次性重架构。
- **工程化**：用 BrainBench 等基准量化检索效果（R@5、graph-oracle 上界），并明确区分产品分数与理论上界，口径诚实。
- **安全设计**：远程调用受来源/操作授权和可见性过滤约束，并清晰说明哪些信任边界无法仅靠来源隔离。

🌟 特别亮眼的地方

它精准踩中 Agent 的核心短板——**跨会话、跨工具的长期记忆**。当 Agent 越来越多，一个「你自己拥有、可移植、可追溯」的记忆层，价值不亚于模型本身；而「显式说明不知道什么」的缺口分析，是让记忆系统可信的关键设计。

📖 项目是干什么的

RuView 是一个 WiFi 感知平台，核心思路是：**每个 WiFi 路由器都在空间里充满无线电波，人移动、呼吸甚至静坐都会以可测量的方式扰动这些波。** 它用廉价 ESP32 传感器采集信道状态信息（CSI），把无线电信号变成可执行的空间智能——谁在房间里、在做什么、状态是否安好，全程穿墙、在黑暗中工作、无需摄像头或穿戴设备，「只靠物理」。

它能感知人员存在与计数、呼吸率和心率、动作识别（走路、坐下、手势、跌倒）、房间射频指纹、睡眠质量与呼吸暂停筛查，还能从 WiFi CSI 估计 17 个身体关键点的「无摄像头姿态」。生态上它原生接入四大智能家居体系：通过 MQTT 接入 Home Assistant，作为 HAP 桥接 Apple Home/HomePod，并经 Matter 端点支持 Google Home、Alexa、SmartThings；每个节点输出 21 个实体（11 个原始信号 + 10 个语义状态，如「老人久未活动异常」「跌倒风险升高」「会议室占用」），附带 3 个 Home Assistant 蓝图，并提供完整的 CSI 采集、模型训练、LoRA 切换工作流和预训练模型。

💡 可借鉴的优点

- **产品思维**：用隐私友好的无线感知替代摄像头，切中养老监护、跌倒检测、占用感知等真实场景，且语义状态可直接驱动家居自动化。
- **架构设计**：硬件（ESP32 节点）+ 模型 + Agent 工具链 + 家居集成分层，软硬一体但边界清晰。
- **生态策略**：一次接入同时覆盖 Home Assistant、Apple、Google、Amazon 四大生态，Matter 桥接最大化兼容面。
- **工程化**：提供从数据采集、训练到部署的完整模型工作流和预训练权重，降低复现门槛。

🌟 特别亮眼的地方

它代表了 Agent 感知的一个独特方向：**不依赖视觉，而是把环境本身变成传感器。** 当 Agent 主要还活在数字世界里，RuView 让它第一次能「穿墙感知」真实的人和空间——这正是 Agent 走向物理世界的关键一块。

📖 项目是干什么的

MuJoCo 全称 **Mu**lti-**Jo**int dynamics with **Co**ntact（带接触的多关节动力学），是由 Google DeepMind 维护的通用物理引擎，面向机器人、生物力学、图形动画、机器学习等需要快速精确仿真「铰接结构与环境相互作用」的领域。它提供 C API，运行时模块针对性能调优，操作由内置 XML 编译器预分配的底层数据结构，并支持原生桌面窗口和浏览器内的交互式可视化。

它提供 Python 绑定和 Unity 插件，文档位于 ReadTheDocs。上手路径很友好：可在浏览器里通过 WebAssembly 版 MuJoCo Studio 直接拖放自己的模型，也可下载预编译版本运行查看器，或在 Colab 上跟学入门、模型编辑、多线程 rollout、LQR 控制等系列 notebook。在强化学习和机器人策略训练中，MuJoCo 是事实上的标准仿真环境之一。

💡 可借鉴的优点

- **架构设计**：XML 模型编译器 + 预分配数据结构 + 高性能运行时，把「建模」与「求解」清晰分离。
- **产品思维**：浏览器 WebAssembly、桌面查看器、Colab notebook 多入口，让不同背景用户都能低门槛上手。
- **工程化**：GitHub Actions 持续构建、完整文档与 changelog、Python/Unity 多语言绑定，生态成熟。
- **开放策略**：DeepMind 持续维护并开放这一基础工具，实质为整个机器人和 RL 社区提供公共底座。

🌟 特别亮眼的地方

在 Agent 向物理世界延伸的今天，MuJoCo 的位置很关键：**它是「数字大脑」和「物理身体」之间的桥梁**——大量机器人 Agent 先在 MuJoCo 里学会控制，再走进真实世界。它与今天 #8 的真实感知一起，构成了「仿真 + 现实」的完整闭环。

## 📊 今日趋势洞察

**核心方向：Agent 长出记忆与感知，从纯软件能力向物理世界延伸——记忆层和物理感知成为能力新边界。**

今天的 10 个项目可归成三条线：

- **持续发酵的技能生态**：sherlock（#1）、OpenMausBot（#2）、astryx（#3）、agent-browser（#4）、anthropics/skills（#5），连续在榜，技能 + 多 Agent + 浏览器 + 设计系统已沉淀为稳定基础设施。
- **记忆与感知新能力**：gbrain（#7，跨 Agent 持久记忆）、RuView（#8，WiFi 穿墙空间感知）、mujoco（#9，物理仿真），补齐 Agent 的「记住过去」与「理解物理世界」。
- **垂直应用与上手**：daily_stock_analysis（#6，金融决策仪表盘）、claude-quickstarts（#10，官方可运行模板）。

**升温领域：**
1. **Agent 记忆层**——带溯源、可纠正、可跨 Agent 共享的持久记忆，从向量库升级为可信任的知识系统，知识图谱与综合层成为新组件。
2. **物理世界感知**——WiFi CSI、无摄像头姿态、接触式物理仿真等，让 Agent 能感知环境、理解身体、在仿真中学习控制。
3. **垂直 Agent 自动化**——「定时分析 + 多渠道推送」的决策仪表盘模式，在金融等高频刚需场景率先跑通。
4. **官方可运行模板**——厂商把最佳实践（缓存、压缩、批量调用、轨迹录制）做成 quickstart，开发者上手路径进一步标准化。

**对开发者的启发：**
- 记忆和感知是 Agent 继「技能」之后的下一片机会区，且都强调可溯源、可纠错、可信任，而非单纯堆功能。
- 软硬结合的项目（如 WiFi 感知）门槛虽高，但隐私友好、场景明确，是差异化竞争的好方向。
- 做垂直应用不必贪大，把一个高频决策做成「自动运行 + 主动推送」的闭环，价值远胜通用 Demo。
- 优先在官方 quickstart 和成熟仿真工具上构建，复用经过验证的工程模式，能少走大量弯路。
