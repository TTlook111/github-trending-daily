### #1 obra/superpowers ⭐

| 属性 | 信息 |

📖 项目是干什么的

Superpowers 卖的不是单条技能，而是一整套**给编码 Agent 装上的软件开发方法论**：一批可组合的技能，加上一段保证「Agent 真的会去加载它们」的引导指令。Agent 判断你在造东西之后不会立刻写代码，而是先退一步问你到底想解决什么；把 spec 从对话里逼出来，分段展示给你确认，每段都短到能真正读完；设计签字才进入计划环节。

计划环节的要求很硬——「一个热情但品味差、没有判断力、没有项目背景、还讨厌写测试的初级工程师也能照着做」，每个任务 2–5 分钟，写清文件路径、完整代码和验证步骤。落地时由两套模式二选一：`subagent-driven-development` 每个任务派一个新子 Agent，做完立刻两段式评审（先查是否符合 spec、再查代码质量）；`executing-plans` 则在当前会话内逐条实现，最后统一评审整个分支。今天它把工作流写成了七步：brainstorming → git worktrees → writing-plans → 子 Agent 执行 → 红绿 TDD → 代码评审 → 收尾分支。

安装面是它真正的护城河：Claude Code（官方插件市场）、Codex App / CLI、Cursor、Antigravity、Gemini CLI、GitHub Copilot CLI、Grok Build CLI、Kimi Code、OpenCode、Pi、Qwen Code、Hermes Agent、Muse、Devin CLI、Factory Droid——**16 个 harness，一套技能**。MIT 协议，作者是 Jesse Vincent 与 Prime Radiant 团队。

💡 可借鉴的优点

- **产品思维**：它不卖「能力」，卖「流程」和「否决权」。TDD 技能会删掉那些先写实现、后补测试的代码；评审技能把 Critical 问题设为硬阻断。这种「宁可慢一点，也不让烂代码进主干」的定位，恰好是 Agent 最缺的约束。
- **架构设计**：技能之间用「触发时机」串成流水线，而不是靠一张总提示词硬压；引导技能在每个会话启动时注入，压缩上下文后再注入一次。技能可组合、可单装，这比一个大而全的提示词可维护得多。
- **工程化**：技能行为用 drill eval harness（superpowers-evals）做回归测试，插件基础设施另有 `tests/` 与 `npm test`；连「会话跑歪了怎么办」都有 `diagnosing-superpowers` 去读会话记录、给出行级证据、打包脱敏报告。这是把「技能」当「有测试的代码」在维护。
- **社区运营**：明确不接受新技能投稿、只接受跨 harness 的修改，且不接受「替别人修 issue」的 Agent PR——用规则守住了质量下限；Discord、发布订阅、诊断工具构成完整的反馈闭环。

🌟 特别亮眼的地方

昨天 +822 排第 4，今天 +2,028 重新登顶，翻了一倍多，说明「流程型产品」在技能供给过剩时反而更值钱：当所有人都能写 SKILL.md，真正稀缺的是**知道什么时候该停下来问、什么时候该判不合格**。它最反直觉的一点是，整个系统里最贵的能力是「拒绝」——拒绝在需求不清时动手、拒绝在没有失败测试时写代码、拒绝让 Critical 问题过关。

📖 项目是干什么的

Claude-BugHunter 是一个面向**授权漏洞赏金与外部红队**的 Claude 技能包：README 标注 **83 条技能、15 个斜杠命令、681 条已披露报告模式**（其中 433 条单独引用、可逐条审计），覆盖 24 类核心漏洞，另附企业身份与基础设施攻击矩阵、engagement 目录脚手架、Burp MCP 集成。安装一次，Claude Code 就不再是聊天机器人，而是按资深赏金研究员的方式工作——按主题自动加载技能，不需要记名字。

它的结构是四层堆叠：Think（方法论与红队思维）、Hunt（58 条 `hunt-*` 技能，逐类给出检测模式、绕过表与链式模板）、Perimeter（M365/Entra、Okta、vCenter、SSL-VPN、SharePoint、云 IAM 的 2024–2026 CVE 链）、Ship（7-Question Gate 分诊、VRT 分级、OOS 反驳、PII 脱敏与报告交付）。同一套知识层可以装进 Claude Code、OpenCode、Codex CLI、Hermes、Google AntiGravity 五个宿主，斜杠命令与 `/hunt` 引擎保留在 Claude Code。

值得单独说的是它的「自我限制」。README 用一整节列出**故意不做**的部分——内网 AD 攻击、C2 框架、后渗透与持久化、免杀对抗、二进制与内核利用，并给出理由：这些属于不同的操作风险模型。它还明确要求授权资产、把范围问题写进校验闸门（Q3 查是否在范围内、Q2 查是否在项目接受的影响清单内）。许可证是代码 MIT + 内容 CC BY 4.0。

💡 可借鉴的优点

- **产品思维**：把「资深研究员的判断」拆成可加载的技能，而不是写成一篇长文档。用户只需要用自然语言描述在测什么，正确的技能自己会浮出来——这是技能系统相对提示词的核心优势。
- **架构设计**：四层堆叠各管一段，58 条 hunt-* 按漏洞类别而不是按工具组织；外层用一份确定性 engine 把目标面映射到技能，避免「模型随手挑一个技能」。
- **工程化**：681 条模式里有 433 条带单独引用，等于给每条知识装了出处；CVE 覆盖有周更 workflow；安装脚本同时支持 macOS/Linux 与 Windows，并把技能分发到多个 harness 的约定路径。
- **社区运营**：文档拆成 INSTALL / USAGE / architecture / cve-coverage / credits 五层，贡献指南写清技能质量标准；赞助商进 README，但不影响内容分层。

🌟 特别亮眼的地方

隔一天回到第 2，并把日增推到自身新高的 +1,349。它最值得学的不是「技能多」，而是**把合规做成了产品的一部分**：范围校验、证据卫生、可审计引用、明确的能力边界，这四件事让一个「攻击性」工具具备了被企业允许安装的理由。对任何做高风险领域 Agent 的人来说，这是一份现成的模板——先写清不做什么，再谈能做什么。

📖 项目是干什么的

last30days 是一个「由 Agent 驱动、按真人互动排序」的搜索引擎。你给它一个题目、一个人名或一家公司，它并行扫 Reddit、X、YouTube、TikTok、Instagram、Hacker News、Polymarket、GitHub、Digg、arXiv、Techmeme、LinkedIn、Meta Ads、StockTwits、Threads、Pinterest、Bluesky、Trustpilot、Amazon、专利申报、招聘页、Yahoo Finance 与本地语料，把过去 30 天真实发生的事按 upvotes、likes、播放量和真金白银的赔率排好，再由一个 Agent 裁判合成带引用的简报。

它的产品哲学写在标题里：**「Google 聚合的是编辑，last30days 搜索的是人。」** 一个 1,500 赞的 Reddit 帖，比没人读的博客更有信号；一个有真实成交量的 Polymarket 盘口，比评论员的猜测更难反驳。v4 加了两个很刁的「秘密信号」：读一家公司的美国专利申报，挑出那些「不像它会做、也没发布过」的申请；读它自己的招聘页，找出泄露了新团队或新产品的岗位。

今天的看点其实是它「让报告好引用」的一组改动：每条结论下面单独一行放原话引用（Reddit / X / YouTube / TikTok / IG，必要时翻译），一条 Polymarket 赔率行标注变动幅度，一条 Yahoo Finance 行对比标普 500 与 30 天涨跌。工程上来源是插件化的：Reddit、HN、Polymarket、GitHub 零配置即用，X、YouTube、TikTok、arXiv 首轮向导解锁，需要登录态的明确标 opt-in；`--preflight` 可以先干跑一遍看清要读什么、写什么。

💡 可借鉴的优点

- **产品思维**：用「时间窗 + 真人互动」做差异化。全网所谓「最新信息」都被编辑过滤过一遍，它直接回到原始投票现场——这是搜索类产品少有的结构性空位。
- **架构设计**：来源插件化 + 多查询扩展 + 实体解析 + 同题聚类 + Agent 裁判，五步流水线各司其职；同一件事在 Reddit、X、TikTok 出现时合并成一个故事，而不是三条链接。
- **工程化**：输出有版本化 JSON 契约，脚本与 Agent 两种消费方式都照顾到；`--store` 落 SQLite 做趋势累积，watchlist 定时跑并推 Slack / webhook，briefing 出日报周报，library feed 把历史简报变成可订阅的 Atom 源。
- **社区运营**：Claude 官方市场 + `npx skills` 覆盖 50 多个宿主，Grok Bot、ClawHub 各有入口；README 十种语言，用户原话直接放进首页当证言。

🌟 特别亮眼的地方

以 +954 稳在第三。它今天真正提供的方法论是「**让每条结论都带抓手**」：一句可核对的原话、一行可验证的赔率、一条可对比的股价。这比多接十个数据源更重要——研究报告的价值不在于长，而在于读者能顺着任意一行回去查。这也是「交付物」思路在内容类项目上的体现。

📖 项目是干什么的

CLI-Anything 的目标一句话说清：**让所有软件都对 Agent 原生可用。** 它给两条路。第一条是直接用现成的：`pip install cli-anything-hub`，然后 `cli-hub list / search / info / install / launch`，从注册表里挑一个已经做好的 CLI 装上就跑。第二条是造一个新的：装上插件后执行 `/cli-anything <软件路径>`，走一套 7 阶段 harness 生成器，把一个有源码的软件变成可安装的 Python CLI 包——从代码库分析、架构设计、实现、测试计划、测试编写到文档，全流程自动化。

它有一套叫 `HARNESS.md` 的方法论 SOP 当唯一事实源，核心原则五条：必须调用真实软件渲染，不做替代实现；每个 CLI 同时提供有状态 REPL 与子命令两种模式；统一 REPL 皮肤与输出格式；每条命令都带 `--json` 给机器读；真后端缺失时测试必须失败而不是跳过。README 里那份「关键教训」清单很值钱：渲染鸿沟（GUI 在渲染时才应用效果）、滤镜翻译（MLT → ffmpeg 的参数空间差异）、非整数帧率的时间码累积误差、以及「退出码 0 不等于导出成功」——必须验 magic bytes、容器结构、像素与音频 RMS。

项目由港大数据智能实验室（HKUDS）维护，仓库里已经有 40 多个软件的 harness（GIMP 107 个测试、Blender 208 个、Inkscape 202 个、Audacity 161 个……），徽章标注 2,461 个测试通过，另有一份 arXiv 技术报告，Apache 2.0 协议。

💡 可借鉴的优点

- **产品思维**：押注「CLI 是人和 Agent 的通用接口」，而不是再造一个 GUI 或一堆工具调用。命令行天然自带 `--help` 自描述、可组合、可管道、可脚本化——这是 Agent 最省力的入口。
- **架构设计**：软件适配层（每个软件一个 agent-harness 包）+ 统一 UX 层（repl_skin）+ 后端包装层，三层分明；同一套 SOP 既能生成新 harness，也能用 `refine` 扩覆盖、用 `validate` 查合规。
- **工程化**：「零妥协依赖」这条最硬——宁可测试红，也不让 mock 混过去；输出验证细到像素分析与音频 RMS；每个 harness 都带可安装的包与独立测试目录。
- **社区运营**：CLI-Hub 注册表 + wishlist 请求 + contributor signup + 「PR 合并即上架」的机制，把生态扩张做成了流水线；同时支持 Claude Code、Cursor、Codex、Pi、OpenCode 等多个宿主。

🌟 特别亮眼的地方

从 +389 直接翻到 +898，热度接近翻倍。它补的是技能生态里最容易被忽略的一环：**没有可执行的接口，Agent 再会规划也只能聊天。** 当别的项目在比「谁的技能写得好」，它在解决「技能怎么真的把 Blender 的一个场景、LibreOffice 的一份文档、FreeCAD 的一个零件做出来」。这也解释了为什么它反复回到榜单——它是「技能的手」。

### #5 firecrawl/firecrawl ⭐

| 属性 | 信息 |
| --- | --- |

| ⭐ Stars | 204,301 (+825) |
| 💻 语言 | TypeScript |
| 📦 分类 | Agent 数据层 / 网页抓取与知识供给 |

📖 项目是干什么的

Firecrawl 的自我定位已经换了一版：从「网页抓取 API」变成「让 Agent 更聪明的知识基础设施」。它现在有三种用法。**Firecrawl Local** 是这份 README 里分量最重的一块——一个 Rust 二进制，`cargo install firecrawl-local` 装上就能在本地 scrape / crawl / map，用你机器上已有的 Chrome 渲染 JS 页面，PDF 与 Office 文档也在本地解析，还能 `init` 自动把 MCP 服务接进 Claude Code、Claude Desktop、Cursor、Windsurf、Gemini CLI、Codex，并先备份每一份配置；`serve` 则在 3002 端口跑一份兼容 v2 的 API，现有 SDK 改个地址就能用。

**Firecrawl Cloud** 提供规模化版本：96% 网页覆盖率、P95 延迟 3.4 秒、结构化 JSON / 截图 / 浏览器动作，外加 Search 与 Alexandria——一个打包了 550 多个数据源的知识库；免登录每月 1,000 额度（Keyless）。**Self-hosting** 则把 `apps/api` 的队列、worker 与数据库整套搬到你自己的基础设施上。

三者的分工写得很清楚：抓取、爬取、映射跑在本地；需要搜索、Alexandria、Interact、Agent、Monitor 时走云端；`FIRECRAWL_CLOUD=off` 可以强制全部留在本机。

💡 可借鉴的优点

- **产品思维**：把「给 Agent 供数据」做成独立生意，并且用「本地免费 + 云端按量」分层。本地版不是阉割版，而是把隐私与延迟敏感的场景先兜住——这是数据类产品少见的克制。
- **架构设计**：本地与云共用同一套 API 契约，代码可平移、SDK 不用重写；`init` 自动识别六种宿主并写配置、先备份，这种「零摩擦接入」比写十页文档有效。
- **工程化**：公开 benchmark 说清覆盖率与 P95 延迟，而不是只说「快」；本地渲染复用系统 Chrome 而不是自带一个浏览器；云端调用失败会标注 `source: firecrawl-cloud`，来源不糊弄。
- **社区运营**：多语言 SDK、playground、Discord、X / LinkedIn 三条反馈渠道；免费额度不要求注册，先把「试一下」的门槛降到零。

🌟 特别亮眼的地方

204,301 星的成熟项目，靠「本地化 + 数据源扩张」重新上桌。它反映的是今天榜面另一条暗线：**Agent 的瓶颈正在从「会不会推理」转向「看到的是不是真的」。** 当模型能力趋同，谁能提供更干净、更新鲜、更可追溯的上下文，谁就决定了输出质量的上限。技能决定下限，数据决定上限。

## 📊 今日趋势洞察

**核心方向：验收前置——把「不合格」变成机器能判定的东西。**

今天十个项目可以按「谁在拦、拦什么」排一遍。第一类是流程闸门：superpowers 用 TDD 与 Critical 阻断，CLI-Anything 规定后端缺失时测试必须失败，diagram-design 要求先报计划再落笔。第二类是合规闸门：Claude-BugHunter 把范围校验写进代码，app-store-compliance 用 hook 在提交命令前拦截，cursor/plugins 用 create-plugin 与 agent-compatibility 校验插件本身。第三类是证据层：last30days 给每条结论配原话与赔率，firecrawl 把「抓到的是不是真页面」摊开讲 benchmark 与来源标注。三条线指向同一个结论——**Agent 的竞争力，正在从「能产出多少」转向「能保证多少」**。

**升温领域：提交前检查、真实后端、自包含产物。**

四个信号值得记住。其一，app-store-compliance 这种 1,891 星的小项目能排到第 7，说明市场对「拦一下」的付费意愿不低于对「多做一点」。其二，CLI-Anything 的「零妥协依赖」被反复讨论：宁可测试红也不许 mock，代表一类新的工程伦理——**真实比通过更重要**。其三，diagram-design 与 stitch-skills 都在做同一件事：把主观质量（好看、合理）翻译成可执行规则（4px 网格、DESIGN.md、self_check）。其四，firecrawl 与 Ghost-Downloader 提醒我们，Agent 的另一半能力在「接口」而非「智能」：一个能 `wait` 到任务结束的 CLI、一份干净的网页 Markdown，比多写十条技能更能决定最终产出。

**对开发者的三点启发。**

第一，**给你的 Agent 装一道闸门**：不一定是安全，也可以是「没有失败测试不许提交」「没有演示账号不许上架」「没有 self_check 不许交付」。第二，**把验收写成脚本，而不是写成文档**：文档会被跳过，脚本会返回非零退出码；`self_check.py`、`verify-citations.py`、`doctor` 都是这个思路。第三，**优先做接口，而不是做功能**：能被脚本稳定调用、能返回结构化 JSON、能明确成功与失败，这三件事决定了你的东西能不能被别人的 Agent 用起来——**在 Agent 时代，能被验收的交付物，才配叫交付物。**
