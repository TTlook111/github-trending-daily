- **架构设计**：主题管"材质"不管"结构"，避免同一模板生成千篇一律的页面。
- **工程化**：分层门禁 + 多宽度浏览器检查 + 新上下文复审，把审美变成可重复的质量流程。
- **社区运营**：每套主题都有成品图集中展示，视觉项目用视觉传播。

🌟 特别亮眼的地方

📖 项目是干什么的

这是一个"越狱"（jailbreak）提示词合集，简介就一句"LIST OF ALL MY JAILBREAKS"。按 README 的说法，它收录了针对 26 个以上模型的 30 多份提示词，形式包括完整系统提示词、人格锁定（persona lock）、工作区策略、`AGENTS.md` 文件、配置块和 Ollama Modelfile，并强调每个文件都是"完整、可直接粘贴"的。从文件名看，覆盖了 Claude（Sonnet / Opus）、Grok、Gemini、DeepSeek、Qwen、Kimi、GLM、Mistral、gpt-oss、Nemotron 等闭源和开源权重模型，也包括通过 OpenCode Zen 提供的免费"隐身"模型。

所谓越狱，就是用特定的提示词绕开模型自带的安全限制。这类内容的用途很两面：安全研究和红队测试会用它来检验模型和 Agent 的防线，但直接拿去用，很可能违反各模型服务商的使用条款，也可能让模型输出有害内容。仓库共 80 次提交、约 1.1k fork，今天 +1,477。**本报告只做现象记录，不复述、不推荐使用其中任何提示词。**

💡 可借鉴的优点（给防守方）

- **安全视角**：它把攻击载体从"聊天框里的一句话"扩展到了 `AGENTS.md`、工作区策略和 Modelfile——也就是 Agent 启动时自动读取的配置文件。做 Agent 产品的团队应该把这些文件当作不可信输入来审查。
- **红队测试**：对模型厂商和 Agent 平台来说，这类公开合集是现成的回归测试样本，可以用来检查自家护栏有没有被已知手法绕过。
- **供应链提醒**：Agent 技能和规则文件大多是"复制粘贴即用"的 markdown，来源不明的规则文件可能夹带这类内容，安装前要看清楚。

🌟 特别亮眼的地方

它能单日 +1,477，说明"绕开限制"的需求和 Agent 的普及是同步增长的。和今天的 openbot 放在一起看尤其有意味：一边是 Agent 默认拥有完全权限，一边是专门针对 Agent 配置文件的越狱合集——**Agent 的能力越大，提示词层面的安全就越不能只靠模型自觉。** 👉 做 Agent 平台的团队：权限最小化、敏感操作人工确认、对第三方规则文件做来源校验，这三件事比任何单条提示词防护都更可靠。

📖 项目是干什么的

superpowers 由开源开发者 Jesse Vincent（obra）及其 Prime Radiant 团队打造，自称"一套给编码 Agent 的完整软件开发方法论"，建立在一组可组合技能和确保 Agent 会用它们的初始指令之上。关键机制是**技能自动触发**：Agent 发现你要构建东西时，不会马上写代码，而是先退一步问清楚要做什么、为什么做。

它的工作流是一条强制链：brainstorming（问出真实需求、产出设计文档）→ using-git-worktrees（隔离工作区、验证干净的测试基线）→ writing-plans（拆成 2–5 分钟一块、带精确路径和验证步骤的小任务）→ subagent-driven-development（每个任务派一个全新子 Agent 并事后审查）→ test-driven-development（强制红绿重构，甚至删掉测试之前写的代码）→ requesting-code-review（critical 问题直接阻断）→ finishing-a-development-branch（验证、合并或清理）。支持 Claude Code、Codex、Cursor、Gemini、Copilot、OpenCode 等十几个 harness。10 月 17 日上榜时总 star 约 30.1 万，今天到 30.8 万、+1,095。

💡 可借鉴的优点

- **产品思维**：把资深工程师的工作纪律（先对齐、再计划、小步 TDD、勤审查）做成自动触发的技能，不依赖用户每次叮嘱。
- **架构设计**：每个任务一个全新子 Agent、事后审查，隔离了上下文污染。
- **工程化**：计划粒度细到"2–5 分钟 + 验证步骤"，TDD 强制执行，还有技能行为测试。
- **社区运营**：为十几个 harness 逐一写安装文档并标注平台差异。

🌟 特别亮眼的地方

在今天"多 Agent 工作台"扎堆的背景下，superpowers 补上的是另一半：工作台解决"怎么同时开多个 Agent"，superpowers 解决"每个 Agent 怎么按规矩干活"。30 万 star 之后还能日增千余，说明方法论类技能有很长的生命周期。👉 想让 Agent 稳定交付的团队：它的工作流拆分值得逐条研读。

📖 项目是干什么的

thinkrail 是 JetBrains 开源的"agentic IDE"，口号是"用 pi 在一个轻量、真正的 IDE 里 vibe coding，它会按你的工作方式定制自己"。它围绕 pi 编码代理做了完整界面：打开任意 git 仓库，**按任务切出独立的 git worktree 工作区**，多个 Agent 并行干活互不干扰；完成或闲置一周的工作区自动"收架"，PR 合并或关闭后自动归档。顶栏显示分支状态和 PR，可一键推送、开 PR、查看 CI 和评审结论，把失败的检查直接丢给 Agent 修。

其他设计包括：**活的规格（living specs）**——代码旁维护一张相互关联的规格图谱，由 Agent 读、搜、维护，让意图跨会话保留；每个会话有自己的模型和实时 token / 成本读数；可以在文件和 diff 上留锚定评论发给 Agent；非只读的 MCP 调用会先征求同意。有桌面版和 CLI，内置简体中文。10 月 27 日上榜时总 star 2,923，两天后到 5,579，今天 +1,068。

💡 可借鉴的优点

- **产品思维**：没有把 AI 塞进现有的重型 IDE，而是另起一个轻量形态，专为"人 + 多个 Agent 并行"设计。
- **架构设计**：git worktree 隔离 + 自动归档，用 git 原生能力解决 Agent 并行改代码互相踩的问题。
- **工程化**：PR、CI、评审结论进 IDE 闭环，失败检查一键交给 Agent。
- **安全设计**：非只读 MCP 调用先征求同意，给 Agent 的外部操作加了人工确认点。

🌟 特别亮眼的地方

和今天的 openbot 一对比很有意思：两者都做多 Agent 并行，thinkrail 默认对外部操作"先问再做"，openbot 当前默认"完全权限、不逐项确认"。**同一类产品在权限设计上的取舍，正是今天榜单安全话题的具体体现。** 👉 用多个 Agent 并行开发的团队：worktree 隔离 + 每会话单独计成本，今天就能用进自己的流程。

📖 项目是干什么的

OpenBot 是一个"本地优先"的桌面工作区，用来养一组**持久化的 AI 队友**。它支持本地的 Codex App Server 和 Claude Code，并通过 ACP 接入 Grok CLI、OpenCode、Gemini、Cursor CLI、Cline CLI；每个 Agent 有自己的工作区和对话，应用里还提供本地任务队列、文件传输、内嵌浏览器，以及 Agent 之间互发消息的能力。

已实现的功能包括：用提示词创建和编辑 Agent（桌面和手机端都可以）；每个 Agent 背后是独立的会话和本地工作区；支持自定义 OpenAI 兼容端点和 ACP Agent，能检测本地的 Ollama、LM Studio；按 Agent 监控上下文，快满时自动压缩；FIFO 消息队列支持暂停、恢复、取消和崩溃后恢复；共享频道里有明确的任务负责人和委派、停止、重新指派等控制；可选的 Computer Use（macOS / Windows / Linux）。安装覆盖 macOS、Windows、Linux AppImage，还能用一条命令装成 VPS 上的常驻服务、或用 Docker / Nix 部署。README 也说明它是"本地优先而非完全离线"——各家模型仍要连各自的云服务。

⚠️ README 顶部有醒目警告：当前是开发预览版，Agent 以 `danger-full-access` 和 `approvalPolicy: never` 运行，首次启动同意后，就能读写文件、执行命令、联网、控制浏览器，**不再逐项确认**；建议只运行可信的 Agent 和任务、保留备份。另外 Nix 安装说明里写明 OpenBot 不是自由软件，使用前要留意许可条款。今天首次上榜，+1,054。

💡 可借鉴的优点

- **产品思维**：把 Agent 从"一次性对话"变成"有工位的队友"——独立工作区、任务队列、彼此能发消息，更接近真实团队协作。
- **架构设计**：通过 ACP 统一接入多家 CLI Agent，再在上层做队列、委派和共享频道，底层引擎可替换。
- **工程化**：上下文自动压缩、崩溃安全的队列持久化、桌面 / 服务器 / Docker 多种部署形态，考虑得很完整。
- **诚实披露**：把"完全权限、不逐项确认"写在首页最显眼的位置，而不是藏在文档深处。

🌟 特别亮眼的地方

OpenBot 把"多 Agent 工作台"往前推了一步：不只是并排开几个 Agent，而是让它们**常驻、排队、互相委派**。但它现阶段的默认权限也最激进，和 thinkrail 的"先问再做"形成鲜明对比。👉 想试用的开发者：先在虚拟机或独立账户里跑，等权限确认机制完善后再放进主力机器。

📖 项目是干什么的

## 📊 今日趋势洞察

### 核心方向

1. **多 Agent 工作台成为最拥挤的赛道**：thinkrail（agentic IDE）、openbot（常驻 AI 队友工作区）、cindy（多 harness 统一 Agent）同日在榜，再加上方法论框架 superpowers。共同的问题是"一个人怎么同时指挥好几个 Agent"，答案也开始趋同：git worktree 或独立工作区做隔离、任务队列做调度、子 Agent 做复审。
2. **设计技能进入"多家竞争"阶段**：ai-design-skills（+2,139）反超 hallmark（+2,110），impeccable（+1,472）保持稳定。三家打法不同——面向转化的落地页、分层门禁的材质主题、确定性规则引擎——说明"给 Agent 配审美"已经从单一爆款变成有分工的品类。

### 升温领域

1. **Agent 安全与提示词攻击面**：jailbreaks 合集单日 +1,477，攻击载体已经覆盖 `AGENTS.md`、工作区策略等 Agent 会自动读取的配置文件；同一天，openbot 默认"完全权限、不逐项确认"，thinkrail 则对非只读操作"先问再做"。权限怎么设计，正在成为多 Agent 产品之间实打实的差异。
2. **垂直学习应用**：DeepTutor 以 +2,371 登顶且明显提速，说明在通用工具之外，"把 Agent 能力编排进一件具体的事"依然最能打动用户。

### 对开发者的启发

- **做多 Agent 工作台**：隔离（worktree / 独立工作区）是共识，真正的差异在于权限和确认机制——默认最小权限、敏感操作人工确认，会比功能多寡更早决定用户敢不敢用。
- **做 Agent 平台或技能市场**：把 `AGENTS.md`、规则文件、技能包当作不可信输入，安装前做来源校验和内容审查；公开的越狱合集可以拿来做护栏回归测试。
- **做设计技能**：赛道已有三种成熟打法，新进入者要么选一个更窄的高频场景（像 ai-design-skills 选落地页），要么提供别人没有的确定性检查。
- **一个贯穿的共性**：今天表现好的项目都在把"规矩"写清楚——hallmark 的三层门禁、superpowers 的强制工作流、openbot 首页的权限警告、LinkSwift 的免责边界。**Agent 越能干，把边界讲明白就越重要。**
