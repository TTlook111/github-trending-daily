📖 项目是干什么的

security-audit-skill 是 Cloudflare 开源的一个 coding-agent 技能，把编码代理变成一名安全审计员。它不是扫描器，而是一套编排多个隔离子代理、分六个阶段跑完的审计方法论，核心主张是"发现漏洞的代理和验证漏洞的代理必须是两拨人"。README 明说这正是 Cloudflare 内部漏洞发现 harness 的种子——那套 harness 后来长成了跨团队的多阶段系统，而这个仓库是它最初的单仓库起点。今天它以当日 +2,979 star 登顶，是本期增速最猛的项目，连续三天稳居前列。

六个阶段依次是：①侦察（映射架构、信任边界、输入面，并建立确定性的覆盖账本 coverage ledger）；②猎捕（从账本单元派发隔离的猎手，用覆盖批评者找盲区）；③验证（把每个候选交给一个全新的验证者去尝试证伪）；④结构化输出（写 `confirmed` / `needs_validation` / `rejected` 三种裁决的 findings.json 并校验）；⑤独立复核（新代理复核最终源码主张）；⑥报告（从已验证记录派生出目标中立的报告）。整个流程由父代理用零依赖的 `.cjs` 校验器在每次账本/发现更新后反复校验。三种裁决定义极其克制：`confirmed` 必须有完整源码追踪链，`needs_validation` 有确切未解事实且不给严重度，`rejected` 记录被证伪的候选。README 坦诚写明：单次运行大约只能发现重复运行累计发现漏洞的一半。

💡 可借鉴的优点

- **产品思维**：Cloudflare 把本应是内部竞争优势的安全审计方法论直接开源，并诚实标注"单次只找到一半"这种对自己不利的数据来建立可信度；`npx skills add` 一键安装，门槛极低。
- **架构设计**：严格的"发现者≠验证者"隔离 + 覆盖账本这个确定性记账层，把 LLM 审计最大的毛病——幻觉报告和覆盖黑洞——用工程手段摁住。
- **工程化**：用零依赖 `.cjs` 校验器在每一步做机器校验，findings 和 coverage 都有 JSON schema 和配套测试；强制 OS 级沙箱才执行目标代码，否则标 blocked。
- **社区运营**：按攻击面把猎捕提示词拆成十几个专题文件，每类都是独立可复用的方法论资产。

🌟 特别亮眼的地方

它今天登顶且增速逆势走高，说明"把安全审计方法论封装成一键安装技能"这件事的需求还在加速。它最值得抄的工程决策是把"审计覆盖度"做成显式的确定性账本，而非依赖 LLM 自称"我看完了"。"发现者和验证者永远不是同一个代理"这条原则，仍是这些天 Agent 工程最稳固的共识——**单个 Agent 自评不可信，可信度来自隔离的独立验证 + 确定性记账**。👉 面向做安全工具或任意高风险 Agent 流程的开发者：可直接借鉴它的六阶段隔离编排和覆盖账本设计。

📖 项目是干什么的

Ponytail 是一个让 AI 编码代理"像房间里最懒的资深开发者那样思考"的技能，口号是"最好的代码是你永远没写的代码"——你给他看五十行，他什么都不说，换成一行。它本质是一个提示词（`skills/ponytail/SKILL.md`，精简版 `AGENTS.md`），仓库里其它一切都是把这个提示词装进不同 agent 的适配层。连续三天在榜且已突破 17 万 star，是这波"技能化"浪潮里最具标志性的项目之一。

官方基准：在 Claude Code 里同一个 agent 开/不开该技能、39 个任务、Opus 5.5、各跑 5 次——代码量 -53%、时间 -41%、成本 -26%、token -45%；更关键的是带风险的逻辑有 98% 随附测试发车（不开时仅 68%），六个安全任务 30 次运行全过。它反复强调规则不是"最少 token"，而是"只写任务需要的，但验证、错误处理、安全、可访问性绝不砍"。功能上 `/ponytail-review` 评审当前 diff、`/ponytail-audit` 审整个仓库、`/ponytail-debt` 把 `shortcut:` 注释收集成技术债账本；5.3 版的 band 条在 Claude Code 里实时显示成本、token、agent 用时和测试状态。

💡 可借鉴的优点

- **产品思维**：用极具人格化的隐喻（懒资深开发者）把"少写代码"变得可感知、可传播，并给出 before/after 实例（日期选择器 335 行 → 复用现有组件 → 10 行）。
- **架构设计**：核心只有一个提示词文件，所有适配层加载同一份 SKILL.md/AGENTS.md，换 harness 不换方法论；明确"对解法懒、对读代码绝不懒"。
- **工程化**：带可复现基准（公开方法、逐任务表格），band 条把成本/测试状态实时可见，`/ponytail-debt` 把技术债制度化为账本。
- **社区运营**：多语言 README，明确供应链警告（"只从官方源安装，从不发 .exe/.dll"）。

🌟 特别亮眼的地方

Ponytail 代表"技能"形态的成熟用法：不给 agent 加能力，反而加约束。它最硬的地方是把一个纯提示词项目做出了可复现的量化基准，并诚实把"安全/验证/可访问性绝不砍"写进第一原则，避免"少写代码"滑向"偷工减料"。👉 面向做 agent 技能或 prompt 工程的开发者：可借鉴它"用人格化隐喻承载工程原则 + 用可复现基准背书"的打法。

| 属性 | 信息 |

| 📦 分类 | AI 开发工具 / 代码库知识图谱技能 |

📖 项目是干什么的

Graphify 是一个 `/graphify` 技能，在 AI 编码助手里输入它，就能把整个项目（代码、文档、PDF、图片、视频）映射成一张可查询的知识图谱，让你用"查图谱"代替"grep 翻文件"。核心取舍很鲜明：代码用 tree-sitter AST 本地解析——确定性、无 LLM、不出本机；每条连接都打 `EXTRACTED`（源码显式）或 `INFERRED`（推导）标签；没有 embedding、没有向量库，是一张你真正去遍历的图。连续三天在榜。

用法是 `uv tool install graphifyy` 装 CLI、`graphify install` 自动注册技能，`/graphify .` 产出 `graph.html`、`GRAPH_REPORT.md`、`graph.json` 三个文件。能力含 God nodes（最高连接度概念）、Communities（Leiden 算法切子系统、无 LLM 标签）、跨文件链接（约 40 种语言）、`query`/`path`/`explain` 三种查询。基准 LOCOMO recall@10 0.497、LongMemEval-S QA 76%，建图 0 LLM credits。官方有 Graphify Cloud 商业版，CLI 开源，Apache-2.0/MIT 双许可。

💡 可借鉴的优点

- **产品思维**：切中"agent 在大代码库里靠 grep 翻文件、烧 token"的痛点，给出"建一次图、随后查图"的替代路径，开源 CLI 做入口、Cloud 做持续化商业版。
- **架构设计**：代码走确定性 AST、不出本机，只有非代码才走模型；用真正的图遍历而非向量库，每条边带置信标签，可解释性做进数据结构。
- **工程化**：Leiden 社区发现 + 无 LLM 标签把大图切成子系统；`graph.json` 带 schema_version 便于集成检测。
- **社区运营**：一键适配 20+ 助手、全平台，30+ 语言 README；明确警示官方包是 `graphifyy`（双 y）。

🌟 特别亮眼的地方

它最值得抄的是"代码走确定性本地解析、非代码才走模型"的分层，以及把 `EXTRACTED`/`INFERRED` 置信标签做进每条边——反驳了"记忆/理解必须靠向量库 + LLM 摘要"的主流叙事。👉 做 Agent 平台或代码智能工具的开发者，可参考它"派生索引可重建、图谱可解释、建图零 LLM"的存储哲学。

📖 项目是干什么的

Supabase 是"Postgres 开发平台"，用企业级开源工具复刻 Firebase 的能力：给你一个专属的 Postgres 数据库来构建 Web、移动和 AI 应用。开箱能力包括托管 Postgres、认证授权、自动生成的 API（REST / GraphQL / Realtime）、数据库函数与 Edge Functions、文件存储、AI + 向量/Embeddings 工具包和管理 Dashboard。它的工程哲学是"能用现成开源工具就不自己造"——Realtime 是 Elixir 服务、PostgREST 把 Postgres 变 REST API、GoTrue 做 JWT 认证、pg_graphql 暴露 GraphQL、postgres-meta 管理 Postgres，前面挡着 Envoy 边缘代理。可完全自托管或本地开发。

💡 可借鉴的优点

- **产品思维**：用"开源版 Firebase"一句话锚定心智，但不做 1:1 克隆而是对齐开发体验；提供托管、自托管、本地开发三条路径。
- **架构设计**："组合现成开源工具 + 缺失才自建开源"的组装式架构，每个能力都是独立服务/扩展，围绕 Postgres 内核拼装。
- **工程化**：把 Postgres 既有能力（复制、RLS 权限、扩展）直接复用成产品特性，最大化借力成熟基础设施。
- **社区运营**：客户端库官方 + 社区分层维护覆盖十余种语言，40+ 语言 README。

🌟 特别亮眼的地方

在今天这份以 Agent/技能为主角的榜单里，Supabase 的上榜提醒了一件事：AI 应用的爆发同样在抬升底层数据与后端平台的需求——它明确列了"AI + Vector/Embeddings 工具包"，pgvector 式向量能力让 Postgres 直接成为 AI 应用的存储底座。👉 面向做平台型产品的团队：Supabase 证明"站在成熟开源基础设施肩上做组装与体验整合"比全自研更快也更可持续。

这是 Anthropic 官方开源的插件仓库，面向知识工作者，主要给 [Claude Cowork](https://claude.com/product/cowork) 使用，也兼容 Claude Code。核心理念是：Cowork 让你设定目标、Claude 交付成品，而插件让你更进一步——告诉 Claude 你喜欢怎么干活、从哪些工具和数据取数、关键工作流怎么处理、暴露哪些斜杠命令，让整个团队得到更好、更一致的产出。每个插件捆绑了某一职能的 skills、connectors、slash 命令和子代理。

Anthropic 一次性开源了 **11 个插件**，覆盖面远超编码场景：productivity（任务/日历/日常流）、sales（销售，接 HubSpot/Close/Clay/ZoomInfo 等）、customer-support（客服，接 Intercom/Guru 等）、product-management（产品，接 Linear/Figma/Amplitude 等）、marketing（市场，接 Canva/Ahrefs/Klaviyo 等）、legal（法务，接 Box/Egnyte 等）、finance（财务，接 Snowflake/Databricks/BigQuery）、data（数据分析，写 SQL/建仪表盘）、enterprise-search（跨邮件/聊天/文档/wiki 的统一检索）、bio-research（临床前研究，接 PubMed/bioRxiv/ChEMBL 等十余个库），以及 cowork-plugin-management（创建/定制插件本身）。每个插件结构统一：`.claude-plugin/plugin.json` 清单 + `.mcp.json` 工具连接 + `commands/` 斜杠命令 + `skills/` 领域知识，全部是 markdown + JSON，无代码、无基建、无构建步骤。安装走 `claude plugin marketplace add anthropics/knowledge-work-plugins` 再 `claude plugin install sales@knowledge-work-plugins`。

💡 可借鉴的优点

- **产品思维**：把"插件"从开发者场景扩展到销售/客服/法务/财务等全职能知识工作者，并明确插件是"通用起点"、真正威力来自用公司自己的工具/术语/流程去定制——把 Claude 变成"为你团队量身打造"的专家。
- **架构设计**：所有插件遵循同一结构（manifest + MCP 连接 + commands + skills），skills 是自动触发的领域知识、commands 是显式斜杠动作、MCP 连外部工具，职责分层极清晰。
- **工程化**：全部 file-based（markdown + JSON），无代码、无基建、无构建步骤，贡献就是 fork 改文件发 PR——把"企业定制 AI 工作流"的门槛降到编辑文本文件。
- **社区运营**：Anthropic 官方背书 + 11 个真实业务场景插件 + Cowork 一键安装 + GitHub 可浏览可贡献，直接为整个插件生态立了标准范式。

🌟 特别亮眼的地方

这个项目最大的信号意义在于：**平台方（Anthropic）亲自下场定义"技能/插件"的标准结构和分发方式**。这些天榜上一堆第三方技能（ponytail、security-audit-skill、graphify）都在用 `SKILL.md` + 一键 install 的形态，而 Anthropic 官方插件市场等于给这股浪潮盖了认证章，并把它从"给程序员的编码技能"正式推向"给所有知识工作者的职能插件"。它把企业定制做成"编辑 markdown 文件"而非写代码/搭基建，这意味着未来定义 AI 工作流的人可能不再是工程师，而是每个业务团队自己。👉 面向做企业 AI 或 Agent 平台的团队：这是研究"插件标准结构 + MCP 连接 + 可定制 skills"的权威样板，值得直接对照它的目录规范来设计自己的技能体系。

php-src 是 PHP 语言的官方解释器源码仓库——驱动全球海量网站的那门服务端语言的心脏，用 C 编写，包含 Zend 引擎、标准库和扩展。它是互联网基础设施级别的常青项目，日常并不"上榜"，今天以当日 +287 star 出现在清淡的榜单里，更多是基础设施型经典项目在整体热度低时的自然浮现，而非出现了什么新热点或新版本爆点。

💡 可借鉴的优点

- **工程化**：数十年持续维护、庞大 C 代码库 + 严格的 RFC 流程驱动语言演进，是"大型长生命周期开源项目治理"的教科书案例。

📖 项目是干什么的

FastAPI 是一个现代、高性能的 Python Web 框架，用于基于标准 Python 类型提示构建 API。它的核心卖点是：用类型提示自动完成数据校验、序列化和交互式 API 文档生成（Swagger UI / ReDoc），性能对标 NodeJS 和 Go，同时开发体验极佳、代码量少、bug 少。它是过去几年 Python 后端生态最成功的框架之一，被大量 AI/ML 服务用作模型推理接口层（前两天 graphify 的 benchmark 里就是拿 FastAPI 代码库做示例）。今天当日 +101 star，是本期增幅最小的项目，纯属榜单清淡时的经典项目自然浮现。

💡 可借鉴的优点

- **产品思维**：把"类型提示"这个 Python 原生特性转化成自动校验 + 自动文档的巨大开发体验红利，用最小的学习成本换最大的生产力提升。
- **架构设计**：站在 Starlette（ASGI）和 Pydantic（数据校验）两个成熟组件肩上组装，而非从零造轮子——与 Supabase 的"组装式"哲学异曲同工。
- **工程化**：自动生成 OpenAPI schema 和交互式文档，让 API 契约成为代码的自然产物而非额外负担。
- **社区运营**：极其详尽的官方文档（本身就是最佳实践教程）+ 活跃维护，是开源项目"文档即产品"的标杆。

🌟 特别亮眼的地方

FastAPI 今天上榜信号意义不大（增幅 +101、无事件驱动），主要是榜单清淡所致。但它在 AI 时代的隐性地位值得一提：它几乎成了 Python 侧"把模型包成 API"的默认选择，大量 Agent/推理服务的 HTTP 层都是 FastAPI。它和 Supabase 一起印证：AI 应用的繁荣，始终在悄悄抬升底层 Web 框架和数据平台的使用量。👉 做 Python API 或模型服务层的开发者，FastAPI 基本是默认起点，它"类型提示驱动一切"的设计仍是降低 API 开发成本的最佳实践。
