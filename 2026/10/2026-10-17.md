## 总览摘要

今天榜单最直观的信号，是**平台方正式进场收编 Agent 技能生态**。排第 3 的 **anthropics/claude-plugins-official（+1,552）** 是 Anthropic 官方维护的 Claude Code 插件市场——它规定了插件的标准目录结构（`plugin.json` + `commands/agents/skills`）、不可变的命名 slug、以及第三方插件的质量与安全审批流程。换句话说，过去几个月里野蛮生长、靠 `npx skills add` 和各自 README 口口相传的"技能"，开始有了**官方分发渠道与准入门槛**。同一日榜单边缘还能看到 `cursor/plugins`（+278）和 `android/skills`（+36）的身影——Cursor、Android 等平台也在各自立标准。技能从"野生脚本"变成"官方市场里的商品"，这是 Agent 生态走向成熟的标志性一步。

但真正占据今天榜单主体的，是一场围绕 **Agent harness（智能体外壳/操作系统）** 的"军备竞赛"。**obra/superpowers（+973）、affaan-m/ECC（+1,057）、ruvnet/ruflo（+672）** 三个项目本质上在做同一件事：光给模型一个对话框不够，得在它外面套一层"工程化操作系统"——开工前先头脑风暴对齐需求、写计划、派子智能体、强制 TDD、每步做代码审查、跨会话记忆、把成功经验沉淀成可复用技能。ECC 一口气塞进 **71 个 agent、311 个技能、97 条命令**外加安全扫描；superpowers 用一套"brainstorm → plan → subagent → TDD → review"的强制流程让 Agent 能自主工作数小时不跑偏；ruflo（原 Claude Flow）则干脆提出"**Agent = Model + Harness**"，主打多智能体 swarm 与跨机器联邦。它们都以官方插件为分发载体，harness 正在成为 Agent 时代的"框架之争"。

而今天最硬、也最能体现工程含量的一条暗线，是**上下文工程（Context Engineering）**——解决 Agent"烧 token、读文件、会失忆"的真实瓶颈。冠军 **VoiceStudio（+2,301）** 是本地优先的语音工作台；**xerj（+1,648）** 用 Rust 写了个单二进制的本地搜索引擎，让 Agent 用检索代替 grep/读文件，并用对照实验证明输出 token 比 grep 少 2.7 倍、比纯靠记忆少 26 倍；**context-mode（+449）** 则从"沙箱隔离工具输出、SQLite 记录会话、让 LLM 写脚本而非读数据"四个面把上下文占用压缩 98%。再加上把 Agent 变成"AI 科学家"的 **scientific-agent-skills（+1,158）**、跑在本机的求职框架 **ai-job-search（+898）**，以及唯一非 AI、靠刚需长青的中文网盘工具 **LinkSwift（+538）**——今天的叙事高度一致：**当模型能力趋于同质化，竞争焦点彻底上移到"外壳、记忆、上下文、分发标准"这一层，而"本地优先、数据自有、可量化收益"正成为新项目的共同卖点。**

📖 项目是干什么的

VoiceStudio 今天以 **+2,301 断层登顶**，它把自己定位成"开源、完全本地化的 ElevenLabs 替代品"——一句话讲清定位：**不把你的声音和文本上传到任何云端，在自己的硬件上完成声音克隆、声音设计、视频配音、听写、转录和有声书制作**，覆盖多达 646 种语言。它瞄准的痛点很明确：ElevenLabs 这类 SaaS 音质好、功能全，但订阅贵、声音数据要上传、商用授权不透明；VoiceStudio 把整条语音生产链搬进一个本地桌面应用。项目 2026 年 4 月创建，采用 AGPL-3.0 许可证。

它是一个完整的桌面工作台，按"Create / Produce / Connect"组织能力：**克隆或设计一个声音、用对齐时间轴的语音给视频配音、批量制作故事和有声书、用悬浮小窗做听写**；连接层则暴露本地 API 与 MCP，让 Agent 也能调用，还支持可复用的"配方（recipes）"和监听文件夹自动批处理。默认引擎是 k2-fsa/OmniVoice，但架构允许切换其他引擎，并提供功能与引擎目录。技术栈是 Electron 桌面壳 + Python 语音后端（0.5.3 是最后一个 Tauri 版本，之后全面迁移到 Electron），本地工作流完全跑在自己硬件上，远程服务纯属可选、用量分析需明确同意。

硬件适配做得相当扎实：NVIDIA 显卡走 CUDA、Apple Silicon 走 Metal（MPS）、没有独显的老机器也能纯 CPU 跑（只是慢，安装器会装约 5GB 的小型 PyTorch CPU 版），连 Windows on ARM 都有实验性原生包。安装是一条命令（macOS/Linux 走 `curl voicestudio.sh/install | sh`，Windows 走 `irm ... | iex`），也提供各平台安装包与 Docker；甚至能直接对编码 Agent 说"从仓库安装并验证"，它会按 agent 指南自行完成硬件检测、下载前询问和一次试生成。

💡 可借鉴的优点

- **产品思维**："开源 + 完全本地 + ElevenLabs 级功能矩阵"精准切中付费 SaaS 用户对成本、隐私和声音资产归属的三重焦虑；把克隆、配音、听写、有声书这些高频场景做进一个工作台，而不是一堆零散脚本
- **架构设计**：引擎可插拔（默认 OmniVoice，另附引擎目录），UI/API/MCP 共用同一套本地能力；Create-Produce-Connect 三段式把"生产内容"和"被 Agent 调用"同时纳入设计，是典型的 Agent 原生应用架构
- **工程化**：多硬件后端（CUDA/Metal/CPU/ARM）差异化处理、smoke-test 打包验证、安装脚本保留数据与模型、提供卸载与版本迁移文档；Model Manager 会显式标注每个模型的来源声明、证据链接和尚未审查的缺口
- **社区运营**：中英日多语言 README、GIF 与截图直观展示四大工作区、Trendshift 徽章、Discord 与赞助位；AGPL 许可证保证衍生开源，同时明确"应用版权"与"模型权重/声音/生成物授权"分离，并反复强调"只在获许可时克隆声音"，把合规和伦理摆在台面

🌟 特别亮眼的地方

VoiceStudio 代表了生成式 AI 应用一个越来越强的方向——**"本地优先"（local-first）的专业级替代**：它不只是把云端模型简单打包，而是认真解决了本地部署最难的硬件适配、模型管理、商用授权与伦理边界，并额外给 Agent 暴露了 MCP 接口。它以 +2,301 夺冠说明，"数据不出本机、一次性买断、还能被自动化调用"的 AI 媒体工具，需求比想象中更强烈。👉 任何需要语音合成/克隆/配音、却因成本、隐私或授权不敢用云服务的个人和团队，或想学习"如何把一个重型多模态模型包装成跨平台、Agent 可调用的本地工作台"的开发者，VoiceStudio 都是目前完成度最高的开源参考之一。

| 📦 分类 | AI 基础设施 / 本地代码搜索与 Agent 记忆 |

📖 项目是干什么的

xerj 是一个用 Rust 写的**本地 AI 搜索引擎**，2026 年 6 月底才创建、今天就以 +1,648 冲到第 2，解决的是每个重度 Agent 用户都在忍受的浪费：**Agent 习惯一个一个读文件、用 grep 找线索，把整个文件塞进上下文，token 烧得飞快，而 grep 命中的只是一行，要判断这行还得打开整个文件**。xerj 的做法是让 Agent 直接检索到"需要的那段代码"。它给出的旗舰场景叫"reference coding（参考式编程）"：给 Agent 一个任务，让它先克隆、索引最接近的开源仓库，检索别人怎么解决同一问题，再动手写自己的代码。

它的价值主张是用数据撑起来的：在一项受控对照研究里（8 个任务、4 种语言、每组 16 次真实 `claude -p` 计费），纯靠模型记忆输出 26 万 token、只解出 11/16；grep 驱动约 2.6 万 token、16/16；而 xerj 只用约 1 万 token、同样 16/16——**比 grep 少 2.7 倍输出 token、比纯记忆少 26 倍**，单个 Java 任务上甚至少 278 倍，真实开发中用户反馈普遍在 5 倍左右。它也诚实标注了边界：在私有、内部、冷门或模型截止日期之后的代码上收益最大，对模型早就烂熟于心的热门公共库则收益中性甚至为负。

技术上它是一个**单一静态二进制、无 JVM、无依赖**，预编译覆盖 Linux/macOS/Windows 的 x86 与 arm64。最聪明的兼容策略是完整实现 Elasticsearch REST API（索引、bulk、search、聚合、kNN、scroll、`_cat` 等），Kibana 和官方客户端库无需改造就能直连，一致性测试当前通过 1366/1369 项。`autoindex` 会自动嗅探文件类型，用 tree-sitter 把代码解析成带符号和行号的 AST（而非平铺文本），还能吃 PDF、SQLite、DOCX、PPTX、Excel、EPUB、Jupyter、邮件、日志乃至 Unity 工程；检索支持 BM25、向量 kNN 与混合检索，默认词法嵌入器完全离线。同一个二进制还能作为 MCP server 暴露 13 个工具，并用 `/_memory` 命名空间做 Agent 长期记忆和第二大脑知识图谱。

💡 可借鉴的优点

- **产品思维**：把"Agent 读文件烧 token"这个抽象痛点，收敛成一个可量化、可复现的对照实验，用"少 2.7 倍 token、解决率不降"说话，比任何形容词都有说服力；一句话安装 + `xerj init` 一条命令接入 Claude Code/Cursor
- **架构设计**：用"兼容 Elasticsearch 协议"这一极其务实的选择，把生态迁移成本降到零；代码走 tree-sitter AST 索引、检索与记忆共用同一套索引原语，单一二进制同时承担服务器、CLI 与 MCP server
- **工程化**：每次提交跑 ES-YAML 一致性套件，把剩下 3 个未通过项公开列出来而不是藏起来；对 Elasticsearch 8.13.4 的基准是 55 胜 26 平 4 负，4 项失败（高并发写下的读 p99）专门写了完整分析文档，"无法复现的数字都值得怀疑"
- **社区运营**：独创的"加入方式"——运行后提交一份简短的使用反馈 PR 即视为成员，人类和 AI Agent 都欢迎，反馈类 PR 豁免 CLA、只加一个 markdown 文件，极大降低了参与门槛并持续收集真实案例

🌟 特别亮眼的地方

xerj 是"**上下文工程**"这条赛道里工程最硬、姿态最诚实的一个：它没有发明新的检索概念，而是把成熟的 Elasticsearch 能力压缩成一个免运维的本地二进制，再针对 Agent 场景补上 AST 索引、参考式编程和长期记忆。它对安全边界的描述也异常克制——`--insecure` 明确解释为"每个能访问端口的人都是超级用户"，默认只绑 127.0.0.1。一个创建仅三个多月、才 7 千 star 的项目敢用公开基准和"失败清单"说话，这种"证据优于宣称"的纪律本身就是稀缺品质。👉 任何被 Agent 的 token 账单和长仓库读取折磨、想做本地代码 RAG / 安全审计 / Agent 记忆的开发者，或想研究"如何用一个二进制替代重型搜索引擎"的工程师，xerj 都非常值得一读。

📖 项目是干什么的

这是 **Anthropic 官方亲自维护的 Claude Code 插件目录（marketplace）**，今天以 +1,552 排在第 3。它本身代码不多，意义却特殊——它是 Agent 技能生态从"野生"走向"官方收编"的标志性仓库。仓库分两块：`/plugins` 放 Anthropic 团队自研自维护的内部插件，`/external_plugins` 放经过审批的合作伙伴与社区第三方插件。用户在 Claude Code 里用 `/plugin install 插件名@claude-plugins-official` 安装，或在 `/plugin > Discover` 里浏览。项目 2025 年 11 月创建，采用 Apache-2.0 许可证。

它的价值在于**立规矩**。文档明确了插件的标准结构：一个 `.claude-plugin/plugin.json` 元数据清单（必需），可选地挂 `.mcp.json`（MCP server 配置）、`commands/`（斜杠命令）、`agents/`（子智能体）、`skills/`（技能）四个目录。它还规定了若干容易被忽视但很关键的工程约束：插件名是**不可变的 slug**——一旦发布就不能改，因为用户是按这个 slug 安装的，改名会直接导致 `plugin-not-found`；如果确实要改，必须在市场的 `marketplace.json` 顶层 `renames` 映射里登记，加载器会在用户下次同步时透明迁移。此外还支持"技能包"型插件：源仓库只有 SKILL.md、没有插件清单时，可用 `strict: false` 加显式 `skills` 数组把一批技能作为一个插件暴露。

它同时是一份**安全与治理契约**。文档开头就用醒目警告提醒：安装、更新或使用插件前必须自行信任它——Anthropic 不控制插件里包含的 MCP server、文件或其他软件，也无法保证它们按预期运行。第三方插件要进入市场，必须通过质量与安全标准审批，走官方提交表单。

💡 可借鉴的优点

- **产品思维**：平台方亲自下场建"应用商店"，把过去散落各处的命令/技能/Agent 统一成一种可发现、可安装、可更新的商品，解决了 Agent 能力"分发混乱、难以信任"的问题
- **架构设计**：用一份极简清单（plugin.json）+ 四个约定目录，就把 MCP server、命令、子智能体、技能四种异构扩展统一进同一插件模型；`strict` 模式与技能包模式兼顾规范与灵活
- **工程化**："不可变 slug + renames 自动迁移"是成熟包管理体系才会有的细节，直面"改名会破坏用户安装"这一真实问题；技能注册名用 `<插件>:<技能>` 命名空间避免冲突
- **社区运营**：内部插件提供参考实现、外部插件给出明确准入路径与表单；开篇即强调安全边界，既不越权背书也不回避责任，是平台治理的标准姿势

🌟 特别亮眼的地方

claude-plugins-official 的意义不在代码量，而在它标志着 **Agent 生态进入了"平台 + 市场"的制度化阶段**。今天榜单里的 superpowers、ECC、context-mode 等几乎所有头部项目，都在以 `xxx@市场名` 的方式通过官方市场分发——这套目录正在成为 Agent 能力的"App Store 规则"。同一天 Cursor、Android 的插件/技能仓库也在榜单上，说明各家平台都在抢着确立自己的扩展标准。👉 任何想开发或分发 Claude Code 插件、研究 Agent 扩展点设计与平台治理的开发者，都应该先读这份官方目录——它是理解"技能如何被标准化、信任如何被建立"的第一手资料。

📖 项目是干什么的

LinkSwift 是今天榜单上**唯一与 AI 无关的项目**，也是一个典型的中文本土刚需工具——一个基于 JavaScript 的网盘文件下载地址获取工具，以油猴脚本（Tampermonkey/脚本猫）形式运行，支持**百度、阿里、中国移动、天翼、迅雷、光鸭、夸克、UC、123 共九大网盘**。它基于知名的"网盘直链下载助手"（作者油小猴，syhyz1990/baiduyun）二次修改，在其基础上增加了更多功能：直链获取、UI 美化，并对接 IDM、Aria2、AB Download Manager、比特彗星等多种下载器。项目 2022 年 8 月创建，AGPL-3.0 许可证，正式版 v1.1.3、测试版 v1.1.4，目前 2.4 万 star。

它解决的是国内用户一个非常具体的痛点：各大网盘官方客户端限速、体积臃肿、强制登录，而很多用户（尤其是在服务器、NAS 或习惯用第三方下载器的人）希望拿到文件的真实直链、用自己趁手的工具下载。脚本在网盘网页端注入下载助手，能批量获取直链、推送到 IDM/Aria2，支持多块多线程、RPC 任务查看、下载进度显示等，并适配各网盘不断变化的页面和接口策略。

最值得注意的是它的**合规姿态**。README 用两段醒目声明反复强调：所有下载链接都基于各大网盘服务商**公开的 API 接口**获取，项目从未以任何形式承诺、宣传或实现对限速机制的破解；如果实际下载较快，那是服务商接口策略或用户网络环境所致，不得误解为具备破解能力。它坚持"技术中立"，不触及、不损害服务商核心利益，仅帮助无法使用官方客户端的用户实现合法下载，并与第三方的"加速""破解限速"等夸大宣传划清界限。分发上它覆盖 GitHub、OpenUserJS、脚本猫等多个脚本源，并提醒用户 GreasyFork 上存在黑产刷子导致更新不及时，建议从可信源安装。

💡 可借鉴的优点

- **产品思维**：在一个被大厂客户端垄断、体验割裂的细分场景里，用一个脚本统一九大网盘的直链获取与多下载器对接，刚需明确、切换成本极低（装个脚本即可）
- **架构设计**：以用户脚本注入网盘网页、调用公开 API 的方式实现，不做服务端、不碰用户账号密码；多网盘/多下载器以适配层形式持续迭代，跟随官方页面变化快速跟进
- **工程化**：从更新日志可见长期维护轨迹（紧跟官方 V6.x 接口、废弃不安全的 BDUSS Cookie 改用 AccessToken、用 eslint 检查代码），正式版与金丝雀版分离，降低新功能风险
- **社区运营**：单人维护、更新日志写得有人情味、明确只在 GitHub issue 受理反馈；多脚本源分发、贡献者墙、合规声明和"唯一发布渠道"防钓鱼，在灰色边缘地带尽量保持干净

🌟 特别亮眼的地方

在满屏 Agent 项目的榜单里，LinkSwift 提醒我们一件朴素的事：**能长期上榜的，往往是精准解决真实刚需、且在合规边界上走得稳的工具**。一个 2022 年的"老"项目，靠持续跟进九大网盘的接口变化、并坚持"只调公开 API、不碰限速破解"的自我约束，至今仍能日增 500+ star，这本身就是对"技术中立、克制合规"的最好背书。👉 任何需要跨网盘获取直链、用第三方下载器管理下载的用户，以及想研究油猴脚本工程化或"如何在敏感边界内做合规工具"的开发者，都可以看看这个项目。

### #10 mksglu/context-mode ⭐

| 属性 | 信息 |
| --- | --- |
| 🔗 链接 | [mksglu/context-mode](https://github.com/mksglu/context-mode) |
| ⭐ Stars | 30,288 (+449) |
| 💻 语言 | TypeScript |
| 📦 分类 | AI 基础设施 / Agent 上下文窗口优化 |

📖 项目是干什么的

context-mode 自称"上下文问题的另一半"，今天以 +449 收尾榜单，曾登上 Hacker News 第一（570+ 分）。它精准描述了编码 Agent 的一个普遍困境：**每次 MCP 工具调用都把原始数据倒进上下文**——一次 Playwright 快照 56KB、20 个 GitHub issue 59KB、一条访问日志 45KB，半小时后 40% 的上下文就没了；而当 Agent 为腾空间压缩对话时，又会忘记自己在编辑哪些文件、进行到哪一步、你上一句要它做什么，同时还在寒暄和废话上浪费输出 token。它是一个 MCP server，从四个面系统解决这个问题。项目 2026 年 2 月创建，采用 ELv2 许可证。

四个解法各有针对性：① **Context Saving（上下文节省）**——用沙箱工具把原始数据挡在上下文窗口之外，315KB 变成 5.4KB，**约 98% 的缩减**；② **Session Continuity（会话连续性）**——每次文件编辑、git 操作、任务、错误和用户决策都记录进 SQLite，对话压缩时不把数据倒回上下文，而是把事件索引进 FTS5、用 BM25 只检索相关内容，让模型精确地从断点继续；若不用 `--continue`，上一段会话数据立即删除、干净重来；③ **Think in Code（用代码思考）**——与其把 50 个文件读进上下文来数函数，不如让 Agent 写一段脚本去数、只 `console.log` 结果，"一个脚本替代十次工具调用、省 100 倍上下文"，并把这条范式强制推广到全部 17 个支持的客户端；④ **No prose-style enforcement**——它只负责把原始数据挡在外面，**绝不规定模型最终回答该怎么写**，理由是引用 Moonshot 的研究表明"强制简短"反而会降低编码和推理基准，路由层只该管"数据去哪"，不该管"模型怎么说话"。

工程实现上，它在 Claude Code 里通过插件市场一键安装，注册 PreToolUse、PostToolUse、UserPromptSubmit、PreCompact、SessionStart、Stop 六个钩子和 11 个 MCP 工具（6 个沙箱工具如 `ctx_execute`、`ctx_search`，5 个元工具如 `ctx_stats`、`ctx_doctor`、`ctx_purge`）；SessionStart 钩子在运行时注入路由指令、不往项目里写文件；还提供 `ctx-doctor` 诊断、状态栏实时显示"本会话/累计节省了多少 token"。对 Gemini、其他不支持钩子的平台则给出一次性格子的路由文件方案，覆盖 17 个客户端和 OpenClaw 网关。

💡 可借鉴的优点

- **产品思维**：把抽象的"上下文不够用"拆成"原始数据灌入、压缩即失忆、不会用代码算、废话占位"四个具体可治的病因，并给出可量化的节省数字（98%、100x），痛点和收益都极其具体
- **架构设计**：沙箱执行（数据不入上下文）+ SQLite 事件日志 + FTS5/BM25 按需检索 + 脚本化分析，构成"数据外置、按需召回"的完整闭环；六个钩子覆盖工具调用与压缩的全生命周期
- **工程化**："只管数据去哪、不管表达风格"是非常清醒的边界设计，并有研究依据；doctor 诊断命令、一次性 MCP-only 试用路径、状态栏可观测、按平台复杂度分级安装
- **社区运营**：HN 第一的讨论背书、企业用户徽章、Discord 与托管洞察看板；清晰区分"全自动钩子集成"与"需手动复制路由"的平台，不夸大兼容性

🌟 特别亮眼的地方

context-mode 和今天的 xerj 是一对"上下文工程"双璧：xerj 解决的是"**怎么找到需要的那一小段**"，context-mode 解决的是"**怎么让其余一切都别进上下文、同时还不丢记忆**"。它最有见地的一点是第四条——在整个行业都在给 Agent 加"少废话、直接答"的指令时，它明确反对替模型规定表达风格，并把这种克制建立在基准测试证据之上。这种"只做一件事、严守边界、用数字说话"的设计哲学，正是基础设施类工具最该有的样子。👉 任何被 Agent 上下文爆炸、频繁压缩失忆、token 账单困扰的开发者，context-mode 都是当前最对症、跨平台最广的开源工具，也是"上下文工程"产品化的上乘范例。
