📖 项目是干什么的

Agent Reach 今天从昨天的第 4（+696）一跃登顶，以 +1,696 成为全场最热——这是 Agent 赛道轮动以来，"联网能力层"第一次压过所有"思考方法论"。它一句话概括自己："给你的 AI Agent 一键装上互联网能力"。痛点极其具体：Agent 已经能写代码、改文档、管项目，但你让它去网上找点东西就抓瞎——看 YouTube 教程拿不到字幕、搜推特发现 API 要付费、去 Reddit 直接 403、看小红书必须登录、总结 B站视频被风控全面拦截，抓个网页回来全是 HTML 标签。项目 2026 年 2 月创建，Python 编写，采用 MIT 许可证，目前近 9 万 star。

它最关键的自我定位是：**Agent Reach 是一个能力层（capability layer），不是又一个工具**。它比任何具体实现高一层，负责选型、安装、体检、路由，而不做底层读取的包装——真正的读取由 Agent 直接调用上游工具完成，没有中间层。每个平台都被建模成「首选 + 备选」的有序后端列表，渠道文件会真实探测各候选后端，第一个完整可用的当选，坏掉的给出修复处方；换接入方式等于调整列表顺序，而不是重写代码。比如 yt-dlp 被 B站风控以 412 封死时，它就把 B站路由切到 bili-cli，用户零操作。

从支持矩阵能看出它在"啃硬骨头"：网页、YouTube 字幕、RSS、V2EX、雪球等零配置即用；GitHub、Twitter、B站、LinkedIn 配置后解锁；Reddit、Facebook、Instagram、小红书这些没有零配置路径的，则统一走 OpenCLI 复用用户已有的真实 Chrome 会话。全网搜索走 Exa、以 MCP 接入免 key。安装方式也极符合 Agent 时代——把一句"帮我安装 Agent Reach"丢给 Agent，它自己读文档、装 CLI、体检基建；`agent-reach doctor` 一条命令告诉你每个渠道当前走哪条后端、通不通、怎么修。

💡 可借鉴的优点

- **产品思维**：把"给 Agent 配网络环境"这件人人都要反复踩坑的脏活，收敛成"一句话安装 + 一句话体检"；诚实把平台分成"零配置即用 / 配置后解锁 / 必须登录"三档，不夸大能力
- **架构设计**："能力层管选型路由、上游工具管实际读取"的分层非常干净，杜绝包装层；有序后端列表 + 真实探测 + 自动 failover，把爬虫世界"反爬与反反爬"的长期军备竞赛，抽象成可维护的路由配置
- **工程化**：默认安全（`install` 只检查不改系统，显式 `--system` 才写入，另有 `--dry-run`）；凭据本地 600 权限、不上传；自带 doctor 诊断、tests、CI、CONTRIBUTING/SECURITY/CHANGELOG 全套
- **社区运营**：README 提供中英日韩多语言、llms.txt、国内镜像；用赞助商位形成"能力层 + 上下游服务"生态；并主动反复提醒"Cookie 登录有封号风险，请用专用小号"

🌟 特别亮眼的地方

一天之内热度翻 2.4 倍、登顶全场，说明开发者已经用 star 完成了一次价值重估：当"怎么思考"的技能严重内卷，"能摸到哪个真实世界"才是更稀缺、更痛的能力。它最深刻的洞察是承认**「接入方式必然会换代」**——单平台 CLI 会停更、API 会收费、风控会升级——于是不押注任何单一工具，而是把"选型与换代"本身做成产品。这正是单个开发者最不愿自己维护、也最愿意外包出去的部分。👉 任何要让 Agent 真正联网干活（尤其要碰 B站、小红书、Reddit、Twitter 这些硬平台）的开发者，以及想学习"能力层 / 可插拔路由"架构范式的人，Agent Reach 都是目前最成体系、最接地气的开源参考。

📖 项目是干什么的

ponytail 把一个经典职场形象装进了 AI Agent——那个扎着马尾、比版本控制系统还早进公司的"最懒资深开发"：你给他看五十行代码，他一言不发，直接换成一行。项目口号是"最好的代码是你从没写过的代码"，它让 Agent 在动手写代码前先走一道「懒惰阶梯（ladder）」。项目 2026 年 6 月创建，采用 MIT 许可证，官方称可与约 20 种编码 Agent 协作。连续两天霸榜第一后，今天它以 +1,281 退居第二，但热度仍处于极高水位，总 star 稳步来到 15.3 万。

这道阶梯按顺序停在第一个成立的层级：① 这东西需要存在吗？不需要就跳过（YAGNI）；② 代码库里已有？复用而非重写；③ 标准库能做？用标准库；④ 平台有原生特性？用原生（比如日期选择直接用 `<input type="date">`，而不是装 flatpickr、写组件、加样式、再讨论时区）；⑤ 已装依赖能做？用它；⑥ 能一行？就一行；⑦ 只有这些都不满足，才写"最小可工作"的代码。关键在于：阶梯在理解问题之后才运行——"懒于解决方案，但绝不懒于阅读"；而信任边界校验、数据丢失处理、安全性和可访问性永远不在削减之列。

它最难得的是基准做得极其诚实。作者用无头 Claude Code 去编辑 tiangolo 的真实开源仓库 full-stack-fastapi-template，以留下的 git diff 为准，跑 12 个功能任务、每组重复 4 次：相比无技能基线，代码量 -54%、token -22%、成本 -20%、耗时 -27%，且安全性 100%。它还专门设置 caveman（只压缩文风）和裸提示作为对照组，并主动修正自己早期单局测试宣称 80-94% 的虚高数字。

💡 可借鉴的优点

- **产品思维**：用一个人人都见过、会心一笑的"懒汉资深开发"人格承载方法论，比干巴巴的 YAGNI 原则好记得多；"少写代码但不砍安全"把价值和边界同时讲清
- **架构设计**：七级阶梯本质是一套有序的决策优先级（复用 > 原生 > 依赖 > 新增），把资深工程师的隐性直觉显式化、可执行
- **工程化**：基准设计堪称典范——真实仓库、真实任务、可复现、有对照组、区分均值与极值，还敢于自我修正；提供 Claude Code/Codex/Copilot 插件和 Cursor hooks
- **社区运营**：多语言 README、Trendshift 日/周/月徽章、waitlist 与"已用 ponytail 构建"的作品展示，把社会证明做足；连续三天高位，口碑正在复利

🌟 特别亮眼的地方

把榜首让给 Agent Reach 但仍以 +1,281 高居第二，恰恰说明"对抗过度构建"是长期刚需而非一日热点。编码 Agent 最常见的毛病不是写得不够多，而是急着装依赖、写包装、加抽象；ponytail 用一道"先问该不该存在"的阶梯系统性纠偏，更用严谨、敢于自我修正的基准证明"少写"不等于"偷工减料"。👉 任何想给编码 Agent 注入"资深工程师品味"、或想学习如何为 Agent 行为做可信基准的团队，这都是必看项目。

📖 项目是干什么的

ECC 是今天的三张新面孔里体量最庞大的一个，一上榜就以 +897 冲到第 3。它把自己定位成「**Agent Harness 操作系统（the agent harness operating system）**」——不是给你几个技能，而是想一整套接管 Agent 的运行环境。项目由单名维护者 affaan-m 维护，2026 年 1 月创建，采用 MIT 许可证，短短八个多月积累 27.2 万 star、4 万 fork，维护者称自己"每周跨 7 个 harness 发布"。今天它提供了与"轻量技能集"截然相反的另一种答案：大而全、开箱即用。

它的体量本身就是卖点：**68 个 agents、293 个 skills、94 个遗留命令垫片**，外加 hooks、记忆、持续学习和 AgentShield 安全扫描。68 个 agents 按规划、评审、构建修复、安全、架构、领域工作分工；293 个 skills 覆盖 TDD、调研、安全、文档、前端、数据、ML、运维；hooks 与记忆层负责强制执行、会话摘要、持续学习、"本能（instincts）"和上下文管控；而 AgentShield 专门扫描提示词、hooks、MCP 配置、权限、密钥和 agent 文件，防止供应链投毒。

安装与商业化设计得很清晰。开源仓库 MIT 永久免费，通过 `npx ecc-universal@2.2.3 setup` 引导安装（当前 2.2 版支持 Claude Code、Codex、Kimi Code，另有 Cursor、Antigravity、Gemini、OpenCode 等托管适配器）；商业版 ECC Pro 是一个 GitHub App，面向私有仓库，按 19 美元/席位/月收费。它还极其强调"只从官方渠道安装"，警告第三方重传可能夹带恶意软件，并要求"每个 harness 只选一种安装方式、不要叠加"，避免重复技能与 hooks。

💡 可借鉴的优点

- **产品思维**："操作系统"的定位把零散的技能/记忆/安全/编排收敛成一个完整心智；开源永久免费 + 私有仓库 GitHub App 收费，边界划得很干净，个人与企业各取所需
- **架构设计**：agents（按职能分工）/ skills（按领域覆盖）/ hooks-memory（运行时强制与学习）/ AgentShield（安全扫描）四层各司其职，是"全家桶"里少见的有清晰分层的设计
- **工程化**：引导安装器会先盘点官方市场和所有安装范围再动手，支持 `--dry-run`、doctor 诊断；明确不自动上传诊断数据；对"叠加安装""版本锁定不等于安全审计"等坑都有显式提醒
- **社区运营**：README 翻译达 14 种语言，用 CodeRabbit、Greptile、Moonshot Kimi 等赞助商位构建生态，Discord + GitHub App + npm 多入口分发，社会证明与渠道工程都很扎实

🌟 特别亮眼的地方

当榜单上大多数项目都在做"小而美、可组合、不夺权"时，ECC 勇敢地站到了"大而全、我全都管"的另一端，并且真的把一个单人维护的项目做到了 27 万 star、每周跨 7 个 harness 迭代。它最值得研究的是**商业化与开源的协同**：用 MIT 开源把个人用户和口碑做到极致，再用"私有仓库 GitHub App"这一企业愿意付费的形态变现，赞助商和采用伙伴又反过来供养开源。👉 如果你想要开箱即用、带安全扫描和持续学习、不想自己拼装几十个技能，ECC 是"全家桶"路线目前最完整的样本；只是要清楚它选择的是"被操作系统接管"，与 mattpocock/skills、pi 的轻量路线正好相反。

📖 项目是干什么的

这是 TypeScript 教育专家、Total TypeScript 创始人 Matt Pocock 每天用来做"真正工程（real engineering），而非 vibe coding"的个人 Agent 技能集。它的设计哲学是小、易适配、可组合、与任何模型兼容，明确和 GSD、BMAD、Spec-Kit 这类"试图接管整个流程、却夺走控制权"的重型方法论划清界限。项目 2026 年 2 月创建，采用 MIT 许可证，今天以 +751 排在第 4（昨天 +955），总 star 达 27.5 万，是榜单上 star 总数最高的项目之一。

它围绕编码 Agent 的三大失败模式组织技能。第一，"Agent 没做出我想要的"——本质是需求错位，解法是 `/grill-me`、`/grill-with-docs`，让 Agent 在动手前用一连串尖锐问题把需求问透，这也是作者最受欢迎的技能。第二，"Agent 太啰嗦"——借用领域驱动设计（DDD）"通用语言"的思想，建立项目术语表和 ADR，用一个精确术语替代一长串解释，让命名更一致、思考更省 token。第三，"代码不工作"——核心是补上反馈闭环，让 Agent 基于代码实际运行结果迭代，而不是盲目飞行。

安装上它刻意提供"两种哲学"：Claude Code 插件以托管、只读、自动更新的方式装整套（"订阅"）；skills.sh 则把可编辑的技能文件复制进项目（"拥有并改造"）。安装后运行一次 `/setup-matt-pocock-skills`，它会询问 issue 追踪器、分诊标签和文档保存位置。

💡 可借鉴的优点

- **产品思维**：把"重型流程框架 vs 轻量可组合技能"的取舍讲得很透，用"订阅 vs 拥有"两条安装路径尊重不同习惯；每个技能都对应一个具体、高频的失败模式
- **架构设计**：技能按 productivity / engineering 分层、按需组合，而非一个大而全的流程黑箱；grilling（对齐）→ 共享语言（降熵）→ 反馈闭环（验证）构成完整工程链路
- **工程化**：用 ADR 记录难以言说的决策，把 DDD 的通用语言迁移到 Agent 协作；setup 技能通过一次性问答把工具适配到具体仓库
- **社区运营**：作者用 newsletter 作为技能更新与分发的私域渠道，skills.sh 徽章和官方插件市场共同构成曝光入口，连续多日高位

🌟 特别亮眼的地方

当 ECC 这样的"操作系统"试图把一切都接管、pi 只给你一个极简内核时，Matt Pocock 占据了中间的甜点位：只提供小而锋利的技能积木，把判断权和改造权留给工程师。它把《程序员修炼之道》《领域驱动设计》这些经典工程思想，重新编码成 Agent 能直接执行的工作流。👉 如果你觉得重型 Agent 流程框架让你失控、又不想从极简内核自己拼装，这套"grill 对齐 + 通用语言 + 反馈闭环"的轻量组合，是最贴近真实工程习惯的选择。

📖 项目是干什么的

impeccable 是一套给 AI 编码 Agent 用的"设计语言"——1 个技能、24 个命令、实时浏览器迭代，外加 61 条确定性检测器规则，专治 AI 生成前端那股一眼就能认出的"模板味"。它的立论非常精准：如今每个模型都在同一批 SaaS 模板上训练，跳过设计指导，你就会在每个项目里看到同样的"破绽（tells）"——什么都用 Inter 字体、紫到蓝的渐变、卡片里套卡片、彩色背景上压灰字、每个标题上方都顶着一个圆角方块图标。项目由 Paul Bakaus 维护，2025 年 11 月创建，采用 Apache-2.0 许可证。今天它 +699 排在第 5（昨天 +722），连续多日稳定在榜。

用法是从项目根目录运行 `npx impeccable install`，再在 AI 工具里执行 `/impeccable init`。`init` 会先检查项目，只就"持久产品真相"中真正缺失的部分提问，把受众、目的、使用场景、约束、语气写进 `PRODUCT.md`，视觉系统则单独记录在 `DESIGN.md`。24 个命令构成共享设计词汇：`polish`、`audit`（无障碍/性能/响应式）、`critique`、`distill`、`bolder`/`quieter`、`harden`（错误处理、i18n、文本溢出）、`layout`、`colorize`、`delight`、`generate`（在实时浏览器里生成多个变体）等。

最硬核的是那 61 条确定性检测器：CLI 和浏览器扩展无需 LLM、无需 API key 就能跑，覆盖 AI slop（侧边标签边框、紫色渐变、弹跳缓动、暗色光晕）和通用设计质量（行宽、拥挤 padding、过小触控目标、跳过的标题层级）。技能本身不依赖运行时——每个副本带一个小启动器，运行自包含二进制，Node 只在 npx 安装器里出现。

💡 可借鉴的优点

- **架构设计**：技能（命令词汇）+ 确定性检测器（二进制）+ 浏览器扩展三层分工，确定性规则不烧 token、LLM 只负责需要判断力的批评，把贵的推理用在刀刃上
- **工程化**：设计 hook 深度接入各 harness——Cursor 能在坏代码写入前拦截，Claude/Codex/Copilot 在编辑后回灌发现；CLI 提供 `--json`、明确 exit code（0/2/1），可直接进 CI
- **社区运营**：一个安装器自动识别 17+ 种 harness（Claude Code、Codex、Cursor、Copilot、Gemini、Grok、Trae、Antigravity 等），并为每个平台的信任机制写清说明，兼容性工程极其扎实

impeccable 第一次把"设计品味"做成了可执行、可检测、可进 CI 的工程资产，而不是一句"做得更好看些"的模糊指令。它用 61 条确定性规则证明：审美里相当大一部分，其实是能被 lint 的。连续多日稳定在榜，说明"去 AI 味"已是前端团队的普遍诉求。👉 任何在用 Agent 写前端、却受困于"模板味"的团队，或想学习如何把垂直专长做成跨平台技能的开发者，impeccable 都是目前最完整的样板。

📖 项目是干什么的

caveman 把一句 meme 式口号做成了正经产品——"why use many token when few token do trick（为什么用很多 token，很少的 token 就能搞定）"。它的洞察很直接：你的 Agent 按词计费，却写得像在写求职信、读得像在喝消防水管。项目 2026 年 4 月一个周五玩笑式起步，一周冲到 4,000 star，如今已破 10.9 万；今天它从昨天榜外（+209）大幅升温，以 +507 冲进前 10。项目采用 Apache-2.0 许可证，主体用 Go 编写，同时发布 npm 与 PyPI 包。

它从"说"和"读"两端同时压缩，提供三件套。**技能（skill）** 压缩 Agent 说出口的内容——一个规则文件、永久免费、适配 30 多种 Agent；**代理（proxy）** 跑在你本机、夹在 Agent 和 AI 提供商之间，压缩 Agent 读到的日志、测试输出、JSON、diff、搜索结果，每个被压缩的字节都有备份、随时可取回原文；**中间件（middleware）** 让你在自己的代码里包一层 LangChain、Vercel AI SDK、OpenAI 或 Anthropic 调用，工具结果在进模型前先缩水。官方给出的例子是：一段 63 token 的 React 重渲染解释，被压成 20 token——"New object ref each render, so React re-renders. Wrap the prop in `useMemo`."，诊断、修复、`useMemo` 完全一致，死掉的只有开场白。

关键边界划得很清楚：代码、命令、文件路径、确切错误信息从不被"穴居化"，只压缩围绕它们的散文；安全警告和"你确定吗？"确认会以完整句子单独返回，之后才恢复穴居人口吻——"Caveman no make brain smaller. Caveman make mouth smaller.（穴居人没有让脑子变小，只是让嘴巴变小）"。它如今已被 Adobe Research 的论文 CAVEWOMAN 引用（测得穴居式输出能把成本降低 1.4 到 2.4 倍、最高 3 倍），JetBrains 也在 86 个真实编码任务上实测"质量上无可测量的损失"，并有 ThePrimeagen 的反应视频。

💡 可借鉴的优点

- **产品思维**：用一句极具传播力的 meme 口号承载真实的省钱价值，记忆点拉满；技能/代理/中间件三种形态，分别覆盖"用现成 Agent""自建 Agent 应用"两类用户
- **架构设计**："说"与"读"两端分离、压缩与备份成对出现（任何缩水都可取回原文），把有损压缩做成了可回退的安全操作；安全信息永不压缩，边界清晰
- **工程化**：一个 Go 核心同时分发到 npm、PyPI、skills.sh，原生 wrap 10 种 Agent、适配 30+；一条 `npx skills add` 即可安装，无需账号和 API key
- **社区运营**：主动集齐"学术论文 + 大厂实验室实测 + 头部 KOL 视频 + Hacker News/Product Hunt 上榜"四类社会证明，把一个玩笑项目的可信度堆到了严肃产品的水平

🌟 特别亮眼的地方

caveman 证明了一件反直觉的事：**最容易被砍掉、又完全不伤质量的成本，藏在 Agent 的"礼貌性废话"和"原始数据洪流"里**。它没有试图让模型更聪明，而是用最朴素的"少说、少读、可回退"直接砍掉 65% 的 token，更难得的是用论文和大厂实测把"省了但没变差"这件事钉死。今天它与 context-mode 同台，恰好代表省 token 的两条路线——caveman 连文风带输入一起压、context-mode 只压数据流且明确不碰行文风格。👉 任何在为 Agent 账单头疼、或想学习如何给一个 meme 想法建立严肃可信度的开发者，caveman 都是最有趣也最实用的样本。

📖 项目是干什么的

context-mode 自称"上下文问题的另一半"，是专门给 AI 编码 Agent 做上下文窗口优化的 MCP server。它先把问题量化：每次 MCP 工具调用都把原始数据倒进上下文——一次 Playwright 快照 56KB、20 个 GitHub issue 59KB、一条访问日志 45KB，半小时吃掉 40% 窗口；而 Agent 为腾地方压缩对话时，又会忘掉正在编辑哪些文件、手头有哪些任务；同时还在填充词、客套话上从另一侧烧 token。项目 2026 年 2 月创建，TypeScript 编写，今天仍有提交。它今日 +256，是 Top 10 里唯一未达 300 门槛、按补齐规则入选的项目（昨天 +282），已连续多日在榜。

它从四个面系统求解。① **节省上下文**：沙箱工具把原始数据挡在窗口外，315KB 变 5.4KB（98% 缩减）。② **会话连续性**：每次文件编辑、git 操作、任务、错误、用户决策都记进 SQLite；压缩对话时不把数据倒回上下文，而是索引进 FTS5、用 BM25 只检索相关片段，让模型精确"从上次停下的地方"接上。③ **用代码思考**：与其把 50 个文件读进上下文数函数，不如让 Agent 写脚本去数、只 `console.log` 结果——一次脚本替代十次工具调用、省约 100 倍上下文，核心主张是"别把 LLM 当数据处理器，要把它当代码生成器"。④ **不干预行文风格**：只管数据往哪去，不规定回答怎么写，并引用研究指出激进的"少说话"提示反而拉低编码与推理基准。

它提供 11 个 MCP 工具：`ctx_execute`（12 种语言跑代码，只有 stdout 进上下文）、`ctx_batch_execute`、`ctx_execute_file`、`ctx_index`/`ctx_search`、`ctx_fetch_and_index`（抓取、转 markdown、分块索引，带 TTL 缓存）以及 stats/doctor/upgrade/purge；`gh`、`aws`、`gcloud`、`kubectl`、`docker` 等已登录 CLI 通过凭证透传继承配置、却不把凭证暴露给对话。

💡 可借鉴的优点

- **产品思维**：把"上下文窗口"这个抽象焦虑，用 56KB、40%、98% 一组具体数字讲成用户能直接感知的成本；区分"数据进不进窗口"和"回答怎么写"两个问题，边界感清晰
- **架构设计**：沙箱（原始数据不外泄）+ SQLite/FTS5（持久记忆）+ 代码执行（让 LLM 生成分析程序）三件套正交；输出超 5KB 且给意图时自动切到"意图驱动过滤"，全量入库、只返回匹配片段
- **工程化**：检索层下足功夫——BM25 + Porter 词干 + 标题 5 倍权重，再用 Reciprocal Rank Fusing 融合词干与 trigram 两套策略，辅以邻近词重排、Levenshtein 纠错、智能片段和 TTL 清理，几乎是一个小型检索引擎的完整实现
- **社区运营**：为 17+ 平台逐一给出安装与 hook 配置，诚实标注每个平台能力差异（Cursor 不回传 hook、Antigravity/Zed 需手工放规则、Codex 部分能力受版本门控），兼容性矩阵透明到罕见

🌟 特别亮眼的地方

"上下文工程"是 2026 年 Agent 领域最核心的命题之一，context-mode 是把它讲得最成体系、最工程化的开源代表。它最深刻的主张——让 LLM 写代码处理数据，而不是把数据喂给 LLM 自己处理——重新划定了"模型干什么、沙箱干什么"的分工；而"不插手行文风格"的克制，又与 caveman 的"连文风一起压"形成鲜明对照，避免了多数输出约束工具牺牲推理质量的通病。它连续多日以补齐规则在榜，说明价值被持续认可。👉 任何构建长周期、跨会话编码 Agent 的团队，或想系统理解上下文工程包含哪几块的开发者，它的"沙箱 + 持久记忆 + 代码思考"都是目前最完整的开源参考实现。

## 📊 今日趋势洞察

- **核心方向**：**从「能力层闭合」到「能力层领跑」，对外触手首次压过对内方法论**。Agent Reach 一天之内从 #4（+696）冲到 #1（+1,696），热度翻 2.4 倍；连续两天第一的 ponytail（+1,281）退居第二。当"Agent 怎么思考"的技能严重内卷，开发者真正愿意额外 star 的，变成了"让 Agent 摸到多真实的世界"——联网能力层正在成为 Agent 栈里最被低估、最痛的一层。
- **升温领域**：**一张榜单集齐「地基 → 内核 → 全家桶 → 方法论 → 触手」完整栈谱**。新面孔 ECC（+897，68 agents/293 skills/安全扫描，"大而全操作系统"）、pi（+408，极简可扩展内核、刻意不做 subagent/plan mode）、effect（+302，函数式 TS 地基：类型化错误/DI/并发/可观测）分别占据全家桶、极简内核、生产地基三个位置；叠加 superpowers（完整 SDLC）、skills（轻量组合）、Agent Reach（联网触手），Agent 技术栈的纵向光谱今天前所未有地完整。
- **值得注意的信号**：**「省 token」赛道分化并获得严肃背书**。caveman 从榜外（+209）升温到 +507 冲进前 10，如今有 Adobe Research 论文（成本降 1.4-2.4 倍）和 JetBrains 86 个真实任务实测（质量无可测量损失）背书；它与连续在榜的 context-mode（+256）代表两条路线——caveman 连文风带输入一起压、context-mode 只压数据流且明确不碰行文风格。"怎么省 token"正从玄学变成有论文、有实测、有方法论的工程命题。
- **对开发者的启发**：① 选 Agent 框架先想清楚自己要哪一极——ECC/superpowers 的"全家桶强流程"、skills 的"轻量组合"、还是 pi 的"极简内核自己装"，没有绝对优劣，只有是否匹配你的掌控欲；② 别忽视联网能力层，尤其要碰 B站/小红书/Reddit/Twitter 时，学 Agent Reach 用"多后端可替换路由"而非押注单一工具，并坚守 Cookie 用小号、凭据本地存储；③ 省 token 优先砍"礼貌废话"和"原始数据洪流"，但代码/错误/安全警告绝不能压，且任何压缩都要可回退；④ Agent 应用最终仍需可靠地基，effect 所代表的类型化错误、结构化并发和可观测性，是从 demo 走向生产绕不开的功课。
