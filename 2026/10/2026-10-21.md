📖 项目是干什么的

这是一个跑在你自己机器上的 AI 求职框架，核心思路是把 Claude Code（CLI）变成一个全栈求职助手：你 fork 仓库、填好个人档案，然后用 `/setup`（建立档案）、`/scrape`（抓取招聘门户）、`/apply <职位URL>`（评估匹配度并生成定制简历+求职信）三条命令走完整个投递流程。作者本人是地球物理学家，2025 年底被裁员后用这套工作流每周跑自己的求职，最终 69 份定制申请、20 场一面、1 份签约，2026 年 6 月以 AI 工程师身份入职——README 用这个真实漏斗作为全部说服力的来源。

技术栈上，它不是一个独立应用，而是一套"prompt + 技能 + 脚本"的工作流骨架：主体是 Python 3.10+ 脚本（`tools/` 目录下约 15 个脚本负责安装 CLI、PDF 校验、安全门禁），招聘门户抓取用 Bun 写的零依赖 CLI，简历和求职信用 LaTeX 编译——CV 走 lualatex，求职信走 xelatex。扩展点设计得很克制：`/add-portal` 可以为任意本地招聘网站自动脚手架一个新门户技能，`/add-template` 可以注册 LaTeX / Typst / 任意命令行可编译 PDF 的模板。

工程化细节是这个项目最硬的部分。`/apply` 采用 drafter–reviewer 双代理分离：起草代理写完后，再起一个全新上下文的评审代理去调研公司并挑刺，然后起草代理修改。之后强制走 PDF 校验循环——Claude 自己读渲染出来的页面，迭代 LaTeX 直到 CV 恰好 2 页、求职信恰好 1 页。更特别的是 ATS 校验：用 `pdftotext` 抽取 PDF 文本层，模拟 ATS 系统"读内嵌文字"而非"看渲染图"的行为，并严格执行诚实原则——简历不支持的关键词承认是 gap，绝不堆砌。仓库目前近 400 次提交、18.9k forks，MIT license。

💡 可借鉴的优点

- **产品思维**：作者没有做成 SaaS，而是"fork 即用"的个人工作流仓库，把求职这种强隐私场景的数据完全留在用户本地，并专门警告"fork 一定是 public"、给出"用私有仓库 + upstream"的配方，隐私边界讲得极清楚。
- **架构设计**：三条核心命令 + 十余个扩展命令（`/rank` 批量打分、`/outcome` 记录结果、`/interview` 面试准备等），门户技能通过统一契约被 `/scrape` 自动发现，新增门户零注册零接线。
- **工程化**：把 agentic 工作流当代码工程对待——`posting_guard.py` 对职位描述做确定性完整性门禁，`robots_check.py` 把带浏览器 header 的重试挡在 robots.txt 之外，所有 Agent 产出要进外部系统（PDF、邮件）的地方都用脚本做客观校验。
- **社区运营**：用 Discussion 做社区门户索引，各国市场适配的招聘门户 fork 都挂在那里，并把安全审查环节故意做成手动步骤写进 README 当安全决策而非缺功能。

🌟 特别亮眼的地方

它最有信号意义的地方在于：证明了"AI 应用"的下一种形态可能不再是 Web 产品，而是一套以 coding agent 为运行时的、可 fork 的工作流仓库——prompt、技能、CLI、LaTeX 模板、CI 全部版本化，用户把自己的私有数据填进去就得到一个专属系统。drafter–reviewer 分离、PDF 自校验循环、ATS 文本层校验这三件事，把"生成一份看起来不错的文档"提升到了"生成的文档在真实下游系统里真的可用"的程度，这是大多数 LLM 简历工具跳过的最后一公里。👉 面向正在做 agentic workflow / AI SaaS 的开发者：可以直接借鉴它的"确定性门禁 + agentic 生成"分层设计——凡是 Agent 产出要进入外部系统的地方，都用脚本做客观校验、用新上下文的第二代理做主观评审，而不是让单个 Agent 自说自话。

📖 项目是干什么的

security-audit-skill 是 Cloudflare 开源的一个 coding-agent 技能，把你的编码代理变成一名安全审计员。它不是扫描器，而是一套编排多个隔离子代理、分六个阶段跑完的审计方法论，核心主张是"发现漏洞的代理和验证漏洞的代理必须是两拨人"。README 明说这正是 Cloudflare 内部漏洞发现 harness 的种子——那套 harness 后来长成了跨团队的多阶段系统，而这个仓库是它最初的单仓库起点。

六个阶段依次是：①侦察（映射架构、信任边界、输入面、既有证据，并建立确定性的覆盖账本 coverage ledger）；②猎捕（从账本单元派发隔离的猎手，记录每项检查，用覆盖批评者找盲区）；③验证（把每个候选交给一个全新的验证者去尝试证伪）；④结构化输出（写 `confirmed` / `needs_validation` / `rejected` 三种裁决的 findings.json，并用校验器核对）；⑤独立复核（新代理复核最终源码主张，重大替换再派一个独立验证者）；⑥报告（从已验证记录和覆盖账本派生出目标中立的报告）。整个流程由父代理用零依赖的 `validate-coverage-ledger.cjs` 和 `validate-findings.cjs` 在每次账本/发现更新后反复校验。

三种裁决的定义极其克制：`confirmed` 必须有完整的源码追踪链和有界的观测结果，`needs_validation` 有一个确切的未解事实且不给严重度，`rejected` 记录一个被证伪的候选。多次对同一仓库运行是累加的——它用既有账本和发现去瞄准盲区、复验改动过的源码、把当前源码证据往前带，而不把陈旧或未解的工作当成已覆盖。README 坦诚写明：在他们的测试运行里，单次运行大约只能发现重复运行累计发现漏洞的一半。仓库目前 14 次提交、2.1k forks，MIT license，并留了 `security-ai-research@cloudflare.com` 做交流。

💡 可借鉴的优点

- **产品思维**：Cloudflare 把一套本应是内部竞争优势的安全审计方法论直接开源，并诚实标注"单次运行只能找到一半"这种对自己不利的数据，建立了可信度；按 `npx skills add` 一键安装，门槛极低。
- **架构设计**：严格的"发现者≠验证者"隔离，加上覆盖账本（coverage ledger）这个确定性记账层，把 LLM 审计最大的毛病——幻觉报告和覆盖黑洞——用工程手段摁住；三种裁决各有硬性准入条件，拒绝"大概有问题"的模糊结论。
- **工程化**：用零依赖的 `.cjs` 校验器在每一步做机器校验，findings 和 coverage 都有 JSON schema 和配套测试；强制要求 OS 级沙箱（禁外网、净化环境、资源限额、只许写指定 scratch 路径）才执行目标代码，否则把线索标为 blocked 而非冒险执行。
- **社区运营**：按攻击面把猎捕提示词拆成十几个专题文件（内存安全、Web 协议与认证、客户端、供应链与发布、云与部署、RPC 与消息、数据隔离与生命周期等），每一类都是独立可复用的方法论资产。

🌟 特别亮眼的地方

这个项目踩中的趋势是：安全审计正在从"规则扫描器"转向"多代理协作的方法论"，而方法论本身被封装成了可一键安装的技能。它最值得抄的工程决策是把"审计覆盖度"做成了显式的确定性账本，而不是依赖 LLM 自己声称"我看完了"——这正好解决了 Agent 审计最致命的覆盖黑洞问题。"发现者和验证者永远不是同一个代理"这条原则，和 #1 ai-job-search 的 drafter–reviewer 分离、以及今天多个项目的"第二代理复核"遥相呼应，说明 2026 年 Agent 工程的一条共识正在成形：**单个 Agent 自评不可信，可信度来自隔离的独立验证 + 确定性记账**。👉 面向做安全工具或任意高风险 Agent 流程的开发者：可以直接借鉴它的六阶段隔离编排和覆盖账本设计，把"是否已覆盖"从一句模型自述变成一份可校验的结构化记录。

📖 项目是干什么的

Orca 定位是"给 100x builder 的 AI 编排器"：一个桌面端 IDE，但它不自己做编码模型，而是当各种 CLI 编码代理的"驾驶舱"——Claude Code、Codex、Grok、Cursor CLI、GitHub Copilot、OpenCode、Devin、Goose、Cline 等约 40 种 CLI agent 都能在里面并排跑，用户用自己的订阅，Orca 不卖模型、不抽成。它解决的真实痛点是：现在一个人可能同时订阅三四个编码 agent，每个都跑在自己的终端窗口里，切换、对比、管理状态全靠人肉；Orca 把这些代理统一收进一个界面，并让它们以 git worktree 为隔离单位并行工作。

技术栈是典型的 Electron 桌面应用 + pnpm monorepo，终端是"Ghostty 级别"的 WebGL 渲染终端，编辑器内嵌 VS Code。核心机制里最值得拆的是 Parallel Worktrees：一条 prompt 可以扇出给五个 agent，每个 agent 在自己独立的 git worktree 里干活，用户对比结果后 merge 赢的那个。围绕这个能力，Orca 配了一整套闭环功能——原生浏览 GitHub PR / issue 和 Linear 看板、在 AI 生成的 diff 任意行上挂评论并送回给 agent 继续改、SSH worktree（把 agent 跑在远端高配机器上）、Design Mode（在真实 Chromium 窗口里点任意 UI 元素，把它的 HTML/CSS 和裁剪截图直接塞进 agent 的 prompt）、以及手机伴侣 App。仓库万余次提交、6.3k forks，MIT license，README 明说"我们每天发版"。

💡 可借鉴的优点

- **产品思维**：不造模型、不做托管，做"代理无关的编排层"——支持的 CLI agent 列表长达 40 个，把自己定位成 agent 时代的浏览器/容器，模型换成谁都不影响它的价值，规避了被某一家模型厂商吃掉的风险。
- **架构设计**：用 git worktree 做多代理隔离是教科书级选择——并行任务之间天然文件隔离、可 diff、可 merge，不需要自己发明沙箱；同时提供 SSH worktree 把同一套模型延伸到远端机器，本地/远程统一抽象。
- **工程化**：Electron + WebGL 终端 + pnpm monorepo（cloud/mobile 各自独立 workspace）的工程体量下保持 daily ship；桌面、手机、relay 三端同仓维护，还有配套的签名构建和隐私说明。
- **社区运营**：README 提供六语言版本（含中文、日文、韩文），Discord + X + 微信社群，star history 图和贡献者墙直接嵌进 README，社区存在感做得很足。

🌟 特别亮眼的地方

Orca 踩中的趋势是：编码 agent 正在从"单个人用单个 CLI"走向"一个人同时指挥一整队 agent"，而真正稀缺的不是模型，而是 orchestration——并行隔离、结果对比、review 回路、跨设备监控。它把 IDE 本身重新定义为一个"agent fleet 的指挥台"。值得注意的是它和 #4 opencode 是互补而非竞争——Orca 把 OpenCode 列进了一等支持列表，生态位选得很聪明。👉 面向做 dev tool / agent 平台的开发者：可以照搬"fleet + worktree"的编排范式——当你的产品需要同时跑多个 agent 时，优先复用 git worktree 这种现成隔离原语，把工程量花在对比界面、批注回传和完成通知上，而不是自己造任务隔离层。

📖 项目是干什么的

OpenCode 自称"The open source AI coding agent"——一个开源的终端编码代理（TUI），对标 Claude Code、Codex CLI 这类闭源/半闭源工具，但整个仓库 MIT 开源。它的核心价值主张是：你可以用自己任意的 LLM provider 订阅跑一个编码 agent，而不被绑死在某一家的 CLI 里。用户在终端里对话，agent 可以读写文件、跑命令、做多步任务。安装极其分散化：一行 `curl` 脚本，或 npm、Homebrew 双 tap、pacman、AUR、mise，甚至 Nix flake——包管理器覆盖之全在同类项目里罕见。

技术栈是 TypeScript monorepo：`packages/` 多包 + `turbo.json` 构建编排 + Bun 做运行时和包管理，基建部分用 SST 和 Nix flake，还带 `sdks/vscode`、`services/`、`infra/`、`perf/` 目录——说明它不只是一个 CLI，还在维护服务端、VS Code SDK 和性能基线。内置 agent 模型设计得很克制：两个用 `Tab` 键切换的主 agent——`build`（默认，全权限开发）和 `plan`（只读探索，默认拒绝改文件、跑 bash 前要授权，适合读陌生代码库），外加一个内部 `general` 子 agent 处理复杂搜索和多步任务。除了 TUI，还有 BETA 阶段的桌面 App。仓库 218.9k stars、29.2k forks、2 万余次提交，维护了 22 种语言的 README，MIT license。

💡 可借鉴的优点

- **产品思维**："开源 + 自带 provider 无关"直击编码 agent 市场的最大焦虑——用户不想把工作流绑死在 Claude 一家的订阅上；同时用 `build` / `plan` 双权限档（全权限 vs 只读+命令授权）把"agent 乱改文件"的信任问题在交互层解决，Tab 一键切换成本极低。
- **架构设计**：TUI CLI 是唯一第一方界面，但通过 `general` 子 agent + `@` 调用协议扩展复杂度，不堆砌 agent 数量；monorepo 里同时维护 CLI、VS Code SDK、桌面 App、services 和 HTTP API，对外部集成者透明。
- **工程化**：安装渠道全到 npm / Homebrew 双 tap / pacman / AUR / mise / Nix / 一键 curl 全平台铺开，且安装路径有四级优先级兜底；Bun + Turbo monorepo + Nix flake 的工具链组合说明发布工程高度自动化。
- **社区运营**：22 语言 README、Discord + X 社群、明确的商标规则（"如果你的项目名字里有 opencode，必须在 README 注明与官方无关"），对一个 20 万 star 的项目来说品牌治理已经制度化。

🌟 特别亮眼的地方

OpenCode 的行业意义在于它是"开源对抗闭源编码 agent"这条路线的标杆样本：21 万 star、29k fork、2 万次提交的体量证明，开发者社区愿意用脚投票支持一个不锁订阅、API 可审计的开源替代品。它把 Claude Code 类工具的核心体验（终端 TUI、多步 agent、文件/命令工具调用）完整复制，同时用 provider 无关和 MIT license 拆掉对方的护城河。值得注意的是它和 #3 Orca 形成了上下层关系——Orca 把 OpenCode 列为一等支持的 CLI agent 之一，终端 agent 和编排 IDE 正在分层。👉 面向想做开发者工具或 agent 平台的开发者：OpenCode 的分发策略（一个 CLI 同时进 7 种包管理器 + 一键 curl 兜底）和权限分档（build/plan 用 Tab 切换）是低成本高回报的范本——如果你的产品是 CLI 工具，先把安装渠道铺到用户的既有工作流里，再把"只读探索"和"全权执行"做成一键切换，比堆功能更能建立信任。

📖 项目是干什么的

Ponytail 是一个让 AI 编码代理"像房间里最懒的资深开发者那样思考"的技能，口号是"最好的代码是你永远没写的代码"。它把那个形象具象化——留着马尾、戴椭圆眼镜、在公司比版本控制还资深的老工程师：你给他看五十行，他什么都不说，换成一行。Ponytail 做的就是把这个人塞进你的 AI agent。它本质是一个提示词（`skills/ponytail/SKILL.md`，精简版是 `AGENTS.md`），仓库里其它一切都是把这个提示词装进不同 agent 的适配层。

Ponytail 5 号称从头重建，官方给出的基准是：在 Claude Code 里用同一个 agent 开/不开该技能、39 个任务（含一个真实 FastAPI + React 仓库）、Opus 5.5、各跑 5 次——代码量 -53%、时间 -41%、成本 -26%、token -45%。但更关键的数字是：带风险的逻辑有 98% 随附测试发车（不开 ponytail 时只有 68%），六个安全任务（SQL 注入、路径遍历、伪造令牌、限流、畸形 CSV 行、缓存）30 次运行全过——代码更少但不更不安全。它反复强调规则从来不是"最少 token"，而是"只写任务需要的，但验证、错误处理、安全、可访问性绝不砍"，代码小是因为必要而非 golf。

功能上，`/ponytail-review` 像被 paged 的资深开发者那样评审当前 diff（读改动触及的代码而非只读 diff，检查 bug、安全、真实负载、缺失测试、速度、该删什么），`/ponytail-audit` 对整个仓库跑同样的检查并按优先级排序，`/ponytail-debt` 把代码里 `shortcut:` 注释收集成技术债账本。5.3 版在 Claude Code 里加了提示框上方的"band"条，实时显示当前任务的成本、token、agent 用时、代码复用率和测试是否通过。安装覆盖 Claude Code、Codex、Cursor、OpenCode、Gemini、Copilot、Kiro 等十余种 harness，MIT license。

💡 可借鉴的优点

- **产品思维**：精准定位了 AI 编码的一大隐性成本——agent 倾向于过度工程、重复造轮子；用一个极具人格化的隐喻（懒资深开发者）把"少写代码"这个抽象原则变得可感知、可传播，还给出 before/after 实例（日期选择器 335 行 → 复用现有 Input + 浏览器原生 → 10 行）。
- **架构设计**：核心只有一个提示词文件，所有适配层都加载同一份 SKILL.md/AGENTS.md，换 harness 不换方法论；明确区分"对解法懒、对读代码绝不懒"——先理解问题、读改动触及的代码、追真实流程，再决定砍什么。
- **工程化**：带可复现的基准测试（公开方法、逐任务表格、限制说明），band 条把成本/token/测试状态做成实时可见，`/ponytail-debt` 把"shortcut:"注释制度化为技术债账本，让"以后再说"不变成"永远不做"。
- **社区运营**：多语言 README（中/西/韩/日），明确的供应链警告（"只从 DietrichGebert/ponytail 或 @dietrichgebert/ponytail 安装，它从不发 .exe/.dll"），FAQ 用老工程师的人格口吻写得极有辨识度。

🌟 特别亮眼的地方

Ponytail 代表了"技能"这一形态的一种成熟用法：它不给 agent 加能力，反而给 agent 加约束——这与昨天榜上的 i-have-adhd（让 agent 少废话）是同一思路的延续，说明"用约束而非能力提升 agent 体验"正在成为一个独立品类。它最硬的地方是把一个纯提示词项目做出了可复现的量化基准（-53% 代码、98% 风险逻辑带测试），并且诚实地把"安全/验证/可访问性绝不砍"写进第一原则，避免了"少写代码"滑向"偷工减料"。band 条把 token 成本和测试状态实时推到开发者眼前这个细节，也呼应了今天榜上多个项目对"成本可见、可控"的共同关注。👉 面向做 agent 技能或 prompt 工程的开发者：可以借鉴它"用人格化隐喻承载工程原则 + 用可复现基准背书"的打法，以及"对解法懒、对读代码勤"这条可直接写进 SKILL.md 的清晰边界。

📖 项目是干什么的

ComfyUI 是一个基于节点图（graph/nodes interface）的扩散模型创作引擎，同时提供 GUI、Python API 和后端服务，官方自称"世界上最快的本地推理引擎"。它解决的问题是：Stable Diffusion、Flux 这类模型的参数极多，单一 Prompt 框式界面无法控制采样器、VAE、LoRA、ControlNet 之间的接线关系，而 ComfyUI 把整条推理流水线拆成可拖拽、可复用的节点，让创作者像搭电路一样搭建图像、视频、音频、3D 的生成工作流。工作流可保存为 JSON，也能从生成的图片里反解出完整工作流和种子。

💡 可借鉴的优点

- **产品思维**：同一份引擎做了多层分发——桌面 App（新手一键装）、Windows portable 压缩包、手动 pip 安装、Comfy Cloud 云版，把"不会装环境"的用户和"要嵌流水线"的工程师同时接住；App Mode 能把复杂节点图封装成简单表单给运营用。

- **社区运营**：custom_nodes 第三方节点生态 + ComfyUI-Manager 扩展负责节点安装更新，模型一发布，社区节点通常几天内就适配完。

🌟 特别亮眼的地方

ComfyUI 实际上已经成为扩散模型时代的"事实标准工作台"：每出一个新 SOTA 模型，社区的第一反应往往是"有没有 ComfyUI 节点/工作流"，它把模型发布转化成了可分享、可复用的图形化资产。它今天还能日增 1k star，靠的不是某个单点功能，而是"模型跟进速度 + 本地推理性能 + 节点生态"三件事同时在线——README 里那一长串 2026 年新模型的支持清单就是最直接的证据。它和今天的 Kronos、以及这些天的"本地优先"主线一起说明：在生成式 AI 领域，"可控性"本身就是产品力。👉 做 AI 工具链或多媒体管线的开发者，值得直接读它的 execution.py 与节点注册机制，学它如何把推理流水线做成可局部重算、可 API 化的 DAG 服务。

### #7 Graphify-Labs/graphify ⭐

| 属性 | 信息 |

📖 项目是干什么的

Graphify 是一个 `/graphify` 技能，在 AI 编码助手里输入它，就能把整个项目（代码、文档、PDF、图片、视频）映射成一张可查询的知识图谱，让你用"查图谱"代替"grep 翻文件"。它的核心取舍很鲜明：代码用 tree-sitter AST 本地解析——确定性、无 LLM、不出本机（文档/PDF/图片/视频才走助手的模型或配置的 API key 做语义处理）；每条连接都打标签，`EXTRACTED`（源码里显式存在）或 `INFERRED`（由 graphify 解析推导），让你分得清哪些是直接读到的、哪些是推断的；而且没有 embedding、没有向量库——是一张你真正去遍历的图。

用法是 `uv tool install graphifyy` 装 CLI、`graphify install` 自动检测助手并注册技能，然后在助手里打 `/graphify .`，产出三个文件：`graph.html`（浏览器里点节点、过滤、搜索）、`GRAPH_REPORT.md`（关键概念、惊喜连接、建议问题）、`graph.json`（完整图，随时查而不必重读文件）。能力上包括 God nodes（最高连接度的概念）、Communities（用 Leiden 算法把图切成子系统、无 LLM 打标签）、跨文件链接（calls/imports/inherits/mixes_in，经 tree-sitter AST 在约 40 种语言间解析）、`query`/`path`/`explain` 三种查询（问问题、追两点之间的路径、解释一个概念），以及把 `# NOTE:` / `# WHY:` 注释和 ADR/RFC 引用变成一等节点。

基准上它给出 LOCOMO recall@10 0.497（对比 mem0 0.048、supermemory 0.149）、LongMemEval-S QA 准确率 76%（与密集 RAG 持平），且建图消耗 0 LLM credits——评测用同一 harness、同一模型、盲校验的双评审（90.6% 一致、Cohen's kappa 0.81）。官方有 Graphify Cloud 商业版做持续、跨仓、形式化验证和 Sentry/Jira 连接器。CLI 开源，Apache-2.0/MIT 双许可，2,463 次提交。

💡 可借鉴的优点

- **产品思维**：精准切入"agent 在大代码库里靠 grep 翻文件、烧 token"这个痛点，给出"建一次图、随后查图"的替代路径，并用开源 CLI 做入口、Graphify Cloud 做持续化商业版（号称省 80% agent token），开源/商业分层清晰。
- **架构设计**：代码走确定性 AST、不出本机，只有非代码才走模型——隐私和确定性优先；用真正的图遍历而非 embedding/向量库，每条边带 `EXTRACTED`/`INFERRED` 置信标签，可解释性直接做进数据结构。
- **工程化**：用 Leiden 社区发现 + 无 LLM 标签把大图切成子系统，God nodes 指出枢纽概念；产出 `graph.json` 带 schema_version 和 graphify_version 便于集成检测格式变更；基准用盲校验双评审，可复现命令公开。
- **社区运营**：`graphify install` 一键适配 20+ 助手（Claude Code、Cursor、Codex、Gemini、Copilot 等）、全平台，30+ 语言 README；明确警示官方包是 `graphifyy`（双 y），防李鬼。

🌟 特别亮眼的地方

Graphify 代表了"技能化"浪潮里一个很有工程含量的方向：把"代码库理解"这件 agent 每天都要做、却极烧 token 的事，用确定性 AST 建图 + 可遍历知识图谱一次性解决，而不是每次都让 agent grep。它最值得抄的是"代码走确定性本地解析、非代码才走模型"的分层，以及把 `EXTRACTED`/`INFERRED` 置信标签做进每条边——这正好反驳了"记忆/理解必须靠向量库 + LLM 摘要"的主流叙事。它和今天的 security-audit-skill、ponytail、agency-agents 一样用 `install` 一键进二十多种 harness，共同印证了技能分发格式的标准化。👉 做 Agent 平台或代码智能工具的开发者，可以直接参考它"派生索引可重建、图谱可解释、建图零 LLM"的存储哲学。

### #8 shiyu-coder/Kronos ⭐

| 属性 | 信息 |

📖 项目是干什么的

Kronos 是首个面向金融 K 线（candlestick）的开源基础模型，在全球 45+ 交易所的数据上预训练，定位是给金融市场这门"语言"造一个 decoder-only 大模型。它明确区别于通用时间序列基础模型（TSFM），专门处理金融数据高噪声、多维 OHLCV 并存的特性，目标是成为一个能统一支撑多种量化任务的底座。

核心是两阶段框架：先由专用 tokenizer 把连续的多维 K 线数据量化成分层离散 token（hierarchical discrete tokens），再用一个大的自回归 Transformer 在这些 token 上做预训练。官方在 Hugging Face（组织名 NeoQuasar）发布了三档开放权重——mini（4.1M 参数，context 2048）、small（24.7M，ctx 512）、base（102.3M，ctx 512），499.2M 的 large 暂未开源。推理侧封装了 KronosPredictor 类，自动处理数据预处理、归一化和反归一化，几行代码即可出预测；支持 T（温度）、top_p、sample_count 做概率采样，并用 predict_batch 在 GPU 上并行预测多资产。

论文为 arXiv:2508.02739《Kronos: A Foundation Model for the Language of Financial Markets》，已于 2025.11.10 被 AAAI 2026 接收。代码 MIT License，要求 Python 3.10+；官方附带基于微软 Qlib 的 A 股微调全流程（数据预处理 → torchrun 多卡分别微调 tokenizer 和 predictor → top-K 策略回测），并反复 disclaimer：demo 输出只是原始信号，不是生产级量化系统，真实策略还需组合优化与风险因子中性化。在线 demo 展示了 BTC/USDT 未来 24 小时的预测曲线。

💡 可借鉴的优点

- **产品思维**：KronosPredictor 把预处理、归一化、反归一化全部藏起来，用户只需喂入含 open/high/low/close 列的 DataFrame 和时间戳；另给 predict_wo_vol 示例照顾没有成交量数据的用户，把"用基础模型"的门槛从团队级降到脚本级。
- **架构设计**："领域 tokenizer 先把 OHLCV 量化为分层离散 token + decoder-only 自回归 Transformer"的两阶段范式，把 LLM 在文本上验证过的成熟路径迁移到金融时序；mini/small/base/large 四档容量覆盖从笔记本到服务器的不同算力。
- **工程化**：微调管线与微软 Qlib 深度集成，tokenizer 与 predictor 两阶段训练拆开、用 torchrun 多卡启动；预测可采样多条路径取平均做概率预测。
- **社区运营**：Hugging Face 全量开放权重 + 实时 Live Demo + 八语言 README + 官方 BibTeX 引用格式，学术开放度和可复现性都很规范。

🌟 特别亮眼的地方

Kronos 的意义在于把"金融 K 线是一种语言"这个类比工程化：当 BERT/GPT 式的"离散 token + decoder-only"范式在文本上被反复验证后，它证明同一套范式可以迁移到高噪声的 OHLCV 时序上，而且是开源权重里少有的、预训练数据覆盖 45+ 全球交易所的金融基础模型。论文中稿 AAAI 2026 也说明主流学术会议对"垂直领域基础模型"这条路线的认可。它和今天的 ComfyUI、以及这些天的"本地、垂直、紧跟模型迭代"主线一起印证：在通用大模型之外，"为某个具体领域、某种具体数据形态专门造模型或工作台"正在成为新的创新密度区。👉 做时序预测或垂直领域基础模型的开发者，值得重点参考它的两阶段设计（先学领域 tokenizer、再训 decoder），以及"开源预训练底座 + Qlib 式行业数据微调 + 回测验证"这套从 demo 到生产的完整交付范式。

📖 项目是干什么的

ruflo（前身 Claude Flow，作者 Reuven Cohen 即 rUv）给自己的定位是"Agent 元 Harness"：它不自己训练模型，而是套在 Claude Code 和 Codex 外面的执行层。README 的第一性原理是"Agent = Model + Harness"——模型负责写，harness 负责给它工具、记忆、循环、沙箱和权限控制。ruflo 干的就是这件事：一次 `npx ruflo init` 给 Claude Code 装上"神经系统"，内置 100+ 专职 Agent、Swarm 群体协作、跨会话自学习记忆、跨机器联邦通信和企业级安全护栏，让多个 Agent 不是各跑各的而是组队协作。

技术栈是 TypeScript/Node 生态：通过 npm 包 `ruflo` 分发，提供 CLI、MCP server、hooks 和后台 daemon 四种形态。安装分两条路：轻量路是 Claude Code 插件市场 `/plugin marketplace add ruvnet/ruflo`，只给斜杠命令和 Agent 定义、工作区零污染；完整路是 `npx ruflo@latest init wizard`，装上 98 个 Agent、60+ 命令、30 个 skill、MCP server 和 hooks。记忆层是 HNSW 索引的 AgentDB 向量库，README 附了 benchmark 结论：N=20k 时比暴力检索快约 1.9 倍、recall@10 约 0.99。最有野心的模块是 Agent Federation——README 称之为"Agent 的 Slack"：跨机器/跨组织的 Agent 通过 mTLS + ed25519 验证身份，出站消息先过 14 类 PII 检测管线，行为信任分动态升降，全程审计日志可接 HIPAA/SOC2/GDPR 合规模式。MIT license。

💡 可借鉴的优点

- **产品思维**：把安装拆成"Lite 插件试玩（零文件污染）"和"Full CLI 生产部署"两条路，并明确告诉你各自文件落在哪、MCP 注册了什么；控制台还给 Claude 开放 read/write/manage/full 四档控制权，且默认 read + ask，危险动作即使 auto 也要确认。
- **架构设计**：用户 → Ruflo(CLI/MCP) → Router → Swarm → Agents → Memory → LLM providers 的分层清晰；联邦层把"跨信任域协作"抽象成身份校验 + PII 管线 + 信任评分三件套，不要求用户手动配证书。
- **工程化**：向量记忆带公开 benchmark 脚本和日期审计报告；关键行为有 ADR 文档和 e2e 复现脚本，不吹空指标；`ruflo eject` 可把项目导出成独立工具包。
- **社区运营**：35 个插件每个都有独立 README 和目录、配 plugin-creator 脚手架让用户自己发插件；README 中英双语，还写了一篇 14 章的《RuFlo Explained》教程和"起源可查验"页面（贴出首个 commit hash）来回应身份争议。

🌟 特别亮眼的地方

ruflo 代表了 2026 年 Agent 工具链的一个明显走向：竞争点正在从"单个编码 Agent 多聪明"转向"harness 层怎么组织一群 Agent"——Swarm 拓扑、自学习轨迹、跨机器联邦、成本追踪和安全护栏，都是模型本身不提供、必须由外围层补齐的东西。它把自己叫 meta-harness 是准确的：连"你的 Agent 配置好不好"都做成了评分插件（MetaHarness）。值得注意的是它的诚实度：README 里多处明确标注"这是概念示意图，不是真实执行轨迹""数据为示例""mods 跑在你账号权限下、装前先审代码",在一个容易夸大宣传的赛道里反而建立了可信度。👉 做 Agent 平台或编排框架的开发者，重点读它的 federation 文档和 swarm 拓扑设计——跨 Agent 信任与数据出域控制，会是下一个企业落地绕不开的模块。

📖 项目是干什么的

agency-agents 自称"一个随叫随到的完整 AI 代理公司"——从前端魔法师到 Reddit 社区忍者、从奇思注入者到现实核查员，每个 Agent 都是一个带人格、带流程、带可交付物的专家角色。项目源自一个 Reddit 帖子和数月迭代，核心主张是：每个 Agent 都有深度领域专长（不是通用提示词模板）、独特的声音与沟通风格、真实代码/流程/可量化产出、以及经过实战检验的工作流和成功指标。你把它想成"组建你的梦之队，只不过他们是永不睡觉、永不抱怨、永远交付的 AI 专家"。

角色库按部门组织成一棵目录树：engineering（前端、后端架构、移动端、AI 工程、DevOps、网络工程、嵌入式固件、事件响应指挥官等）、design、finance、healthcare、gis、game-development、marketing、paid-media、product、project-management、academic 等十几个 division，每个 Agent 是一个 `.md` 文件，内含身份与人格特质、核心使命与工作流、带代码示例的技术交付物、成功指标与沟通风格。

分发有四条路：①推荐装原生桌面 App（agencyagents.app，macOS/Linux/Windows，浏览整个角色库并一键装进 Claude Code、Cursor、Codex、Gemini、OpenCode、Qwen、Osaurus 等，自动更新，Mac 可 `brew install --cask`）；②`./scripts/install.sh --tool claude-code` 脚本安装；③当参考资料手动复制；④`./scripts/convert.sh` + `install.sh` 为 GitHub Copilot、Antigravity、Gemini CLI、OpenClaw、Cursor、Aider、Windsurf、Kimi、Codex、Osaurus、Hermes 等十余种工具生成集成文件并交互式安装。还支持按 division/agent 粒度选装、用 `strategy/runbooks.json` 的 runbook 成团安装。MIT license，837 次提交、26.2k forks——注意它语言标为 Shell（安装脚本），本体其实是 Markdown 角色文件集合。

💡 可借鉴的优点

- **产品思维**：把"一堆 prompt"做成了"一家可雇佣的 AI 代理公司"的叙事，按真实公司部门组织角色，降低用户的选择成本；并专门做了跨平台原生 App 把"浏览角色库 + 一键安装 + 自动更新"做成零终端体验。
- **架构设计**：每个 Agent 是一个自包含的 `.md`（身份/使命/工作流/交付物/指标/风格），用 `convert.sh` 把同一份角色转换成十余种工具的集成格式，一份角色多处复用；用 runbooks.json 把"一个场景需要哪几个 Agent 组队"固化下来。
- **工程化**：安装器支持 `--division`/`--agent`/`--agents-file` 多粒度选装、`--dry-run` 预演、`--list` 查看团队和角色数；甚至为 OpenCode 只注册约 119 个 agent 的上游 bug 做了超限警告——对一个角色库来说工程细节相当到位。
- **社区运营**：26.2k forks、1150 watch 说明社区二次创作极活跃；多工具集成文档齐全，App 走 GitHub Releases + Homebrew cask 双渠道分发。

🌟 特别亮眼的地方

agency-agents 踩中的是"技能化"浪潮的另一面——不是单个强力技能，而是把成规模的 Agent 人格做成可浏览、可成团安装的角色库，并用一个跨平台 App 把分发体验抹平。它证明了"Agent 角色"本身正在成为一种可分享、可复用的内容资产：从 Reddit 帖子长成 16 万 star、26k fork 的角色生态，靠的是把每个角色都做成带人格、带可交付物、带成功指标的自包含文件，而非一句话提示词。它和今天的 security-audit-skill、ponytail、graphify 一起,用同一套"一键装进 20+ harness"的分发逻辑,共同印证了技能/角色分发格式的标准化——Agent 的能力和人格都在被封装成可移植的包。👉 做 Agent 工具生态的团队，值得抄它两件事：一是"按真实组织结构组织角色、用 runbook 成团交付"的内容组织法，二是"一份角色定义 → convert 成多工具格式 → 跨平台 App 一键装"的分发链路。

## 📊 今日趋势洞察

### 核心方向

1. **技能（Skill）正在成为 Agent 能力的标准封装与分发格式**：今天四个新上榜项目——cloudflare/security-audit-skill（安全审计方法论）、DietrichGebert/ponytail（YAGNI 行为约束）、Graphify-Labs/graphify（代码库知识图谱）、msitarzewski/agency-agents（跨领域角色库）——形态完全不同，却共享同一套工程范式：核心是 `SKILL.md` / `AGENTS.md` 提示词文件，通过 `npx skills add`、`/plugin marketplace add`、`graphify install`、`install.sh` 一键装进 Claude Code、Codex、Cursor、Gemini、OpenCode 等二十多种 harness，换 Agent 不换方法论。Agent 能力、方法论乃至人格，都在从"绑死在某个 CLI"变成"可移植、可版本化、可跨工具复用的包"。
2. **单 Agent 自评不可信，可信度来自隔离验证**：security-audit-skill 的"发现者≠验证者"六阶段隔离 + 覆盖账本、ai-job-search 的 drafter–reviewer 分离 + PDF/ATS 客观校验、ponytail 的"风险逻辑必带测试"——三者不约而同指向同一条共识：Agent 产出进入真实/敏感环节时，可信度来自隔离的独立验证 + 确定性记账，而不是让单个 Agent 自说自话。

### 升温领域

1. **编排与群体智能（Orchestration）**：stablyai/orca（一提示词扇出五代理、worktree 并行择优）和 ruvnet/ruflo（自组织蜂群、跨机器联邦、信任评分）解决的都是"怎么组织一群 Agent"。竞争点正从"单个 Agent 多聪明"转向"harness 层怎么编排一整队 Agent"——并行隔离、结果对比、review 回路、跨设备监控、跨信任域协作。
2. **成本与上下文工程**：ponytail 的 band 条把 token/成本/测试状态实时推到开发者眼前、graphify 用确定性建图替代 grep 省 80% agent token，共同说明"省 token、控成本、让成本可见"正在从技巧变成一等工程目标。
3. **本地优先与垂直/紧跟模型**：Comfy-Org/ComfyUI（近 14 万星、节点生态、2026 新模型几天内适配）与 shiyu-coder/Kronos（金融 K 线基础模型、中稿 AAAI 2026）分别从多媒体生成与金融时序两个方向印证，"本地跑得动 + 紧跟最新模型 + 把垂直场景做深"依然是开源工具最稳固的护城河。

### 对开发者的启发

- **如果你在做 Agent 能力/工具**：今天的榜单强烈建议把能力做成"技能"而非绑死的 CLI——用 `SKILL.md` / `AGENTS.md` 做核心、用一键 `install` 适配二十多种 harness、用可复现基准背书。能力、方法论、人格都能被封装成可移植的包，分发格式的标准化已成事实。
- **如果你在做高风险 Agent 流程**：直接借鉴 security-audit-skill 与 ai-job-search 的"隔离验证 + 确定性记账"——发现者和验证者永远不是同一个代理，凡 Agent 产出要进外部系统的地方都用脚本做客观校验、用新上下文的第二代理做主观评审。
- **如果你在做编排平台**：参考 Orca 的"fleet + worktree"和 ruflo 的 federation/swarm——优先复用 git worktree 这类现成隔离原语，把工程量花在对比界面、批注回传、跨信任域协作和成本追踪上。
- **一个值得贯穿的共性**：今天最受信任的项目都在做"克制"与"诚实"的工程决策——ponytail 把"安全/验证/可访问性绝不砍"写进第一原则、security-audit-skill 诚实标注"单次只找到一半"、Kronos 把"不是稳赚信号"的 disclaimer 写得很醒目、ruflo 明确区分"概念示意图"与"真实执行轨迹"。当 Agent 深入真实工作与敏感数据，**保守的默认值、可复现的指标、诚实的边界感，正在成为 Agent 项目赢得生产级用户的关键品质。**
