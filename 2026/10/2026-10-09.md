📖 项目是干什么的

rea 是一个**本地逆向工程工具**，核心创新在于把 MCP（Model Context Protocol）代理连接到 Hopper、Ghidra 等专业逆向工具和应用运行时行为分析上。它不是又一个反编译器，而是一个"代理驱动的逆向分析工作台"——让 AI 代理能够直接操作逆向工具、读取二进制分析结果、追踪运行时行为，从而自动化逆向分析流程。

昨日它以 +4,700 登顶，今日 +7,700 蝉联第一，两天累计 +12,400，总星从 15.2K 飙升至 26.5K，增长速度惊人。这种爆发式增长说明安全社区对"AI 辅助逆向"的需求极其强烈——逆向工程是一个高度依赖经验和耐心的领域，AI 代理的加入可能显著降低分析门槛。

它的定位非常精准：传统逆向工具功能强大但操作繁琐，AI 代理擅长推理但缺乏直接操作专业工具的能力。rea 通过 MCP 协议填补了这个鸿沟，让代理能够调用逆向工具的 API、读取分析结果、执行批量分析任务。项目强调"evidence and limitations"（证据与局限性），不夸大 AI 能力，明确标注分析结果的可信度。

💡 可借鉴的优点

- **产品思维**：精准切入"AI 代理 + 专业工具"的交叉地带，做代理与现有工具的桥梁而非重复造轮子
- **增长策略**：连续两日 +4,000 以上的日增，说明"MCP + 专业领域"的组合具有极强的传播力——每个专业领域都可能诞生类似的"rea"
- **工程化**：强调"evidence and limitations"，在安全工具领域这种诚实的设计非常难得
- **架构设计**：基于 MCP 协议的插件化架构，天然支持多种逆向工具和多种代理

🌟 特别亮眼的地方

rea 两天累计 +12,400 星，是近期增长最迅猛的项目之一。它证明了"MCP 驱动的专业工具自动化"不是概念，而是真实的生产力革命。当 AI 代理能够操作 Hopper、Ghidra 这些专业工具时，逆向工程师的工作方式将发生根本变化——从"手动分析每个二进制"变成"指导代理批量分析、人工复核关键结果"。这种"代理做初筛、人类做决策"的模式，可能成为所有专业领域（安全、金融、医疗、法律）AI 化的标准范式。

昨日 +2,700，今日 +4,700，连续两日高速增长，总星从 10.6K 升至 15.8K。这种加速增长说明游戏社区对"PS5 游戏原生 PC 化"的需求正在被快速点燃——当玩家发现不需要购买 PS5 主机也能玩到独占游戏时，传播力是爆炸性的。

技术上，这种"原生移植"比模拟器更激进也更有挑战。模拟器兼容性好但性能损失大，原生移植性能接近原生但需要为每个游戏做适配。AnyPS5 试图通过自动化的二进制转译工具减少人工适配工作量，同时保留原生性能优势。

💡 可借鉴的优点

- **产品思维**：用"原生性能"作为核心卖点，与模拟器形成差异化竞争

- **社区潜力**：游戏开源社区传播力极强，围绕它可以形成移植、兼容性测试、优化补丁等完整生态

🌟 特别亮眼的地方

| 属性 | 信息 |

| 📦 分类 | AI 创意工具 / 图像视频 IDE |

📖 项目是干什么的

artcraft 是一个**面向艺术家和电影人的 AI 图像和视频 IDE**，核心创新是"把提示词变成可编辑的 2D 和 3D 场景制作"。传统的 AI 图像视频工具（如 Midjourney、Sora）是"一次性生成"——你输入一段提示词，得到一张图或一段视频，如果不满意只能重新生成，无法对生成结果进行精细编辑。artcraft 要改变这种模式，把 AI 生成变成一个"可迭代、可编辑"的工程化流程。

它的定位类似于"AI 时代的 Photoshop/After Effects"——不是替代艺术家，而是给艺术家提供更强大的创作工具。艺术家可以在 2D 和 3D 场景中直接编辑 AI 生成的内容，调整光照、相机、物体位置，而不是只能靠"提示词炼金术"来碰运气。

技术栈使用 Rust，这在 AI 创意工具中比较少见（通常是 Python/C++），但考虑到 IDE 需要高性能的实时渲染和交互，Rust 是合理的选择。8.0K 总星 +2,100 日增，对于一个新项目来说增长非常迅猛。

💡 可借鉴的优点

- **产品思维**：精准切中"AI 生成不可编辑"的核心痛点，把"提示词碰运气"升级为"场景化精细编辑"，定位从"玩具"升级为"专业工具"
- **设计理念**："AI 不替代艺术家，而是增强艺术家"——这种定位更容易获得专业创作者的认可，也避免了与纯生成工具的同质化竞争
- **技术选型**：Rust 实现保证了 IDE 的实时渲染和交互性能，这对于创意工具来说至关重要
- **工程化**：把 AI 生成变成"可编辑的场景"，本质上是把创意工作流程化、工程化，这是 AI 创意工具走向专业应用的必经之路

🌟 特别亮眼的地方

artcraft 代表了 AI 创意工具的"第二阶段"——从"一次性生成"走向"可编辑、可迭代的工程化创作"。当 AI 生成的质量越来越高，"能不能编辑"就成了新的瓶颈。艺术家需要的不是"AI 帮我画一张图"，而是"AI 帮我快速迭代一个可精细调整的场景"。artcraft 的出现说明 AI 创意工具正在从"消费级玩具"走向"专业级生产力工具"，这个转变可能催生整个新的创作工具生态。Rust 技术栈的选择也值得关注——它说明这个项目不是简单的 AI API 包装，而是有深度的工程化产品。

📖 项目是干什么的

claude-mem 是一个**专为 Claude Code 用户设计的记忆插件**，核心功能是"自动回忆会话知识"。它使用 SQLite 作为结构化存储、Chroma 作为向量数据库，通过生命周期钩子在 Claude Code 的会话开始、结束、工具调用等关键节点自动保存和检索记忆。

昨日 +578，今日 +670，稳定增长，总星接近 10 万。它解决的是 Claude Code（以及所有 AI 编码代理）的核心痛点：**无状态**。每次新会话，代理都从零开始，不记得之前做过什么、学过什么、用户的偏好是什么。claude-mem 通过在本地存储会话历史、代码上下文、用户偏好，并在新会话开始时自动检索相关记忆注入上下文，让代理能够"记住"之前的工作。

SQLite + Chroma 的双引擎架构既支持精确查询（如"上次修改的文件"），也支持语义检索（如"类似的问题怎么解决的"）。所有记忆存储在本地，不上传云端，保证了代码隐私。

💡 可借鉴的优点

- **产品思维**：精准切中 AI 编码代理"无状态"的核心痛点，用"自动回忆"而非"手动管理"降低使用门槛
- **增长稳定**：连续多日 +500 以上，总星接近 10 万，说明"代理记忆"已经从锦上添花变成不可或缺
- **架构设计**：SQLite（结构化）+ Chroma（向量）双引擎存储，兼顾精确查询和语义检索
- **隐私设计**：所有记忆本地存储，不上传云端，这对于需要处理敏感代码的企业用户至关重要

🌟 特别亮眼的地方

claude-mem 总星接近 10 万，与 vectorize-io/hindsight 一起构成了"代理记忆"赛道的两大热门项目。hindsight 是"通用的代理记忆层"，claude-mem 是"专为 Claude Code 设计的记忆插件"——两个项目的同时火热说明"代理记忆"已经成为 AI 编码工具的标配。claude-mem 的优势在于它的"专用性"——深度集成 Claude Code 的生命周期钩子，能够在最合适的时机保存和检索记忆。本地存储的设计也非常聪明：在代码隐私越来越受重视的今天，"记忆不上云"是一个强卖点。未来每个主流 AI 编码工具都会有自己的记忆系统，而"记忆的质量"可能成为代理工具竞争的下一个战场。

### #10 mvschwarz/openrig ⭐（weekly 榜补齐）

| 属性 | 信息 |

| 💻 语言 | TypeScript |
| 📦 分类 | 开发者工具 / 多 harness 编排 |

📖 项目是干什么的

openrig 的核心抽象一句话：**"harness（代理外壳）包裹一个模型，rig（钻机/套件）包裹你的一堆 harnesses。"** 你用 YAML 定义代理团队、一条命令启动，让 Claude Code 和 Codex 在同一个 rig 里作为一个系统被管理。它把一堆散乱的终端会话，变成一个持久、有组织的团队——你和一个 lead agent 谈想要的结果，它跨团队协调专家，把结果和需要你拍板的决策带回来。

它需要 Node.js 20/22/24 和 tmux，通过 npm 安装。典型流程是 `rig setup` → 在仓库里 `rig up` 启动（示例启动两个 Codex 席位：一个 owner 负责实现、一个 checker 负责复核）→ `rig tui` 看共享看板 → `rig ps` 检查席位就绪 → `rig send` 给 owner 派任务 → `rig queue` 追踪。

它最难得的一点是**极度透明**：用一张大表逐一列出它会在你机器上改动什么——trust settings、可执行 hooks、`~/.tmux.conf`、Codex 的 config.toml、Claude 的 trust 文件等，并明确内置引导**不会**擅自给 `rig` 命令加允许规则，权限放宽必须由用户显式选择。

💡 可借鉴的优点

- **产品思维**："rig 包裹 harnesses"的抽象精准，把"多代理多终端"的混乱收敛为一个可命名、可持久运行的团队单元
- **透明度**：对"会改哪些文件、写哪些 hooks、不做什么"逐条披露，这种诚实对需要写入系统配置的工具是建立信任的关键
- **架构设计**：owner/checker 双席位（实现 + 复核）天然内置质量关卡；lead agent 统筹、专家席位执行，是小尺度的多代理组织
- **工程化**：dry-run 预览、就绪检查、队列追踪、TUI 看板，CLI 工作流闭环完整

🌟 特别亮眼的地方

openrig 与 paperclip、orca 同处"多代理组织"赛道，但它切的是开发者本机最轻量的一层——不做宏大的"公司"，只把你手头几个 harness 管成一个 rig。它对系统改动的透明披露尤其值得所有"会动配置"的开发者工具学习：权限交给用户、默认不越界。在 AI 工具普遍"默认授权、悄悄改配置"的大环境下，这种"先告诉你我会动什么、再问你同不同意"的设计，本身就是一种差异化竞争力。今日作为 weekly 补齐入选，也说明多代理编排工具的热度正在从 daily 榜延伸到 weekly 榜，成为一个持续升温的赛道。
